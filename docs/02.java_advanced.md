# 11. 객체지향 프로그래밍(OOP) 기초

객체지향 프로그래밍(Object-Oriented Programming, OOP)은 컴퓨터 프로그램을 단순한 명령어의 나열로 보지 않고, 독립된 단위인 객체들이 모여서 서로 메시지를 주고받으며 협력하는 형태로 작성하는 프로그래밍 패러다임

- 핵심 지향점:
    + 프로그램의 부품화: 데이터와 이를 처리하는 메서드를 객체라는 하나의 부품으로 결합하여 구조화함
    + 재사용성과 유지보수성: 완성도 높은 객체를 만들어 여러 곳에서 다시 사용하며, 변경 사항이 생겼을 때 해당 객체만 수정하여 부작용을 최소화함

## 11.1 객체, 클래스, 인스턴스
- 객체(Object): 우리가 인지하고 표현하려는 유무형의 모든 실체(예: 자동차, 사람, 은행 계좌 등). 고유한 속성(상태)과 행위(동작)를 가짐
    + 일상생활 속 객체의 예시:
        - 자동차:
            + 속성(필드): 모델명, 색상, 현재 속도
            + 기능(메서드): 출발하기, 가속하기, 브레이크 밟기
        - 은행 계좌:
            + 속성(필드): 계좌번호, 예금주, 잔액
            + 기능(메서드): 입금하기, 출금하기, 잔액조회
- 클래스(Class): 객체를 생성하기 위한 설계도(틀). 객체의 형태와 기능(속성과 행위)을 자바 코드로 사전에 명세해 둔 규격이며 메모리에 실체는 없음
- 인스턴스(Instance): 클래스라는 설계도를 바탕으로 'new' 연산자를 사용하여 힙 메모리에 실제로 만들어진 실체화된 결과물(객체)

## 11.2 클래스의 구성 요소
1. 필드 (Field): 객체의 상태, 속성을 정의한 변수
2. 메서드 (Method): 객체의 동작, 행위, 기능
3. 생성자 (Constructor): 객체가 new로 생성될 때 초기 세팅을 담당

- 형식:
  ```java
  [접근제어자] class 클래스명 {
    // 1. 필드 (객체의 상태, 속성 변수)
    [접근제어자] 타입 필드명;

    // 2. 생성자 (객체의 초기 세팅 담당)
    [접근제어자] 클래스명(매개변수타입 매개변수명, ...) {
      // 초기 세팅 코드
      // ...
    }

    // 3. 메서드 (객체의 동작, 행위 함수)
    [접근제어자] 반환타입 메서드명(매개변수타입 매개변수명, ...) {
      // 실행할 코드
      // ...
      return 반환값;
    }
  }
  ```

- 예시:
  ```java
  public class Car {
    // 필드
    String model;
    int speed;

    // 생성자
    public Car(String model) {
      this.model = model;
      this.speed = 0;
    }

    // 메서드
    public void accelerate() {
      this.speed += 10;
      System.out.println(model + " 속도 증가! 현재 속도: " + speed);
    }
  }
  ```

## 11.3 필드 (Field)
필드(Field)는 클래스 내부(메서드 외부)에 선언되어 객체의 상태와 속성을 정의하는 변수임. 멤버 변수라고도 부름.

### 11.3.1 필드의 주요 특징
- 자동 초기화: 필드는 명시적으로 초기화하지 않아도 객체가 생성될 때 각 자료형의 기본값으로 자동 초기화함.
- 기본값 목록:
    + 정수형 (byte, short, int, long): 0
    + 실수형 (float, double): 0.0
    + 논리형 (boolean): false
    + 문자형 (char): '\u0000' (공백 문자)
    + 참조형 (String, 배열, 클래스 등): null

### 11.3.2 필드 선언 예시
```java
public class Product {
  // 필드 선언 (기본값으로 자동 초기화됨)
  String name;       // null로 초기화
  int price;         // 0으로 초기화
  boolean isSoldOut; // false로 초기화
}
```

## 11.4 객체의 생성과 사용 방법
클래스를 설계도로 삼아 실제 메모리에 실체(객체/인스턴스)를 올리려면 `new` 연산자를 사용해야 하며, 생성된 객체의 멤버(필드와 메서드)에 접근하기 위해서는 도트(`.`) 연산자를 활용함.

### 11.4.1 new 연산자를 통한 인스턴스화 과정
- `new` 연산자는 JVM에게 객체를 저장할 메모리 공간을 힙(Heap) 영역에 할당하도록 요청함.
- 메모리 할당이 완료되면 클래스에 정의된 필드들이 힙 공간에 생성되고, 생성자를 호출하여 초기 설정을 마침.
- 마지막으로 생성된 객체가 위치한 힙 영역의 참조 주소값(Reference)을 반환하여 변수에 대입할 수 있게 함.

### 11.4.2 도트(.) 연산자를 통한 속성 및 기능 제어
- 대입받은 참조 변수 이름 뒤에 도트(`.`)를 붙여서 객체 내부의 변수(필드) 값을 읽거나 수정하고, 함수(메서드)를 호출하여 특정 동작을 수행시킴.

```java
// 클래스 설계도
class Person {
  String name;
  int age;

  void introduce() {
    System.out.println("제 이름은 " + name + "이고, 나이는 " + age + "세입니다.");
  }
}

public class ObjectUsageExample {
  public static void main(String[] args) {
    // 1. new 연산자를 이용한 객체 생성 및 참조 주소 보관
    Person person = new Person();

    // 2. 도트(.) 연산자를 통해 필드에 값 대입
    person.name = "이순신";
    person.age = 30;

    // 3. 도트(.) 연산자를 통해 인스턴스 메서드 호출
    person.introduce(); // 출력: 제 이름은 이순신이고, 나이는 30세입니다.
  }
}
```

## 11.5 생성자 (Constructor)
- 객체가 new 연산자를 통해 메모리에 생성될 때 가장 먼저 호출되어 인스턴스 변수의 초기 세팅을 담당하는 특수한 메서드

- 형식:
  ```java
  [접근제어자] 클래스명(매개변수타입 매개변수명, ...) {
    // 인스턴스 변수 초기화 코드
  }
  ```

- 주요 특징:
    + 반환 타입이 없음: 일반 메서드와 달리 void조차 지정하지 않으며, 이름은 반드시 소속 클래스명과 대소문자까지 일치해야 함
    + 기본 생성자 (Default Constructor): 클래스 내부에 개발자가 생성자를 단 하나도 선언하지 않으면 컴파일러가 매개변수와 코드가 없는 빈 기본 생성자를 자동으로 삽입해 줌. 단, 매개변수가 있는 생성자를 하나라도 정의하면 기본 생성자는 자동으로 생성되지 않으므로 필요시 직접 명시해야 함

```java
public class Member {
  String id;

  // 생성자 정의: 반환 타입이 없으며 클래스명과 동일함
  public Member(String id) {
    this.id = id; // 인스턴스 필드 초기화
  }

  public static void main(String[] args) {
    // 객체 생성 시 생성자에 인수 전달
    Member member = new Member("user1");
    System.out.println("회원 아이디: " + member.id); // 출력: 회원 아이디: user1
  }
}
```

## 11.6 생성자 오버로딩
- 매개변수의 개수와 타입을 다르게 하여 하나의 클래스 내부에 생성자를 여러 개 조립하여 다형성을 제공할 수 있음

- 예시:
  ```java
  public class Book {
    String title;
    String author;

    // 기본 생성자 (개발자가 명시적으로 정의)
    public Book() {
      this.title = "제목없음";
      this.author = "작자미상";
    }

    // 매개변수가 있는 생성자 (오버로딩)
    public Book(String title, String author) {
      this.title = title;
      this.author = author;
    }
  }
  ```

## 11.7 this와 this()
- this: 생성된 자기 자신 객체를 가리키는 참조 변수. 매개변수와 필드명이 같을 때 구별하기 위해 사용
- this(): 같은 클래스 내의 다른 생성자를 호출할 때 사용. 생성자 내부의 첫 줄에만 작성 가능

- 예시:
  ```java
  public class User {
    String name;
    int age;

    public User() {
      this("기본이름", 1); // 다른 생성자 호출
    }

    public User(String name, int age) {
      this.name = name;
      this.age = age;
    }
  }
  ```

## 11.8 패키지와 임포트
- 패키지: 관련된 클래스들을 그룹화하는 폴더 구조
- 임포트(import): 다른 패키지에 있는 클래스를 사용할 때 명시

```java
// 패키지 선언 (클래스의 실제 디렉토리 경로와 매핑됨)
package com.example.project;

// 외부 패키지에 포함된 java.util.ArrayList 클래스 임포트
import java.util.ArrayList;

public class PackageExample {
  public static void main(String[] args) {
    // 임포트한 클래스 사용
    ArrayList<String> list = new ArrayList<>();
    list.add("Hello Package");
    System.out.println(list.get(0));
  }
}
```

## 11.9 캡슐화와 접근 제어자
- 캡슐화: 중요한 데이터를 외부에서 임의로 변경하지 못하도록 은닉하는 기법
- 접근 제어자: private < default < protected < public
- 필드를 private으로 선언하고 Getter/Setter 메서드를 통해 접근을 제어

- 예시:
  ```java
  public class Account {
    private int balance; // 외부 접근 차단

    public int getBalance() {
      return this.balance;
    }

    public void deposit(int amount) {
      if (amount > 0) {
        this.balance += amount;
      }
    }
  }
  ```

## 11.10 변수의 종류와 비교 (지역 변수, 인스턴스 변수, 클래스 변수)
자바 프로그래밍에서 변수는 선언 위치와 static 키워드 사용 여부에 따라 크게 세 가지 종류로 구분되며, 각각 메모리 저장 영역, 생명 주기, 초기화 방식이 다름.

| 구분 | 지역 변수 (Local Variable) | 인스턴스 변수 (Instance Variable / 필드) | 클래스 변수 (Class Variable / 정적 필드) |
| :--- | :--- | :--- | :--- |
| 선언 위치 | 메서드, 생성자, 블록 내부 | 클래스 블록 내부 (static 없음) | 클래스 블록 내부 (static 있음) |
| 저장 영역 | 스택 (Stack) 영역 | 힙 (Heap) 영역 | 메서드 (Method / Static) 영역 |
| 초기화 방식 | 자동 초기화 안 됨 (사용 전 초기화 필수) | 기본값으로 자동 초기화 | 기본값으로 자동 초기화 |
| 생성 시점 | 변수 선언문이 실행될 때 | 객체(인스턴스)가 생성될 때 | 클래스가 메모리에 로드될 때 |
| 소멸 시점 | 선언된 블록이 종료될 때 | 객체가 GC에 의해 소멸할 때 | 프로그램이 종료될 때 |

### 11.10.1 메모리 저장 영역과 생명 주기의 차이
- 지역 변수: 메서드가 호출될 때 JVM 스택 영역의 스택 프레임 내부에 생성됨. 메서드 실행이 완료되면 해당 스택 프레임이 제거되면서 지역 변수도 메모리에서 즉시 소멸함.
- 인스턴스 변수(필드): 객체가 new 연산자로 생성될 때 JVM 힙 영역에 생성됨. 객체가 더 이상 참조되지 않아 가비지 컬렉터(GC)에 의해 수거되어 소멸할 때까지 힙 메모리에 유지됨.
- 클래스 변수(정적 필드): 프로그램 실행 시 해당 클래스가 메모리에 로드될 때 JVM 메서드 영역에 단 한 번 생성됨. 프로그램 전체에서 공유되며, 프로그램이 종료될 때까지 메모리에 유지됨.

### 11.10.2 초기화 방식의 차이가 발생하는 이유
- 인스턴스 변수 및 클래스 변수: 객체의 일관된 속성 상태를 보장하기 위해 선언 시 명시적으로 초기화하지 않더라도 JVM이 각 자료형의 기본값으로 자동 초기화함.
- 지역 변수: 특정 블록 안에서 임시로 사용되는 변수임. 스택 영역은 메서드 호출과 복귀가 매우 빠르게 일어나고 생명 주기가 짧으므로 성능 최적화가 중요함. 따라서 변수 생성 시 메모리를 매번 초기화하는 오버헤드를 피하기 위해 자동 초기화를 수행하지 않음. 대신 사용하기 전에 반드시 직접 값을 할당하도록 유도하며, 초기화되지 않은 지역 변수를 읽으려고 하면 컴파일 에러를 발생시켜 안전성을 보장함.

```java
public class VariableScope {
  // 인스턴스 변수: 힙 영역에 생성되며, 객체마다 독립된 값을 가짐
  int instanceVar;

  // 클래스 변수: 메서드 영역에 생성되며, 모든 객체가 공유함
  static int classVar;

  public void method() {
    // 지역 변수: 스택 영역에 생성되며, 호출 시점에 생성되고 메서드 종료 시 소멸함
    int localVar = 10;

    System.out.println(instanceVar); // 출력: 0 (자동 초기화)
    System.out.println(classVar);    // 출력: 0 (자동 초기화)
    System.out.println(localVar);    // 출력: 10 (명시적 초기화 필요)
  }
}
```

## 11.11 정적(static) 멤버
- static 키워드가 붙은 필드나 메서드는 인스턴스 생성을 하지 않아도 클래스명으로 바로 접근 가능
- 모든 인스턴스가 공유하는 메모리(메서드 영역)에 저장됨

- 예시:
  ```java
  public class MathUtils {
    public static final double PI = 3.14159;

    public static int add(int a, int b) {
      return a + b;
    }
  }
  // 호출: MathUtils.add(10, 20);
  ```

# 12. 객체지향 심화 - 상속(Inheritance)

## 12.1 상속의 개념
- 기존 부모 클래스의 필드와 메서드를 자식 클래스가 그대로 물려받아 확장하는 것
- 자바는 단일 상속만 지원 (`extends` 사용)
- 코드의 중복을 제거하고 다형성을 구현하는 기반이 됨

```java
public class Animal {
  public void eat() {
    System.out.println("냠냠 먹는다");
  }
}

public class Dog extends Animal {
  public void bark() {
    System.out.println("멍멍!");
  }
}
```

## 12.2 메서드 오버라이딩
- 부모 클래스에게 상속받은 메서드를 자식 클래스에서 재정의하는 것
- `@Override` 애노테이션을 붙여주면 컴파일러가 검증해줌

```java
public class Cat extends Animal {
  @Override
  public void eat() {
    System.out.println("츄르를 먹는다");
  }
}
```

## 12.3 super와 super()
- `super`: 부모 객체의 필드나 메서드에 접근할 때 사용
- `super()`: 부모 생성자를 호출. 자식 생성자의 첫 줄에 반드시 부모 생성자가 호출되어야 함

```java
class Parent {
  String name = "Parent";

  Parent() {
    System.out.println("부모 생성자 호출");
  }
}

class Child extends Parent {
  String name = "Child";

  Child() {
    super(); // 부모 생성자 호출 (생략 가능, 컴파일러가 자동 추가)
    System.out.println("자식 생성자 호출");
  }

  void printNames() {
    System.out.println("부모 이름: " + super.name); // 부모 멤버 접근
    System.out.println("자식 이름: " + this.name);
  }
}
```

## 12.4 final 키워드
- 변수: 상수가 되어 값 변경 불가
- 메서드: 자식 클래스에서 오버라이딩 불가
- 클래스: 상속 불가 (예: `String` 클래스는 `final`로 선언되어 있음)

```java
// final 클래스는 상속 불가
public final class FinalClass {
  // final 변수는 값 변경 불가 (상수)
  public static final double PI = 3.14159;

  // final 메서드는 오버라이딩 불가
  public final void printPI() {
    System.out.println(PI);
  }
}
```

## 12.5 Object 클래스
- 자바의 모든 클래스는 암묵적으로 `java.lang.Object` 클래스를 상속받음
- 주요 메서드: `toString()`, `equals()`, `hashCode()`

```java
public class User {
  String name;

  public User(String name) {
    this.name = name;
  }

  // toString 오버라이딩
  @Override
  public String toString() {
    return "User name=" + name;
  }

  // equals 오버라이딩
  @Override
  public boolean equals(Object obj) {
    if (obj instanceof User) {
      User other = (User) obj;
      return this.name.equals(other.name);
    }
    return false;
  }
}
```

# 13. 객체지향 심화 - 다형성(Polymorphism)과 인터페이스

## 13.1 다형성과 업캐스팅/다운캐스팅
- 하나의 부모 타입 변수로 여러 자식 객체를 다룰 수 있는 특징
- 업캐스팅: 자식 객체를 부모 타입에 담는 것 (자동 형변환)
- 다운캐스팅: 부모 타입에 담긴 객체를 다시 자식 타입으로 돌려놓는 것 (명시적 형변환 필요)

```java
Animal myPet = new Dog(); // 업캐스팅
myPet.eat(); // Dog의 오버라이딩된 eat() 실행
// myPet.bark(); // 에러 발생

Dog realDog = (Dog) myPet; // 다운캐스팅
realDog.bark(); // 정상 작동
```

## 13.2 instanceof 연산자
- 참조 변수가 실제로 어떤 타입의 객체를 가리키고 있는지 확인할 때 사용

```java
if (myPet instanceof Cat) {
  Cat myCat = (Cat) myPet;
  myCat.meow();
}
```

## 13.3 추상 클래스
- 미완성 설계도. 구현부가 없는 추상 메서드를 포함할 수 있음
- 자기가 직접 `new`로 객체가 될 수 없음

```java
public abstract class Shape {
  public abstract void draw(); // 구현 강제
}
```

## 13.4 인터페이스의 개념과 구현
- 객체가 수행해야 할 동작의 규격만을 정의
- 다중 구현(`implements`)이 가능

```java
public interface Flyable {
  void fly();
}

public class Bird extends Animal implements Flyable {
  @Override
  public void fly() {
    System.out.println("파닥파닥 날아감");
  }
}
```

## 13.5 인터페이스의 디폴트 메서드
- 자바 8부터 인터페이스에 구현부를 가진 `default` 메서드를 정의할 수 있게 됨
- 기존 코드를 깨뜨리지 않고 인터페이스를 확장할 때 유용함

```java
interface Printable {
  void print();

  // default 메서드로 공통 기능 추가
  default void printStatus() {
    System.out.println("인쇄 준비 완료");
  }
}

class Document implements Printable {
  @Override
  public void print() {
    System.out.println("문서를 인쇄합니다.");
  }
}
```

# 14. 자바 주요 패키지와 API

자바는 풍부한 표준 라이브러리(Application Programming Interface)를 탑재하고 있어, 개발자가 유용한 기능들을 직접 구현하지 않고도 미리 만들어진 클래스들을 가져와 편리하게 사용할 수 있습니다. 여기서는 자바 백엔드 개발에서 널리 활용되는 핵심 패키지와 클래스들의 명세 및 사용법을 학습합니다.

## 14.1 자바 API 문서
자바 API 문서(Java API Specification)는 자바가 표준으로 설계하여 탑재해 둔 수천 개의 클래스, 인터페이스, 메서드들의 상세 명세서(사용 가이드, 파라미터, 반환 규격)를 정리한 공식 온라인 문서입니다.

```java
public class ApiDocumentExample {
  public static void main(String[] args) {
    // 자바 표준 API인 System 클래스의 정적 필드 out과, PrintStream의 println 메서드 호출
    System.out.println("API 문서를 통해 사용법을 익힐 수 있습니다.");
  }
}
```

### 14.1.1 공식 API 문서 확인
- 오라클 공식 자바 표준 문서 저장소: https://docs.oracle.com/en/java/javase/
- JDK 버전을 선택한 후 API Documentation 확인
- API 문서가 매우 방대하므로 검색 기능을 주로 활용합니다.

### 14.1.2 공식 문서를 통한 String 클래스 분석
- 클래스 기본 명세 확인: java.lang.String 클래스가 최상위 클래스인 Object로부터 어떻게 파생되었는지 상속 계층도(Hierarchy) 확인합니다.
- 구현하는 인터페이스 확인: String 클래스가 Comparable 이나 Serializable 같은 표준 인터페이스들을 구현함을 확인합니다.
- Constructor Summary (생성자 요약): 다양한 매개변수를 받는 여러 생성자들의 리스트와 그에 따른 오버로딩 설계를 확인합니다.
- Method Summary (메서드 요약):
    - Modifier and Type: 해당 메서드가 static으로 공유되는 메서드인지, 혹은 일반 인스턴스 메서드인지와 리턴되는 타입(int, boolean, String 등)을 확인합니다.
    - Method and Description: 메서드명과 매개변수를 매핑하여, 어떠한 기능을 수행하고 예외 상황 시 어떤 동작을 하는지 확인합니다.
    - Throws: 메서드 사용 중 파라미터 유효성에 문제가 생길 때(예: NullPointerException) 어떤 내부 예외를 개발자에게 호출하여 던져주는지 확인합니다.

### 14.1.3 통합 개발 환경(IDE) 내에서의 API 툴팁 활용
- IntelliJ에서 웹 브라우저를 직접 열지 않고도, 소스코드 내 클래스명이나 메서드명 위에 마우스를 올리면 공식 자바 API 문서 설명이 팝업으로 나타납니다.
- 단축키: Ctrl + Q (Windows) 또는 F1 (Mac) 키를 누르면, API 주석 설명문을 새로운 탭으로 확인 가능합니다.

## 14.2 주요 패키지 개요
자바 표준 클래스들은 용도와 기능별로 묶여서 패키지 형태로 제공됩니다. 대표적인 핵심 패키지는 다음과 같습니다.

- java.lang: 자바 프로그래밍의 가장 기본적인 클래스들을 담고 있는 패키지입니다. 이 패키지의 클래스들은 import 구문 없이도 자동으로 사용이 가능합니다. (예: System, String, Object, Math 등)
- java.util: 자료구조, 날짜 처리, 난수 생성 등 프로그래밍의 다양한 유틸리티 도구를 제공하는 패키지입니다. 사용 시 명시적인 import가 필요합니다. (예: Scanner, Random, Date, Calendar, List 등)

```java
// java.lang 패키지의 클래스는 import 없이 사용 가능
// java.util 패키지의 클래스는 명시적 import가 필요함
import java.util.ArrayList;

public class PackageOverviewExample {
  public static void main(String[] args) {
    String str = "java.lang 패키지"; // import 없이 사용
    ArrayList<String> list = new ArrayList<>(); // java.util 패키지 임포트 후 사용
  }
}
```

## 14.3 문자열 클래스 (String, StringBuffer, StringBuilder)

### 14.3.1 String 클래스의 내부 메커니즘과 불변성 (Immutability)
String 객체는 한 번 생성되면 메모리 상에서 그 내부 값을 절대로 변경할 수 없는 불변 객체입니다.

#### 1) 문자열 상수 풀 (String Constant Pool)
자바는 메모리 효율성과 안정성을 높이기 위해 힙 메모리 영역 내부에 문자열 상수 풀이라는 특수한 공유 메모리를 구성합니다.
문자열을 리터럴(예: "Hello")로 선언할 경우, JVM은 먼저 이 상수 풀에 동일한 문자열이 있는지 찾아보고 있으면 새로운 객체를 생성하지 않고 기존 객체의 주소값을 공유하여 참조합니다.
이로 인해 문자열 값의 비교 시 주소 비교(==)가 아닌 내용 비교(equals)를 사용해야 합니다.

#### 2) 문자열 결합 연산의 부작용
String 객체에 결합 연산자(+)를 사용하여 문자열을 더하면 기존 객체의 내용이 바뀌는 것이 아니라, 결합된 새로운 문자열 객체가 상수 풀에 생성되고 참조 변수는 그 새 객체의 주소를 가리킵니다.
따라서 루프 안에서 문자열을 덧붙이는 연산을 무수히 수행하면 힙 영역에 무수히 많은 임시 찌꺼기 객체들이 쌓여 가비지 컬렉터(GC)의 성능 하락을 초래하게 됩니다.

```java
public class StringImmutabilityExample {
  public static void main(String[] args) {
    String s1 = "Hello";
    String s2 = "Hello";
    String s3 = new String("Hello");

    // 문자열 리터럴 주소 비교 (참조 풀 활용)
    System.out.println(s1 == s2); // true

    // new를 통한 신규 생성 주소 비교
    System.out.println(s1 == s3); // false

    // 문자열 내용 비교 (equals 권장)
    System.out.println(s1.equals(s3)); // true
  }
}
```

### 14.3.2 가변 문자열 클래스: StringBuffer와 StringBuilder
문자열의 잦은 추가, 삽입, 삭제가 일어나는 프로그램에서는 힙 공간의 낭비를 방지하기 위해 가변 객체 클래스를 사용해야 합니다.
이들은 내부에 가변적인 크기의 메모리 버퍼를 탑재하여 객체를 새로 복사하지 않고 즉석에서 문자열을 편집할 수 있게 해 줍니다.

#### 1) StringBuffer
멀티스레드 환경에 매우 안전하도록 동기화(Thread-safe) 처리가 되어 있습니다.
여러 실행 흐름이 동시에 하나의 문자열에 접근하더라도 데이터가 깨지거나 꼬이는 현상을 방지합니다.

#### 2) StringBuilder
동기화 처리가 빠진 대신 싱글스레드 환경에서 StringBuffer에 비해 훨씬 뛰어난 동작 속도와 효율성을 보여줍니다.
일반적인 웹 백엔드의 로컬 변수 조작 과정에서는 속도 최적화를 위해 StringBuilder를 우선적으로 사용하는 것이 관례입니다.

```java
public class StringBuilderExample {
  public static void main(String[] args) {
    StringBuilder sb = new StringBuilder("Hello");
    sb.append(" World"); // 문자열 결합 시 객체를 새로 생성하지 않음
    sb.insert(5, ",");  // 문자열 삽입
    System.out.println(sb.toString()); // 출력: Hello, World
  }
}
```

### 14.3.3 String 주요 메서드
- length(): 문자열의 총 길이를 숫자로 반환합니다.
- charAt(int index): 지정된 인덱스 위치에 있는 하나의 문자를 반환합니다.
- substring(int begin, int end): 시작 인덱스부터 끝 인덱스 직전까지의 문자열을 잘라내어 반환합니다.
- equals(Object obj): 대상 객체와 내용이 같은지 여부(true/false)를 반환합니다.
- indexOf(String str): 찾고자 하는 문자열이 처음 시작하는 인덱스를 반환하며, 존재하지 않으면 -1을 반환합니다.
- replace(CharSequence target, CharSequence replacement): 특정 텍스트를 대상 텍스트로 전부 치환한 새 문자열을 반환합니다.
- split(String regex): 지정된 구분 기호를 기준으로 쪼갠 후 문자열 배열(String[])로 반환합니다.

```java
public class StringMethodsExample {
  public static void main(String[] args) {
    String text = "Java Programming";

    System.out.println(text.length()); // 16
    System.out.println(text.charAt(5)); // P
    System.out.println(text.substring(5, 12)); // Program
    System.out.println(text.indexOf("Pro")); // 5
    System.out.println(text.replace("Java", "Modern Java")); // Modern Java Programming

    String[] words = text.split(" ");
    System.out.println(words[0]); // Java
  }
}
```

### 14.3.4 StringBuffer 주요 메서드
- append(String str): 기존 버퍼의 끝 부분에 인자로 주어진 문자열을 즉석에서 추가합니다.
- insert(int offset, String str): 특정 오프셋 위치에 인자로 주어진 문자열을 즉석에서 삽입합니다.
- delete(int start, int end): 특정 시작 범위부터 끝 범위 직전까지의 문자를 제거합니다.
- reverse(): 저장되어 있는 문자열을 좌우로 완전히 뒤집습니다.
- toString(): 버퍼 내의 가변 조작 연산이 끝난 후 최종적으로 String 객체 타입으로 변환하여 반환합니다.

```java
public class StringBufferExample {
  public static void main(String[] args) {
    StringBuffer sb = new StringBuffer("Java");
    sb.append(" buffer");
    sb.insert(4, "script");
    System.out.println(sb.toString()); // Javascript buffer

    sb.delete(10, 17);
    System.out.println(sb.toString()); // Javascript
    System.out.println(sb.reverse().toString()); // tpircsavaJ
  }
}
```

## 14.4 래퍼 클래스 (Wrapper Class)
기본 자료형(Primitive Type)의 8가지 데이터를 객체로 다루어야 할 때 사용하는 클래스들입니다.

### 14.4.1 기본 자료형과 래퍼 클래스 매핑

| 기본 자료형 (Primitive Type) | 래퍼 클래스 (Wrapper Class) |
| :--- | :--- |
| byte | Byte |
| short | Short |
| int | Integer |
| long | Long |
| float | Float |
| double | Double |
| char | Character |
| boolean | Boolean |

### 14.4.2 박싱(Boxing)과 언박싱(Unboxing)
- 박싱: 기본 자료형의 데이터를 대응되는 래퍼 클래스의 객체로 만드는 과정입니다.
- 언박싱: 래퍼 클래스의 객체로부터 기본 자료형의 데이터를 꺼내는 과정입니다.

자바 5 버전부터는 컴파일러가 박싱과 언박싱이 필요한 곳에 자동으로 코드를 넣어주는 오토 박싱(Auto-boxing) 및 오토 언박싱(Auto-unboxing)을 지원합니다.

```java
// 명시적 박싱과 언박싱 (예전 방식)
Integer num1 = Integer.valueOf(100);
int value1 = num1.intValue();

// 오토 박싱과 오토 언박싱 (자바 5 이후)
Integer num2 = 100; // 자동 박싱
int value2 = num2; // 자동 언박싱
```

### 14.4.3 주요 문자열 변환 정적 메서드
래퍼 클래스는 문자열 형태의 숫자를 실제 기본형 데이터로 파싱해주는 유용한 메서드를 가지고 있습니다.
- Integer.parseInt(String s): 문자열을 int 정수로 변환하여 반환합니다.
- Double.parseDouble(String s): 문자열을 double 실수로 변환하여 반환합니다.
- Boolean.parseBoolean(String s): 문자열을 boolean 논리값으로 변환하여 반환합니다.

```java
public class WrapperParsingExample {
  public static void main(String[] args) {
    int num = Integer.parseInt("123");
    double decimal = Double.parseDouble("3.14");
    boolean flag = Boolean.parseBoolean("true");

    System.out.println(num + 10); // 출력: 133
    System.out.println(decimal * 2); // 출력: 6.28
    System.out.println(flag); // 출력: true
  }
}
```

## 14.5 Math 클래스
수학 계산에 유용한 정적 상수와 정적 메서드들을 제공하는 클래스입니다. 인스턴스를 생성할 수 없도록 설계되어 있습니다.

### 14.5.1 주요 정적 메서드
- Math.abs(double a): 주어진 값의 절대값을 구합니다.
- Math.max(double a, double b): 두 값 중 큰 값을 반환합니다.
- Math.min(double a, double b): 두 값 중 작은 값을 반환합니다.
- Math.round(double a): 소수점 첫째 자리에서 반올림하여 정수형으로 반환합니다.
- Math.ceil(double a): 소수점 첫째 자리에서 올림하여 반환합니다.
- Math.floor(double a): 소수점 첫째 자리에서 내림하여 반환합니다.
- Math.random(): 0.0 이상 1.0 미만 사이의 임의의 double형 난수를 반환합니다.
- Math.pow(double a, double b): a의 b 거듭제곱을 구합니다.
- Math.sqrt(double a): a의 제곱근을 구합니다.

```java
public class MathExample {
  public static void main(String[] args) {
    System.out.println(Math.abs(-10)); // 10
    System.out.println(Math.max(10, 20)); // 20
    System.out.println(Math.round(3.5)); // 4
    System.out.println(Math.ceil(3.1)); // 4.0
    System.out.println(Math.floor(3.9)); // 3.0
    System.out.println(Math.pow(2, 3)); // 8.0
    System.out.println(Math.sqrt(16)); // 4.0
  }
}
```

## 14.6 Scanner 클래스
화면(키보드), 파일, 문자열 등 다양한 입력 소스로부터 데이터를 읽어와 파싱해주는 유틸리티 클래스입니다.

### 14.6.1 콘솔 입력 예시
```java
import java.util.Scanner;

public class ScannerExample {
  public static void main(String[] args) {
    // System.in (표준 입력 스트림)을 통해 키보드 입력을 받는 Scanner 생성
    Scanner scanner = new Scanner(System.in);

    System.out.print("이름을 입력하세요: ");
    String name = scanner.nextLine(); // 문자열 한 줄 읽기

    System.out.print("나이를 입력하세요: ");
    int age = scanner.nextInt(); // 정수 하나 읽기

    System.out.println("안녕하세요, " + name + "님! 귀하의 나이는 " + age + "세입니다.");

    scanner.close(); // 사용이 끝난 스캐너 자원 해제
  }
}
```

### 14.6.2 주요 메서드
- next(): 공백(스페이스, 탭, 줄바꿈)을 기준으로 구분된 다음 문자열 토큰을 반환합니다.
- nextLine(): 줄바꿈(\n)을 기준으로 구분된 한 줄의 전체 문자열을 반환합니다.
- nextInt(): 입력받은 토큰을 int형으로 변환하여 반환합니다.
- nextDouble(): 입력받은 토큰을 double형으로 변환하여 반환합니다.
- hasNext(): 입력받을 수 있는 토큰이 더 남아 있는지 검사하여 boolean으로 반환합니다.

## 14.7 Random 클래스
난수(임의의 수)를 생성하는 기능을 제공하는 클래스입니다. Math.random()보다 다양한 자료형의 난수를 더 유연하게 얻을 수 있습니다.

### 14.7.1 주요 메서드
- nextInt(): 정수 범위 전체 내에서 무작위 int 값을 생성합니다.
- nextInt(int bound): 0 이상 bound 미만 사이의 무작위 int 값을 생성합니다. (예: random.nextInt(10)은 0~9 사이의 정수를 생성함)
- nextDouble(): 0.0 이상 1.0 미만의 무작위 double 값을 생성합니다.
- nextBoolean(): 무작위 boolean 값(true 또는 false)을 생성합니다.

```java
import java.util.Random;

public class RandomExample {
  public static void main(String[] args) {
    Random random = new Random();

    int randomInt = random.nextInt(10) + 1; // 1부터 10 사이의 난수 생성
    double randomDouble = random.nextDouble();
    boolean randomBool = random.nextBoolean();

    System.out.println("주사위 눈(1~10): " + randomInt);
    System.out.println("난수(실수): " + randomDouble);
    System.out.println("동전 앞뒤(논리): " + randomBool);
  }
}
```

## 14.8 날짜와 시간 클래스 (Date, Calendar)
자바에서 시간과 날짜를 처리하는 대표적인 전통적인 클래스들입니다.

### 14.8.1 Date 클래스
특정 시점의 날짜와 시간 정보를 관리하는 클래스입니다. 자바 초기 버전부터 제공되었으나 많은 메서드가 지원 중단(Deprecated)되어 주로 현재 시간의 정보 보관용이나 다른 날짜/시간 포맷 라이브러리와 연동하여 사용됩니다.

```java
import java.util.Date;

public class DateExample {
  public static void main(String[] args) {
    Date now = new Date(); // 현재 시간 객체 생성
    System.out.println("현재 날짜와 시간: " + now.toString());
  }
}
```

### 14.8.2 Calendar 클래스
추상 클래스로 설계되어 있으며, 날짜 요소를 각각 추출하거나(연, 월, 일 등) 날짜 연산(일수 더하기/빼기)을 수행할 수 있도록 해 줍니다. 월(Month) 정보를 얻을 때 0이 1월을 의미한다는 특이점이 있으므로 주의가 필요합니다.

```java
import java.util.Calendar;

public class CalendarExample {
  public static void main(String[] args) {
    Calendar cal = Calendar.getInstance(); // 기본 지역 및 시간대를 가진 인스턴스 획득

    int year = cal.get(Calendar.YEAR);
    int month = cal.get(Calendar.MONTH) + 1; // 0이 1월이므로 반드시 +1을 함
    int day = cal.get(Calendar.DAY_OF_MONTH);
    int hour = cal.get(Calendar.HOUR_OF_DAY);
    int minute = cal.get(Calendar.MINUTE);

    System.out.println("현재 날짜: " + year + "년 " + month + "월 " + day + "일");
    System.out.println("현재 시간: " + hour + "시 " + minute + "분");
  }
}
```


# 15. 자료 구조와 컬렉션 프레임워크(Collection)

## 15.1 컬렉션 프레임워크 구조
- 배열의 크기 고정 문제를 해결하고 동적 크기 변경, 정렬 등의 기능을 제공하는 자료구조 모음집
- 핵심 인터페이스: List, Set, Map

```java
import java.util.*;

public class CollectionOverviewExample {
  public static void main(String[] args) {
    // 인터페이스 다형성을 이용한 컬렉션 생성 예시
    Collection<String> list = new ArrayList<>();
    Collection<String> set = new HashSet<>();

    list.add("Data1");
    set.add("Data1");
  }
}
```

## 15.2 List 인터페이스(ArrayList, LinkedList)
- 순서가 유지되고 중복을 허용
- `ArrayList`: 내부적으로 배열을 사용. 인덱스 조회가 빠르지만 데이터 삽입/삭제 시 이동 작업으로 인해 느림
- `LinkedList`: 노드들이 체인처럼 연결된 구조. 데이터 삽입/삭제가 빠르지만 인덱스 조회가 느림

```java
List<String> list = new ArrayList<>();
list.add("Java");
list.add("Spring");
System.out.println(list.get(1)); // Spring
```

## 15.3 Set 인터페이스(HashSet, TreeSet)
- 순서를 유지하지 않으며 중복 저장을 허용하지 않음
- `HashSet`: 해시 알고리즘 기반. 검색 속도가 가장 빠름
- `TreeSet`: 이진 탐색 트리 기반. 데이터가 자동 정렬되어 저장됨

```java
Set<Integer> set = new HashSet<>();
set.add(10);
set.add(10); // 중복 무시됨
System.out.println(set.size()); // 1
```

## 15.4 Map 인터페이스(HashMap, TreeMap)
- 키와 값의 쌍(Key-Value)으로 데이터를 저장
- 키는 중복 불가, 값은 중복 가능

```java
Map<String, Integer> map = new HashMap<>();
map.put("사과", 1000);
map.put("사과", 1500); // 덮어씌워짐
System.out.println(map.get("사과")); // 1500
```

## 15.5 제네릭(Generic)
- 컬렉션에 들어갈 데이터 타입을 컴파일 시점에 지정하여 타입 안정성을 높이는 문법

```java
// 제네릭 클래스 정의
public class Box<T> {
  private T content;

  public void set(T content) {
    this.content = content;
  }

  public T get() {
    return content;
  }

  public static void main(String[] args) {
    // String 타입을 보장하는 제네릭 객체 생성
    Box<String> stringBox = new Box<>();
    stringBox.set("제네릭 데이터");
    String text = stringBox.get(); // 형변환 없이 꺼내기 가능
    System.out.println(text);
  }
}
```

# 16. 모던 자바 - 람다(Lambda)와 함수형 프로그래밍

## 16.1 함수형 프로그래밍이란?
- 상태 변경을 피하고 순수 함수를 조합하여 프로그램을 작성하는 패러다임
- 자바 8부터 람다식을 통해 함수를 일급 객체처럼 다룰 수 있게 됨

```java
public class PureFunctionExample {
  // 입력값이 같으면 항상 같은 결과를 반환하는 순수 함수
  public static int add(int a, int b) {
    return a + b;
  }

  public static void main(String[] args) {
    int result = add(3, 5);
    System.out.println(result); // 8
  }
}
```

## 16.2 람다식 문법
- 메서드의 이름과 반환타입을 생략하고 화살표 `->` 를 이용
- `(매개변수) -> { 실행문; }`

```java
// 기존 익명 클래스
Runnable r1 = new Runnable() {
  @Override
  public void run() {
    System.out.println("달린다");
  }
};

// 람다식 적용
Runnable r2 = () -> System.out.println("달린다");
```

## 16.3 표준 함수형 인터페이스
자바 라이브러리(`java.util.function`)에서 자주 쓰이는 패턴을 미리 정의해 두었음.
- `Predicate<T>`: 매개변수를 받아 `boolean`을 반환
- `Consumer<T>`: 매개변수를 받아서 소모만 하고 반환하지 않음 (`void`)
- `Function<T, R>`: 매개변수를 받아서 다른 타입으로 변환하여 반환
- `Supplier<T>`: 매개변수 없이 값을 제공

```java
import java.util.function.*;

public class FunctionalInterfaceExample {
  public static void main(String[] args) {
    // Predicate: 입력값이 짝수인지 검사
    Predicate<Integer> isEven = num -> num % 2 == 0;
    System.out.println(isEven.test(4)); // true

    // Consumer: 입력값 출력
    Consumer<String> printer = str -> System.out.println(str);
    printer.accept("Java Consumer");

    // Function: 문자열을 정수로 변환
    Function<String, Integer> parser = Integer::parseInt;
    System.out.println(parser.apply("100") + 50); // 150
  }
}
```

## 16.4 메서드 참조
- 람다식이 단 하나의 메서드만 호출할 때 코드를 더 간결하게 줄이는 문법 `클래스명::메서드명`

```java
// 람다
Consumer<String> printer = s -> System.out.println(s);
// 메서드 참조
Consumer<String> betterPrinter = System.out::println;
```


# 17. 데이터 가공 - 스트림(Stream) API

## 17.1 스트림 API 개념
- 컬렉션의 데이터들을 파이프라인 형태로 연결하여 필터링, 매핑 등의 처리를 선언형으로 작성하는 기능

```java
import java.util.*;

public class StreamConceptExample {
  public static void main(String[] args) {
    List<String> list = Arrays.asList("a", "b", "c");
    // 스트림을 이용한 선언형 출력
    list.stream().forEach(System.out::println);
  }
}
```

## 17.2 스트림 파이프라인 3단계
1. 생성: 컬렉션이나 배열에서 스트림을 엶
2. 중간 연산: 데이터를 필터링하거나 변환함 (여러 개 연결 가능)
3. 최종 연산: 결과를 모으거나 순회하며 스트림을 닫음

```java
import java.util.*;

public class StreamPipelineExample {
  public static void main(String[] args) {
    List<Integer> list = Arrays.asList(1, 2, 3, 4, 5);

    long count = list.stream()          // 1. 생성
                     .filter(n -> n > 2) // 2. 중간 연산
                     .count();           // 3. 최종 연산

    System.out.println("3보다 큰 수의 개수: " + count); // 3
  }
}
```

## 17.3 주요 중간 연산
- `filter()`: 조건에 맞는 요소만 남김
- `map()`: 요소를 다른 형태로 변환
- `flatMap()`: 중첩된 구조를 평탄화
- `sorted()`: 요소를 정렬
- `distinct()`: 중복을 제거

```java
import java.util.*;

public class StreamIntermediateExample {
  public static void main(String[] args) {
    List<String> list = Arrays.asList("a", "b", "a", "c", "b");

    list.stream()
        .distinct() // 중복 제거
        .sorted()   // 정렬
        .map(String::toUpperCase) // 대문자로 매핑
        .forEach(System.out::println); // 출력: A, B, C
  }
}
```

## 17.4 주요 최종 연산
- `forEach()`: 각 요소를 순회하며 소비
- `collect()`: 결과를 리스트나 맵 등으로 변환하여 수집
- `count()`, `sum()`, `max()`, `min()`: 집계 연산을 수행

```java
List<String> names = Arrays.asList("Kim", "Park", "Lee", "Kang", "Koo");

List<String> result = names.stream()
.filter(name -> name.startsWith('K'))
.map(String::toUpperCase)
.collect(Collectors.toList());

System.out.println(result); // [KIM, KANG, KOO]
```

## 17.5 지연 연산(Lazy Evaluation)
- 최종 연산이 호출되기 전까지 중간 연산은 실행을 미루며 대기
- 최종 연산이 호출될 때 최적의 경로로 한 번에 처리하여 성능을 높임

```java
import java.util.*;

public class StreamLazyEvaluationExample {
  public static void main(String[] args) {
    List<Integer> list = Arrays.asList(1, 2, 3);

    list.stream()
        .filter(n -> {
          System.out.println("filter: " + n);
          return n > 1;
        }); // 최종 연산이 없으므로 "filter: " 문구가 콘솔에 출력되지 않음
  }
}
```

# 18. 예외 처리(Exception)

## 18.1 에러와 예외
- 에러(Error): 메모리 부족 등 프로그램 코드로 수습할 수 없는 심각한 시스템 문제
- 예외(Exception): 프로그램 코드로 수습 가능한 비교적 덜 심각한 오류

```java
public class ExceptionExample {
  public static void main(String[] args) {
    // 0으로 나누기 시도 시 ArithmeticException 예외가 발생함
    int result = 10 / 0;
  }
}
```

## 18.2 예외 클래스의 계층 구조
- 모든 예외의 최고 조상은 `Exception` 클래스
- `RuntimeException`과 그 하위 클래스(Unchecked 예외): 컴파일러가 예외 처리를 강제하지 않음
- 그 외의 `Exception` (Checked 예외): 반드시 `try-catch`로 묶어주거나 예외를 전가해야 컴파일됨

```java
import java.io.*;

public class CheckedExceptionExample {
  public static void main(String[] args) {
    // FileReader 생성자는 checked exception(FileNotFoundException)을 선언하고 있어
    // 예외 처리를 강제함 (try-catch 혹은 throws 필요)
    try {
      FileReader reader = new FileReader("nonexistent_file.txt");
    } catch (FileNotFoundException e) {
      System.out.println("파일을 찾을 수 없습니다.");
    }
  }
}
```

## 18.3 try-catch-finally 블록
```java
try {
  int result = 10 / 0; // 예외 발생
} catch (ArithmeticException e) {
  System.out.println("0으로 나눌 수 없음");
} finally {
  System.out.println("예외 발생 여부와 상관없이 무조건 실행됨");
}
```

## 18.4 throws와 throw
- `throws`: 메서드 선언부에 사용하여, 이 메서드에서 발생할 수 있는 예외를 호출한 곳으로 떠넘김
- `throw`: 개발자가 고의로 예외 객체를 생성하여 발생시킴

```java
public class ThrowsExample {
  // 예외를 호출 부로 떠넘기기
  public static void checkAge(int age) throws IllegalArgumentException {
    if (age < 0) {
      // 예외 직접 발생시키기
      throw new IllegalArgumentException("나이는 음수가 될 수 없습니다.");
    }
  }

  public static void main(String[] args) {
    try {
      checkAge(-5);
    } catch (IllegalArgumentException e) {
      System.out.println(e.getMessage());
    }
  }
}
```

## 18.5 사용자 정의 예외
- 비즈니스 로직에 맞는 구체적인 예외 상황을 표현하기 위해 커스텀 예외 클래스를 만들 수 있음

```java
// 사용자 정의 예외 선언
class CustomException extends Exception {
  public CustomException(String message) {
    super(message);
  }
}

public class CustomExceptionExample {
  public static void main(String[] args) {
    try {
      throw new CustomException("사용자 정의 예외가 발생했습니다.");
    } catch (CustomException e) {
      System.out.println(e.getMessage());
    }
  }
}
```

# 19. 소프트웨어 품질과 TDD 철학

## 19.1 단위 테스트(Unit Test)
- 작성한 코드가 의도대로 동작하는지 가장 작은 단위로 쪼개어 검증하는 것
- 부작용을 조기 발견하고 리팩토링 시 안전망 역할을 함

```java
// 테스트 대상 클래스
class Calculator {
  public int add(int a, int b) {
    return a + b;
  }
}

// 단위 테스트 로직 예시 (JUnit 없이 수동 검증)
public class ManualTestExample {
  public static void main(String[] args) {
    Calculator calc = new Calculator();
    int result = calc.add(10, 20);
    if (result == 30) {
      System.out.println("단위 테스트 통과");
    } else {
      System.out.println("단위 테스트 실패");
    }
  }
}
```

## 19.2 JUnit 프레임워크 기초
- 자바 생태계의 표준 테스트 프레임워크
- `@Test`, `@BeforeEach`, `@AfterEach`, `@DisplayName` 등의 애노테이션을 활용

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

public class CalculatorTest {
  @Test
  void 더하기_테스트() {
    Calculator calc = new Calculator();
    int result = calc.add(2, 3);
    assertEquals(5, result);
  }
}
```

## 19.3 TDD 3단계 사이클
- TDD는 실제 코드 작성 전 실패하는 테스트를 먼저 작성하는 개발 방법론
1. RED: 구현할 기능에 대해 실패하는 테스트 코드를 작성
2. GREEN: 테스트를 통과하기 위한 최소한의 코드를 작성
3. REFACTOR: 테스트 통과를 유지하며 코드를 개선

```java
// TDD 흐름 예시
// 1. RED: 테스트 코드를 먼저 작성 (아직 구현되지 않은 메서드 호출로 에러 발생)
// 2. GREEN: 테스트를 통과하도록 메서드 최소 구현 작성
class Greeter {
  public String sayHello(String name) {
    return "Hello, " + name; // GREEN 단계를 위해 작성됨
  }
}
```

## 19.4 TDD를 도입하는 이유와 아키텍처
- 테스트하기 쉬운 코드를 작성하려 노력하면, 자연스럽게 클래스 간 결합도가 낮아지고 응집도가 높은 유연한 아키텍처가 도출됨
- TDD는 단순한 테스트 기술이 아니라 좋은 객체지향 설계를 유도하는 설계 기법

```java
// 테스트가 용이하도록 의존성 주입(Dependency Injection)을 설계하여 
// 결합도를 낮추고 유연한 아키텍처를 구현하는 예시
interface MessageService {
  String getMessage();
}

class RealMessageService implements MessageService {
  public String getMessage() {
    return "실제 서버 메시지";
  }
}

class UserController {
  private final MessageService messageService;

  // 의존성을 생성자 주입으로 외부에서 수령하도록 하여 테스트를 용이하게 함
  public UserController(MessageService messageService) {
    this.messageService = messageService;
  }

  public void showMessage() {
    System.out.println(messageService.getMessage());
  }
}
```
