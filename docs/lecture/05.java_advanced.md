# 1. 예외 처리(Exception)

## 1.1 에러와 예외
- 에러(Error)
  - 시스템 수준에서 발생하는 복구 불가능한 심각한 문제
  - 메모리 부족(OutOfMemoryError)이나 스택 오버플로우(StackOverflowError) 등 개발자가 코드로 수습할 수 없음
- 예외(Exception)
  - 애플리케이션 수준에서 발생하며 프로그램 코드로 수습 가능한 비교적 가벼운 오류
  - 예외 처리를 통해 프로그램의 비정상 종료를 막고 실행 상태를 유지 가능

- 💻 실습 (Exception과 Error): [ch01/ErrorTest.java](../workspace/04_advanced/ch01/ErrorTest.java)

## 1.2 예외 클래스의 계층 구조
- 모든 예외와 에러의 최상위 클래스는 [Throwable](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Throwable.html) 클래스
- Throwable 하위에 시스템 에러를 나타내는 [Error](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Error.html)와 애플리케이션 예외를 나타내는 [Exception](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Exception.html) 클래스가 존재
- Exception 클래스 계층 구조는 크게 두 가지로 분류됨
  - Checked Exception (일반 예외)
    - [RuntimeException](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/RuntimeException.html) 계층을 제외한 모든 Exception 하위 클래스
    - 컴파일러가 예외 처리를 강제하며, 처리를 하지 않으면 컴파일 에러 발생
    - 주로 외부 자원과의 연동 등 프로그램 외부 요인으로 발생 (예: [IOException](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/io/IOException.html), [SQLException](https://docs.oracle.com/en/java/javase/25/docs/api/java.sql/java/sql/SQLException.html), [FileNotFoundException](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/io/FileNotFoundException.html))
  - Unchecked Exception (실행 예외)
    - [RuntimeException](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/RuntimeException.html)과 그 하위 클래스
    - 컴파일러가 예외 처리를 강제하지 않음
    - 주로 개발자의 코드 로직 오류나 부주의로 발생 (예: [NullPointerException](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/NullPointerException.html), [ArithmeticException](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/ArithmeticException.html), [IndexOutOfBoundsException](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/IndexOutOfBoundsException.html))

- Checked vs Unchecked 비교 표

| 구분 | Checked Exception | Unchecked Exception |
| --- | --- | --- |
| 예외 처리 여부 | 반드시 처리해야 함 (강제) | 명시적인 처리를 강제하지 않음 |
| 확인 시점 | 컴파일 시점 | 실행 시점 (Runtime) |
| 대표 클래스 | IOException, SQLException | NullPointerException, IndexOutOfBoundsException |

## 1.3 try-catch-finally 블록과 자원 관리
- try-catch-finally 동작 구조
  - try 블록: 예외가 발생할 가능성이 있는 코드를 작성하는 영역
  - catch 블록: 특정 예외가 발생했을 때 처리할 코드를 작성하며, 여러 개를 선언할 수 있음
  - finally 블록: 예외 발생 여부와 상관없이 항상 실행되며 주로 입출력 스트림, 데이터베이스 커넥션 등 자원 해제에 사용함
  - try-catch-finally 예시
    ```java
    try{
        int num2 = str.length(); // str이 null일 경우 NullPointerException 발생
        int result = num1 / num2; // str이 ""일 경우 ArithmeticException 발생
        System.out.println(num1 + " / " + num2 + " = " + result);
    }catch(ArithmeticException e){
        System.out.println("0으로 나눌 수 없습니다.");
    }catch(NullPointerException e){
        System.out.println("str이 null입니다.");
    }finally{
        System.out.println("finally는 try-catch 블럭이 실행된 뒤 항상 실행을 보장.");
    }
    ```

  - 다형성을 이용한 예외 처리
    - catch 블록에 상위 예외 클래스를 지정하면, 그 하위 예외 클래스의 인스턴스들도 모두 다형성에 의해 함께 잡을 수 있음
    - 예를 들어, catch(Exception e) 로 지정하면 모든 하위 예외를 일괄 처리할 수 있음
    - 단, 다중 catch 블록을 구성할 때 상위 예외 클래스를 하위 예외 클래스보다 먼저 선언하면 아래의 하위 catch 블록은 도달할 수 없는 코드가 되어 컴파일 에러가 발생하므로, 반드시 하위 예외 클래스부터 순차적으로 배치해야 함
    - 다형성 활용 예시
      ```java
      // 올바른 예시: 하위 예외를 먼저 catch하고 상위 예외를 나중에 catch함
      try {
          int num2 = str.length();
          int result = num1 / num2;
          System.out.println(result);
      } catch (NullPointerException e) {
          System.out.println("Null 예외 발생");
      } catch (Exception e) {
          System.out.println("그 외의 일반 예외 발생");
      }

      // 잘못된 예시: 상위 예외를 먼저 catch하면 하위 catch 블록에서 컴파일 에러 발생
      try {
          int num2 = str.length();
          int result = num1 / num2;
          System.out.println(result);
      } catch (Exception e) {
          System.out.println("모든 예외 처리");
      } catch (NullPointerException e) { // 컴파일 에러: 도달할 수 없는 코드(Unreachable catch block)
          System.out.println("Null 예외 발생");
      }
      ```
  - 💻 실습 (try-catch-finally): [ch01/TryCatchTest.java](../workspace/04_advanced/ch01/TryCatchTest.java)

- 멀티 캐치(Multi-catch) 문법
  - 자바 7부터 지원하며 한 catch 블록에서 여러 예외를 파이프(|) 기호로 연결하여 동시에 처리함
  - catch(ArithmeticException | ArrayIndexOutOfBoundsException e)
  - 멀티 캐치 예시
    ```java
    try{
        int num2 = str.length(); // str이 null일 경우 NullPointerException 발생
        int result = num1 / num2; // str이 ""일 경우 ArithmeticException 발생
        System.out.println(num1 + " / " + num2 + " = " + result);
    }catch(ArithmeticException | NullPointerException e){
        System.out.println(e.getMessage());
    }
    ```

  - 💻 실습 (Multi-catch): [ch01/MultiCatchTest.java](../workspace/04_advanced/ch01/MultiCatchTest.java)

- try-with-resources 문법 (자원 자동 해제)
  - 자바 7에서 도입된 자원 자동 반납 문법
  - [AutoCloseable](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/AutoCloseable.html) 인터페이스를 구현한 자원 객체를 try 괄호 안에 선언하면 블록 종료 시 자동으로 close() 메서드가 호출됨
  - 기존 finally 블록에서 자원을 해제할 때 발생하던 복잡한 예외 처리와 누수 문제를 방지함
  - try-with-resources 사용전 예시
    ```java
    static void insert(int memberId, String title, String content){
        String sql = "INSERT INTO post (member_id, title, content) VALUES ("+memberId+", '"+title+"', '"+content+"')";

        // finally에서 접근 가능하도록 try 블럭 외부에서 선언
        Connection conn = null;
        Statement stmt = null;
        try{
            conn = DriverManager.getConnection(DB_URL, DB_USER, DB_PASSWORD);
            stmt = conn.createStatement();
            int affectedRows = stmt.executeUpdate(sql);
            System.out.println("게시글 등록 완료: " + affectedRows + "건 반영됨.");

        }catch(Exception e){
            System.out.println("에러 발생: " + e.getMessage());
        }finally{
            // 생성된 리소스를 생성의 역순으로 해제
            try{ if(stmt != null) stmt.close(); } catch (Exception e){ }
            try{ if(conn != null) conn.close(); } catch (Exception e){ }
        }
    }
    ```

  - try-with-resources 사용후 예시
    ```java
    static void insert(int memberId, String title, String content){
        String sql = "INSERT INTO post (member_id, title, content) VALUES ("+memberId+", '"+title+"', '"+content+"')";
        try(Connection conn = DriverManager.getConnection(DB_URL, DB_USER, DB_PASSWORD);
            Statement stmt = conn.createStatement()){
            int affectedRows = stmt.executeUpdate(sql);
            System.out.println("게시글 등록 완료: " + affectedRows + "건 반영됨.");
        }catch(Exception e){
            System.out.println("에러 발생: " + e.getMessage());
        }
    }
    ```

## 1.4 throws와 throw
- throw (예외를 발생시키는 행위)
  - 개발자가 로직 내부에서 직접 예외 객체를 생성하여 명시적으로 던질 때 사용함
  - `throw new IllegalArgumentException(메시지)`
  - 주요 사용 시점 (어떤 상황에서 예외를 던지는가):
    - 전달받은 아규먼트가 비즈니스 규칙에 위배되어 즉각적인 예외를 생성해야 할 때 (예: 회원가입 시 나이 필드에 음수가 들어왔을 때)
    - 현재 프로그램의 비즈니스 로직상 흐름 진행이 불가능할 때 (예: 계좌 잔액보다 많은 금액을 출금 요청했을 때)
    - 시스템 예외(SQLException 등)를 비즈니스적 의미를 담은 사용자 정의 예외로 재포장하여 던지고자 할 때
- throws (예외 발생 가능성을 외부에 선언하는 행위)
  - 메서드 선언부에 작성하며, 해당 메서드 내부에서 발생할 가능성이 있는 예외 목록을 호출자에게 명시하고 예외 처리를 상위로 전가할 때 사용함
  - `public void check() throws IOException`
  - 주요 사용 시점 (어떤 상황에서 예외를 메서드 밖으로 넘기는가):
    - 발생한 예외를 현재 메서드 내에서 try-catch로 해결(데이터 복구나 롤백 등)할 수 없어 호출자에게 해당 대처 방법을 떠넘겨야 할 때
    - Checked Exception이 발생하는 API나 라이브러리를 메서드 내부에서 호출하는 경우, 컴파일러를 통해 호출자 측에서 이 예외를 처리하도록 강제하고 싶을 때
  - 무분별한 throws Exception 사용의 문제점
    - 구체적인 예외 타입을 명시하지 않고 `throws Exception`을 남발하면 어떤 예외가 발생하는지 파악하기 어렵고, 호출하는 측에서 유의미한 예외 처리를 수행할 수 없음
    - 호출 측에 불필요한 예외 처리 의무를 떠넘기는 안티 패턴[^1]이므로 반드시 발생할 수 있는 구체적인 예외들을 명시해야 함
- 예외 재발생(Exception Re-throwing)
  - catch 블록에서 예외를 처리한 후 다시 throw를 통해 예외를 발생시켜 호출한 곳으로도 예외 사실을 전달하는 방식

## 1.5 사용자 정의 예외
- 사용자 정의 예외 선언
  - 비즈니스 요구사항에 맞는 명확한 이름의 예외 클래스를 직접 정의하여 사용함
  - `Exception` 또는 `RuntimeException`을 상속받아 구현하며 일반적으로 에러 메시지와 에러 코드를 포함시킴
- 현대 자바 예외 처리의 트렌드
  - 예외 처리를 강제하여 코드가 복잡해지는 Checked Exception보다는, 유연한 예외 처리가 가능한 Unchecked Exception(RuntimeException)을 상속받아 정의하는 것이 권장됨
  - 스프링 프레임워크를 포함한 현대적 프레임워크들의 대다수 예외도 RuntimeException을 기반으로 작동함
  - 무분별한 사용자 정의 예외 선언을 지양하고 자바의 표준 예외(IllegalArgumentException, IllegalStateException 등)를 우선적으로 재사용하는 것을 권장함

# 2. 자료 구조와 컬렉션 프레임워크(Collection)

## 2.1 자료 구조
- 자료구조(Data Structure)는 데이터를 효율적으로 저장, 조직, 관리하기 위한 논리적인 구조나 보관 방식을 의미함
- 자바의 컬렉션 프레임워크는 이러한 자료구조를 표준화된 인터페이스로 구현하여 제공함

### 2.1.1 대표적인 자료구조
#### 1) List (리스트)
- 순서가 있으며 데이터의 중복 저장을 허용하는 선형 자료구조
- 자바에서는 [ArrayList](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/ArrayList.html), [LinkedList](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/LinkedList.html) 등이 있음

#### 2) Set (셋)
- 데이터의 저장 순서를 보장하지 않으며 중복 저장을 허용하지 않는 자료구조
- 자바에서는 [HashSet](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/HashSet.html), [TreeSet](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/TreeSet.html) 등이 있음

#### 3) Map (맵)
- 키(Key)와 값(Value)의 쌍으로 데이터를 저장하는 자료구조
- 키는 중복될 수 없으나 값은 중복을 허용
- 동일한 키로 중복 저장할 경우 마지막에 저장된 자료로 덮어씌움
- 자바에서는 [HashMap](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/HashMap.html), [TreeMap](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/TreeMap.html) 등이 있음

#### 4) Stack (스택)
- 후입선출(Last In First Out, LIFO) 구조를 갖는 자료구조로, 마지막에 들어온 데이터가 먼저 나감
- 자바에서는 [Stack](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Stack.html) 클래스를 제공

#### 5) Queue (큐)
- 선입선출(First In First Out, FIFO) 구조를 갖는 자료구조로, 먼저 들어온 데이터가 먼저 나감
- 자바에서는  [LinkedList](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/LinkedList.html), [Queue](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Queue.html) 등이 있음

## 2.2 컬렉션 프레임워크
- 컬렉션 프레임워크 정의
  - 자바에서 데이터를 효율적으로 저장하고 관리할 수 있도록 표준화하여 제공하는 자료구조[^2] 및 알고리즘[^3]의 집합체
  - 표준화된 인터페이스를 통해 일관된 방식으로 데이터를 처리할 수 있도록 지원
- 핵심 인터페이스 계층 구조
  - [Collection](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Collection.html) 인터페이스: [List](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/List.html), [Set](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Set.html), [Queue](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Queue.html) 등의 상위 규격 역할을 담당
  - [Map](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Map.html) 인터페이스: Key-Value 구조로 데이터를 보관하므로 Collection 인터페이스와 별개의 구조로 설계

## 2.3 Collection 인터페이스
- 특징: List, Set, Queue 인터페이스의 공통 부모 인터페이스로, 데이터를 그룹으로 묶어 관리하는 기본적인 공통 메서드들을 정의함
- 주요 메서드
  - `boolean add(E e)`: 컬렉션에 요소를 추가함
  - `boolean remove(Object o)`: 컬렉션에서 지정된 요소를 삭제함
  - `int size()`: 컬렉션에 포함된 요소의 개수를 반환함
  - `boolean isEmpty()`: 컬렉션이 비어있는지 여부를 판단함
  - `boolean contains(Object o)`: 컬렉션에 지정된 요소가 포함되어 있는지 확인함
  - `void clear()`: 컬렉션의 모든 요소를 삭제함
  - `Iterator<E> iterator()`: 컬렉션의 요소를 순회하기 위한 [Iterator](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Iterator.html)를 반환함

## 2.4 List 인터페이스
- 특징: 순서를 유지하며 데이터의 중복 저장을 허용
- 주요 메서드
  - `E get(int index)`: 지정된 인덱스 위치의 요소를 반환함
  - `E set(int index, E element)`: 지정된 인덱스의 요소를 새로운 객체로 대체함
  - `void add(int index, E element)`: 지정된 인덱스 위치에 요소를 삽입함
  - `E remove(int index)`: 지정된 인덱스 위치의 요소를 삭제함
  - `int indexOf(Object o)`: 지정된 객체가 위치한 인덱스를 탐색하여 반환함
- ArrayList
  - 특징: 내부적으로 크기 조절이 가능한 배열 구조를 사용
  - 장점: 인덱스를 통한 데이터 조회 속도가 매우 빠름
  - 단점: 리스트 크기 확장 시 배열 복사가 일어나고, 중간에 데이터를 삽입/삭제할 때 기존 데이터들을 뒤로 밀어내거나 앞으로 당기는 이동 연산이 추가되어 성능이 저하
- LinkedList
  - 특징: 이중 연결 리스트 구조로 각 노드[^4]가 이전 노드와 다음 노드의 참조 주소를 보유
  - 단점: 특정 인덱스의 요소를 찾기 위해 처음 또는 끝부터 링크를 타고 순차적으로 조회해야 하므로 검색 성능이 저하
  - 장점: 중간에 데이터를 삽입하거나 제거할 때 링크 연결 정보만 변경하므로 빠르지만 대상 노드를 찾는 성능이 좋지 않기 때문에 전반적으로 느림
- 구현체 비교 분석
  | 항목 | ArrayList | LinkedList |
  | --- | --- | --- |
  | 내부 구조 | 가변 배열 | 이중 연결 리스트 |
  | 인덱스 조회 | 빠름 | 느림 |
  | 첫 위치 삽입/삭제 | 느림 | 빠름 |
  | 마지막 위치 삽입/삭제 | 빠름 | 빠름 |
  | 중간 삽입/삭제 | 느림 | 느림 |
  | 메모리 사용량 | 적음 (데이터만 저장) | 많음 (참조 주소 보관용 메모리 추가 필요) |

```java
List<String> arrayList = new ArrayList<>();
arrayList.add("Java");
arrayList.add("Spring");
arrayList.add(1, "JDBC");
arrayList.add(2, "Java"); // 중복 허용
arrayList.add("기초 프로젝트");
System.out.println(arrayList); // [Java, JDBC, Java, Spring, 기초 프로젝트]

List<String> linkedList = new LinkedList<>();
linkedList.add("Docker");
linkedList.add("응용 프로젝트");
linkedList.add(0, "AWS");
System.out.println(linkedList); // [AWS, Docker, 응용 프로젝트]
```

## 2.5 Set 인터페이스
- 특징: 데이터의 저장 순서를 보장하지 않으며 중복 저장 불가
- 주요 메서드
  - `boolean add(E e)`: 중복이 없는 경우에만 요소를 추가함 (추가 성공 시 true, 이미 존재 시 false 반환)
  - `boolean remove(Object o)`: 지정된 객체를 삭제함
  - `boolean contains(Object o)`: 지정된 객체가 포함되어 있는지 여부를 확인함
  - `Iterator<E> iterator()`: 컬렉션의 요소를 순회하기 위한 [Iterator](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Iterator.html)를 반환함
- HashSet
  - 특징: 해시 테이블[^5] 구조를 사용하여 데이터를 보관
  - 장점: 요소의 추가, 삭제, 검색 성능이 데이터 양에 관계없이 일정하고 신속
- TreeSet
  - 특징: 이진 탐색 트리 (Red-Black Tree)[^6] 구조를 기반으로 설계
  - 장점: 추가하는 데이터가 자동으로 오름차순 정렬되어 보관
  - 단점: 데이터가 들어올 때마다 트리 구조 재조정이 일어나므로 HashSet에 비해 삽입/삭제 성능이 느림
- 구현체 비교 분석
  | 항목 | HashSet | TreeSet |
  | --- | --- | --- |
  | 내부 자료구조 | 해시 테이블 | 이진 탐색 트리 (Red-Black Tree) |
  | 정렬 특징 | 순서 없음 (정렬 없음) | 정렬 있음 (기본 오름차순) |
  | 성능 | 상대적으로 매우 빠름 | 정렬을 동반하므로 상대적으로 느린 편 |

```java
// Set 사용 방법 및 중복 제거 예시 (부분 코드)
Set<String> set = new HashSet<>();
set.add("사과");
set.add("오렌지");
set.add("사과"); // 중복을 허용하지 않고 순서를 기억하지 않음
System.out.println(set); // [오렌지, 사과]
```

## 2.6 Map 인터페이스
- 특징: Key와 Value가 한 쌍(Entry)을 이루는 방식으로 데이터를 저장하며 Key는 중복 불가, Value는 중복을 허용
- 주요 메서드
  - `V put(K key, V value)`: 지정된 키와 값을 추가함 (동일한 키가 존재하면 기존 값을 덮어씀)
  - `V get(Object key)`: 지정된 키에 대응하는 값을 반환하며, 존재하지 않으면 null을 반환함
  - `V getOrDefault(Object key, V defaultValue)`: 지정된 키가 존재하면 해당 키의 값을 반환하고, 없으면 지정한 기본값을 반환함
  - `V putIfAbsent(K key, V value)`: 지정된 키가 없거나 null로 매핑되어 있을 때만 값을 추가함
  - `V remove(Object key)`: 지정된 키와 그에 대응하는 값을 함께 삭제함
  - `Set<K> keySet()`: 모든 키 정보를 Set 형태로 반환함
  - `Set<Map.Entry<K, V>> entrySet()`: 모든 Key-Value 쌍(Map.Entry[^7])을 Set 형태로 반환함
- HashMap
  - 특징: 해시 함수[^8]를 통해 Key의 저장 위치를 결정하므로 정렬 순서가 보장되지 않음
  - 장점: 추가, 삭제, 검색 속도가 매우 빠름
- TreeMap
  - 특징: 이진 탐색 트리 (Red-Black Tree)[^6]<sup>2</sup> 기반으로 동작하여 Key 값을 기준으로 자동 오름차순 정렬 상태를 유지
  - 장점: 범위 검색이나 정렬된 리스트를 반환할 때 적합
  - 단점: 요소를 추가할 때 정렬 연산이 동반되어 HashMap 대비 성능이 떨어짐
- Map의 데이터 탐색 기법
  - keySet(): 전체 Key 정보를 Set 형태로 반환받아 순회함. 순회 루프 안에서 Value를 꺼내기 위해 get() 메서드를 반복 호출하므로 비효율적
  - entrySet(): Key와 Value가 결합된 Entry 정보를 Set 형태로 가져와 순회함. 추가적인 조회 없이 Key와 Value를 한 번에 다룰 수 있어 대량 데이터를 순회할 때 권장
- 구현체 비교 분석
  | 항목 | HashMap | TreeMap |
  | --- | --- | --- |
  | 내부 자료구조 | 해시 테이블 | 이진 탐색 트리 (Red-Black Tree) |
  | 정렬 기준 | 순서 보장 없음 | Key 기준 자동 오름차순 정렬 |
  | Null 허용 | Key 및 Value 모두 Null 지정 허용 | Key로 Null 지정 불가 |

```java
// Map 사용 방법 및 Entry 순회 예시
Map<String, Integer> map = new HashMap<>();
map.put("사과", 1000);
map.put("사과", 1500); // 동일한 Key를 넣으면 기존 Value가 덮어쓰기 처리

// 권장되는 entrySet() 순회 기법
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println("과일: " + entry.getKey() + ", 가격: " + entry.getValue());
}
```

## 2.7 제네릭(Generic)

### 2.7.1 제네릭 도입 배경과 필요성
- 제네릭이란?
  - 클래스나 메서드 내부에서 사용할 데이터 타입을 클래스 작성시에 결정하지 않고 사용할 때 결정하는 타입 선언 방법
  - 특정 타입으로 제한하여 타입 안전성을 높이고, 불필요한 타입 캐스팅 작업을 제거함

- 제네릭 이전의 한계 (JDK 1.5 미만)
  - 제네릭이 없던 시절에는 다양한 타입의 객체를 저장하기 위해 모든 클래스의 최상위 부모인 Object 타입을 활용함
  - 이 방식은 객체를 컬렉션에 임시 보관한 뒤 다시 꺼내서 쓸 때, 매번 명시적인 캐스팅(강제 타입 변환) 처리를 거쳐야 했음
  - 코드가 지저분해질 뿐만 아니라, 개발자의 실수로 엉뚱한 타입으로 변환하려고 시도할 경우 컴파일 시점에는 에러가 발견되지 않고 실행 도중(Runtime)에 ClassCastException을 일으켜 프로그램이 돌발 종료되는 치명적인 결함이 존재했음
- 제네릭 도입에 따른 이점
  - 타입 안정성 확보: 클래스나 메서드 내부에서 다룰 데이터 타입을 선언 시점이 아닌 객체 생성 시점(인스턴스화)에 정하도록 하여, 엉뚱한 객체가 보관되는 일을 컴파일 수준에서 완벽하게 필터링함
  - 타입 캐스팅 생략: 데이터를 꺼낼 때 컴파일러가 대입된 타입에 맞게 자동 타입 변환을 지원하므로 불필요하고 번거로운 캐스팅 코드가 생략되어 코드가 한결 간결해짐

### 2.7.2 제네릭 기본 사용법
- 제네릭 클래스 선언과 객체 생성
  - 클래스 이름 옆에 다이아몬드 기호 `<T>`를 붙여 해당 클래스가 제네릭 타입 파라미터 T를 사용함을 명시함
  - 인스턴스화할 때 생성자 뒤의 다이아몬드 연산자 내 타입은 생략 가능함 (컴파일러의 타입 추론 지원)
- 타입 파라미터 이름 약속 기호
  - 관례적으로 의미를 유추하기 쉬운 단일 대문자 영문을 약속 기호로 사용함
  - T: Type (가장 범용적인 타입을 지칭)
  - E: Element (컬렉션에 보관할 요소를 타겟으로 지정할 때 사용)
  - K: Key (Map 구조 등에서 식별자 키 타입을 지칭)
  - V: Value (Map 구조 등에서 식별 데이터의 값 타입을 지칭)
  - N: Number (숫자 관련 타입으로 범위를 좁힐 때 사용)

### 2.7.3 제한된 타입 파라미터(Bounded Type Parameter)
- 필요성: 제네릭 타입 파라미터에 아무 타입이나 다 대입할 수 있으면, 객체 내부에서 특정 클래스의 전용 메서드(예: 숫자 연산 메서드 등)를 호출하는 안전한 비즈니스 로직 설계가 불가능함
- 구현 방법: `extends` 키워드를 선언부의 타입 변수 뒤에 붙여 특정 클래스나 인터페이스를 상속받은 타입들만 주입받도록 강제 범위를 고정함
  - `<T extends Number>`: 이 경우 T에는 Number 클래스 및 그 하위 클래스(Integer, Double 등)만 대입 가능하며, 객체 내부에서 Number 클래스의 메서드(doubleValue() 등)를 안전하게 호출할 수 있음

# 3. 자바 입출력(I/O)

## 3.1 입출력의 개념과 데이터 흐름

### 3.1.1 입출력(I/O)의 정의
- Input(입력)과 Output(출력)의 약어로, 컴퓨터 프로그램이 외부 환경(콘솔 창, 파일, 네트워크 등)과 데이터를 주고받는 모든 동작을 의미함

### 3.1.2 데이터 근원지(Source)와 목적지(Destination)
- 데이터 근원지(Source): 프로그램으로 데이터가 흘러 들어오는 출발 지점으로, 키보드, 파일, 네트워크 등이 해당함
- 데이터 목적지(Destination): 프로그램에서 가공된 데이터가 최종적으로 도착하는 지점으로, 콘솔 창, 파일, 네트워크 등이 해당함

### 3.1.3 스트림의 정의
- 데이터 근원지(출발지)와 목적지 사이에 데이터를 순서대로 주고받기 위해 형성되는 단방향 데이터 흐름을 의미
- 입력 장치로부터 데이터를 읽어 들이는 입력 스트림과 데이터를 외부로 송출하는 출력 스트림이 완전 분리되어 독립적으로 동작함

### 3.2.4 자바 I/O 다형성과 상속 관계
- 데이터의 근원지나 목적지가 물리적으로 다를지라도(콘솔 창, 파일, 네트워크 등), 자바 프로그램 내부에서는 다형성(Polymorphism)을 활용해 공통된 코드로 다룰 수 있도록 java.io 패키지의 입출력 클래스들이 체계적인 상속 관계를 형성하고 있음
- 모든 바이트 단위의 입력 클래스는 최상위 추상 클래스인 InputStream을, 출력 클래스는 OutputStream을 상속함
- 모든 문자 단위의 입력 클래스는 최상위 추상 클래스인 Reader를, 출력 클래스는 Writer를 상속함
- 이를 통해 개발자는 실제 데이터 소스가 파일(FileInputStream)이든, 콘솔 창이든 상관없이, 상위 추상 클래스 타입으로 통일하여 read()나 write() 메서드를 호출하는 단일화된 공통 코드를 작성할 수 있음

## 3.2 입출력 클래스의 분류 체계
- java.io 패키지에는 무수히 많은 입출력 클래스가 제공되지만 두가지 분류체계로 나누어 볼 수 있음

### 3.2.3 데이터 이동 단위에 따른 분류
- 바이트(byte) 단위 입출력: 1byte 단위 데이터 처리 수행. 그림, 동영상, 압축 파일 등 모든 형태 바이너리 데이터 대상 적용. 최상위 클래스는 InputStream / OutputStream
- 문자(char) 단위 입출력: 2byte(또는 유니코드 가변 단위) 크기 텍스트 데이터를 문자 단위로 처리. 최상위 클래스는 Reader / Writer

### 3.2.4 연결 방식 기준에 따른 분류
- 1차 스트림 (기본 스트림 또는 노드 스트림): 실제 입출력 장치(파일, 메모리 등)와 직접 연결되어 입출력 수행
- 2차 스트림 (보조 스트림 또는 프로세싱 스트림): 1차 스트림 또는 다른 2차 스트림과 연결되어 데이터 가공, 버퍼링 등 추가 기능 수행

## 3.3 InputStream과 OutputStream의 주요 메서드
- 모든 바이트 기반 입출력 클래스의 최상위 추상 클래스인 InputStream과 OutputStream은 공통 입출력 제어를 위해 아래와 같은 주요 메서드들을 정의하고 있으며, 상속을 통해 모든 하위 스트림 클래스에서 다형성 형태로 호출하여 사용함

### 3.3.1 InputStream 주요 메서드
- `int read()`: 입력 스트림으로부터 1바이트 데이터를 읽어 정수형(0~255)으로 반환함. 읽을 데이터가 없을 시 -1을 반환함
- `int read(byte[] b)`: 바이트 배열 b 크기만큼 데이터를 읽어 배열에 저장함. 읽은 바이트 수를 반환하며 끝 도달 시 -1을 반환함
- `int read(byte[] b, int offset, int length)`: 바이트 배열 b의 offset 위치부터 length 크기만큼 데이터를 읽어 저장하고 읽은 바이트 수를 반환함. 끝 도달 시 -1을 반환함
- `void close()`: 스트림 자원을 반환하고 입력 스트림 연결을 끊음

### 3.3.2 OutputStream 주요 메서드
- `void write(int b)`: 출력 스트림에 1바이트 데이터를 기록함
- `void write(byte[] b)`: 바이트 배열 b의 모든 데이터를 출력 스트림에 기록함
- `void write(byte[] b, int offset, int length)`: 바이트 배열 b의 offset 위치부터 length 크기만큼 데이터를 읽어 출력 스트림에 기록함
- `void flush()`: 출력 버퍼에 남아있는 데이터를 강제로 전송함
- `void close()`: 시스템 자원을 반환하고 출력 스트림 연결을 끊음

### 3.3.3 Reader와 Writer의 주요 메서드
- Reader와 Writer는 InputStream, OutputStream과 동일하며 데이터 단위만 byte에서 char로 달라짐
- 추가로 문자 단위 출력 편의를 위해 문자열을 곧바로 전송할 수 있는 `void write(String str)` 메서드가 Writer 클래스에 별도로 제공됨

- 💻 실습 (키보드 입력을 콘솔로 출력): [ch03/KeyboardToConsole.java](../workspace/04_advanced/ch03/KeyboardToConsole.java)

## 3.4 파일 입출력 클래스

### 3.4.1 파일 입출력 및 파일 관리 클래스
- [File](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/io/File.html): 시스템의 파일이나 디렉터리를 관리하는 클래스. 파일의 생성, 삭제, 존재 여부 확인 등 파일 자체의 정보와 물리적 속성을 제어하는 기능을 제공함
  - 주요 생성자
    - `File(String pathname)`: 지정된 경로 이름의 문자열을 기반으로 File 객체를 생성
    - `File(String parent, String child)`: 부모 디렉터리 경로와 자식 파일 이름을 조합하여 File 객체를 생성
  - 주요 메서드
    - `boolean exists()`: 해당 경로에 파일 또는 디렉터리가 실제로 존재하는지 여부를 판단
    - `boolean createNewFile()`: 해당 경로에 새로운 물리 파일을 생성
    - `boolean delete()`: 해당 파일 또는 디렉터리를 물리적으로 삭제
    - `boolean isFile()`: 해당 객체가 일반 파일인지 여부를 판단
    - `boolean isDirectory()`: 해당 객체가 디렉터리인지 여부를 판단
    - `String getName()`: 파일 또는 디렉터리의 이름을 반환
    - `String getAbsolutePath()`: 해당 파일의 절대 경로를 반환
    - `long length()`: 파일의 크기를 반환
- [FileInputStream](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/io/FileInputStream.html): 파일로부터 1바이트씩 데이터를 읽어 들이는 입력 클래스
  - 주요 생성자
    - `FileInputStream(String name)`: 지정된 파일 경로 이름을 기준으로 `입력 객체`를 생성
    - `FileInputStream(File file)`: 지정된 File 객체를 기준으로 `입력 객체`를 생성
  - 주요 메서드
    - `int read()`: 파일로부터 1바이트 데이터를 읽어 정수형(0~255)으로 반환. 파일 끝에 도달하면 -1을 반환함
    - `int read(byte[] b)`: 파일로부터 배열 b의 크기만큼 데이터를 읽어 배열에 저장. 읽은 바이트 수를 반환하며 파일 끝 도달 시 -1을 반환함
    - `int read(byte[] b, int offset, int length)`: 파일로부터 length 크기만큼 데이터를 읽어 배열 b의 offset 위치부터 저장. 읽은 바이트 수를 반환하며 파일 끝 도달 시 -1을 반환함
    - `void close()`: 파일 입력 연결을 닫고 시스템 자원을 반환함
- [FileOutputStream](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/io/FileOutputStream.html): 대상 파일에 1바이트씩 데이터를 기록하는 출력 클래스.
  - 주요 생성자
    - `FileOutputStream(String name)`: 지정된 파일 경로 이름을 기준으로 `파일 출력 객체`를 생성. 파일이 존재하지 않으면 새로 생성하고, 기존 파일이 존재하면 덮어씀
    - `FileOutputStream(String name, boolean append)`: 지정된 파일 경로 이름을 기준으로 `파일 출력 객체`를 생성. 파일이 존재하지 않으면 새로 생성하고, 기존 파일이 존재하면 append 값에 따라서 덮어쓸지 이어쓸지 결정됨(true면 기존 내용 뒤에 이어서 기록, 기본값은 false)
    - `FileOutputStream(File file)`: 지정된 File 객체를 기준으로 `파일 출력 객체`를 생성. 파일이 존재하지 않으면 새로 생성하고, 기존 파일이 존재하면 덮어씀
    - `FileOutputStream(File file, boolean append)`: 지정된 File 객체를 기준으로 `파일 출력 객체`를 생성. 기존 파일이 존재하면 append 값에 따라서 덮어쓸지 이어쓸지 결정됨(true면 기존 내용 뒤에 이어서 기록, 기본값은 false)
  - 주요 메서드
    - `void write(int b)`: 1바이트 데이터를 파일에 기록함
    - `void write(byte[] b)`: 바이트 배열 b의 모든 데이터를 파일에 기록함
    - `void write(byte[] b, int offset, int length)`: 바이트 배열 b의 offset 위치부터 length 크기만큼의 데이터를 파일에 기록함
    - `void flush()`: 출력 버퍼에 잔류하는 데이터를 물리 파일에 즉시 강제 전송함
    - `void close()`: 파일 출력 연결을 닫고 시스템 자원을 반환함

### 3.4.2 파일 입출력의 예외 처리와 자원 해제
- 파일 입출력 API는 파일이 없거나 디스크 접근에 실패하는 상황 등에 대비하여 예외 처리가 강제되는 Checked Exception 계열로 설계되어 있음
- 외부 시스템 자원을 점유하므로 작업 완료 후 안전하게 닫아주기 위해 try-with-resources 구문 사용을 권장함
- try-with-resources 자원 해제 예시
  ```java
  // try괄호 내에 선언한 객체들은 try블록을 벗어날 때 자동으로 close()가 호출됨
  try (
    InputStream fis = new FileInputStream("source.txt");
    OutputStream fos = new FileOutputStream("target.txt")) {
    // 입출력 작업
    // ...
  } catch (IOException e) {
    System.err.println("파일 처리 중 예외 발생: " + e.getMessage());
  }
  ```

## 3.6 입출력 예외와 자원 누수 대처

### 3.6.1 파일 접근 실패 예외 (FileNotFoundException)
- 발생 원인: 지정한 경로에 대상 파일이 실제 존재하지 않거나, 읽기 전용 파일 쓰기를 시도할 경우, 혹은 디렉토리 경로를 파일명으로 지정하여 접근을 시도할 때 발생함
- 대처 요령: 파일 경로의 알파벳 대소문자 확인 및 실제 물리적인 파일의 존재 위치를 점검해야 함. 프로그램 코드 내에서 File 객체의 exists() 메서드를 사용하여 파일 존재 여부를 확인 후 사용

### 3.6.2 스트림 미폐쇄로 인한 자원 누수
- 발생 원인: 스트림은 자바 내부 메모리가 아니라 운영체제(OS)로부터 권한을 얻어 개설하는 외부 데이터 연결 상태. 컴퓨터 전체에서 한 번에 열 수 있는 스트림의 개수가 한정되어 있으므로, 사용을 마친 후 닫아서 반납하지 않으면 사용 가능한 스트림이 고갈되어 새로운 파일이나 네트워크 연결을 열지 못하는 시스템 마비 현상이 생길 수 있음
- 대처 요령: 다 사용한 스트림을 반납하기 위해 잊지 말고 close()를 호출하거나 try-with-resources 문법을 사용해서 블록이 끝날 때 사용한 스트림 자원을 자동으로 안전하게 반납하도록 구성

### 3.6.3 출력 데이터의 실시간 미반영과 버퍼 비우기
- 발생 원인: 자바 출력 스트림은 효율을 위해 메모리 버퍼를 거치는 특성이 있어, 버퍼에 데이터가 갇힌 상태에서는 실제 목적지로 데이터가 실시간 전송되지 않는 지연 현상이 발생함
- 대처 요령:
  - 출력 스트림을 닫는 `close()` 메서드는 내부적으로 버퍼를 비워내는 `flush()`를 자동으로 함께 호출하므로 스트림 종료 시에는 데이터 누락이 발생하지 않음
  - 다만, 스트림 연결을 닫지 않고 계속 열어둔 상태로 데이터를 실시간 즉시 전송해야 하는 상황(예: 네트워크 채팅 통신, 실시간 콘솔 데이터 모니터링 등)에서는 쓰기 작업 직후 반드시 명시적으로 `flush()`를 호출하여 버퍼에 데이터가 다 차지 않았더라도 즉각 전송하도록 해야함

# 4. 자바 네트워크 프로그래밍

## 4.1 네트워크 기초

### 4.1.1 IP 주소와 포트 번호
- IP: 네트워크 환경에서 고유한 컴퓨터 위치 식별용 주소
- Port: 컴퓨터 내부의 어떤 프로세스가 데이터 패킷을 수령해야 하는지 정확한 어플리케이션 목적지를 결정하는 고유 식별 번호 (0 ~ 65535 범위 분배)
- 포트의 3가지 분류 체계
  - 잘 알려진 포트 (Well-Known Ports, 0 ~ 1023): 주요 통신 규약용으로 국제인터넷주소관리기구(IANA)에 의해 사전 예약된 포트군 (OS 수준의 관리 권한이 필요함)
  - 등록된 포트 (Registered Ports, 1024 ~ 49151): 특정 기업의 솔루션이나 미들웨어 서비스 프로세스들이 사전 등록하여 활용하는 포트군 (예: 자바 톰캣 서버 등)
  - 동적/사설 포트 (Dynamic/Private Ports, 49152 ~ 65535): 클라이언트가 서버에 임시 접속할 때 운영체제가 즉석에서 무작위로 배정해 주는 발신용 임시 포트군
- 실무적으로 자주 쓰이는 주요 표준 포트 번호
  - 22: SSH (보안 셸 원격 제어 및 터미널 접속)
  - 25: SMTP (메일 전송 규약)
  - 80: HTTP (기본 웹 통신 프로토콜)
  - 443: HTTPS (보안 암호화 웹 통신 프로토콜)
  - 3306: MySQL / MariaDB (관계형 데이터베이스 기본 포트)
  - 8080: WAS / Tomcat (자바 웹 애플리케이션 서버 기본 테스트 포트)

### 4.1.2 프로토콜 (Protocol)
- 컴퓨터나 네트워크 장비들이 서로 데이터를 올바르게 주고받기 위해 정의한 공통의 통신 규약(규칙)
- 우체국을 통해 편지나 택배를 보낼 때 우표 부착 위치, 보내는 사람과 받는 사람 주소 기재 방식, 규격 봉투 등의 강제 서식을 정확히 준수해야만 우편물이 정상 배달되듯이, 컴퓨터 통신도 전송하려는 데이터 패킷의 헤더 구성과 작성 서식이 해당 프로토콜(웹은 HTTP, 메일은 SMTP 등)의 엄격한 형식 규칙에 완벽히 들어맞아야만 전송이 이루어짐

### 4.1.3 주요 프로토콜의 종류와 특징

#### 1) TCP (Transmission Control Protocol)
- 연결 지향성 프로토콜: 데이터를 주고받기 전에 송수신 컴퓨터 간의 논리적인 가상 연결 통로를 먼저 개설함 (3-Way Handshake 과정 거침)
- 높은 신뢰성: 패킷의 전송 순서를 보장하고 데이터 유실 발생 시 자동으로 재전송을 요청하는 흐름 제어 및 오류 복구 메커니즘이 내장됨
- 적용 분야: 웹 브라우징(HTTP), 이메일, 파일 전송(FTP) 등 데이터 정합성이 절대적으로 중요한 분야에 사용되며 속도는 UDP에 비해 다소 느림

#### 2) UDP (User Datagram Protocol)
- 비연결성 프로토콜: 연결을 수립하는 과정 없이 데이터를 독립적인 패킷(Datagram) 단위로 목적지를 향해 일방적으로 던지는 방식
- 빠른 속도와 경량성: 흐름 제어나 수신 확인 절차가 없기 때문에 지연 시간이 거의 없고 속도가 극도로 빠름
- 적용 분야: 동영상 실시간 스트리밍, 온라인 게임, IP 전화(VoIP) 등 일부 데이터가 유실되더라도 실시간 전송 속도가 중요한 서비스에 적합함

#### 3) HTTP (HyperText Transfer Protocol)
- 웹 환경(Web)에서 클라이언트(브라우저)와 서버가 텍스트, 이미지, HTML 문서 등을 주고받기 위해 사용하는 프로토콜.
- TCP 프로토콜 기반으로 동작
- 요청(Request)과 응답(Response) 구조: 클라이언트가 서버에 데이터를 요청하면 서버가 이에 대응하는 결과를 돌려주고 연결을 끊는 무상태성(Stateless)을 기본 특징으로 함

### 4.1.4 소켓 (Socket)이란?
- 운영체제(OS) 수준에서 네트워크를 통해 멀리 떨어진 두 컴퓨터의 프로세스 간 양방향 통신이 가능하도록 연결해 주는 소프트웨어 접점(통신 창구)
- 벽면의 전화선 잭에 전화를 연결해서 쓰듯이, 네트워크 프로그램은 이 소켓을 통해 데이터를 읽거나 쓰는 스트림 입출력 작업을 통해 통신을 수행함

## 4.2 TCP 소켓 통신

### 4.2.1 Socket과 ServerSocket
#### 1) Socket 클래스
- [Socket](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/net/Socket.html) 클래스는 클라이언트와 서버 간의 1대1 양방향 통신을 처리하는 객체로, 소켓에 연동된 바이트 입출력 스트림을 통해 원격지 간의 실제 데이터를 직접 읽고 쓰는(송수신) 역할
- 주요 생성자
  - Socket(String host, int port): 지정한 호스트 주소(IP 혹은 도메인)와 포트 번호로 서버에 즉시 연결을 시도하는 클라이언트 소켓을 생성
- 주요 메서드
  - InputStream getInputStream(): 소켓을 통해 상대방이 전송한 원격 데이터를 수신(읽기)하는 InputStream을 반환
  - OutputStream getOutputStream(): 소켓을 통해 상대방에게 데이터를 전송(쓰기)하는 OutputStream을 반환
  - void close(): 소켓의 양방향 입출력 스트림을 차단하고 연결을 즉시 끊음
  - boolean isClosed(): 현재 소켓이 닫혀 있는지 여부를 확인하여 상태를 반환

```java
try (Socket socket = new Socket("localhost", 50000)) {
  InputStream in = socket.getInputStream(); // 서버의 메세지 수신에 사용
  OutputStream out = socket.getOutputStream(); // 서버에 메세지 송신시 사용

  PrintWriter writer = new java.io.PrintWriter(out, true); // autoFlush: true
  writer.println("안녕하세요. 클라이언트입니다."); // 문장 단위로 전송

} catch (IOException e) {
  System.err.println("통신 중 에러 발생: " + e.getMessage());
}
```

#### 2) ServerSocket 클래스
- [ServerSocket](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/net/ServerSocket.html) 클래스는 지정한 포트 번호를 할당받아 외부 클라이언트의 연결 요청이 들어올 때까지 기다리고, 연결 요청이 오면 실제 통신을 담당할 소켓(Socket) 객체를 생성하여 전달해 주는 역할

- 주요 생성자
  - ServerSocket(int port): 지정된 포트 번호를 할당받아 연결 대기용 서버 소켓을 생성함
- 주요 메서드
  - Socket accept(): 클라이언트의 연결 요청이 들어오면 OS 수준에서 TCP 연결 프로세스를 완료한 후 OS의 Accept Queue에 소켓을 저장함. accept() 메서드는 JVM이 이 큐에서 대기 중인 소켓을 꺼내어 실제 양방향 통신을 처리할 Socket 객체로 반환하는 역할을 수행함 (Accept Queue에 소켓이 들어올 때까지 스레드를 블로킹[^9] 시킴)
  - void close(): 서버 소켓을 닫고 할당된 네트워크 포트 리소스를 OS에 반환함

```java
try (ServerSocket server = new ServerSocket(50000)) {
  Socket client = server.accept(); // 클라이언트 접속 시까지 대기(블로킹)
  InputStream in = socket.getInputStream(); // 클라이언트의 메세지 수신에 사용
  OutputStream out = socket.getOutputStream(); // 클라이언트에 메세지 송신에 사용
} catch (IOException e) {
  System.err.println("서버 에러: " + e.getMessage());
}
```

## 4.3 멀티스레드 다중 접속 서버

### 4.3.1 단일 스레드 접속 처리 서버의 한계
- 서버 소켓이 1명의 클라이언트 연결을 수령하여 I/O를 수행 중인 경우, 다른 클라이언트들의 연결은 대기열에 계속 블로킹되어 서비스 불능 상태에 도달
  + Socket의 accept(), InputStream의 read() 메서드가 블로킹 메서드이기 때문에 accept()를 실행해서 클라이언트 접속을 대기하거나 read() 메서드를 실행해서 클라이언트의 메세지를 대기하는 상황이 발생

### 4.3.2 멀티스레드를 이용한 다중화 구조
- 클라이언트가 accept()를 통과하여 연결을 생성하면, 즉시 새 실행 스레드를 생성하여 개별 소켓 통신을 이관하고 메인 스레드는 다시 accept 대기로 복귀하여 다중 접속 분산 처리 달성

# 5. 멀티스레드(Multi-Thread)

## 5.1 프로세스와 스레드
- 프로세스(Process)의 개념
  - 운영체제로부터 독립적인 메모리 및 필요한 자원을 할당받아 컴퓨터 실행 컨텍스트에 등록되어 구동 중인 단일 프로그램을 의미
- 스레드(Thread)의 개념
  - 하나의 프로세스 내부에서 실행 흐름의 가장 작고 기초적인 단위를 뜻함
  - 메모리 중 스레드마다 독립적으로 가지는 Stack 영역을 제외하고 아래의 JVM 런타임 메모리 영역을 공유하여 협력함
    - 메서드 영역 (Method Area, 클래스/정적 영역): JVM이 구동될 때 생성되며 클래스의 구조 정보, 메서드의 바이트코드 명령어, 정적(static) 변수 등이 저장되어 모든 스레드가 공유함 (OS 프로세스의 Code 및 Data 영역에 대응)
    - Heap 영역: 동적으로 할당되는 객체(new 인스턴스)와 배열이 저장되는 공간으로, 여러 스레드가 해당 객체의 참조 주소를 공유하여 함께 사용할 수 있음
    - Stack 영역 (공유 제외): 메서드 호출 시 사용되는 지역변수, 매개변수, 리턴 주소 등이 저장되는 스레드별 독립적인 공간으로, 각 스레드는 서로 간섭할 수 없는 독립적인 실행 흐름을 가짐
- 싱글 스레드(Single-Thread)
  - 프로세스 내부에서 단 하나의 스레드만 생성되어 모든 작업을 하나의 스레드가 순차적으로 처리하는 방식
  - 구조가 단순하고 공유 자원 경쟁에 따른 오류가 발생하지 않는 장점이 있으나, 네트워크 요청 대기나 파일 입출력처럼 오래 걸리는 작업(블로킹)이 발생할 경우 그 뒤의 모든 코드가 대기 상태에 걸려 프로그램의 반응성이 저하됨
- 멀티 스레드(Multi-Thread)
  - 하나의 프로세스 내부에서 동시에 여러 개의 스레드를 생성하여 다중 작업을 병렬적으로 동시 처리하는 방식
  - 대용량 데이터 처리 속도를 높이고 백그라운드 작업을 분리해 프로그램의 반응성을 극대화하는 장점이 있으나, 메모리 공간(Heap 등)을 공유하므로 동기화 제어가 부적절할 시 데이터 오염이나 교착 상태(데드락) 문제를 야기할 수 있어 세밀한 설계가 요구됨

## 5.2 Thread 클래스
- java.lang 패키지에 소속된 클래스로서, 자바에서 스레드를 생성하고 제어하기 위한 핵심 클래스
- 스레드로 동작시키고 싶은 클래스는 [Thread](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Thread.html) 클래스를 상속받아 run() 메서드를 오버라이딩해서 구현함

### 5.2.1 주요 생성자
- `Thread()`: 기본 생성자. 스레드 이름이 자동으로 부여됨 (예: Thread-0, Thread-1)
- `Thread(String name)`: 스레드의 이름을 직접 지정하여 생성함. 디버깅이나 로그 추적 시 식별에 유용함
- `Thread(Runnable target)`: 실행할 작업이 정의된 Runnable 구현 객체를 전달받아 스레드를 생성함
- `Thread(Runnable target, String name)`: Runnable 구현 객체와 스레드 이름을 함께 지정하여 생성함

### 5.2.2 주요 메서드
- `void start()`: 스레드를 시작함. 내부적으로 새로운 호출 스택(Call Stack)을 생성한 뒤 run() 메서드를 자동으로 호출함. 직접 run()을 호출하면 새로운 스레드가 생성되지 않고 현재 스레드에서 일반 메서드처럼 순차 실행되므로 반드시 start()를 사용해야 함
- `void run()`: 스레드가 실행할 작업 내용을 정의하는 메서드. Thread를 상속한 경우 이 메서드를 오버라이딩하여 실행 코드를 작성함
- `static void sleep(long millis)`: 현재 실행 중인 스레드를 지정한 밀리초(1/1000초) 동안 일시 정지시킴. InterruptedException 예외 처리가 필요함

## 5.3 스레드 생성과 실행

### 5.3.1 Thread 클래스 직접 상속 방식
- Thread 클래스를 부모로 삼아 run() 메서드를 오버라이딩하여 스레드가 실행할 코드를 명시함
- 자바는 단일 상속만 지원하므로 다른 클래스를 상속받아야 하는 경우 다중 상속 제약이 발생하는 단점이 있음

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Thread 상속 기반 동작");
    }
}

// 스레드 객체 생성 및 실행
new MyThread().start();
```

### 5.3.2 Runnable 인터페이스 구현 방식
- Runnable 인터페이스의 run() 추상 메서드를 구현하여 실행할 작업을 정의함
- 인터페이스를 구현했으므로 다른 클래스 상속에 제한이 없고 실행 스레드와 작업 태스크 단위를 독립적으로 분리할 수 있어 결합도가 낮은 구조 설계가 가능함 (권장 방식)

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("Runnable 인터페이스 구현 기반 동작");
    }
}

// Thread 객체 생성 시 Runnable 구현체를 전달하여 시작
new Thread(new MyRunnable()).start();
```

### 5.3.3 익명 클래스(Anonymous Class)를 통한 즉석 구현 방식
#### 1) 익명 클래스란?
- 클래스의 선언과 동시에 객체(인스턴스) 생성을 한 번에 처리하는 이름이 없는 일회성 클래스
- 주로 특정 부모 클래스를 상속받거나 인터페이스를 구현한 후 내부에 선언된 추상 메서드를 일회용으로 즉석에서 구현해 사용할 때 활용함

#### 2) 익명 클래스를 만드는 방법
- 별도의 클래스를 만들지 않고 new 연산자 뒤에 대상이 될 부모 클래스 이름 또는 인터페이스 이름을 지정한 뒤 곧바로 중괄호 {}를 열고 내부에서 추상 메서드를 직접 오버라이딩하여 구현함
```java
new 부모클래스_또는_인터페이스() {
    // 추상 메서드 재정의
};
```

- 원래 자바에서 인터페이스는 자체적으로 인스턴스(객체)를 생성할 수 없지만, 이처럼 new 인터페이스명() 뒤에 중괄호 {}를 붙여 추상 메서드의 본문을 완전히 즉석에서 완성해 주면 자바 컴파일러는 이를 이름 없는 임시 구현 클래스로 인식하여 정상적인 객체 생성을 허용함

```java
// 1. 일반적인 구현 방식 (이름 있는 클래스 정의)
class Task implements Runnable {
    @Override
    public void run() {
        System.out.println("일반 클래스 기반 동작");
    }
}
new Thread(new Task()).start();

// 2. 익명 클래스(Anonymous Class) 구현 방식
new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("익명 클래스 기반 동작");
    }
}).start();
```
## 5.4 스레드 스케줄링과 컨텍스트 스위칭
### 5.4.1 스레드 스케줄링 (Thread Scheduling)
- 컴퓨터의 CPU 코어 수는 한정되어 있으나 실행해야 할 스레드의 수는 훨씬 많은 것이 일반적임
- 이에 따라 운영체제(OS)와 자바 가상 머신(JVM)의 스레드 스케줄러가 각 스레드에게 CPU 자원을 나누어 주어 공평하게 실행될 수 있도록 순서와 실행 시간(Time Slice)을 제어하고 분배하는 작업을 스레드 스케줄링이라고 함
- 자바 스레드는 OS의 스레드 스케줄링 정책(선점형 우선순위[^10] 방식 및 라운드 로빈[^11] 등)을 바탕으로 관리됨

### 5.4.2 컨텍스트 스위칭 (Context Switching)
- 멀티 스레드 환경에서 하나의 CPU를 공유하여 여러 작업을 동시에 처리하는 것처럼 보이게 하는 시분할[^12](Time Sharing) 연산 과정에서 발생함
- 현재 CPU를 할당받아 실행 중이던 스레드의 작업 정보를 임시로 보관하고, 새롭게 실행할 다음 스레드의 이전 보관 정보를 CPU로 로딩하여 교체하는 작업을 뜻함
- 컨텍스트 스위칭이 발생할 때마다 CPU 레지스터[^13] 데이터를 저장하고 복원하는 오버헤드(시간 소모)가 누적됨

### 5.4.3 스케줄링/스위칭과 동기화의 상관관계
- 자바 소스코드 상에서 `balance -= amount`라는 코드는 단 한 줄의 명령처럼 보이지만, 실제 기계어 수준에서는 1) 현재 메모리 잔액 값을 CPU로 읽어오기(Load), 2) 차감 연산 수행하기(Sub), 3) 연산된 결과 값을 다시 메모리에 덮어쓰기(Store)의 3가지 다단계 세부 명령어로 쪼개어져 실행됨
- 초기 잔액이 10,000원인 계좌에서 스레드 A와 B가 동시에 7,000원씩 출금을 시도할 때
  - 스레드 A가 1단계(Load)를 수행하여 메모리에서 10,000원을 읽어 자신의 레지스터에 보관함
  - 스레드 A가 2단계(Sub)를 수행하여 레지스터 내부 연산으로 결과 값 3,000원(10,000 - 7,000)을 도출함
  - [컨텍스트 스위칭 발생] 스레드 A가 결과 값을 메모리에 기록(3단계 Store)하기 직전에 멈추고 스레드 B가 실행권을 넘겨받음
  - 스레드 B가 1단계(Load)를 수행함. 아직 스레드 A가 결과를 저장하지 않았으므로 메모리 잔액은 여전히 10,000원으로 읽힘
  - 스레드 B가 2단계(Sub) 및 3단계(Store)를 끝까지 수행하여 결과 값 3,000원을 메모리에 최종 저장함 (메모리 잔액 = 3,000원)
  - 스레드 A가 다시 CPU를 할당받아 멈췄던 지점인 3단계(Store)부터 시작함. 스레드 A는 자신이 이전에 연산해 둔 결과 값 3,000원을 메모리에 덮어씀 (메모리 잔액 = 3,000원)
  - 결과적으로 총 14,000원의 출금이 연이어 접수되었음에도 최종 잔액은 3,000원만 남게 되어 데이터 정합성이 깨지는 경쟁 상태[^14](Race Condition, 레이스 컨디션)가 유발됨
- 따라서 이러한 순서 교체 환경 속에서 여러 단계의 기계어 연산들이 도중에 끊기지 않고 하나의 묶음(원자성)으로 완전히 종료될 수 있도록 해주는 안전장치인 동기화(Synchronization)의 활용이 필수적으로 요구됨

## 5.5 스레드 동기화
- 동기화(Synchronization)의 필요성
  - 여러 스레드가 동시에 공유 자원에 접근하여 쓰기 처리를 진행할 때 데이터의 정합성이 깨지는 경쟁 상태(Race Condition)가 나타나 데이터 불일치가 발생하는 걸 막기 위해서 필요
- synchronized 키워드
  - 특정 객체나 메서드에 락(Lock)을 설정하여, 오직 키를 얻은 유일한 스레드만 임계 영역[^15](Critical Section) 내부 코드를 통과할 수 있도록 강제적으로 제한하는 키워드

```java
class Account {
    private int balance = 10000;

    // synchronized 키워드로 임계 영역을 설정하여 두 스레드가 동시에 출금하지 못하도록 차단함
    public synchronized boolean withdraw(int amount) {
        if (balance >= amount) {
            balance -= amount;
            return true;
        }
        return false; // 잔액 부족
    }
}
```

## 5.6 스레드 안전성 확보
- 스레드 안전성(Thread Safety)
  - 여러 스레드가 동시에 접근하여 작업을 수행하더라도 문제없이 항상 예측 가능한 정상 데이터를 도출하는 성질
- 안전성 확보 전략
  - 무상태성 설계: 상태를 저장하는 클래스의 멤버 변수(필드)를 최대한 배제하고 메서드 내부 지역 변수만을 활용하여 동시성 마찰을 사전 회피
  - 불변성(Immutable) 활용: 한 번 선언되면 절대 수정 불가능한 객체(final 지시어 등 활용)를 공유하여 스레드가 상태 변경 자체를 하지 못하도록 차단
  - 스레드 안전 컬렉션 적용: Vector나 Hashtable과 같이 모든 동작에 락이 걸려 성능이 저하되는 구조 대신, CopyOnWriteArrayList이나 ConcurrentHashMap 등 정교하게 튜닝된 락 구조를 갖춘 컬렉션을 활용

## 5.7 가상 스레드(Virtual Thread)
### 5.7.1 가상 스레드 도입 배경
- 기존 자바의 전통적인 플랫폼 스레드(Platform Thread)는 OS 스레드를 1:1로 매핑하여 사용함
- 이 방식은 생성 및 컨텍스트 스위칭 비용이 매우 크며, 동시 요청 처리를 위해 많은 수의 스레드를 생성하면 메모리 고갈 문제를 야기함
- 자바 21부터 정식 도입된 가상 스레드는 OS 스레드에 종속되지 않고 JVM이 자체적으로 관리하는 경량 스레드로, 적은 리소스로 수백만 개의 동시 실행 흐름을 지원함

### 5.7.2 플랫폼 스레드와 가상 스레드 비교
- 플랫폼 스레드: OS 스레드와 1:1 대응하며 크기가 큼 (약 1MB 스택 할당). 생성 비용이 비쌈. 주로 스레드 풀을 통해 재사용함.
- 가상 스레드: OS 물리 스레드와 M:N 대응(수많은 가상 스레드가 소수의 실제 OS 스레드에 번갈아 얹혀 동작)하며 크기가 극도로 작음 (수 KB 범위). 생성 비용이 매우 저렴함. 풀링하지 않고 필요할 때마다 생성하고 폐기함.

### 5.7.3 동작 원리
- 가상 스레드는 실행될 때, JVM이 관리하는 플랫폼 스레드인 캐리어 스레드(Carrier Thread)에 배정되어 실행됨
- 실행 중 데이터베이스 조회나 파일 읽기 등의 대기 작업(블로킹 I/O)을 만나 멈추게 되면, 가상 스레드는 캐리어 스레드로부터 즉시 분리됨
- 이때 가상 스레드의 작업 상태 정보는 힙 메모리 영역에 임시 저장되고, 캐리어 스레드는 대기하지 않고 다른 가상 스레드를 실행하는 데 투입됨
- 대기 작업이 끝나면 가상 스레드는 힙에 저장해 두었던 상태를 복구하여 가용한 캐리어 스레드에 다시 배정되어 작업을 이어서 수행함
- 핵심 요약
  - 가상 스레드를 사용하면 실제 물리 OS 스레드는 OS 레벨에서 무겁게 멈추거나 컨텍스트 스위칭을 겪지 않고 계속 가동 상태를 유지하며 동작함
  - 대신 JVM이 가상 스레드들의 작업 상태 정보를 자체 힙 메모리에 객체로 저장하고 복원하면서 컨텍스트 스위칭을 흉내 내어 구현하기 때문에 오버헤드가 압도적으로 적고 빠른 속도를 보장함

### 5.7.4 가상 스레드 사용 예시
  ```java
  // 1. 단일 가상 스레드 직접 생성 및 실행
  Thread virtualThread = Thread.ofVirtual().start(new Runnable() {
      @Override
      public void run() {
          System.out.println("가상 스레드 실행: " + Thread.currentThread());
      }
  });

  // 2. 가상 스레드 전용 Executor 사용 (Task당 스레드 생성 방식)
  // var: 지역 변수 타입 추론 (컴파일러가 우변의 대입 값인 ExecutorService 타입을 자동으로 유추함)
  try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
      executor.submit(new Runnable() {
          @Override
          public void run() {
              System.out.println("Executor 기반 가상 스레드 실행");
          }
      });
  } // executor가 자동으로 close 되면서 모든 가상 스레드가 종료될 때까지 대기
  ```

# 6. 모던 자바 - 람다(Lambda)와 함수형 프로그래밍

## 6.1 함수형 프로그래밍 패러다임
- 함수형 프로그래밍 개요
  - 애플리케이션의 상태 변화를 유발하지 않고 오직 `순수 함수`만을 결합하여 신뢰성 높은 결과물을 생성하는 개발 패러다임
  - 기존 객체 지향 프로그래밍과 달리 함수(메서드) 자체를 변수에 대입하거나 다른 함수(메서드)의 인자로 전달하고 반환값으로 사용하는 `일급 객체`[^16] (First-class Object) 로 다룸
- 순수 함수(Pure Function) 조건
  - 입력 데이터가 일치하면 언제나 동일한 출력 데이터를 보장하여 예측 가능성을 확보
  - 함수 동작 실행 중 외부의 전역 변수나 상태값(필드)을 수정하는 부수 효과(Side Effect)[^17] 가 없어야 함

```java
public class PureFunctionTest {
    // 동일한 입력값에 대해 항상 동일한 연산 결과를 반환하는 순수 함수
    public static int add(int a, int b) {
        return a + b;
    }
}
```

## 6.2 람다식(Lambda Expression) 문법
- 정의: 익명 함수(Anonymous Function)를 표기하기 위해 리턴 타입과 메서드 명을 제거하고 화살표 기호 `->`를 사용하여 구현하는 문법 규칙
- 람다식의 동작 원리
  - 자바에서 람다식은 독립적인 함수가 아니라, 하나의 추상 메서드만 가진 함수형 인터페이스의 익명 구현 객체로 취급됨.
  - 컴파일 시점에 JVM이 동적으로 클래스 구현체를 생성하므로, 매번 새로운 익명 클래스 파일(.class)을 물리적으로 생성하여 사용하는 방식에 비해 메모리 효율성과 실행 속도가 개선됨
    ```java
    // 단 하나의 추상 메서드만 가지는 인터페이스 정의 (함수형 인터페이스)
    interface Calculator {
      int add(int a, int b);
    }

    public class LambdaTest {
      public static void main(String[] args) {
        // 1. 람다식 미사용 (전통적인 익명 클래스 구현 방식)
        Calculator classic = new Calculator() {
          @Override
          public int add(int a, int b) {
            return a + b;
          }
        };
        System.out.println(classic.add(5, 3)); // 8

        // 2. 람다식 사용 (행위만 간결하게 즉석에서 구현)
        Calculator lambda = (a, b) -> a + b;
        System.out.println(lambda.add(5, 3)); // 8
      }
    }
    ```
  - 람다식 도입의 이점
    - 코드 간결화 및 가독성 제고: 클래스 정의와 메서드 오버라이딩 선언부 등의 무의미한 보일러플레이트 코드를 생략하여 핵심 로직만 명확히 표기함
    - 선언형 프로그래밍과 스트림 결합: 함수 자체를 다른 메서드의 인자로 안전하게 전달함으로써 스트림 API 등과 연계해 유연한 선언형 처리를 구현함
    - 메모리 및 클래스 로딩 최적화: 매번 물리적인 익명 클래스 인스턴스 파일(.class)을 새로 로딩하지 않고 invokedynamic을 통해 동적으로 바인딩하므로 성능적 이점이 존재함
- 람다식 표기 형식 비교
  ```java
  // 일반 메서드 선언
  int add(int a, int b) {
    return a + b;
  }
  ```

  ```java
  // 람다식(익명 함수)
  (int a, int b) -> {
    return a + b;
  }
  ```

  ```java
  // 단일 실행 명령문일 경우 중괄호 `{}`와 return 키워드, `;` 생략 가능
  (int a, int b) -> a + b
  ```

- 람다 캡처링[^18]과 로컬 변수 제약 사항
  - 람다식 내부에서 외부 범위에 속한 메서드 내 지역 변수를 참조할 때, 해당 변수는 명시적으로 final 상수로 선언되어 있거나 대입 연산이 추가 발생하지 않는 사실상 final[^19](effectively final) 상태에 도달해 있어야 사용 가능
  - 지역 변수는 스택(Stack) 메모리 영역에 생성되므로 스레드가 종료되면 소멸되는데, 람다의 생명 주기는 다를 수 있어 자바 런타임이 해당 지역 변수를 복사(Copy)하여 독립적으로 소장
  - 복사된 데이터와 원본의 일관성을 유지하기 위해 변경이 불가한 final 제약을 준수하도록 강제 설계됨

## 6.3 표준 함수형 인터페이스
- 정의: 함수형 프로그래밍을 돕기 위해 자바 표준 라이브러리 패키지인 [java.util.function](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/function/package-summary.html) 내부에서 미리 범용 프로토타입으로 제안한 인터페이스 계층
- 핵심 표준 어댑터 비교
  | 분류 | 매개변수 종류 | 반환 값 형식 | 주요 가동 메서드 명칭 | 핵심 목표 |
  | --- | --- | --- | --- | --- |
  | Predicate | T (단일 객체) | boolean | test(T t) | 입력된 객체의 유효성 검사 및 통과 필터링 |
  | Consumer | T (단일 객체) | 없음 (void) | accept(T t) | 입력값을 소모하여 가공 결과를 화면 출력 등 처리 |
  | Function | T (변환 타겟) | R (변환 완료) | apply(T t) | 입력 데이터를 특정 포맷이나 다른 유형으로 매핑 |
  | Supplier | 없음 | T (신규 생성) | get() | 지연 로딩 방식을 통한 신규 데이터 조달 및 리턴 |

```java
// 표준 함수형 인터페이스 응용 문법
Predicate<Integer> checkLimit = num -> num > 100;
System.out.println("제한 초과 판단: " + checkLimit.test(150));

Consumer<String> writeLog = msg -> System.out.println("로그 누적: " + msg);
writeLog.accept("이벤트 발생");
```

## 6.4 메서드 참조(Method Reference)
- 정의: 람다식이 메서드를 정의하지 않고 다른 클래스의 메서드를 매개변수 그대로 호출할 때, 코드 중복을 정리하여 간결하게 압축 표기하는 기법
- 문법: `타겟_클래스_혹은_인스턴스::메서드명`
- 참조 형식 구분
  - 정적 메서드 참조: `Class::staticMethod`
    - 예: `(s) -> Integer.parseInt(s)` 대신 `Integer::parseInt`
  - 임의 객체의 인스턴스 메서드 참조: `Class::instanceMethod`
    - 예: `(s) -> s.length()` 대신 `String::length`
  - 특정 객체의 인스턴스 메서드 참조: `instance::instanceMethod`
    - 예: `(s) -> System.out.println(s)` 대신 `System.out::println`
  - 생성자 호출 참조: `Class::new`
    - 예: `() -> new ArrayList<>()` 대신 `ArrayList::new`

```java
// 람다 기본 형태
Function<String, Integer> lambdaWay = s -> Integer.parseInt(s);

// 메서드 참조 기법으로 축소 구현
Function<String, Integer> refWay = Integer::parseInt;
```

## 6.5 어노테이션(Annotation)
- 어노테이션의 역할
  - 자바 소스코드 컴파일 시점이나 클래스 배포, 애플리케이션 가동 시점에 코드에 메타데이터를 밀착시켜 특정 정보를 런타임에 리플렉션[^20] 기술로 파싱하거나 컴파일 룰 지시 목적으로 주입하는 특수 문법
- 필수 주요 표준 어노테이션
  - @Override: 해당 메서드가 부모 타입의 멤버를 알맞게 덮어쓰기 구현했는지 컴파일 단계에서 강도 높게 유효성 검증 수행
  - @Deprecated: 안전성이나 아키텍처 상의 이유로 사용 자제를 유도하며, 적용 지점을 호출할 시 경고 출력 유발
  - @FunctionalInterface: 클래스가 오직 하나의 추상 메서드만을 보유한 유효한 함수형 인터페이스인지 검증하며 규칙 위배 시 컴파일 차단
- 메타 어노테이션 및 사용자 정의 어노테이션
  - 어노테이션을 생성하기 위해 대상 어노테이션 상단에 선언하여 속성을 제한하는 부모 어노테이션
  - @Target: 클래스, 메서드, 필드 중 어떤 부분에 어노테이션을 적용할 수 있는지 대상 범위를 확정
  - @Retention: 어노테이션 정보의 보존 생명 주기 결정 (SOURCE: 컴파일 후 즉시 소멸, CLASS: 클래스 파일까지 수록되나 런타임에 소멸, RUNTIME: 실행 시점 리플렉션[^20] 지원)

```java
// 표준 어노테이션 및 커스텀 어노테이션 정의 기법 (부분 코드)
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface ExecutionCount {
  int value() default 1; // 단일 속성 값 보관
}
```

# 7. 소프트웨어 품질과 TDD 철학

## 7.1 단위 테스트(Unit Test)
- 정의: 프로그램 동작 검증을 위한 최소 기본 단위(일반적으로 개별 메서드 수준)를 격리하여 테스트 시나리오를 구성하고 오류 여부를 확인하는 과정
- 단위 테스트 작성 이유
  - 디버깅 비용을 극적으로 낮추고, 코드 변경이나 리팩토링 진행 시 기존 기능이 오작동하지 않는지 안전장치로 기여

```java
// 단위 테스트 로직 예시 (수동 검증 부분 코드)
Calculator calc = new Calculator();
int result = calc.add(10, 20);
if (result == 30) {
  System.out.println("테스트 합격");
}
```

## 7.2 JUnit 프레임워크 기초
- JUnit 개요
  - 자바 생태계에서 가장 널리 도입된 업계 표준 단위 테스트 도구
  - 어노테이션 기법(@Test, @BeforeEach, @AfterEach 등)을 이용해 테스트 흐름을 정의하고 Assertions 단언 함수들로 예측 값 부합 여부를 검사

```java
// JUnit 5 기본 테스트 구성 예시 (부분 코드)
class CalculatorTest {
    @Test
    void addTest() {
        Calculator calc = new Calculator();
        assertEquals(5, calc.add(2, 3));
    }
}
```

## 7.3 TDD 3단계 사이클
- TDD(Test Driven Development) 정의
  - 실제 구동 코드를 개발하기에 앞서, 실패 시나리오를 지닌 테스트 코드를 선행 작성하여 설계를 구체화하고 유도해가는 방법론
- TDD 가동 사이클 과정
  1. RED 단계: 가동 가능한 테스트를 제일 먼저 빌드 (구현체가 아직 없어 반드시 실패를 유발)
  2. GREEN 단계: 실패 테스트를 간신히 넘기기 위해 최소 수준의 코드로 조속히 구현 및 통과 완료
  3. REFACTOR 단계: 중복이 나돌거나 가독성이 저하된 부분들을 리팩토링하여 구조를 보강하며, 기 작성된 테스트의 통과 상태를 유지

```java
// TDD GREEN 단계를 완료한 최소 코드의 구조 (부분 코드)
class Greeter {
    public String sayHello(String name) {
        return "Hello, " + name; // GREEN 통과만을 위해 하드코딩 형태로 구현
    }
}
```

## 7.4 TDD를 도입하는 이유와 아키텍처
- TDD 도입의 이점과 객체지향 설계 유도
  - 테스트가 용이한 코드로 깎아가는 과정에서, 클래스 사이에 의존 관계가 단단히 굳어지는 하드코딩이 붕괴되고, 인터페이스 중심 설계와 의존성 주입[^21] (Dependency Injection)이 자연스럽게 유도
  - 결국 느슨한 결합(Loose Coupling)과 뚜렷한 응집도(High Cohesion)를 지닌 유지보수가 용이한 모범 아키텍처 구축

# 8. 데이터 가공 - 스트림(Stream) API

## 8.1 스트림 API 개념
- 스트림의 정의
  - 다양한 데이터 소스(컬렉션, 배열 등)를 추상화하여 일관된 방식으로 다룰 수 있도록 지원하는 기능
  - 기존의 for 루프나 Iterator를 사용한 외부 반복자 방식 대신, 컬렉션 내부에서 연산을 알아서 처리하는 내부 반복자 방식을 사용하여 가독성을 개선
  - 표준 API 명세 문서: [Stream](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/stream/Stream.html)
- 스트림의 핵심 특징
  - 데이터 원본 보존: 원본 데이터를 직접 변경하지 않고 읽기 전용으로 가공하여 새로운 결과물 반환
  - 일회용 소멸 구조: Iterator와 유사하게 한 번 사용되어 최종 연산이 끝나면 스트림이 닫혀 재사용 불가
  - 선언형 코드 구현: 무엇을 수행할지 가독성 높은 코드로 기술하여 비즈니스 로직에만 집중 가능

```java
import java.util.*;

public class StreamConceptTest {
  public static void main(String[] args) {
    List<String> list = Arrays.asList("a", "b", "c");
    // 스트림을 이용한 내부 반복 기반 선언형 출력
    list.stream().forEach(System.out::println);
  }
}
```

## 8.2 스트림 파이프라인 3단계
- 스트림이 최종 결과물을 도출하기 위해 여러 연산을 파이프 형태로 연결하는 흐름 구조
- 단계별 동작 설명
  1. 스트림 생성: 컬렉션, 배열, 파일 등의 데이터 소스로부터 스트림 인스턴스를 마련
  2. 중간 연산: 데이터를 변환, 필터링, 정렬 등을 수행하며 반환값이 다시 스트림 형태를 유지하여 여러 개를 체이닝 연계 가능
  3. 최종 연산: 전체 스트림 요소를 소모하며 통계치 집계, 리스트 수집, 콘솔 출력 등을 통해 결과를 도출하고 스트림 파이프라인을 종료

```java
import java.util.*;

public class StreamPipelineTest {
    public static void main(String[] args) {
        List<Integer> list = Arrays.asList(1, 2, 3, 4, 5);

        // 1단계(생성) -> 2단계(중간 연산 filter) -> 3단계(최종 연산 count) 연동
        long count = list.stream()
                         .filter(n -> n > 2)
                         .count();

        System.out.println("3보다 큰 수의 개수: " + count); // 3
    }
}
```

## 8.3 주요 중간 연산
- 스트림의 가공 과정을 담당하며 결과를 다시 스트림으로 돌려주는 메서드
- 중간 연산 카테고리 요약
  | 중간 연산 메서드 | 기능 및 역할 설명 |
  | --- | --- |
  | filter(Predicate) | 조건식에 부합하는 데이터만 선택적으로 통과 처리 |
  | map(Function) | 스트림 요소를 가공하여 다른 형태의 값으로 변환 매핑 |
  | flatMap(Function) | 중첩된 컬렉션 구조를 1차원의 평탄화된 단일 스트림으로 재구성 |
  | sorted() / sorted(Comparator) | 요소를 오름차순 또는 지정된 기준에 맞춰 정렬 배치 |
  | distinct() | 요소 간의 중복을 배제하여 단일 값들만 추출 |
  | limit(long) / skip(long) | 스트림 요소의 개수를 제한하거나 앞부분 데이터 배제 처리 |

```java
// 복합적인 중간 연산 구현 방식 (부분 코드)
List<String> list = Arrays.asList("a", "b", "a", "c", "b");
list.stream()
    .distinct() // 중복 데이터 배제
    .sorted()   // 기본 순서 정렬
    .map(String::toUpperCase) // 대문자 치환
    .forEach(System.out::println); // A, B, C 출력
```

## 8.4 주요 최종 연산
- 파이프라인 of 종착역에 해당하며 데이터 처리를 매듭짓고 스트림 객체를 소멸시키는 메서드
- 최종 연산 카테고리 요약
  | 최종 연산 메서드 | 기능 및 역할 설명 |
  | --- | --- |
  | forEach(Consumer) | 각 요소를 순회하며 지정된 동작을 실행 (출력 등) |
  | collect(Collector) | 요소를 가공하여 List, Set, Map 등의 자료구조로 가공 수집 |
  | reduce(BinaryOperator) | 요소를 하나씩 줄여가며 연산을 누적 수행하여 단일 결과 도출 |
  | count() / sum() / average() | 요소의 총합, 평균값 등 다양한 수치 통계 집계 연산 |
  | anyMatch() / allMatch() / noneMatch() | 조건식에 일부 또는 전체가 부합하는지 여부 검증 (boolean 리턴) |

```java
// collect 수집 연산 활용 방식 (부분 코드)
List<String> names = Arrays.asList("Kim", "Park", "Lee", "Kang", "Koo");
List<String> result = names.stream()
                           .filter(name -> name.startsWith("K"))
                           .map(String::toUpperCase)
                           .collect(Collectors.toList()); // 리스트 변환 수집
```

## 8.5 지연 연산(Lazy Evaluation)과 루프 퓨전(Loop Fusion)
- 지연 연산 메커니즘
  - 스트림 파이프라인에서 최종 연산이 호출되기 직전까지는 중간 연산이 실제로 수행되지 않고 예약을 마친 상태로 대기
  - 데이터의 전체 조회를 미루다가 반드시 결과가 필요한 시점에만 계산을 진행하므로 메모리 및 성능 효율 개선
- 루프 퓨전 동작
  - 여러 단계의 중간 연산을 개별적으로 전체 반복하는 방식이 아님
  - 각 데이터 요소 단위로 필터, 매핑 등의 전체 파이프라인 라인을 수직으로 관통하며 한꺼번에 연산을 병합하여 처리하는 현상

```java
// 지연 연산 및 루프 퓨전 관측 (부분 코드)
List<Integer> list = Arrays.asList(1, 2, 3);
list.stream()
    .filter(n -> {
        System.out.println("filter 체크: " + n);
        return n > 1;
    }); // 최종 연산이 누락되어 콘솔 출력이 전혀 발생하지 않는 구조
```

### 각주

[^1]: 안티 패턴 - 소프트웨어 개발에서 자주 발생하지만 비효율적이거나 해로운 결과를 초래하는 잘못된 설계나 코딩 패턴
[^2]: 자료구조 - 컴퓨터 분야에서 데이터를 효율적으로 저장, 조직, 관리하기 위해 사용하는 논리적인 구조나 데이터의 보관 방식
[^3]: 알고리즘 - 주어진 문제를 해결하거나 특정 작업을 수행하기 위해 컴퓨터가 따라야 하는 명확하고 논리적인 단계적 절차
[^4]: 노드 - 연결 리스트 등의 자료구조에서 데이터 값과 함께 이전 혹은 다음 데이터의 위치(참조 주소)를 담고 있는 메모리 내의 독립적인 객체 단위
[^5]: 해시 테이블 - 해시 함수를 사용해 키를 해시값으로 매핑하고, 이를 주소 또는 인덱스로 삼아 데이터(값)를 검색 및 저장하는 키-값 쌍의 자료구조
[^6]: 레드-블랙 트리 - 자가 균형 이진 탐색 트리의 일종으로, 노드에 색상을 부여하여 트리의 균형을 유지함으로써 탐색, 삽입, 삭제 연산의 성능을 항상 일정하게 보장하는 자료구조
[^7]: 중첩 인터페이스 - 클래스나 인터페이스 내부에 선언된 인터페이스로, 관련된 타입들을 함께 묶어 캡슐화를 강화하며 자동으로 public static 특성을 가짐. 대표적인 예시로 Map.Entry 선언부는 다음과 같음:
  ```java
  public interface Map<K, V> {
  interface Entry<K, V> {
    K getKey();
    V getValue();
  }
}
  ```
[^8]: 해시 함수 - 임의의 길이를 가진 데이터를 고정된 길이의 고유한 숫자 값(해시 코드)으로 매핑하여 빠른 데이터 검색을 지원하는 함수
[^9]: 블로킹 - 특정 작업(예: 입출력, 네트워크 연결 대기 등)이 완료될 때까지 호출한 스레드가 대기 상태에 머무르며 CPU 제어권을 반환하지 않아, 다음 코드를 실행하지 못하고 멈춰 서 있는 동작 상태
[^10]: 선점형 우선순위 - 스레드가 가지는 우선순위에 따라 스케줄러가 판단하여 높은 우선순위의 스레드가 실행 중인 낮은 스레드의 CPU 점유를 강제 제어하고 먼저 CPU를 점유하는 스케줄링 방식
[^11]: 라운드 로빈 - CPU를 할당받은 스레드들이 차별 없이 정해진 시간 단위(Time Slice)만큼 공평하게 순환 대기하며 공평하게 연산을 수행하는 스케줄링 방식
[^12]: 시분할 - 하나의 CPU 코어의 처리 시간을 매우 짧은 시간 단위로 쪼개어 여러 프로세스나 스레드에게 번갈아 할당함으로써 여러 작업이 동시에 병렬로 처리되는 것처럼 느끼게 만드는 다중 작업(멀티태스킹) 방식
[^13]: 레지스터 - CPU 내부에서 명령어와 데이터를 처리하는 과정에서 필요한 정보들을 극도로 빠르게 임시 저장하고 참조하기 위해 사용되는 초고속 미세 기억 장치
[^14]: 레이스 컨디션 - 둘 이상의 스레드가 공유 자원에 동시에 접근하여 값을 변경하려고 경쟁할 때, 실행 순서에 따라 결과가 달라져 데이터 일관성이 깨지는 현상
[^15]: 임계 영역 - 멀티스레드 환경에서 여러 스레드가 동시에 접근해 실행할 경우 데이터 일관성이 깨질 위험이 있어, 한 번에 단 하나의 스레드만 진입하여 실행하도록 보장해야 하는 코드 영역
[^16]: 일급 객체 - 컴퓨터 프로그래밍에서 다른 객체들에 적용 가능한 연산을 모두 지원하는 객체를 뜻하며, 함수를 매개변수로 전달하거나 반환값으로 사용하는 등 변수처럼 자유롭게 다룰 수 있음을 의미함
[^17]: 부수 효과 - 함수 실행 중 외부 영역에 선언된 상태(객체의 인스턴스 필드, 전역 변수 등)를 직접 조작하거나, 파일 쓰기 및 네트워크 송신 등의 출력 행위를 통해 프로그램의 상태나 주변 환경에 흔적이나 변경을 남기는 모든 외부 작용
[^18]: 람다 캡처링 - 람다식 외부 영역에 선언된 지역 변수를 람다식 내부에서 참조하여 사용할 수 있도록 값을 복사해 오는 행위
[^19]: 사실상 final - 명시적으로 final 키워드를 붙이지 않았으나 변수가 초기화된 이후 한 번도 값이 변경되지 않아 컴파일러가 final 변수처럼 취급하는 상태
[^20]: 리플렉션 - 실행 중인 자바 프로그램이 자기 자신을 검사하거나 내부 클래스 정보, 메서드 등의 메타데이터를 동적으로 분석하고 수정할 수 있게 돕는 기법
[^21]: 의존성 주입 - 객체지향 설계에서 필요한 의존 객체를 직접 생성하지 않고, 생성자나 세터를 통해 외부에서 공급받아 객체 간 결합도를 낮추는 기법
