# 11. 객체지향 프로그래밍(OOP) 기초

객체지향 프로그래밍(Object-Oriented Programming, OOP)은 컴퓨터 프로그램을 단순한 명령어의 나열로 보지 않고, 독립된 단위인 객체들이 모여서 서로 메시지를 주고받으며 협력하는 형태로 작성하는 프로그래밍 패러다임

- 핵심 지향점:
  + 프로그램의 부품화: 데이터와 이를 처리하는 메서드를 객체라는 하나의 부품으로 결합하여 구조화함
  + 재사용성과 유지보수성: 완성도 높은 객체를 만들어 여러 곳에서 다시 사용하며, 변경 사항이 생겼을 때 해당 객체만 수정하여 부작용을 최소화함

## 11.1 객체, 클래스, 인스턴스
- 객체(Object): 우리가 인지하고 표현하려는 유무형의 모든 실체(예: 자동차, 사람, 은행 계좌 등). 고유한 속성(상태)과 행위(동작)를 가짐
  + 일상생활 속 객체의 예시:
    - 자동차:
      + 속성(필드): 모델명, 색상, 현재 속도
      + 기능(메서드): 출발하기, 가속하기, 브레이크 밟기
    - 은행 계좌:
      + 속성(필드): 계좌번호, 예금주, 잔액
      + 기능(메서드): 입금하기, 출금하기, 잔액조회
- 클래스(Class): 객체를 생성하기 위한 설계도(틀). 객체의 형태와 기능(속성과 행위)을 자바 코드로 사전에 명세해 둔 규격
- 인스턴스(Instance): 클래스라는 설계도를 바탕으로 'new' 연산자를 사용하여 힙 메모리에 실제로 만들어진 실체화된 결과물(객체)

- 💻 실습 (학사 관리 시스템 클래스 설계): [ch11/lms](../workspace/ch11/lms)

## 11.2 클래스의 구성 요소
1. 필드 (Field): 객체의 상태, 속성을 정의한 변수
2. 메서드 (Method): 객체의 동작, 행위, 기능을 담고 있는 코드 블럭
3. 생성자 (Constructor): 객체가 new로 생성될 때 초기 세팅을 담당

- 형식:
  ```java
  [접근제어자] class 클래스명 {
    // 1. 필드 (객체의 상태, 속성 변수)
    [접근제어자] 타입 필드명;

    // 2. 생성자 (객체의 초기 세팅 담당)
    [접근제어자] 클래스명(매개변수타입 매개변수명, ...) {
      // 초기 세팅 코드
      // ...
    }

    // 3. 메서드 (객체의 동작, 행위 함수)
    [접근제어자] 반환타입 메서드명(매개변수타입 매개변수명, ...) {
      // 실행할 코드
      // ...
      return 반환값;
    }
  }
  ```

- 예시:
  ```java
  public class Car {
    // 필드
    String model;
    int speed;

    // 생성자
    public Car(String model) {
      this.model = model;
      this.speed = 0;
    }

    // 메서드
    public void accelerate() {
      this.speed += 10;
      System.out.println(model + " 속도 증가! 현재 속도: " + speed);
    }
  }
  ```

## 11.3 필드 (Field)
필드(Field)는 클래스 내부(메서드 외부)에 선언되어 객체의 상태와 속성을 정의하는 변수로, 멤버 변수라고도 부름.

### 11.3.1 필드의 주요 특징
- 자동 초기화: 필드는 명시적으로 초기화하지 않아도 객체가 생성될 때 각 자료형의 기본값으로 자동 초기화 됨.
- 기본값 목록:
  + 정수형 (byte, short, int, long): 0
  + 실수형 (float, double): 0.0
  + 논리형 (boolean): false
  + 문자형 (char): '\u0000' (공백 문자)
  + 참조형 (String, 배열, 클래스 등): null

### 11.3.2 필드 선언 예시
```java
public class Product {
  // 필드 선언 (기본값으로 자동 초기화됨)
  String name;       // null로 초기화
  int price;         // 0으로 초기화
  boolean isSoldOut; // false로 초기화
}
```

## 11.4 객체의 생성과 사용 방법
클래스를 설계도로 삼아 실제 메모리에 실체(객체/인스턴스[^1])를 올리려면 `new` 연산자를 사용해야 하며, 생성된 객체의 멤버(필드와 메서드)에 접근하기 위해서는 닷(`.`) 연산자를 활용함.

### 11.4.1 new 연산자를 통한 인스턴스화 과정
- `new` 연산자는 JVM에게 객체를 저장할 메모리 공간을 힙(Heap) 영역에 할당하도록 요청.
- 메모리 할당이 완료되면 클래스에 정의된 필드들이 힙 공간에 생성되고, 생성자를 호출하여 초기 설정을 완료.
- 마지막으로 생성된 객체가 위치한 힙 영역의 참조 주소값(Reference)을 반환하여 변수에 대입할 수 있도록 함.

### 11.4.2 닷(.) 연산자를 통한 속성 및 기능 제어
- 대입받은 참조 변수 이름 뒤에 닷(`.`)을 붙여서 객체 내부의 변수(필드) 값을 읽거나 수정하고, 함수(메서드)를 호출하여 특정 동작을 수행시킴.

```java
// 클래스 설계도
class Person {
  String name;
  int age;

  void introduce() {
    System.out.println("제 이름은 " + name + "이고, 나이는 " + age + "세입니다.");
  }
}

public class ObjectUsageTest {
  public static void main(String[] args) {
    // 1. new 연산자를 이용한 객체 생성 및 참조 주소 보관
    Person person = new Person();

    // 2. 닷(.) 연산자를 통해 필드에 값 대입
    person.name = "하루";
    person.age = 6;

    // 3. 닷(.) 연산자를 통해 인스턴스 메서드 호출
    person.introduce(); // 출력: 제 이름은 하루이고, 나이는 6세입니다.
  }
}
```

## 11.5 생성자 (Constructor)
- 객체가 new 연산자를 통해 메모리에 생성될 때 가장 먼저 호출되어 인스턴스[^1]<sup>2</sup> 변수의 초기 세팅을 담당하는 특수한 메서드

- 형식:
  ```java
  [접근제어자] 클래스명(매개변수타입 매개변수명, ...) {
    // 인스턴스 변수 초기화 코드
  }
  ```

- 주요 특징:
  + 반환 타입이 없음: 일반 메서드와 달리 void조차 지정하지 않으며, 이름은 반드시 소속 클래스명과 대소문자까지 일치해야 함
  + 기본 생성자 (Default Constructor): 클래스 내부에 개발자가 생성자를 단 하나도 선언하지 않으면 컴파일러가 매개변수와 코드가 없는 빈 기본 생성자를 자동으로 삽입해 줌. 단, 매개변수가 있는 생성자를 하나라도 정의하면 기본 생성자는 자동으로 생성되지 않으므로 필요시 직접 명시해야 함

```java
public class Member {
  String id;

  // 생성자 정의: 반환 타입이 없으며 클래스명과 동일해야 함
  public Member(String id) {
    this.id = id; // 인스턴스 필드 초기화
  }

  public static void main(String[] args) {
    // 객체 생성 시 생성자에 인수 전달
    Member member = new Member("user1");
    System.out.println("회원 아이디: " + member.id); // 출력: 회원 아이디: user1
  }
}
```

## 11.6 생성자 오버로딩
- 매개변수의 개수와 타입을 다르게 하여 하나의 클래스 내부에 생성자를 여러 개 조립하여 다형성[^2]을 제공할 수 있음

- 예시:
  ```java
  public class Book {
    String title;
    String author;

    // 기본 생성자 (개발자가 명시적으로 정의)
    public Book() {
      this.title = "제목없음";
      this.author = "작자미상";
    }

    // 매개변수가 있는 생성자 (오버로딩)
    public Book(String title, String author) {
      this.title = title;
      this.author = author;
    }
  }

  public class BookTest {
    public static void main(String[] args) {
      // 기본 생성자 호출
      Book book1 = new Book();
      // book1 제목: 제목없음, 저자: 작자미상
      System.out.println("book1 제목: " + book1.title + ", 저자: " + book1.author);

      // 매개변수가 있는 생성자 호출
      Book book2 = new Book("자바를 잡아라", "용쌤");
      // book2 제목: 자바를 잡아라, 저자: 용쌤
      System.out.println("book2 제목: " + book2.title + ", 저자: " + book2.author);
    }
  }
  ```

- 💻 실습 (생성자 오버로딩, 하나의 소스에 두개의 클래스 정의): [ch11/BookTest.java](../workspace/ch11/BookTest.java)

## 11.7 this와 this()
- this: 생성된 자기 자신 객체를 가리키는 참조 변수. 매개변수와 필드명이 같을 때 구별하기 위해 사용
- this(): 같은 클래스 내의 다른 생성자를 호출할 때 사용. 생성자 내부의 첫 줄에만 작성 가능
  + Java 25 부터는 생성자의 어느곳에 위치해 있어도 상관없음. 단, 인스턴스[^1]<sup>3</sup> 생성 후에 만 사용 가능한 this나 인스턴스[^1]<sup>4</sup> 메서드의 호출보다는 먼저 작성해야 함.

- 예시:
  ```java
  public class User {
    String name;
    int age;

    public User() {
      this("기본이름", 1); // 다른 생성자 호출
    }

    public User(String name, int age) {
      this.name = name;
      this.age = age;
    }
  }

  public class UserTest {
    public static void main(String[] args) {
      // 기본 생성자 호출 (this()를 통해 다른 생성자가 내부적으로 호출됨)
      User user1 = new User();
      // user1 이름: 기본이름, 나이: 1
      System.out.println("user1 이름: " + user1.name + ", 나이: " + user1.age);

      // 매개변수가 있는 생성자 직접 호출
      User user2 = new User("하루", 6);
      // user2 이름: 하루, 나이: 6
      System.out.println("user2 이름: " + user2.name + ", 나이: " + user2.age);
    }
  }
  ```

- 💻 실습 (this() 사용): [ch11/BookTest.java](../workspace/ch11/BookTest.java)

## 11.8 패키지와 임포트
- 패키지: 관련된 클래스들을 그룹화하는 폴더 구조
- 임포트(import): 다른 패키지에 있는 클래스를 사용할 때 명시. 단, java.lang 패키지에 속한 클래스(예: String, System 등)는 임포트 없이 자동으로 사용할 수 있음

```java
// 패키지 선언 (클래스의 실제 디렉토리 경로와 매핑됨)
package net.likelion.bebc25;

// 외부 패키지에 포함된 java.util.Scanner 클래스 임포트
import java.util.Scanner;

public class PackageTest {
  public static void main(String[] args) {
    // 임포트한 Scanner 클래스 사용
    Scanner scanner = new Scanner(System.in);
    System.out.print("이름을 입력하세요: ");
    String name = scanner.nextLine();
    System.out.println("입력된 이름: " + name);
  }
}
```

## 11.9 캡슐화와 접근 제어자
- 캡슐화: 중요한 데이터와 이를 처리하는 메서드를 하나로 묶고, 외부에서 임의로 변경하지 못하도록 데이터를 은닉하는 기법
- 접근 제어자: private < default < protected < public 순서로 접근 권한을 제한함(오른쪽으로 갈수록 접근 범위가 넓음)
- 필드를 private으로 선언하고 Getter/Setter 및 유효성 검증 메서드를 통해서만 접근하도록 제한함
  + 잔고 확인 없는 출금의 문제점: 필드에 직접 접근할 수 있거나 검증이 없다면, 현재 잔액보다 많은 금액을 출금하여 계좌 잔고가 음수(마이너스)가 되는 금융 사고가 발생할 수 있음. 캡슐화를 통해 잔고 확인 등의 검증 로직을 거쳐서만 출금하도록 제어함

### 11.9.1 접근 제어자별 세부 접근 범위
클래스, 필드, 메서드, 생성자의 사용 허용 범위를 결정하는 접근 제어자의 세부 허용 한계는 다음과 같음.

| 접근 제어자 | 클래스 내부 | 동일 패키지 | 동일 패키지 또는 자식 클래스 | 어디서나 |
| :--- | :--- | :--- | :--- | :--- |
| public | 허용 (O) | 허용 (O) | 허용 (O) | 허용 (O) |
| protected | 허용 (O) | 허용 (O) | 허용 (O) | 차단 (X) |
| default | 허용 (O) | 허용 (O) | 차단 (X) | 차단 (X) |
| private | 허용 (O) | 차단 (X) | 차단 (X) | 차단 (X) |

- public: 어떠한 제한 없이 모든 곳에서 접근이 가능함
- protected: 동일한 패키지 내의 클래스 및 다른 패키지에 있더라도 해당 클래스를 상속[^3]받은 자식 클래스에서 접근이 가능함
- default (package-private): 제어자를 생략했을 때 자동으로 부여되며, 동일 패키지 내부에서만 접근을 허용함
- private: 오직 선언된 해당 클래스 내부에서만 호출 및 접근이 가능함

### 11.9.2 Getter와 Setter 작성 규칙 (네이밍 관례)
클래스 외부에서 private 필드에 안전하게 접근하고 값을 변경하기 위해 사용하는 Getter와 Setter 메서드는 다음과 같은 네이밍 규칙을 따름.

- 일반적인 필드 네이밍 규칙:
  + Getter: get + 필드명 (첫 글자 대문자) (예: String name -> getName())
  + Setter: set + 필드명 (첫 글자 대문자) (예: setName(String name))
- 논리형 (boolean) 필드 예외 규칙:
  + 논리형 필드의 Getter는 get 대신 is로 시작하는 것이 관례이며, Setter는 다른 자료형과 동일하게 set으로 시작함
    - 예시: boolean isSoldOut -> Getter: isSoldOut(), Setter: setSoldOut(boolean isSoldOut)

- 예시 1: 캡슐화가 적용되지 않아 데이터 무결성이 깨지는 문제 예시
  ```java
  public class AccountBad {
    public int balance; // 외부 직접 접근 허용

    public void deposit(int amount) {
      if (amount > 0) {
        this.balance += amount;
      }
    }

    // 출금 메서드: 잔고 확인 로직을 구현하여 마이너스 잔고 문제를 예방
    public void withdraw(int amount) {
      if (amount > 0 && this.balance >= amount) {
        this.balance -= amount;
      } else {
        System.out.println("출금 실패: 잔액 부족 또는 부적절한 금액");
      }
    }
  }

  public class AccountBadTest {
    public static void main(String[] args) {
      AccountBad account = new AccountBad();

      account.deposit(10000); // 10000원 입금
      account.withdraw(15000); // 출력: 출금 실패: 잔액 부족 또는 부적절한 금액

      // 제약 조건 없이 필드에 직접 음수 대입이 가능하여 데이터 오염 발생
      account.balance = -5000;
      System.out.println("계좌 잔고: " + account.balance); // 출력: 계좌 잔고: -5000
    }
  }
  ```

- 예시 2: 캡슐화를 적용하여 데이터를 안전하게 보호하는 해결 예시
  ```java
  public class Account {
    private int balance; // 외부 접근 차단 (음수 잔고 예방)

    public int getBalance() {
      return this.balance;
    }

    public void deposit(int amount) {
      if (amount > 0) {
        this.balance += amount;
      }
    }

    // 출금 메서드: 잔고 확인 로직을 구현하여 마이너스 잔고 문제를 예방
    public void withdraw(int amount) {
      if (amount > 0 && this.balance >= amount) {
        this.balance -= amount;
      } else {
        System.out.println("출금 실패: 잔액 부족 또는 부적절한 금액");
      }
    }
  }

  public class AccountTest {
    public static void main(String[] args) {
      Account account = new Account();
      account.deposit(10000); // 10000원 입금
      account.withdraw(15000); // 출력: 출금 실패: 잔액 부족 또는 부적절한 금액
      // account.balance = -5000; // 컴파일 에러 발생 (접근이 차단됨)
      System.out.println("계좌 잔고: " + account.getBalance()); // 출력: 계좌 잔고: 10000 (데이터 안정성 유지)
  ```

## 11.10 정적(static) 멤버
- static 키워드가 붙은 필드나 메서드는 인스턴스[^1]<sup>5</sup> 생성을 하지 않아도 클래스명으로 바로 접근 가능
- 모든 인스턴스[^1]<sup>6</sup>가 공유하는 메모리(메서드 영역)에 저장됨
- static 메서드의 제한 사항:
  + static 메서드는 객체 생성 전 클래스 로딩 시점에 메모리에 올라가므로, 메모리에 존재 여부가 불확실한 인스턴스[^1]<sup>7</sup> 필드나 인스턴스[^1]<sup>8</sup> 메서드에 직접 접근할 수 없음
  + static 메서드 내부에서는 오직 static 필드(클래스 변수)나 static 메서드만 직접 호출이 가능함
  + 객체 자신을 가리키는 참조 키워드인 this는 static 메서드 내부에서 사용할 수 없음
  + 대표적인 static 메서드인 main 메서드 내부에서 동일 클래스의 다른 일반 메서드를 직접 호출하려고 하면 컴파일 에러가 발생함. 이를 호출하려면 대상 메서드가 static이거나, main 메서드 내에서 자기 자신의 객체를 new로 생성하여 접근해야 함


- 예시 1: 정적 멤버 기본 활용
  ```java
  public class MathUtils {
    public static final double PI = 3.14159;

    public static int add(int a, int b) {
      return a + b;
    }
  }
  // 호출: MathUtils.add(10, 20);
  ```

- 예시 2: static 메서드 내에서의 접근 제한
  ```java
  public class Calculator {
    int instanceVal = 10;      // 인스턴스 변수
    static int staticVal = 20; // 클래스(static) 변수

    public static void staticMethod() {
      System.out.println(staticVal); // OK: static 변수 접근 가능
      // System.out.println(instanceVal); // 컴파일 에러: 인스턴스 변수에 직접 접근 불가
    }

    public void instanceMethod() {
      System.out.println(staticVal);   // OK: 인스턴스 메서드에서는 static 변수 접근 가능
      System.out.println(instanceVal); // OK: 인스턴스 변수 접근 가능
    }
  }
  ```

- 예시 3: main 메서드에서의 호출 제한과 해결 방안
  ```java
  public class MainMethodTest {
    public void instanceShow() {
      System.out.println("인스턴스 메서드 호출");
    }

    public static void staticShow() {
      System.out.println("정적 메서드 호출");
    }

    public static void main(String[] args) {
      // static 메서드는 직접 호출이 가능함
      staticShow(); // OK

      // 인스턴스 메서드는 직접 호출 불가능 (컴파일 에러 발생)
      // instanceShow(); // 컴파일 에러: static 영역에서 non-static 메서드 직접 참조 불가

      // 자신의 인스턴스를 직접 생성한 후에 참조 변수를 통해서만 접근할 수 있음
      MainMethodTest test = new MainMethodTest();
      test.instanceShow(); // OK
    }
  }
  ```

## 11.11 변수의 종류와 비교 (지역 변수, 인스턴스 변수, 클래스 변수)
자바 프로그래밍에서 변수는 선언 위치와 static 키워드 사용 여부에 따라 크게 세 가지 종류로 구분되며, 각각 메모리 저장 영역, 생명 주기, 초기화 방식에 차이가 있음.

| 구분 | 지역 변수 (Local Variable) | 인스턴스[^1]<sup>9</sup> 변수 (Instance Variable / 필드) | 클래스 변수 (Class Variable / 정적 필드) |
| :--- | :--- | :--- | :--- |
| 선언 위치 | 메서드, 생성자, 블록 내부 | 클래스 블록 내부 (static 없음) | 클래스 블록 내부 (static 있음) |
| 저장 영역 | 스택 (Stack) 영역 | 힙 (Heap) 영역 | 메서드 (Method / Static) 영역 |
| 초기화 방식 | 자동 초기화 안 됨 (사용 전 초기화 필수) | 기본값으로 자동 초기화 | 기본값으로 자동 초기화 |
| 생성 시점 | 변수 선언문이 실행될 때 | 객체(인스턴스)가 생성될 때 | 클래스가 메모리에 로드될 때 |
| 소멸 시점 | 선언된 블록이 종료될 때 | 객체가 GC에 의해 소멸할 때 | 프로그램이 종료될 때 |

### 11.11.1 메모리 저장 영역과 생명 주기의 차이
- 지역 변수: 메서드가 호출될 때 JVM 스택 영역의 스택 프레임 내부에 생성됨. 메서드 실행이 완료되면 해당 스택 프레임이 제거되면서 지역 변수도 메모리에서 즉시 소멸됨.
- 인스턴스[^1]<sup>10</sup> 변수(필드): 객체가 new 연산자로 생성될 때 JVM 힙 영역에 생성됨. 객체가 더 이상 참조되지 않아 가비지 컬렉터(GC)에 의해 수거되어 소멸할 때까지 힙 메모리에 유지됨.
- 클래스 변수(정적 필드): 프로그램 실행 시 해당 클래스가 메모리에 로드될 때 JVM 메서드 영역에 단 한 번 생성됨. 프로그램 전체에서 공유되며, 프로그램이 종료될 때까지 메모리에 유지됨.

```java
public class VariableScope {
  // 인스턴스 변수: 힙 영역에 생성되며, 인스턴스마다 독립된 값을 보유
  int instanceVar;

  // 클래스 변수: 메서드 영역에 생성되며, 모든 인스턴스가 공유
  static int classVar;

  public void method() {
    // 지역 변수: 스택 영역에 생성되며, 호출 시점에 생성되고 메서드 종료 시 소멸함
    int localVar = 10;

    System.out.println(instanceVar); // 출력: 0 (자동 초기화)
    System.out.println(classVar);    // 출력: 0 (자동 초기화)
    System.out.println(localVar);    // 출력: 10 (명시적 초기화 필요)
  }
}
```

# 12. 객체지향 심화 - 상속(Inheritance)

## 12.1 상속의 개념
상속은 객체지향[^4] 프로그래밍의 핵심 개념 중 하나로, 기존에 정의되어 있는 클래스의 모든 필드와 메서드를 새로운 클래스가 물려받아 사용하는 것을 의미함. 이때 상속을 해주는 기존 클래스를 부모 클래스(상위 클래스, Super Class)라 하고, 상속을 받는 새로운 클래스를 자식 클래스(하위 클래스, Sub Class)라고 함.

### 12.1.1 상속의 특징과 장점
- 코드의 재사용성 향상: 이미 작성되어 검증된 부모 클래스의 코드를 재사용하므로 중복 코드가 줄어들고 개발 시간이 단축됨
- 유지보수성 향상: 부모 클래스의 수정만으로 이를 상속받은 모든 자식 클래스에 변경 사항이 반영되므로 일관성 있는 수정이 가능함
- 다형성[^2]<sup>2</sup> 구현의 기반: 부모 클래스 타입의 참조 변수로 다양한 자식 클래스 객체를 참조할 수 있어, 확장성 높은 프로그램 설계가 가능함
- 단일 상속 지원: 자바는 다중 상속에서 발생할 수 있는 메서드 호출의 모호성(다이아몬드 문제)을 방지하기 위해 클래스의 단일 상속만 지원함. 즉, extends 뒤에는 단 하나의 클래스만 선언할 수 있음

### 12.1.2 상속 선언 형식
자식 클래스를 선언할 때 클래스명 뒤에 extends 키워드를 붙인 후 부모 클래스를 기술해서 상속 관계를 설정함.

```java
[접근제어자] class 자식클래스명 extends 부모클래스명 {
  // 필드 및 메서드 선언
}
```

### 12.1.3 상속 구현 예시
```java
public class Animal {
  public void eat() {
    System.out.println("냠냠 먹는다");
  }
}

public class Dog extends Animal {
  public void bark() {
    System.out.println("멍멍!");
  }
}

public class Test {
  public static void main(String[] args) {
    Dog dog = new Dog();
    dog.eat();  // 부모로부터 물려받은 메서드 호출
    dog.bark(); // 자신의 메서드 호출
  }
}
```

## 12.2 메서드 오버라이딩
부모 클래스로부터 상속받은 메서드의 내부 구현을 자식 클래스에서 필요에 맞게 재정의하는 기법

### 12.2.1 메서드 오버라이딩의 성립 조건
- 메서드 시그니처 일치: 부모 클래스의 메서드와 메서드 이름, 매개변수 타입 및 개수, 반환 타입이 동일해야 함.
  ```java
  class Animal {
    public void sound() {
      System.out.println("동물이 소리를 낸다");
    }
  }

  class Dog extends Animal {
    // 메서드 이름, 매개변수 타입 및 개수, 반환 타입이 모두 일치하므로 오버라이딩 성립
    public void sound() {
      System.out.println("멍멍!");
    }

    // 매개변수가 달라지면 오버라이딩이 아닌 오버로딩이 됨
    public void sound(int count) {
      for (int i = 0; i < count; i++) {
        System.out.println("멍멍!");
      }
    }
  }

  class Cat extends Animal {
    // 메서드 이름, 매개변수 타입 및 개수, 반환 타입이 모두 일치하므로 오버라이딩 성립
    public void sound() {
      System.out.println("야옹~");
    }
  }
  ```

- 접근 제어자[^5] 제한: 자식 클래스에서 오버라이딩[^6]하는 메서드의 접근 제어자[^5]<sup>2</sup>는 부모 클래스의 메서드보다 좁은 범위로 변경할 수 없음. (예: 부모 메서드가 protected이면 자식은 protected 또는 public만 가능)
  ```java
  class Animal {
    protected void breathe() {
      System.out.println("숨을 쉽니다");
    }
  }

  class Dog extends Animal {
    // protected 또는 public으로만 오버라이딩 가능
    public void breathe() {
      System.out.println("강아지가 숨을 쉽니다");
    }

    // 부모 메서드(protected)보다 좁은 접근 제어자(default, private)로는 오버라이딩 불가 (컴파일 에러)
    // void breathe() {} 
  }
  ```

- static, final, private 메서드는 오버라이딩[^6]<sup>2</sup> 불가
  ```java
  class Animal {
    private void sleep() {
      System.out.println("잠을 잡니다");
    }

    public final void live() {
      System.out.println("살아있습니다");
    }

    public static void info() {
      System.out.println("동물 정보");
    }
  }

  class Dog extends Animal {
    // private 메서드는 자식 클래스에서 접근할 수 없으므로 오버라이딩 불가. 아래 메서드는 Dog 클래스 고유의 메서드 정의임
    public void sleep() {
      System.out.println("강아지가 잠을 잡니다");
    }

    // final 메서드는 재정의할 수 없으므로 오버라이딩 불가 (컴파일 에러)
     // public void live() {}

    // static 메서드는 클래스 수준에 소속되므로 오버라이딩 불가. 아래는 메서드 가리기(Shadowing)에 해당함
    public static void info() {
      System.out.println("강아지 정보");
    }
  }
  ```

### 12.2.2 메서드 오버라이딩을 사용하는 이유와 장점
- 자식 클래스에 특화된 동작 구현: 부모 클래스의 일반적인 기능을 자식 클래스만의 구체적인 특성에 맞추어 재구성할 수 있음
  ```java
  class Animal {
    public void sound() {
      System.out.println("동물이 소리를 낸다");
    }
  }

  class Dog extends Animal {
    // 부모의 sound()가 일반적인 동작을 한다면 자식(Dog)은 "멍멍!"으로 재정의함
    @Override
    public void sound() {
      System.out.println("멍멍!");
    }
  }

  class Cat extends Animal {
    // 부모의 sound()가 일반적인 동작을 한다면 자식(Cat)은 "야옹~"으로 재정의함
    @Override
    public void sound() {
      System.out.println("야옹~");
    }
  }
  ```
- 다형성[^2]<sup>3</sup> 구현의 핵심: 부모 클래스 타입의 참조 변수를 사용하더라도 실제 인스턴스[^1]<sup>11</sup>의 오버라이딩[^6]<sup>3</sup>된 메서드가 자동으로 호출되므로 다형성[^2]<sup>4</sup>을 실현할 수 있음
  ```java
  public class PolymorphismTest {
    public static void main(String[] args) {
      // 부모 클래스 타입의 참조 변수를 사용하더라도 실제 인스턴스의 오버라이딩된 메서드가 실행됨
      Animal pet1 = new Dog();
      Animal pet2 = new Cat();

      pet1.sound(); // Dog의 오버라이딩된 sound()가 실행됨 (출력: 멍멍!)
      pet2.sound(); // Cat의 오버라이딩된 sound()가 실행됨 (출력: 야옹~)
    }
  }
  ```
- 코드의 유지보수성과 확장성 향상: 부모 클래스의 틀 안에서 자식 클래스들이 서로 다른 구현을 갖게 하므로, 기존 코드를 수정하지 않고도 새로운 기능을 쉽게 확장할 수 있음
  ```java
  // 기존 Animal, Dog나 Cat 클래스의 수정 없이 Snake 클래스만 새로 추가하여 확장함
  class Snake extends Animal {
    @Override
    public void sound() {
      System.out.println("쉭쉭~");
    }
  }

  public class PolymorphismTest {
    public static void main(String[] args) {
      // 부모 클래스 타입의 참조 변수를 사용하더라도 실제 인스턴스의 오버라이딩된 메서드가 실행됨
      // Animal pet = new Dog();
      Animal pet = new Snake();

      pet.sound(); // 객체가 바뀌어도 이 코드는 수정하지 않음    
    }
  }
  ```

### 12.2.3 오버라이딩(Overriding) vs 오버로딩(Overloading) 비교

| 구분 | 메서드 오버라이딩[^6]<sup>4</sup> (Overriding) | 메서드 오버로딩[^7] (Overloading) |
| :--- | :--- | :--- |
| 정의 | 상속받은 부모의 메서드를 자식 클래스에서 재정의 | 한 클래스 내에서 같은 이름의 메서드를 다중 정의 |
| 메서드 이름 | 부모 메서드와 동일함 | 동일함 |
| 매개변수 | 동일함 (개수, 타입, 순서) | 달라야 함 (개수 또는 타입 또는 순서) |
| 반환 타입 | 동일해야 함 | 상관없음 |
| 접근 제어자[^5]<sup>3</sup> | 부모보다 좁아질 수 없음 | 상관없음 |

### 12.2.4 메서드 오버라이딩 구현 예시
- 부모 클래스의 기능을 자식 클래스에서 재정의하고 다형성[^2]<sup>5</sup>을 활용하여 호출하는 예시

```java
// 부모 클래스 정의
class Animal {
  public void sound() {
    System.out.println("동물이 소리를 낸다");
  }
}

// 자식 클래스에서 부모 메서드 재정의
class Dog extends Animal {
  public void sound() {
    System.out.println("멍멍!");
  }
}

// 또 다른 자식 클래스에서 부모 메서드 재정의
class Cat extends Animal {
  public void sound() {
    System.out.println("야옹~");
  }
}

public class OverridingTest {
  public static void main(String[] args) {
    // 부모 타입 참조 변수로 자식 객체를 참조 (업캐스팅)
    Animal myDog = new Dog();
    Animal myCat = new Cat();

    // 실제 인스턴스에 오버라이딩된 메서드가 알아서 호출됨
    myDog.sound(); // 출력: 멍멍!
    myCat.sound(); // 출력: 야옹~
  }
}
```

## 12.3 super와 super()
상속 관계에서 자식 객체 내부에는 부모 객체의 필드와 메서드가 함께 포함되므로, 이를 명확히 구분하고 생성자 흐름을 제어하기 위해 사용하는 참조 키워드

### 12.3.1 super 참조 변수
- 자식 클래스에서 부모 클래스의 필드나 메서드에 접근할 때 사용하는 참조 변수
- 멤버 변수 가려짐(Shadowing) 해결: 자식 클래스에서 부모 클래스와 동일한 이름의 필드를 선언했을 때, 자식 클래스 내부에서 이름만으로 접근하면 자식 필드가 우선하므로 부모 필드에 접근하기 위해 super.필드명을 명시적으로 사용함

### 12.3.2 super() 생성자 호출
- 부모 클래스의 생성자를 호출하는 함수
- 자식 객체 생성 시 생성자 호출 순서: 자식 클래스의 생성자가 호출되면 내부적으로 가장 먼저 부모 클래스의 생성자가 실행되어 부모 필드가 초기화된 후, 자식 생성자의 나머지 코드가 실행됨
- 첫 줄 배치 제약: super()는 자식 클래스 생성자 코드의 첫 번째 줄에만 위치할 수 있음. 생략할 경우 컴파일러가 생성자 첫 줄에 자동으로 super()를 주입함
  + Java 25 부터는 생성자의 어느곳에 위치해 있어도 상관없음. 단, 인스턴스[^1]<sup>12</sup> 생성 후에 만 사용 가능한 this나 인스턴스[^1]<sup>13</sup> 메서드의 호출보다는 먼저 작성해야 함.
- 기본 생성자가 없는 경우의 제약: 부모 클래스에 매개변수가 있는 생성자만 존재하고 기본 생성자가 정의되어 있지 않았다면, 컴파일러가 자동 삽입하는 super()는 에러를 유발하므로(부모에 존재하지 않는 기본 생성자를 호출하므로) 자식 생성자에서 직접 부모의 매개변수 생성자를 호출(super(인수, ...))하도록 명시해야 함

### 12.3.3 super와 super() 활용 예시
```java
class Parent {
  String name = "부모 필드";

  Parent() {
    System.out.println("부모 기본 생성자 호출");
  }

  Parent(String name) {
    this.name = name;
    System.out.println("부모 매개변수 생성자 호출");
  }
}

class Child extends Parent {
  String name = "자식 필드"; // 부모 필드와 이름이 같음 (Shadowing)

  Child() {
    super(); // 부모 기본 생성자 호출 (생략 가능)
    System.out.println("자식 생성자 호출");
  }

  Child(String parentName, String childName) {
    super(parentName); // 부모의 매개변수 생성자를 직접 지정하여 호출
    this.name = childName;
    System.out.println("자식 매개변수 생성자 호출");
  }

  void printNames() {
    // super와 this를 통해 부모 필드와 자식 필드를 구분하여 참조
    System.out.println("부모 name: " + super.name);
    System.out.println("자식 name: " + this.name);
  }
}
```

## 12.4 final 키워드와 상속
final 키워드는 대상에 따라 변경 불가능하도록 최종적인 상태로 확정하는 제약을 부여함.

### 12.4.1 final 변수
- 변수 선언 시 final이 붙으면 상수가 되어 한 번 결정된 값을 수정할 수 없음

### 12.4.2 final 메서드
- 메서드 선언 시 final이 붙으면 자식 클래스에서 해당 메서드를 오버라이딩[^6]<sup>5</sup>하여 재정의할 수 없음. 부모가 정의한 기능 그대로만 사용하도록 제한할 때 유용함

### 12.4.3 final 클래스
- 클래스 선언 시 final이 붙으면 더 이상 상속의 부모 클래스가 될 수 없음. 즉, 자식 클래스를 생성할 수 없도록 클래스 계층 구조를 제한함 (대표적으로 java.lang.String 클래스가 final 클래스)

### 12.4.4 final 키워드 예시
```java
// final 클래스는 부모 클래스가 될 수 없음 (상속 불가)
public final class FinalClass {
  // final 변수는 값 변경이 불가능한 상수
  public static final double PI = 3.14159;

  // final 메서드는 자식 클래스에서 재정의할 수 없음
  public final void printPI() {
    System.out.println(PI);
  }
}
```

## 12.5 Object 클래스
자바에서 생성되는 모든 클래스는 별도의 extends 선언이 없더라도 기본적으로 java.lang.Object 클래스를 최상위 부모로 상속받음.

### 12.5.1 모든 클래스의 최상위 부모 Object
- 상속 계층의 최상위: 어떤 클래스든 결국 Object 클래스가 자식이 되므로 자바의 모든 객체는 Object 타입으로 선언이 가능함
- 공통 기능 제공: Object 클래스는 모든 객체가 기본적으로 가져야 할 공통 메서드를 제공함

### 12.5.2 Object의 주요 메서드 재정의
- toString(): 객체의 문자열 정보를 반환하는 메서드로, 기본 구현은 클래스명과 해시코드를 출력하지만 개발 시 멤버 필드 값을 출력하도록 재정의하여 디버깅에 활용함
- equals(Object obj): 두 객체의 동등성(내용이 같은지 여부)을 비교하는 메서드로, 기본 구현은 주소값 비교(==)이지만 논리적 내용 비교가 필요한 경우 재정의함
- hashCode(): 객체의 고유한 정수 해시코드를 반환하는 메서드이며, equals 메서드를 재정의할 때 동등한 객체는 동일한 해시코드를 반환해야 한다는 규약에 따라 함께 재정의하는 것이 관례임
  + 해시 (Hash): 임의의 크기를 가진 데이터를 고정된 크기의 고유한 값(해시값)으로 변환하는 기술
    - 입력값이 같으면 항상 동일한 해시값을 반환하며, 출력된 해시값을 통해 역으로 원래 데이터를 유추할 수 없는 단방향성을 가짐
    - HashMap이나 HashSet 같은 해시 기반 자료구조[^8]에서는 객체의 해시값(hashCode())을 내부 저장소(버킷)의 인덱스로 활용하여 데이터 추가, 삭제, 검색 성능을 획기적으로 향상시킴

### 12.5.3 Object 메서드 오버라이딩 예시
- 국제 표준 도서 번호(isbn)가 같으면 도서 제목이나 저자 정보가 일부 다르더라도 동일한 도서로 판단하도록 equals와 hashCode를 재정의하는 예시

```java
public class Book {
  private String isbn; // 국제 표준 도서 번호 (예: 9788965402602)
  private String title;
  private String author;

  public Book(String isbn, String title, String author) {
    this.isbn = isbn;
    this.title = title;
    this.author = author;
  }

  // toString 오버라이딩: 객체의 정보를 가독성 있게 표현
  @Override
  public String toString() {
    return "Book[isbn=" + isbn + ", title=" + title + ", author=" + author + "]";
  }

  // equals 오버라이딩: isbn이 같으면 논리적으로 동일한 객체로 판별
  @Override
  public boolean equals(Object obj) {
    // 주소값이 같으면 동일한 객체임
    if (this == obj) {
      return true;
    }
    // instanceof: 객체가 Book 클래스의 인스턴스인지 검사하여 타입 안정성 확보
    if (obj instanceof Book) {
      Book other = (Book) obj; // 다운캐스팅
      return this.isbn != null && this.isbn.equals(other.isbn);
    }
    return false;
  }

  // equals를 재정의할 때 hashCode도 동일한 기준(isbn)으로 함께 재정의해야 함
  @Override
  public int hashCode() {
    return isbn != null ? isbn.hashCode() : 0;
  }
}

public class BookTest {
  public static void main(String[] args) {
    // isbn이 동일한 두 개의 Book 객체 생성 (동일 도서의 다른 지점 소장본 상황)
    Book b1 = new Book("9788965402602", "자바를 잡아라", "용쌤");
    Book b2 = new Book("9788965402602", "자바를 잡아라 (개정판)", "용쌤");

    // toString() 오버라이딩 결과 확인
    System.out.println(b1); // 출력: Book[isbn=9788965402602, title=자바를 잡아라, author=용쌤]
    System.out.println(b2); // 출력: Book[isbn=9788965402602, title=자바를 잡아라 (개정판), author=용쌤]

    // equals() 오버라이딩을 통해 논리적 동등성 비교 (isbn이 같으므로 true)
    System.out.println("두 도서가 동등한가요? " + b1.equals(b2)); // 출력: 두 도서가 동등한가요? true

    // hashCode() 오버라이딩 결과 확인 (동등한 객체는 해시코드도 일치해야 함)
    System.out.println("b1 해시코드: " + b1.hashCode());
    System.out.println("b2 해시코드: " + b2.hashCode());
  }
}
```

## 12.6 클래스 관계 설계: 포함(Has-A) vs 상속(Is-A)
객체지향[^4]<sup>2</sup> 설계에서 클래스를 재사용하고 확장하기 위해 두 클래스의 관계를 설정하는 대표적인 방법으로 포함과 상속이 존재.

### 12.6.1 포함 관계 (Has-A)
- 한 클래스가 다른 클래스의 인스턴스[^1]<sup>14</sup>를 자신의 필드로 선언하여 소유하는 관계
- "~은 ~을 가지고 있다" (Has-A)로 자연스럽게 설명될 때 포함 관계를 선택 (예: 자동차는 엔진을 가지고 있음, 도서관은 책을 가지고 있음)

```java
public class Engine {
  void start() {
    System.out.println("엔진이 가동됨");
  }
}

public class Car {
  // Engine 객체를 필드로 선언하여 소유 (포함 관계)
  Engine engine = new Engine();

  void drive() {
    engine.start();
    System.out.println("자동차가 주행함");
  }
}
```

### 12.6.2 상속 관계 (Is-A)
- 부모 클래스의 특성을 그대로 물려받아 자식 클래스로 구체화하여 설계하는 관계
- "~은 ~이다" (Is-A)로 자연스럽게 설명될 때 상속 관계를 선택 (예: 강아지는 동물, 노트북은 컴퓨터)

```java
public class Computer {
  void powerOn() {
    System.out.println("전원이 켜짐");
  }
}

public class Laptop extends Computer {
  // 컴퓨터를 상속받아 노트북으로 확장 (상속 관계)
  void useBattery() {
    System.out.println("배터리 전원을 사용함");
  }
}
```

### 12.6.3 올바른 설계 선택 방향
- 상속의 오남용 방지: 상속은 강력한 재사용 도구이지만, 부모와 자식 간의 결합도가 매우 높아져 부모의 변경이 자식에게 큰 영향을 미침. 단순히 코드를 재사용하기 위해 억지로 상속 관계를 맺으면 설계 왜곡 가능성 존재
- Has-A 관계 우선 고려: 두 클래스의 관계가 순수한 Is-A 구조가 아니라면 대부분 포함(Has-A) 관계를 사용하는 것이 설계의 유연성을 확보하고 결합도를 낮추는 방법

# 13. 객체지향 심화 - 다형성(Polymorphism)과 인터페이스

## 13.1 다형성
- 다형성[^2]<sup>6</sup>: 하나의 타입(부모 클래스나 인터페이스[^9])으로 여러 가지 객체(자식 객체)를 참조하고 제어할 수 있는 객체지향[^4]<sup>3</sup>의 핵심 특징. 즉, 동일한 호출(메서드 호출)을 하더라도 참조하는 실제 인스턴스[^1]<sup>15</sup>에 따라 서로 다른 결과와 동작을 나타내는 성질을 의미함

### 13.1.1 다형성 성립의 3대 조건
- 상속 관계: 클래스 간 상속(extends)이나 인터페이스[^9]<sup>2</sup> 구현(implements) 구조가 선언되어 있어야 함
- 메서드 오버라이딩[^6]<sup>6</sup>: 자식 클래스가 부모 클래스의 메서드를 재정의하여 자신의 기능으로 변경해 두어야 함
- 부모 타입의 참조 변수 사용: 부모 클래스나 인터페이스[^9]<sup>3</sup> 타입의 변수로 자식 객체를 가리켜 제어해야 함 (업캐스팅)

### 13.1.2 업캐스팅과 다운캐스팅
- 업캐스팅: 자식 객체를 부모 타입으로 형변환하는 것 (자동 형변환)
- 다운캐스팅: 부모 타입으로 형변환된 객체를 다시 원래의 자식 타입으로 형변환하는 것 (명시적 형변환 필요)
  + 주의: 실제 생성된 인스턴스[^1]<sup>16</sup> 타입과 일치하지 않는 다른 자식 타입으로 잘못 다운캐스팅할 경우 ClassCastException 예외가 런타임에 발생하므로 주의해야 함

```java
class Animal {
  public void eat() {
    System.out.println("냠냠 먹는다");
  }
}

class Dog extends Animal {
  public void eat() {
    System.out.println("강아지가 먹는다");
  }
  public void bark() {
    System.out.println("멍멍!");
  }
}

class Cat extends Animal {
  public void eat() {
    System.out.println("고양이가 먹는다");
  }
  public void meow() {
    System.out.println("야옹~");
  }
}

public class Test {
  public static void main(String[] args) {
    Animal myPet = new Dog(); // 업캐스팅: 자식 객체를 부모 타입으로 형변환
    // Dog의 오버라이딩된 eat() 실행
    myPet.eat(); // 출력: 강아지가 먹는다
    // myPet.bark(); // 메서드 호출 가능 여부는 타입에 따라서 결정되므로 에러 발생(Animal에는 bark가 없음)

    Dog namu = (Dog) myPet; // 다운캐스팅: 업캐스팅된 객체를 원래의 자식 타입으로 형변환
    namu.bark(); // 정상 작동

    // 잘못된 다운캐스팅 시도 (실제 인스턴스가 Dog이므로 Cat으로 형변환 불가)
    // 컴파일 시점에는 문법 에러가 없으나 실행(런타임) 시 ClassCastException 예외가 발생함
    // Cat myCat = (Cat) myPet; 
  }
}
```

## 13.2 instanceof 연산자
- 참조 변수가 실제로 어떤 타입의 객체를 가리키고 있는지 확인할 때 사용

```java
if (myPet instanceof Dog) {
Dog namu = (Dog) myPet;
  namu.bark();
}
```

## 13.3 추상 클래스

### 13.3.1 추상 클래스의 개념
- 추상 클래스는 실체 클래스들의 공통적인 특성(필드, 메서드)을 추출하여 선언한 미완성 설계도
- 미완성 상태의 클래스이므로 단독으로 객체를 생성할 수 없음
- 클래스 선언부에 abstract 키워드를 붙여 정의
  ```java
  // abstract 키워드를 사용하여 추상 클래스 선언
  abstract class Animal {
    // 필드, 생성자, 메서드 선언 가능
  }
  ```

### 13.3.2 추상 클래스의 특징
- 직접적인 객체 생성 불가: 설계도 자체가 미완성이므로 new 연산자를 사용하여 단독으로 인스턴스[^1]<sup>17</sup>를 생성할 수 없음
- 생성자 보유: 직접 객체를 생성할 수는 없지만, 자식 객체가 생성될 때 부모 생성자인 super()를 호출해야 하므로 생성자가 반드시 존재하고 호출됨
- 일반 멤버 포함 가능: 미완성인 추상 메서드 외에도 일반적인 필드(멤버 변수)와 완성된 바디를 가진 일반 메서드를 자유롭게 가질 수 있음

### 13.3.3 추상 메서드 (Abstract Method)
- 선언부만 있고 구현부(중괄호 블록)가 없는 메서드로, abstract 키워드를 사용하여 선언함
  ```java
  abstract class Animal {
    // 선언부만 존재하고 구현부(중괄호)가 없는 추상 메서드
    abstract void sound();
  }
  ```
- 자식 클래스에게 특정 동작의 구현을 강력하게 강제하기 위해 사용함
- 추상 클래스를 상속받은 자식 클래스는 부모의 모든 추상 메서드를 반드시 오버라이딩[^6]<sup>7</sup>하여 구체적으로 구현해야 하며, 그렇지 않을 경우 자식 클래스 역시 추상 클래스로 선언해야 하므로 컴파일 에러가 발생함
  ```java
  // Animal을 상속받은 Dog 클래스는 반드시 sound() 메서드를 오버라이딩하여 구현해야 함
  class Dog extends Animal {
    @Override
    void sound() {
      System.out.println("멍멍!");
    }
  }
  ```

### 13.3.4 실체 클래스가 아닌 추상 클래스로 선언하는 이유
- 부모 클래스의 단독 객체 생성 차단: Animal이나 Shape처럼 그 자체로 실체가 없는 추상적인 개념의 클래스가 new 연산자를 통해 단독 객체로 만들어지는 실수를 방지함
- 자식 클래스의 특정 메서드 구현 강제: 일반 부모 클래스의 메서드는 자식 클래스에서 오버라이딩[^6]<sup>8</sup>을 생략하더라도 문법적인 문제가 없어 실수할 여지가 있음. 반면 추상 메서드는 상속받는 자식 클래스에서 강제적으로 재정의하도록 컴파일 시점에 검증하므로 필수 규격의 누락을 원천 차단함

### 13.3.5 추상 클래스 구현 예시
- 추상 클래스인 Animal을 상속받아 자식 클래스인 Dog와 Cat을 정의하고 추상 메서드를 강제 구현하는 예시

```java
// 추상 클래스 선언
abstract class Animal {
  // 구현부가 없는 추상 메서드 선언
  abstract void sound(); // 동물의 우는 소리는 실제 자식 객체에서 구현이 가능하므로 Animal에서는 해당 메서드의 시그니처만 기술하고 내용을 구현할 수 없음
}

// 자식 클래스 Dog: 추상 클래스 Animal 상속 및 추상 메서드 구현
class Dog extends Animal {
  @Override
  void sound() {
    System.out.println("멍멍!");
  }
}

// 자식 클래스 Cat: 추상 클래스 Animal 상속 및 추상 메서드 구현
class Cat extends Animal {
  @Override
  void sound() {
    System.out.println("야옹~");
  }
}

public class AbstractTest {
  public static void main(String[] args) {
    // 1. 추상 클래스는 직접 new 연산자로 객체 생성 불가 (컴파일 에러 발생)
    // Animal animal = new Animal(); 

    // 2. 자식 클래스를 통한 객체 생성 및 부모 타입 다형성 적용
    Animal myDog = new Dog();
    Animal myCat = new Cat();

    // 각자 오버라이딩하여 구현한 추상 메서드 실행
    myDog.sound(); // 출력: 멍멍!
    myCat.sound(); // 출력: 야옹~
  }
}
```

## 13.4 인터페이스

### 13.4.1 인터페이스의 개념
인터페이스는 객체의 사용 설명서이자 극단적인 추상화 설계도임. 구현부 없이 오직 객체가 수행해야 할 동작의 규격(스펙)만을 정의해 둔 것이며, 클래스들이 가져야 할 기능의 공통 표준 규격을 마련하기 위해 사용함.

### 13.4.2 인터페이스의 문법적 특징
#### 11) 선언부 키워드
- 클래스 선언 시 사용하는 class 키워드 대신 interface 키워드를 사용하여 선언함
  ```java
  // class 키워드 대신 interface 키워드를 사용함
  interface Calculator {
    // ...
  }
  ```
#### 12) 모든 필드는 상수
- 인터페이스 내의 멤버 변수는 컴파일 시 자동으로 public static final 상수로 취급되며, 반드시 선언과 동시에 초기화해야 함
  ```java
  interface Calculator {
    // 선언과 동시에 값을 초기화해야 함 (자동으로 public static final double PI = 3.14159; 로 취급됨)
    double PI = 3.14159; 
  }
  ```
#### 13) 메서드 선언 규칙
- 인터페이스 내부의 메서드는 기본적으로 구현부(중괄호 블록)가 없는 추상 메서드로 선언됨 (자동으로 public abstract 제어자가 지정됨)
  ```java
  interface Calculator {
    // 구현부가 없는 추상 메서드 (자동으로 public abstract int calculate(int a, int b); 로 취급됨)
    int calculate(int a, int b);
  }
  ```
#### 14) 다중 구현 지원
- 자바는 클래스 상속의 단일 상속 제약을 극복하기 위해 인터페이스를 통한 다중 구현을 완벽히 지원함. 하나의 클래스가 여러 인터페이스를 implements 키워드 뒤에 콤마(,)로 나열하여 동시에 구현할 수 있음
  ```java
  interface Calculator {
    int calculate(int a, int b);
  }

  interface Printer {
    void printResult(int result);
  }

  // 두 인터페이스를 동시에 구현함
  class MultiCalculator implements Calculator, Printer {
    @Override
    public int calculate(int a, int b) {
      return a + b;
    }

    @Override
    public void printResult(int result) {
      System.out.println("결과: " + result);
    }
  }
  ```
#### 5) 객체 생성 불가
- 추상 클래스[^10]와 마찬가지로 new 연산자를 사용하여 단독으로 인스턴스[^1]<sup>18</sup>화할 수 없음

### 13.4.3 인터페이스 구현과 규격 일치
- 구현 클래스는 인터페이스에 정의된 모든 추상 메서드를 반드시 오버라이딩[^6]<sup>9</sup>하여 바디를 완성해야 함. 이때 인터페이스의 메서드는 묵시적으로 public이므로, 오버라이딩[^6]<sup>10</sup>할 때 자식 메서드의 접근 제어자[^5]<sup>4</sup>는 반드시 public이어야 함 (더 좁은 접근 권한으로 축소할 수 없음)

### 13.4.4 추상 클래스 vs 인터페이스
- 추상 클래스 (Is-A): 부모와 자식 간의 밀접한 혈연 관계를 정의하며, 상태(필드)와 일반 행위를 상속하여 공유하는 목적
- 인터페이스 (Can-Do): 혈연과 상관없이 공통적인 동작이나 특정 기능을 수행할 수 있는 능력(동작 규격)을 여러 클래스에 부여하는 목적

### 13.4.5 인터페이스 다중 구현 예시
- 날 수 있는 기능(Flyable)과 헤엄칠 수 있는 기능(Swimable)을 가진 오리(Duck) 클래스가 Animal 상속과 두 개의 인터페이스를 다중 구현하는 예시

```java
// 날 수 있는 동작 규격 정의
interface Flyable {
  void fly(); // 컴파일 시 public abstract void fly()로 자동 변환됨
}

// 헤엄칠 수 있는 동작 규격 정의
interface Swimable {
  void swim();
}

// 부모 클래스 Animal
class Animal {
  void breathe() {
    System.out.println("숨을 쉽니다.");
  }
}

// 다중 구현 클래스 Duck: Animal을 상속받으면서 Flyable, Swimable을 동시에 구현
class Duck extends Animal implements Flyable, Swimable {
  // Flyable의 추상 메서드 구현 (반드시 public 제어자 필요)
  @Override
  public void fly() {
    System.out.println("오리가 날개를 파닥이며 날아갑니다.");
  }

  // Swimable의 추상 메서드 구현
  @Override
  public void swim() {
    System.out.println("오리가 발을 저으며 물을 헤엄칩니다.");
  }
}

public class InterfaceTest {
  public static void main(String[] args) {
    Duck duck = new Duck();

    // 1. 상속받은 일반 메서드 실행
    duck.breathe(); // 출력: 숨을 쉽니다.

    // 2. 다중 구현한 인터페이스들의 메서드 실행
    duck.fly();  // 출력: 오리가 날개를 파닥이며 날아갑니다.
    duck.swim(); // 출력: 오리가 발을 저으며 물을 헤엄칩니다.

    // 3. 다형성을 이용한 인터페이스 타입 참조
    Flyable flyingDuck = duck; // 업캐스팅
    flyingDuck.fly(); // 가용한 메서드는 Flyable에 정의된 fly()로 제한됨
  }
}
```

## 13.5 인터페이스의 구현 메서드 (default, static, private)
- 자바 버전이 올라감에 따라 인터페이스의 활용도를 높이고 하위 호환성을 유지하기 위해, 바디(구현부)를 가질 수 있는 세 종류의 구현 메서드가 도입됨

### 13.5.1 default 메서드 (자바 8부터 도입)
- 기존 인터페이스에 새로운 메서드를 추가할 때, 이미 해당 인터페이스를 구현하고 있는 기존 클래스들의 수정 없이 공통적인 기본 기능을 제공하기 위해 도입됨
- 오버라이딩[^6]<sup>11</sup>은 선택적이며, 선언부에 default 키워드를 명시해야 함
- 접근 제어자[^5]<sup>5</sup>는 무조건 public이며 생략 시 자동으로 public으로 취급됨

### 13.5.2 static 메서드 (자바 8부터 도입)
- 객체 생성 없이 인터페이스명으로 직접 호출할 수 있는 정적 유틸리티 메서드
- 접근 제어자[^5]<sup>6</sup>를 생략하는 경우 자동으로 public static으로 취급되며, 인터페이스 외부에서 직접 호출할 수 있음

### 13.5.3 private 메서드 (자바 9부터 도입)
- 인터페이스 내부의 default 또는 static 메서드 내에서만 호출 가능한 비공개 보조 메서드임
- 구현 메서드 간의 공통 코드를 분리하여 코드 중복을 방지하기 위해 도입됨
- 명시적으로 private 접근 제어자[^5]<sup>7</sup>를 선언하며, default 키워드는 붙이지 않음

### 13.5.4 인터페이스 구현 메서드 적용 예시
```java
interface Calculator {
  // 1. 추상 메서드
  int calculate(int a, int b);

  // 2. default 메서드 (자바 8부터 지원, 오버라이딩 선택 가능)
  default void printResult(int result) {
    log("결과 출력: " + result);
  }

  // 3. static 메서드 (자바 8부터 지원, 인터페이스명으로 직접 호출)
  static int add(int a, int b) {
    return a + b;
  }

  // 4. private 메서드 (자바 9부터 지원, 내부 보조용으로만 사용)
  private void log(String msg) {
    System.out.println("[로그] " + msg);
  }
}

// Calculator를 구현하는 클래스
class SimpleCalculator implements Calculator {
  @Override
  public int calculate(int a, int b) {
    return a * b; // 곱셈으로 구현함
  }
}

public class InterfaceMethodTest {
  public static void main(String[] args) {
    Calculator calc = new SimpleCalculator();

    // 1. 추상 메서드 호출
    int res = calc.calculate(5, 4);

    // 2. default 메서드 호출
    calc.printResult(res); // 출력: [로그] 결과 출력: 20

    // 3. static 메서드 호출 (인터페이스명으로 직접 호출함)
    int sum = Calculator.add(5, 4);
    System.out.println("정적 메서드 합계: " + sum); // 출력: 정적 메서드 합계: 9
  }
}
```

## 14.3 String 클래스
- String 클래스는 텍스트 데이터를 저장, 비교, 수정, 파싱 등 문자열과 관련된 모든 처리를 수행하기 위해 사용
- https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/String.html

### 14.3.1 특징
#### 11) 불변성 (Immutability)
- String 객체는 메모리에 한 번 할당되면 내부 값을 변경할 수 없는 불변 객체[^16]
- 내부적으로 자바 9 이후 기준 private final byte[] value 형태로 문자를 저장하며, final 키워드가 지정되어 수정할 수 없음

#### 12) 문자열 상수 풀 (String Constant Pool)
- 자바는 메모리 절약과 동일 텍스트 공유의 안정성을 위해 힙 메모리 내부에 `문자열 상수 풀`이라는 특수한 메모리 영역을 관리함
- 리터럴 방식 생성: String s1 = "Hello"; 와 같이 쌍따옴표로 생성 시, JVM은 상수 풀에서 해당 문자열을 검색하여 이미 존재하면 새로 객체를 만들지 않고 기존 주소값을 재사용(참조 공유)함
- new 키워드 생성: String s3 = new String("Hello"); 와 같이 new 연산자를 사용하면 상수 풀의 존재 여부와 무관하게 힙 영역에 매번 새로운 객체를 생성하여 주소를 할당함
- 비교 연산의 차이: 주소값 비교 연산자(==)를 사용 시 리터럴로 생성한 변수들은 같은 풀의 주소를 공유하므로 true를 반환하지만, new로 생성한 객체와는 주소가 달라 false를 반환함. 따라서 내용의 동등성 비교를 위해서는 반드시 equals() 메서드를 사용해야 함

#### 13) 문자열 결합 연산의 부작용
- 문자열을 합치는 (+) 연산은 편리하지만, 루프(반복문) 내에서 연속적으로 누적하여 사용 시 심각한 성능 저하를 유발함
- 매 반복마다 기존 객체는 버려지고 새로운 임시 문자열 객체가 힙 메모리에 계속 생성되어 누적되는 문제가 발생함
- 이로 인해 쓸모없어진 가비지 객체가 급격히 늘어나며, JVM의 Garbage Collector가 빈번히 가동되어 시스템 리소스를 낭비하고 전체 성능을 저하시키는 원인이 됨
- 잦은 문자열 수정이나 조작이 필요한 경우, 불변 객체가 아닌 가변적으로 문자열을 다룰 수 있는 StringBuilder 또는 StringBuffer를 사용하는 것이 권장됨

```java
public class StringTest {
  public static void main(String[] args) {
    String s1 = "Hello"; // 문자열 상수 풀에 "Hello" 등록 후 참조 주소 반환(예시, 0x12)
    String s2 = new String("Hello"); // 힙 영역에 새로운 객체 생성 후 참조 주소 반환(예시, 0x34)

    System.out.println(s1 == s2); // false: s1은 상수 풀 주소(0x12), s2는 개별 힙 주소(0x34)로 서로 다름
    System.out.println(s1 == "Hello"); // true: 리터럴로 선언된 s1은 상수 풀 주소(0x12)를 가리키므로 동일함
    System.out.println(s2 == "Hello"); // false: s2는 개별 힙 주소(0x34)이므로 상수 풀 주소(0x12)와 다름

    System.out.println(s1.equals(s2)); // true: 문자열의 텍스트 내용이 동일함
    System.out.println(s1.equals("Hello")); // true: 문자열의 텍스트 내용이 동일함
    System.out.println(s2.equals("Hello")); // true: 문자열의 텍스트 내용이 동일함
  }
}
```

### 14.3.2 String 주요 메서드
- `int length()`: 문자열의 총 길이를 반환
- `char charAt(int index)`: 특정 인덱스의 문자를 반환
  + index: 가져올 문자의 인덱스 번호 (0부터 시작)
- `String substring(int beginIndex, int endIndex)`: beginIndex 인덱스부터 endIndex 인덱스 직전까지의 문자열을 추출하여 반환
- `boolean equals(Object anObject)`: 비교할 객체와 현재 문자열의 내용을 비교하여 일치 여부를 반환
  + anObject: 현재 문자열과 비교할 대상 객체
- `int indexOf(String str)`: 지정한 문자열이 처음으로 나타나는 인덱스를 반환
  + str: 검색할 문자열 (찾지 못할 경우 -1 반환)
- `String replace(CharSequence target, CharSequence replacement)`: 대상 문자열을 새 문자열로 치환한 새 문자열을 반환
  + target: 치환 대상이 되는 문자열
  + replacement: 치환할 새로운 문자열
- `String[] split(String regex)`: 구분자(정규표현식)를 기준으로 문자열을 분할하여 배열로 반환
  + regex: 분할 기준이 되는 정규표현식

### 14.3.3 String 클래스 사용 예시
- String 주요 메서드 기본 동작 테스트
```java
public class StringMethodTest {
  public static void main(String[] args) {
    String str = "Hello Java";

    // 1. length(): 문자열의 길이 조회
    System.out.println(str.length()); // 10

    // 2. charAt(): 특정 인덱스의 문자 조회
    System.out.println(str.charAt(6)); // J

    // 3. substring(): 부분 문자열 추출
    // 6번 인덱스부터 10번 인덱스 직전까지
    System.out.println(str.substring(6, 10)); // Java
    // 4번 인덱스부터 끝까지
    System.out.println(str.substring(4)); // o Java

    // 4. equals(): 문자열 내용 비교
    System.out.println(str.equals("Hello Java")); // true

    // 5. indexOf(): 특정 문자열이 시작되는 인덱스 반환
    System.out.println(str.indexOf("Java")); // 6

    // 6. replace(): 문자열 일부 치환
    System.out.println(str.replace("Java", "World")); // Hello World

    // 원본 문자열은 불변
    System.out.println(str); // Hello Java

    // 7. split(): 구분자를 기준으로 문자열 분할
    String str2 = "Hello Java Programming";
    String[] words = str2.split(" ");
    System.out.println(words[0]); // Hello
    System.out.println(words[1]); // Java
    System.out.println(words[2]); // Programming
  }
}
```

## 14.4 StringBuffer와 StringBuilder 클래스
- StringBuffer와 StringBuilder 클래스는 빈번하게 발생할 수 있는 문자열 추가, 삭제, 삽입 등 문자열 편집 작업 시 메모리 낭비를 방지하고 연산 성능을 높이기 위해 사용
- 두 클래스가 제공하는 메서드와 사용법은 거의 동일
- https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/StringBuffer.html
- https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/StringBuilder.html

### 14.4.1 특징
- 가변성 (Mutability): String과 다르게 내부 버퍼(byte[])를 직접 수정할 수 있어 새로운 객체를 생성하지 않고도 값을 수정할 수 있고 버퍼의 크기가 모자라거나 너무 크면 자동으로 크기를 조절하는 기능이 내장되어 있음.
- 동기화 여부에 따른 차이:
  - StringBuffer: 멀티스레드[^13] 환경에서 안전하도록 동기화[^12] (Thread-safe) 처리가 되어 있음
  - StringBuilder: 동기화[^12]<sup>2</sup> 처리가 생략되어 싱글스레드 환경에서 속도가 더 빠름

### 14.4.2 StringBuffer 주요 생성자
- `StringBuffer()`: 기본 크기(16개 문자)의 빈 버퍼를 가진 StringBuffer 객체를 생성
- `StringBuffer(int capacity)`: 지정된 capacity 크기의 빈 버퍼를 가진 StringBuffer 객체를 생성
- `StringBuffer(String str)`: 지정된 문자열 str의 내용을 가진 StringBuffer 객체를 생성 (초기 버퍼 크기는 str 길이 + 16)

### 14.4.3 StringBuffer 주요 메서드

- `StringBuffer insert(int offset, String str)`: offsset 인덱스 위치에 str 문자열을 삽입하고 자신을 반환
- `StringBuffer delete(int start, int end)`: start 인덱스부터 end 인덱스 직전까지의 문자를 제거하고 자신을 반환
- `StringBuffer reverse()`: 버퍼 내 문자열의 순서를 반전시켜 반환
- `String toString()`: 버퍼 내의 문자열 데이터를 일반 String 객체로 반환

## 14.6 래퍼 클래스 (Wrapper Class)
- 래퍼 클래스는 기본 자료형(Primitive Type) 데이터를 객체로서 다루어야 할 때(예: Object[]에 기본 자료형을 저장하거나 Integer.parseInt()같은 객체 지원 메서드를 활용할 때) 사용함
- Byte: https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/Byte.html
- Short: https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/Short.html

- Long: https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/Long.html
- Float: https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/Float.html
- Double: https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/Double.html
- Character: https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/Character.html
- Boolean: https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/Boolean.html

### 14.6.1 특징
- 기본 타입 매핑: 각 기본 타입에 일대일 매핑되는 래퍼 클래스가 제공됨
  + int -> Integer, double -> Double 등
- 오토 박싱[^14] (Auto-boxing) 및 오토 언박싱(Auto-unboxing): 기본 타입과 래퍼 객체 타입이 필요에 따라 자동으로 상호 변환되도록 지원하여 편의성이 높음
- 데이터 파싱 메서드: 외부에서 문자열로 넘어온 데이터를 각 기본 타입 데이터로 파싱하여 리턴하는 static 유틸리티 메서드들을 제공함
  + Integer.parseInt(String str) 등

| 기본 자료형 (Primitive Type) | 래퍼 클래스 (Wrapper Class) |
| :--- | :--- |
| byte | Byte |
| short | Short |
| int | Integer |
| long | Long |
| float | Float |
| double | Double |
| char | Character |
| boolean | Boolean |


### 14.6.2 주요 메서드

- `double Double.parseDouble(String s)`: 숫자로 된 문자열 s를 실수(double)형 값으로 변환하여 반환

### 14.6.3 래퍼 클래스 사용 예시

## 14.7 Math 클래스
- Math 클래스는 절대값, 반올림, 올림, 내림, 거듭제곱, 난수 생성 등 수학 연산과 계산이 필요할 때 사용함
- https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Math.html

### 14.7.1 특징
- 정적 멤버 구조: 모든 필드와 메서드가 static으로 선언되어 있어 별도의 인스턴스 생성 없이 클래스명(Math.round() 등)으로 편리하게 직접 호출함
- 메서드 오버로딩 적용: max, min, abs 등 주요 메서드들이 다양한 데이터 타입(int, long, float, double)을 지원하도록 오버로딩되어 있어 매개변수 타입에 맞춰 알맞은 메서드가 호출됨
- 인스턴스화 차단: 생성자가 private으로 선언되어 있어 new 연산자를 통해 객체를 단독으로 생성할 수 없음

### 14.7.2 주요 메서드
- `int abs(int a)`: a의 절대값을 반환
- `int max(int a, int b)`: a, b 두 정수 값 중 더 큰 값을 반환
- `int min(int a, int b)`: a, b 두 정수 값 중 더 작은 값을 반환
- `long round(double a)`: a의 소수점 첫째 자리에서 반올림한 정수형 값을 반환
- `double ceil(double a)`: a의 소수점 이하를 올림한 값을 반환
- `double floor(double a)`: a의 소수점 이하를 내림한 값을 반환
- `double random()`: 0.0 이상 1.0 미만 범위의 난수(random double)를 생성하여 반환
- `double pow(double a, double b)`: a의 b제곱한 거듭제곱 값을 반환
- `double sqrt(double a)`: 양수 a의 제곱근 값을 반환

### 14.7.3 Math 클래스 사용 예시
- Math 클래스 주요 메서드 기본 동작 테스트
```java

    System.out.println(Math.floor(5.9)); // 5.0

    // 4. random(): 0.0 이상 1.0 미만 난수 생성

    // 5. pow(), sqrt(): 거듭제곱, 제곱근
    System.out.println(Math.pow(2, 3)); // 8.0
    System.out.println(Math.sqrt(16)); // 4.0
  }
}
```

## 14.8 Scanner 클래스
- Scanner 클래스는 콘솔 표준 입력(System.in)이나 파일 등으로부터 텍스트 데이터를 읽어서 원하는 타입으로 파싱하여 가져오기 위해 사용함
- https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Scanner.html

### 14.8.1 특징
- 간편한 토큰[^15] 파싱: 공백(스페이스, 탭 등)이나 개행(줄바꿈)을 구분자로 삼아 문자열, 정수, 실수 등 알맞은 타입의 데이터로 파싱하여 리턴함
- 리소스 누수 주의: 파일로 부터 데이터를 읽을 경우 사용이 끝난 스트림 리소스를 해제하기 위해 반드시 close() 메서드로 닫아주어야 함

### 14.8.2 주요 생성자
- `Scanner(InputStream source)`: 표준 입력(System.in) 등 지정한 입력 스트림으로부터 데이터를 읽는 Scanner 객체를 생성
- `Scanner(String source)`: 지정한 문자열 데이터를 읽는 Scanner 객체를 생성
- `Scanner(File source)`: 지정한 파일로부터 데이터를 읽는 Scanner 객체를 생성

### 14.8.3 주요 메서드
- `String next()`: 다음 공백 이전까지의 텍스트 단어를 문자열로 읽어서 반환
- `String nextLine()`: 다음 개행 문자(엔터) 이전까지의 한 줄 전체 텍스트를 읽어서 반환
- `int nextInt()`: 입력된 다음 토큰을 int형 정수로 파싱하여 반환
- `double nextDouble()`: 입력된 다음 토큰을 double형 실수로 파싱하여 반환
- `boolean hasNext()`: 읽어올 다음 토큰이 있는지 여부를 반환

### 14.8.4 Scanner 클래스 사용 예시
- Scanner 주요 메서드 기본 동작 테스트
```java
import java.util.Scanner;

public class ScannerTest {
  public static void main(String[] args) {
    String input = "Hello 123 3.14 java";
    Scanner scanner = new Scanner(input);

    // 1. next(): 단어 읽기
    System.out.println("첫번째 토큰: " + scanner.next()); // Hello

    // 2. nextInt(): 정수로 읽기
    System.out.println("두번째 토큰: " + scanner.nextInt()); // 123

    // 3. nextDouble(): 실수로 읽기
    System.out.println("세번째 토큰: " + scanner.nextDouble()); // 3.14

    // 4. hasNext(): 다음 읽을 토큰 존재 여부 확인
    if (scanner.hasNext()) {
      System.out.println("네번째 토큰: " + scanner.next()); // java
    }

    // 5. hasNext(): 다음 읽을 토큰 존재 여부 확인
    if (scanner.hasNext()) {
      System.out.println("다섯번째 토큰: " + scanner.next()); // 실행 안됨
    }
  }
}
```

## 14.9 Random 클래스
- Random 클래스는 정수, 실수, 논리값 등 다양한 형태의 무작위 난수를 획득하고자 할 때 사용함
- https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Random.html

### 14.9.1 특징
- 씨드(Seed) 기반 난수: 내부 시드 값을 활용하여 난수 테이블에서 값을 추출함
  + 씨드 값이 같으면 항상 동일한 순서의 난수를 얻을 수 있음
  + Math.random()이나 Random() 생성자에 씨드를 지정하지 않으면 시스템의 시간을 씨드 값으로 사용하므로 매번 다른 난수를 만들게 됨
- 풍부한 데이터 난수 제공: Math.random()에 비해 특정 정수 범위(0~N 미만)를 구하는 nextInt(bound)나 무작위 논리값인 nextBoolean() 메서드를 제공하여 매우 직관적이고 유연하게 활용 가능함

### 14.9.2 주요 생성자
- `Random()`: 현재 시스템 시간(나노초)을 씨드(Seed)로 설정하여 무작위 난수를 발생하는 Random 객체를 생성
- `Random(long seed)`: 지정한 seed 값을 씨드로 설정하여 무작위 난수를 발생하는 Random 객체를 생성 (seed가 같으면 항상 동일한 순서의 난수 생성)

### 14.9.3 주요 메서드
- `int nextInt()`: 모든 정수 범위(음수 포함)에서 무작위 int 정수 값을 반환
- `int nextInt(int bound)`: 0 이상 bound 미만 범위에서 무작위 int 정수 값을 반환
- `double nextDouble()`: 0.0 이상 1.0 미만 범위의 무작위 double 실수를 반환
- `boolean nextBoolean()`: 무작위 boolean 값(true 또는 false)을 반환

### 14.9.4 Random 클래스 사용 예시
- Random 클래스 주요 메서드 기본 동작 테스트

## 14.10 날짜와 시간 클래스 (java.time 패키지)
- java.time 패키지는 자바 8부터 도입되어 날짜와 시간을 효율적이고 안전하게 다룰 수 있는 현대적인 API를 제공함
- 과거에는 Date와 Calendar 클래스를 주로 사용했으나, 값의 변경이 자유로워 스레드에 안전하지 못하고 월(Month)이 0부터 시작하는 등 설계 결함이 많아 현재는 예전에 작성된 코드(레거시)를 다룰 때 외에는 거의 사용하지 않음
- https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/time/package-tree.html

### 14.10.1 특징
- 불변 객체 설계: java.time 패키지의 핵심 클래스들(LocalDate, LocalTime, LocalDateTime 등)은 내부 값을 변경할 수 없는 불변 객체이며, 수정 시 새로운 객체를 반환하여 멀티스레드 환경에서 안전함
- 명확하고 직관적인 표기법: 월(Month) 정보를 다룰 때 1월은 1, 12월은 12로 직관적으로 대응되어 Calendar 클래스처럼 수동 보정(+1)할 필요가 없음
- 용도별 명확한 클래스 구분: 날짜만 관리할 때는 LocalDate, 시간만 관리할 때는 LocalTime, 둘 모두 관리할 때는 LocalDateTime과 같이 목적에 적합한 클래스를 선택할 수 있음

### 14.10.2 주요 메서드
- `static LocalDate LocalDate.now()`: 현재 시스템의 날짜 정보를 가진 LocalDate 객체를 반환
- `static LocalDateTime LocalDateTime.now()`: 현재 시스템의 날짜와 시간 정보를 가진 LocalDateTime 객체를 반환
- `LocalDate plusDays(long daysToAdd)`: 현재 날짜에 daysToAdd 일수만큼 더한 새로운 LocalDate 객체를 반환
- `LocalDate minusDays(long daysToSubtract)`: 현재 날짜에 daysToSubtract 일수만큼 뺀 새로운 LocalDate 객체를 반환
- `int getYear()` / `int getMonthValue()` / `int getDayOfMonth()`: 각각 객체로부터 연도, 월(1-12), 일(1-31) 정보를 정수로 추출하여 반환
- `String format(DateTimeFormatter formatter)`: 지정한 포맷 규칙(DateTimeFormatter)에 맞추어 날짜 및 시간 데이터를 문자열로 출력하여 반환
  + DateTimeFormatter는 ofPattern("yyyy-MM-dd HH:mm:ss") 등의 정적 메서드를 이용해 원하는 포맷 형식을 정의하여 제공함
    - yyyy: 4자리 연도 (예: 2026)
    - yy: 2자리 연도 (예: 26)
    - MM: 2자리 월 (예: 06)
    - M: 1자리 또는 2자리 월 (예: 6, 12)
    - dd: 2자리 일 (예: 09)
    - d: 1자리 또는 2자리 일 (예: 9, 23)
    - HH: 24시간제 시 (00 ~ 23)
    - hh: 12시간제 시 (01 ~ 12)
    - mm: 2자리 분 (00 ~ 59)
    - ss: 2자리 초 (00 ~ 59)
    - a: 오전/오후 표시 (AM/PM)
    - E: 요일 (예: 월, 화, 수)

### 14.10.3 날짜와 시간 클래스 사용 예시
- 날짜와 시간 클래스 주요 메서드 기본 동작 테스트
```java
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

public class TimeTest {
  public static void main(String[] args) {
    // 1. 현재 날짜 및 일시 조회
    LocalDate today = LocalDate.now();
    LocalDateTime now = LocalDateTime.now();
    System.out.println("오늘 날짜: " + today);
    System.out.println("현재 일시: " + now);

    // 2. 날짜 연산 (더하기 및 빼기)
    LocalDate futureDate = today.plusDays(7);
    LocalDate pastDate = today.minusDays(7);
    System.out.println("7일 후: " + futureDate);
    System.out.println("7일 전: " + pastDate);

    // 3. 날짜 세부 정보 개별 추출
    System.out.println("연도: " + today.getYear());
    System.out.println("월(1~12): " + today.getMonthValue());
    System.out.println("일: " + today.getDayOfMonth());

    // 4. DateTimeFormatter를 이용한 커스텀 포맷팅 출력
    DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyy년 MM월 dd일");
    String formattedDate = today.format(formatter);
    System.out.println("포맷된 날짜: " + formattedDate);
  }
}
```

## 14.11 ArrayList 클래스
- ArrayList 클래스는 데이터의 개수가 유동적으로 늘어나거나 줄어드는 동적 목록(가변 리스트)을 안전하고 편리하게 관리하기 위해 사용함
- https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/ArrayList.html

### 14.11.1 특징
- 동적 배열 확장: 내부적으로 관리하는 배열 공간이 가득 차면 자동으로 더 넓은 메모리 배열을 선언하고 데이터를 복사하여 크기 제한 없이 저장 공간을 동적으로 다룸
- 제네릭[^17] (Generic) 적용: 꺾쇠 괄호(< >) 안에 저장할 데이터 타입을 지정하여, 잘못된 타입의 객체가 저장되는 것을 방지하고 타입 안정성을 확보함

### 14.11.2 주요 생성자
- `ArrayList<E>()`: 초기 용량이 10인 비어있는 ArrayList 객체를 생성
  + E: String, Bus 등 저장할 객체의 타입을 명시
- `ArrayList<E>(int initialCapacity)`: 지정한 initialCapacity 용량을 가진 비어있는 ArrayList 객체를 생성

### 14.11.3 주요 메서드
- `boolean add(E e)`: 리스트의 가장 끝 자리에 데이터를 순서대로 삽입하고 성공 여부를 반환
  + `e`: 리스트에 삽입할 요소 객체
- `E get(int index)`: 리스트의 지정한 인덱스 번호에 위치한 요소를 반환
  + `index`: 조회할 요소의 인덱스 번호 (0부터 시작)
- `int size()`: 리스트에 현재 저장되어 축적된 총 데이터(요소)의 개수를 반환
- `E remove(int index)`: 지정한 인덱스 위치에 들어있는 데이터를 삭제하고, 삭제된 그 데이터를 반환
  + `index`: 삭제할 대상 데이터의 인덱스 번호

### 14.11.4 ArrayList 클래스 사용 예시
- ArrayList 주요 메서드 기본 동작 테스트
```java
import java.util.ArrayList;

public class ArrayListTest {
  public static void main(String[] args) {
    ArrayList<String> list = new ArrayList<>(2); // 초기 용량 2로 설정

    // 1. add(): 데이터 추가 및 자동 확장 테스트
    list.add("Apple");
    list.add("Banana");
    System.out.println("기존 크기: " + list.size());

    list.add("Orange"); // 3번째 요소 추가 시 자동으로 크기 확장
    System.out.println("확장 후 크기: " + list.size());
    System.out.println("리스트 내용: " + list);

    // 2. get(): 특정 인덱스 요소 가져오기
    System.out.println("1번 인덱스 요소: " + list.get(1)); // Banana

    // 3. remove(): 특정 인덱스 요소 삭제
    String removed = list.remove(1); // Banana 삭제
    System.out.println("삭제된 요소: " + removed);
    System.out.println("삭제 후 내용: " + list);
    System.out.println("최종 크기: " + list.size()); // 2
  }
}
```

# 각주
[^1]: 인스턴스 (Instance): 클래스라는 설계도를 바탕으로 new 연산자를 사용하여 힙 메모리에 실제로 만들어진 구체적인 객체
[^2]: 다형성 (Polymorphism): 하나의 참조 변수나 객체가 상황에 따라 여러 가지 다양한 클래스 타입이나 동작으로 취급될 수 있는 성질
[^3]: 상속 (Inheritance): 부모 클래스가 가진 멤버(필드, 메서드)를 자식 클래스가 그대로 물려받아 코드를 확장하고 재사용하는 설계 기법
[^4]: 객체지향 (Object-Oriented): 프로그램을 단순히 명령의 나열이 아닌, 데이터와 기능을 가진 객체들의 협력으로 구성하는 개발 패러다임
[^5]: 접근 제어자 (Access Modifier): 클래스, 필드, 메서드 등의 사용 범위를 제한(public, private 등)하여 외부의 직접적인 접근을 차단하는 키워드
[^6]: 오버라이딩 (Overriding): 부모 클래스로부터 상속받은 메서드를 자식 클래스가 자신의 목적에 맞게 메서드 시그니처를 유지한 채 재정의하여 사용하는 기술
[^7]: 오버로딩 (Overloading): 한 클래스 내에 매개변수의 타입이나 개수가 다른 동일한 이름의 메서드나 생성자를 여러 개 정의하는 것
[^8]: 자료구조 (Data Structure): 컴퓨터 메모리 상에서 데이터를 효율적으로 관리하고 조직화하여 다루기 위한 저장 형식 및 프레임워크
[^9]: 인터페이스 (Interface): 클래스가 구현해야 하는 공통 메서드들의 목록과 규격을 선언해 둔 표준 계약서이자 사양서
[^10]: 추상 클래스 (Abstract Class): 온전하지 않은 추상 메서드를 포함할 수 있어, 직접 객체를 생성할 수 없고 자식 클래스가 반드시 상속받아 구현하도록 설계된 미완성 설계도
[^11]: API (Application Programming Interface): 자바가 미리 만들어둔 클래스나 메서드들을 개발자가 가져다 쓸 수 있도록 규칙과 기능을 정리해 놓은 도구 모음
[^12]: 동기화 (Synchronization): 여러 작업이 하나의 자원을 동시에 사용할 때 충돌이 나지 않도록 순서를 맞추어 보호하는 기술
[^13]: 멀티스레드 (Multi-thread): 하나의 프로그램 안에서 여러 개의 독립적인 작업 흐름을 동시에 실행하는 구조
[^14]: 오토 박싱 (Auto-boxing): 자바가 기본 자료형 데이터를 참조형인 객체로 자동 포장해 주는 기능
[^15]: 토큰 (Token): 공백, 탭, 줄바꿈 등으로 구분하여 더 이상 쪼갤 수 없는 가장 기본적인 단어나 데이터 단위
[^16]: 불변 객체 (Immutable Object): 생성된 이후 그 내부 값을 절대 바꿀 수 없는 객체 (수정 시 항상 새로운 객체를 새로 만들어 반환함)
[^17]: 제네릭 (Generic): 클래스나 메서드 내부에서 사용할 데이터 타입을 고정하지 않고, 객체를 생성할 때 꺾쇠 괄호 안에 직접 타입을 유연하게 정해주는 기법
