# 1. 데이터베이스 기초

## 1.1 데이터베이스와 DBMS 개요

### 1.1.1 데이터 저장의 필요성
- 프로그램 실행 중 변수나 임시 객체에 저장된 데이터는 메모리(RAM)의 휘발성 성질로 인해 프로그램이 종료되거나 컴퓨터 전원이 꺼지면 모두 소멸됨
- 사용자 정보, 게시글, 거래 내역 등 지속적으로 유지되어야 하는 데이터는 반드시 보조기억장치(HDD, SSD 등)와 같은 비휘발성[^1] 저장 매체에 기록하여 영구 보존이 필요
- 데이터 저장 기술은 메모리 기반의 임시 저장 단계에서 파일 시스템을 활용한 영구 저장 단계를 거쳐, 이를 체계적으로 제어하고 관리하는 데이터베이스 관리 시스템(DBMS) 형태로 발전함

### 1.1.2 파일 시스템 방식의 한계
- 데이터가 개별 파일 단위로 관리되어 동일한 데이터가 여러 파일에 중복 저장되는 데이터 중복성이 발생함
- 한 파일의 데이터를 수정했을 때 다른 파일에 반영되지 않아 데이터의 일관성[^2]이 깨지는 데이터 불일치 문제가 발생함
- 여러 사용자가 동시에 동일한 파일에 접근하여 수정할 때 충돌 제어가 어려움
- 파일 구조가 변경되면 이를 사용하는 애플리케이션 코드도 함께 변경되어야 하는 데이터 종속성[^3]이 존재함

### 1.1.3 데이터베이스의 정의 및 특징
- 데이터베이스는 특정 조직의 공동 업무 목적을 위해 다수의 사용자와 응용 프로그램이 공유할 수 있도록 통합 및 저장한 데이터의 집합을 의미.
- 데이터베이스는 다음과 같은 4대 필수 요건과 4대 특징을 가짐.

- 데이터베이스의 4대 필수 요건
    + 통합 데이터(Integrated Data): 똑같은 데이터가 여러 곳에 흩어져 중복 저장되는 것을 방지하기 위해, 한곳에 모아서 깨끗하게 합쳐놓은 상태를 의미함
    + 저장 데이터(Stored Data): 종이 문서가 아니라 컴퓨터가 읽고 쓸 수 있는 하드디스크나 SSD 같은 디지털 저장 매체에 보관된 데이터
    + 운영 데이터(Operational Data): 임시로 보관하는 참고용 자료가 아니라, 조직이나 기업이 고유한 핵심 업무를 처리하는 데 반드시 필요한 데이터
    + 공용 데이터(Shared Data): 특정인이나 하나의 프로그램이 독점하는 것이 아니라, 여러 사용자나 업무 시스템들이 다 함께 공유하여 사용할 수 있는 데이터

- 데이터베이스의 4대 특징
    + 실시간 접근성(Real-time Accessibility): 사용자가 데이터를 조회했을 때, 오랜 대기 시간 없이 즉각적으로 빠른 결과를 받아볼 수 있어야 함
    + 계속적인 변화(Continuous Evolution): 새로운 정보가 생기면 추가하고, 틀린 내용은 수정하고, 불필요한 데이터는 삭제하면서 항상 최신의 올바른 정보를 유지함
    + 동시 공용(Concurrent Sharing): 여러 사용자가 같은 시점에 접속하여 동일한 데이터를 조회하거나 사용하더라도 서로 충돌 없이 안전하게 이용할 수 있음
    + 내용에 의한 참조(Content Reference): 데이터가 디스크의 어느 주소나 물리적 위치에 보관되어 있는지 몰라도, 찾고자 하는 데이터의 값(예: 사원 번호, 이름 등)을 기준으로 직접 검색할 수 있음

### 1.1.4 DBMS의 이해
- DBMS(Database Management System, 데이터베이스 관리 시스템)는 데이터베이스를 직접 관리하고 사용자의 요구에 따라 데이터를 조회, 삽입, 수정, 삭제하는 소프트웨어
- 응용 프로그램과 물리적인 데이터 저장소(데이터베이스) 사이에서 중재자 역할을 수행함
    + 사용자가 물리적인 데이터 파일에 직접 접근하여 수정하면 데이터가 손상될 위험이 크므로, 모든 데이터 접근은 DBMS 소프트웨어가 중간에서 대행하고 안전하게 통제함
- 데이터 무결성[^4] 유지, 보안 제어, 동시성 제어[^5], 장애 복구 등의 핵심 기능을 제공함

### 1.1.5 주요 데이터베이스 유형 및 비교
- 데이터베이스는 관리하는 데이터의 구조와 처리 방식에 따라 다양하게 분류됨

#### 1) 관계형 데이터베이스(RDBMS)
- 특징
    + 데이터를 가로(행)와 세로(열)로 구성된 2차원 테이블에 맞추어 정형화하여 관리.
    + 사전에 컬럼 이름과 데이터 타입을 규정하는 스키마[^6]를 엄격히 정의해야 함.
- 장점
    + 데이터의 무결성[^4]<sup>2</sup> (정확성)과 일관성[^2]<sup>2</sup>이 최우선으로 보장됨.
    + 여러 테이블을 조인(JOIN) [^7]하여 복잡한 데이터를 모순 없이 다루기에 적합.
- 단점
    + 데이터 저장 구조를 도중에 바꾸기 어렵고, 대용량의 트래픽[^8]을 처리하기 위해 시스템을 여러 대로 확장(수평 확장) [^9]하는 비용이 큼
- 적합한 서비스
    + 금융 시스템, 회원 정보 관리, 주문 및 결제 시스템 등 데이터 정합성과 신뢰성이 중요한 서비스
- 대표 제품
    + MySQL, Oracle Database, PostgreSQL, Microsoft SQL Server

#### 2) 비관계형 데이터베이스(NoSQL)
- 특징
    + 정해진 표 구조(스키마[^6]<sup>2</sup>)에 얽매이지 않고 자유로운 형태로 데이터를 보관함
- 장점
    + 고정된 구조가 없어 데이터가 시시각각 변해도 쉽게 추가할 수 있으며, 서버를 분산하여 대규모 트래픽[^8]<sup>2</sup>과 데이터를 빠르게 처리하는 데 적합함
- 단점
    + 여러 데이터를 조합(JOIN)하는 연산이 매우 제한적이거나 무겁고, 데이터의 일관성[^2]<sup>3</sup>과 정합성 보장이 상대적으로 약하여 높은 신뢰성과 엄격한 트랜잭션[^10] 관리가 요구되는 핵심 데이터 관리에는 부적합할 수 있음
- 적합한 서비스
    + 실시간 메신저(채팅), 로그 수집 시스템, 소셜 미디어(SNS) 피드 등 비정형 데이터를 대량으로 신속하게 처리해야 하는 서비스
- 대표 제품
    + MongoDB, Redis, Cassandra, Neo4j

#### 3) NewSQL 및 특수 목적 데이터베이스
- NewSQL: 관계형 데이터베이스의 장점(ACID 트랜잭션[^10]<sup>2</sup> 보장, SQL 지원)과 NoSQL의 장점(대량 데이터에 대한 유연한 수평 확장)을 결합한 차세대 데이터베이스 (대표 제품: Google Spanner, CockroachDB)
- 특수 목적 데이터베이스
    + 벡터 데이터베이스(Vector DB): 생성형 AI(LLM)와 유사도 검색에 특화되어 대용량 고차원 벡터 데이터를 다룸. (대표 제품: Pinecone, Milvus)
    + 시계열 데이터베이스(TSDB): 서버 모니터링 로그나 센서 데이터처럼 시간 흐름에 따라 순차적으로 발생하는 대량의 정보를 효율적으로 기록하고 분석 (대표 제품: InfluxDB, Prometheus)

## 1.2 관계형 데이터베이스(RDBMS)의 개념 및 구조
- RDBMS는 앞서 살펴본 다양한 데이터베이스 유형 중, 현대 백엔드 개발에서 가장 핵심이 되는 모델
- 모든 데이터를 2차원 표(Table) 형태로 저장하고 관리하는 시스템

### 1.2.1 데이터베이스, 테이블, Row, Column 구조
- 데이터베이스(Database): RDBMS 내에서 연관된 테이블들을 하나로 묶어 관리하는 논리적 보관 공간(스키마[^6]<sup>3</sup>).
    + 예시: 회원(user) 테이블, 게시글(post) 테이블, 댓글(reply) 테이블들을 하나의 데이터베이스인 board_db에 모아서 관리.
- 테이블(Table): 행과 열로 구성된 2차원 표 구조로 데이터를 저장하는 가장 기본적인 객체.
    + 게시판: 회원 테이블, 게시글 테이블, 댓글 테이블 등
    + 쇼핑몰: 회원 테이블, 상품 테이블, 구매 테이블, 장바구니 테이블 등
- 열(Column): 테이블에서 세로 방향의 한 칸을 의미하며, 저장되는 데이터의 구체적인 종류와 타입을 규정.
    + 회원 테이블의 컬럼 예시
        - 아이디,  이메일,  이름, 전화번호, 주소, 가입일 등
- 행(Row, Record): 테이블에서 가로 방향의 한 줄을 의미하며, 데이터베이스에 저장되는 하나의 데이터 단위.
    + 회원 테이블의 레코드 예시: 특정 회원 한 명의 정보
        - 아이디: 1, 이메일: haru@gmail.com, 이름: 하루, 전화번호: null, 주소: 경기도 김포시, 가입일: 2026-06-11
- 스키마[^6]<sup>4</sup>(Schema): 테이블의 구조와 데이터 타입, 테이블 간의 제약 조건에 대한 명세를 정의.
    + 회원 테이블의 스키마[^6]<sup>5</sup> 예시: 테이블 이름은 member이고, 아이디 컬럼은 중복과 빈 값을 허용하지 않으며 이메일 컬럼은 문자열이며 필수여야 한다

### 1.2.2 기본 키(PK)와 외래 키(FK)
- 기본 키(Primary Key, PK)
    + 테이블에서 각 행을 식별할 수 있는 유일한 값을 가지는 컬럼
    + 기본 키는 null 값을 가질 수 없으며 중복된 값을 가져서도 안 됨
- 외래 키(Foreign Key, FK)
    + 다른 테이블의 기본 키를 참조하여 테이블 간의 유기적인 관계를 형성하는 컬럼
    + 참조 무결성[^4]<sup>3</sup> 규칙에 따라 외래 키의 값은 참조 대상 테이블의 기본 키 값 중 하나이거나 null이어야 함

### 1.2.3 테이블 간의 관계(1:N, N:M)
- 1:N (일대다) 관계
    + 한쪽 테이블의 레코드 1개가 다른 쪽 테이블의 레코드 여러 개와 연결될 수 있는 가장 일반적인 관계
    + 예: 하나의 회원(1)이 여러 개의 게시글을 작성(N)
    + 설계 시 N에 해당하는 테이블에 외래 키(FK)를 배치하여 1에 해당하는 테이블의 기본 키(PK)를 참조하도록 설계함
- N:M (다대다) 관계
    + 양쪽 테이블의 레코드가 서로의 레코드 여러 개와 연결될 수 있는 관계임
    + 예: 한 명의 학생(N)이 여러 개의 과목(M)을 수강하고, 하나의 과목(M)을 여러 명의 학생(N)이 수강하는 관계
    + RDBMS에서는 다대다 관계를 직접 테이블로 생성할 수 없으므로, 두 테이블의 기본 키를 외래 키로 가지는 매핑 테이블(연결 테이블)을 중간에 두어 1:N 및 M:1 관계로 해소하여 설계함

# 2. SQL 기본
- SQL(Structured Query Language)은 관계형 데이터베이스(RDBMS)의 데이터를 정의, 조작, 제어하기 위해 고안된 표준 컴퓨터 언어
- 사용자가 데이터가 저장된 물리적 위치나 처리 방식의 세부 과정을 지시하지 않고, 원하는 결과만 명시하여 명령을 수행하는 비절차적 언어의 성격을 가짐
- 데이터베이스 관리 시스템(DBMS)에 직접 명령을 전달하여 테이블 스키마[^6]<sup>6</sup>를 설계하거나, 레코드를 검색, 추가, 갱신, 삭제할 수 있으며 복잡한 권한 제어 및 트랜잭션[^10]<sup>3</sup> 관리도 통합 수행

- SQL의 주요 기능별 분류
    + DDL(Data Definition Language, 데이터 정의어): 테이블이나 뷰 등 데이터베이스 객체의 구조를 생성, 변경, 삭제하기 위해 사용하며 CREATE, ALTER, DROP 등의 명령어가 포함됨
    + DML(Data Manipulation Language, 데이터 조작어): 테이블 내부의 데이터를 다루기 위해 사용하며 INSERT, SELECT, UPDATE, DELETE 등의 명령어가 포함됨
    + DCL(Data Control Language, 데이터 제어어): 데이터베이스 보안 및 접근 통제를 위해 권한을 관리하며 GRANT, REVOKE 등의 명령어가 포함됨

## 2.1 DDL (CREATE TABLE과 제약조건)
- DDL(Data Definition Language, 데이터 정의어)은 데이터베이스의 물리적인 테이블 구조를 생성, 변경, 삭제하는 명령어 집합
- 관계형 데이터베이스(RDBMS)의 뼈대가 되는 테이블을 DDL을 사용하여 정의

### 2.1.1 데이터베이스 생성, 전환 및 삭제
- 데이터베이스 서버 내에 새로운 데이터 보관소(스키마[^6]<sup>7</sup>)를 생성하고 사용을 위해 전환하거나 필요 없는 데이터베이스를 삭제.
- 테이블을 정의하고 데이터를 적재하기 전에 선행적으로 데이터베이스 인스턴스를 마련하거나 정리하는 기초적인 단계.

#### 1) 데이터베이스 생성
- 문법
  ```sql
  CREATE DATABASE 데이터베이스명;
  ```
- 예시
  ```sql
  -- board_db라는 이름의 데이터베이스 생성
  CREATE DATABASE board_db;
  ```

#### 2) 데이터베이스 전환
- 문법
  ```sql
  USE 데이터베이스명;
  ```
- 예시
  ```sql
  -- 생성한 데이터베이스로 전환하여 이후 쿼리가 해당 데이터베이스를 대상으로 실행되도록 설정
  USE board_db;
  ```

#### 3) 데이터베이스 삭제
- 문법
  ```sql
  DROP DATABASE 데이터베이스명;
  ```
- 예시
  ```sql
  -- 필요 없는 board_db 데이터베이스 삭제 (삭제 시 내부의 모든 테이블과 데이터가 영구히 소멸되므로 주의 필요)
  DROP DATABASE board_db;
  ```

### 2.1.2 테이블 생성(CREATE TABLE) 및 제약조건
- 데이터베이스 내에 데이터를 논리적으로 구조화하여 저장할 수 있도록 물리적인 테이블 구조를 정의하고 생성.
- 컬럼의 이름, 데이터 타입 및 다양한 무결성[^4]<sup>4</sup> 제약조건을 사전에 규정하여 안전한 데이터 저장 공간을 설계하는 출발점.

- 문법
  ```sql
  CREATE TABLE 테이블명 (
      컬럼명 데이터타입 [제약조건],
      ...
      [테이블_제약조건]
  );
  ```
- 예시
  ```sql
  -- member (회원 테이블) 생성
  CREATE TABLE member (
      id INT AUTO_INCREMENT PRIMARY KEY,
      email VARCHAR(100) NOT NULL UNIQUE,
      password VARCHAR(255) NOT NULL,
      name VARCHAR(50) NOT NULL,
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );
  ```

#### 1) 주요 데이터 타입 종류
- 숫자형
    + INT: 정수형 데이터를 저장 (4바이트, 약 -21억 ~ 21억)
    + BIGINT: 대용량 정수형 데이터를 저장 (8바이트, 대규모 식별자 등에 주로 사용)
    + DECIMAL(전체자릿수, 소수자릿수): 고정 소수점 실수를 저장하며 소수점 오차가 없는 정확한 연산이 필요한 금융 데이터 등에 사용
- 문자형
    + CHAR(길이): 고정 길이 문자열 데이터를 저장 (지정한 길이보다 짧은 값을 저장하면 공백으로 채워짐)
    + VARCHAR(길이): 가변 길이 문자열 데이터를 저장 (지정한 길이 내에서 실제 입력된 데이터의 크기만큼만 저장 공간을 사용하므로 효율적)
    + TEXT: 본문글, 댓글 내용 등 대용량 텍스트 데이터를 저장
- 날짜/시간형
    + DATE: 연, 월, 일 날짜 정보만 저장 (YYYY-MM-DD 형식)
    + TIME: 시, 분, 초 시간 정보만 저장 (HH:MM:SS 형식)
    + DATETIME
        - 특징: 타임존의 영향을 받지 않고 입력된 고정 시간값을 보존 (5바이트 저장 공간 사용).
        - 2038년 표현 한계가 없고 타임존 설정 불일치로 인한 오차를 방지할 수 있어 현대 백엔드 개발 시 권장.
    + TIMESTAMP
        - 특징: 시스템의 타임존에 따라 내부적으로 UTC[^11] 시간값으로 자동 변환되어 저장 및 조회됨 (4바이트 저장 공간 사용하며 1970년 ~ 2038년 범위 지원)

#### 2) 주요 제약조건 종류
- PRIMARY KEY (기본 키)
    + 테이블 내의 행을 고유하게 식별할 수 있는 컬럼으로 지정.
    + 중복값과 빈 값(null)을 허용하지 않음.
- FOREIGN KEY (외래 키)
    + 다른 테이블의 기본 키를 참조하여 테이블 간의 연결 관계를 형성.
    + 데이터 참조 무결성[^4]<sup>5</sup>을 보장하기 위해 사용.
    + 외래 키 참조 옵션 종류
        - ON DELETE CASCADE: 부모 테이블의 레코드가 삭제되면 연관된 자식 테이블의 레코드도 함께 자동 삭제.
        - ON DELETE SET NULL: 부모 테이블의 레코드가 삭제되면 자식 테이블의 외래 키 값을 NULL로 변경.
        - ON DELETE RESTRICT: 자식 테이블이 참조하고 있는 부모 테이블의 레코드는 삭제가 불가능하도록 차단. (생략 시 기본값)
    + 외래 키 지정 방법
        - 컬럼 레벨 정의
            + 컬럼 옆에 REFERENCES 부모테이블(부모컬럼) 형태로 직접 정의하는 방식.
            + MySQL(InnoDB) 환경에서는 문법 에러 없이 통과되나 실제 외래 키 제약조건이 작동하지 않고 무시되는 한계가 존재.
            + 예시
              ```sql
              member_id INT REFERENCES member(id)
              ```
        - 테이블 레벨 정의
            + 테이블 생성 쿼리 하단에 FOREIGN KEY (자식컬럼) REFERENCES 부모테이블(부모컬럼) 형태로 명시하여 정의하는 방식.
            + 안정적인 무결성[^4]<sup>6</sup> 보장을 위해 권장하는 방식.
            + 예시
              ```sql
              [CONSTRAINT fk_post_member] FOREIGN KEY (member_id) REFERENCES member(id)
              ```
                - [CONSTRAINT fk_post_member]: 외래 키 이름 정의(생략하면 데이터베이스 엔진이 자동으로 시스템 내부에서 고유한 이름을 생성해서 할당함)
        - 테이블 생성 후 추가 정의
            + 테이블을 이미 생성한 이후 ALTER TABLE 명령어를 통해 외래 키 제약조건을 추가하는 방식.
            + 예시
              ```sql
              ALTER TABLE post ADD [CONSTRAINT fk_post_member] FOREIGN KEY (member_id) REFERENCES member(id);
              ```
- NOT NULL
    + 해당 컬럼에 반드시 값이 존재하도록 규정.
    + 빈 값 입력을 방지.
- UNIQUE: 컬럼 내의 모든 데이터 값이 서로 중복되지 않고 유일하도록 보장
- DEFAULT
    + 데이터를 저장할 때 값을 명시하지 않으면 자동으로 입력될 기본값을 설정.
    + 기본값으로 사용할 수 있는 주요 유형
        - 리터럴 상수: 정수형 기본값(0), 문자형 기본값('N', 'USER'), 빈 문자열('') 등을 사용.
        - NULL: 값을 별도로 지정하지 않았을 때 빈 상태(NULL)로 기록되도록 허용.
        - 내장 함수: 날짜 및 시간 형식에서 시스템의 현재 시각을 채우는 CURRENT_TIMESTAMP 등을 사용.
- AUTO_INCREMENT: 새로운 행이 추가될 때마다 정수형 식별자 값을 자동으로 1씩 증가하여 부여

- 예시
  ```sql
  -- board_db 데이터베이스가 존재하면 삭제
  DROP DATABASE IF EXISTS board_db;

  -- 데이터베이스 생성
  CREATE DATABASE board_db;
  
  -- 생성한 데이터베이스로 전환
  USE board_db;

  -- member (회원 테이블) 생성
  CREATE TABLE member (
      id INT AUTO_INCREMENT PRIMARY KEY,
      email VARCHAR(100) NOT NULL UNIQUE,
      password VARCHAR(255) NOT NULL,
      name VARCHAR(50) NOT NULL,
      phone CHAR(12),
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );

  -- post (게시글 테이블) 생성
  CREATE TABLE post (
      id INT AUTO_INCREMENT PRIMARY KEY,
      member_id INT,
      title VARCHAR(200) NOT NULL,
      content TEXT NOT NULL,
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
      FOREIGN KEY (member_id) REFERENCES member(id) ON DELETE SET NULL
  );

  -- reply (댓글 테이블) 생성
  CREATE TABLE reply (
      id INT AUTO_INCREMENT PRIMARY KEY,
      post_id INT NOT NULL,
      member_id INT NOT NULL,
      content TEXT NOT NULL,
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
      FOREIGN KEY (post_id) REFERENCES post(id) ON DELETE CASCADE,
      FOREIGN KEY (member_id) REFERENCES member(id) ON DELETE CASCADE
  );
  ```

### 2.1.3 테이블 수정(ALTER TABLE)
- 생성된 테이블의 구조를 변경.
- 기존 테이블에 새로운 컬럼을 추가하거나, 기존 컬럼의 데이터 타입 및 제약조건을 수정하고, 더 이상 필요 없는 컬럼을 제거하는 구조 조작 작업을 수행.

- 컬럼 추가
    + 문법
      ```sql
      ALTER TABLE 테이블명 ADD 컬럼명 데이터타입 [제약조건];
      ```
    + 예시
      ```sql
      -- member 테이블에 phone 컬럼(가변 문자열, 최대 20자) 추가
      ALTER TABLE member ADD phone VARCHAR(20);
      ```
- 컬럼 수정
    + 문법
      ```sql
      ALTER TABLE 테이블명 MODIFY 컬럼명 데이터타입 [제약조건];
      ```
    + 예시
      ```sql
      -- member 테이블의 phone 컬럼 데이터타입을 VARCHAR(30)으로 수정하고 필수값(NOT NULL)으로 설정
      ALTER TABLE member MODIFY phone VARCHAR(30) NOT NULL;
      ```
- 컬럼 삭제
    + 문법
      ```sql
      ALTER TABLE 테이블명 DROP COLUMN 컬럼명;
      ```
    + 예시
      ```sql
      -- member 테이블의 phone 컬럼을 삭제
      ALTER TABLE member DROP COLUMN phone;
      ```

### 2.1.4 테이블 삭제(DROP TABLE)
- 데이터베이스 내에서 더 이상 사용하지 않는 테이블을 영구적으로 제거.
- 삭제 시 테이블 구조뿐만 아니라 내부에 저장되어 있던 모든 데이터가 함께 소멸되므로 실행 시 주의 필요.

- 테이블 삭제
    + 문법
      ```sql
      DROP TABLE 테이블명;
      ```
    + 예시
      ```sql
      -- reply 테이블 삭제 (삭제 시 테이블 구조와 저장된 모든 데이터가 영구적으로 소멸되므로 주의 필요)
      DROP TABLE reply;
      ```

### 2.1.5 테이블 초기화(TRUNCATE TABLE)
- 테이블의 구조는 남겨둔 채 내부의 모든 데이터 행을 고속으로 삭제하여 테이블을 생성 초기 상태로 리셋.
- DELETE 명령어와 달리 로그를 남기지 않아 롤백[^12]이 불가능하지만 대용량 데이터를 빠르고 효율적으로 비우고자 할 때 주로 활용.

- 테이블 초기화
    + 문법
      ```sql
      TRUNCATE TABLE 테이블명;
      ```
    + 예시
      ```sql
      -- post 테이블의 모든 데이터를 비우고 처음 생성된 상태로 초기화 (DROP과 달리 구조는 남기며, DELETE보다 연산 속도가 매우 빠름)
      TRUNCATE TABLE post;
      ```

## 2.2 DML (INSERT, SELECT, UPDATE, DELETE)
- DML(Data Manipulation Language, 데이터 조작어)은 생성된 테이블에 데이터를 저장하고, 수정하며, 삭제하기 위해 사용하는 명령어 집합

### 2.2.1 데이터 삽입 (INSERT)
- 정의된 테이블 구조에 맞추어 새로운 레코드 행을 추가.
- 모든 컬럼의 값을 순서대로 명시하여 한 행을 삽입하거나, 특정 필수 컬럼에만 값을 입력하여 저장 영역을 생성할 수 있으며, 하나의 쿼리로 다량의 레코드를 일괄 삽입하는 다중 행 삽입도 가능.

- 모든 컬럼 값 삽입 (컬럼명 생략)
    + 문법
      ```sql
      INSERT INTO 테이블명 VALUES (값1, 값2, ...);
      ```
    + 예시
      ```sql
      -- 모든 컬럼의 값을 순서대로 입력하여 데이터 삽입 (auto_increment는 NULL, default는 DEFAULT 키워드 사용)
      INSERT INTO member
      VALUES (NULL, 'haru@gmail.com', 'pwd123', '하루', '01011112222', DEFAULT);
      INSERT INTO member
      VALUES (NULL, 'haru2@gmail.com', 'pwd123', '하루2', NULL, '2026-05-10 12:13:45');
      ```

- 특정 컬럼 값 삽입 (선택적 컬럼 입력)
    + 문법
      ```sql
      INSERT INTO 테이블명 (컬럼1, 컬럼2) VALUES (값1, 값2);
      ```
    + 예시
      ```sql
      -- 특정 필수 컬럼에만 값을 입력하여 데이터 삽입
      INSERT INTO member (email, password, name, created_at)
      VALUES ('namu@gmail.com', 'pwd789', '나무', '2026-05-29 13:34:32');
      ```
- 다중 행 삽입
    + 문법
      ```sql
      INSERT INTO 테이블명 (컬럼1, 컬럼2) VALUES (값1, 값2), (값3, 값4), (값5, 값6);
      ```
    + 예시
      ```sql
      -- 다중 회원 데이터 일괄 삽입 (네트워크 트래픽을 낮추고 고속으로 대용량 데이터를 넣을 때 활용)
      INSERT INTO member (email, password, name, phone, created_at) VALUES
          ('harong@gmail.com', 'pwd012', '하롱이', '01022223333', '2026-05-29 13:34:32'),
          ('yong@gmail.com', 'pwd456', '용쌤', '0103334444', '2026-06-05 14:34:12');
      ```
- 게시글, 댓글 데이터 삽입
    + 예시
      ```sql
      -- 게시글 데이터 삽입
      INSERT INTO post (member_id, title, content, created_at) VALUES (1, '첫 번째 게시글', '안녕하세요. 반갑습니다.', '2026-05-23 12:33:54');
      INSERT INTO post (member_id, title, content, created_at) VALUES (2, '질문 있습니다', '데이터베이스 기초에 대한 질문입니다.', '2026-05-26 11:33:54');
      INSERT INTO post (member_id, title, content, created_at) VALUES (1, '두 번째 게시글', '오늘 날씨가 아주 좋습니다.', '2026-05-27 12:22:54');
      INSERT INTO post (member_id, title, content, created_at) VALUES (2, 'MySQL 설치 오류 해결방법', '설치 중 Configurator 단계에서 오류가 날 때 대처법 공유합니다.', '2026-05-29 12:33:12');
      INSERT INTO post (member_id, title, content, created_at) VALUES (3, '자기 소개', '안녕하세요 하롱이입니다.', '2026-06-12 11:22:33');
  
      -- 댓글 데이터 삽입
      INSERT INTO reply (post_id, member_id, content) VALUES (1, 2, '환영합니다!');
      INSERT INTO reply (post_id, member_id, content) VALUES (1, 3, '반가워요~');
      INSERT INTO reply (post_id, member_id, content) VALUES (2, 1, '어떤 부분이 궁금하신가요?');
      INSERT INTO reply (post_id, member_id, content) VALUES (4, 3, '정말 유용한 정보네요. 감사합니다!');
      INSERT INTO reply (post_id, member_id, content) VALUES (4, 1, '저도 이 방법으로 해결했습니다.');
      ```

### 2.2.2 데이터 조회 (SELECT)
- 데이터베이스에서 원하는 조건의 데이터를 조회하는 명령어
- 데이터베이스 내 특정 테이블에 보관된 레코드를 조회하여 사용자에게 반환.
- 필터링 조건을 지정하지 않을 경우 테이블에 적재된 모든 데이터 행을 읽어오게 되며, 데이터의 전체적인 상태나 컬럼 구성을 확인하고자 할 때 주로 사용.

- 기본 검색
    + 문법
      ```sql
      -- 특정 컬럼 조회
      SELECT 컬럼명1, 컬럼명2 FROM 테이블명;
  
      -- 전체 컬럼 조회
      SELECT * FROM 테이블명;
  
      -- 별칭(Alias) 사용 시 (AS 생략 가능)
      SELECT 컬럼명1, 컬럼명2 [AS] 별칭 FROM 테이블명;
  
      -- 중복 제거 조회
      SELECT DISTINCT 컬럼명 FROM 테이블명;
      ```
    + 예시
      ```sql
      -- 전체 회원의 이름과 가입일 조회
      SELECT name, created_at
      FROM member;
  
      -- 전체 회원의 모든 컬럼 조회
      SELECT *
      FROM member;
  
      -- 별칭을 사용하여 컬럼명을 가독성 있게 표현
      SELECT name, created_at AS 가입일
      FROM member;
  
      -- 게시글을 작성한 회원 ID 목록을 중복 없이 조회
      SELECT DISTINCT member_id
      FROM post;
      ```

### 2.2.3 데이터 수정 (UPDATE)
- 테이블 내에 이미 저장되어 있는 특정 행의 데이터를 조건에 맞추어 원하는 값으로 갱신.
- 특정 조건에 부합하는 레코드만 필터링하여 안전하게 변경하기 위해 WHERE 절을 필수적으로 결합하는 과정이 요구되며, 이를 생략 시 테이블 전체 행의 데이터가 일괄 갱신되는 결과를 초래할 수 있으므로 주의 필요.
- 안전한 수정을 위해 SELECT를 먼저 수행해서 수정할 레코드만 조회되는지 확인 후 수정을 권장

- 데이터 수정
    + 문법
      ```sql
      UPDATE 테이블명 SET 컬럼1 = 값1, 컬럼2 = 값2 WHERE 조건;
      ```
    + 예시
      ```sql
      -- 1번 회원의 이름을 김하루로 수정
      UPDATE member
      SET name = '김하루'
      WHERE id = 1;
  
      -- 1번 게시글의 제목과 내용을 변경
      UPDATE post
      SET title = '수정된 첫 번째 게시글',
          content = '수정이 반영된 본문입니다.'
      WHERE id = 1;
      ```

### 2.2.4 데이터 삭제 (DELETE)
- 테이블 내부에서 더 이상 불필요해진 데이터를 행 단위로 영구 삭제.
- 조건식을 지정하는 WHERE 절을 활용하여 특정 타겟 레코드만 제거해야 하며, WHERE 절 누락 시 테이블 내의 전체 데이터가 한꺼번에 지워지는 결과로 이어지므로 주의 필요.
- 안전한 삭제를 위해 SELECT를 먼저 수행해서 삭제할 레코드만 조회되는지 확인 후 삭제를 권장

- 데이터 삭제
    + 문법
      ```sql
      DELETE FROM 테이블명 WHERE 조건;
      ```
    + 예시
      ```sql
      -- 1번 댓글 삭제
      DELETE FROM reply
      WHERE id = 1;
  
      -- 2번 게시글 삭제 (댓글 테이블 생성 시 ON DELETE CASCADE 제약 조건을 지정했으므로, 게시글 삭제 시 관련된 하위 댓글 데이터도 함께 자동 삭제됨)
      DELETE FROM post
      WHERE id = 2;
  
      -- 1번 회원 삭제 (게시글 테이블 생성 시 ON DELETE SET NULL 제약 조건을 지정했으므로, 회원 삭제 시 관련된 하위 게시글 데이터의 FK 값이 NULL이됨)
      DELETE FROM member
      WHERE id = 1;
      ```

## 2.3 SELECT 문 기초 (WHERE, ORDER BY, LIMIT)
- 특정 조건에 부합하는 데이터만 선별하는 조건 검색
- 조회 결과의 출력 순서를 제어하는 결과 정렬
- 반환되는 행의 개수를 제약하는 방법

### 2.3.1 조건 검색 (WHERE)
- 테이블 내 전체 데이터 중 원하는 조건에 부합하는 레코드만 선별하여 조회.
- 다양한 비교 연산자와 논리 연산자를 결합하여 복합적인 필터 조건을 정의할 수 있으며, 패턴 매칭 및 범위, 다중 목록 검색 연산자를 활용한 유연한 데이터 필터링도 지원.

- 조건 검색
    + 문법
      ```sql
      SELECT 컬럼명 FROM 테이블명 WHERE 조건;
      ```
    + 주요 연산자 종류
        - 비교 연산자: =, <>, !=, >, <, >=, <=
        - 논리 연산자: AND, OR, NOT
        - 패턴 매칭 연산자: LIKE (%는 길이 제한 없는 모든 문자열, _는 문자 1개 매칭)
        - 기타 조건 연산자: BETWEEN A AND B, IN (값1, 값2, ...), IS NULL / IS NOT NULL
    + 예시
      ```sql
      -- 특정 이메일을 사용하는 회원 정보 조회
      SELECT id, name
      FROM member
      WHERE email = 'haru@gmail.com';
  
      -- 제목에 '게시글'이라는 단어가 들어간 모든 글 조회
      SELECT id, title
      FROM post
      WHERE title LIKE '%게시글%';
  
      -- 이름이 '하'로 시작해서 두글자인 모든 회원 조회
      SELECT id, name
      FROM member
      WHERE name LIKE '하_';
  
      -- member_id가 1번, 3번, 5번인 회원이 작성한 게시글만 선별하여 조회
      SELECT id, title, member_id
      FROM post
      WHERE member_id IN (1, 3, 5);
  
      -- 2026년 6월 1일부터 2026년 6월 10일 사이에 가입한 회원 조회
      SELECT id, name, created_at
      FROM member
      WHERE created_at BETWEEN '2026-06-01' AND '2026-06-10 23:59:59';
  
      -- 전화번호 컬럼 값이 입력되지 않고 비어있는(NULL) 회원 조회
      SELECT id, name
      FROM member
      WHERE phone IS NULL;
  
      -- 이름이 '하루'이고 전화번호가 '01011112222'인 회원 조회
      SELECT id, name, phone
      FROM member
      WHERE name = '하루' AND phone = '01011112222';
  
      -- 이름이 '하루'이거나 '용쌤'인 회원 조회
      SELECT id, name
      FROM member
      WHERE name = '하루' OR name = '용쌤';
      ```

### 2.3.2 결과 정렬 (ORDER BY)
- 검색된 결과를 지정한 컬럼 기준에 따라 정렬하여 화면에 출력.
- 기본적으로 오름차순 정렬이 적용되며 내림차순 정렬도 지정할 수 있고, 정렬 기준 컬럼을 여러 개 나열하여 1차 정렬 후 동일한 값에 대해 2차 정렬을 수행하는 세밀한 구성도 가능.

- 결과 정렬
    + 문법
      ```sql
      SELECT 컬럼명 FROM 테이블명 ORDER BY 컬럼명 [ASC|DESC];
      ```
    + 정렬 방식 구분
        - 오름차순 (ASC, 생략시 기본값): 숫자(작은 값부터), 문자(사전 순), 날짜(과거부터 최신) 순서로 정렬
        - 내림차순 (DESC): 숫자(큰 값부터), 문자(역순), 날짜(최신부터 과거) 순서로 정렬
    + 예시
      ```sql
      -- 가장 최근에 가입한 회원 순서로 정렬하여 조회
      SELECT id, email, name, created_at
      FROM member
      ORDER BY created_at DESC;
  
      -- 다중 컬럼 정렬: 가입일 오름차순 정렬 후, 동일한 가입일인 경우 이름의 내림차순으로 2차 정렬
      SELECT id, name, created_at
      FROM member
      ORDER BY created_at, name DESC;
      ```

### 2.3.3 행 개수 제한 (LIMIT)
- 쿼리 실행 결과로 반환되는 레코드의 최대 개수를 제한하여 출력.
- 불필요하게 많은 데이터가 한 번에 조회되는 현상을 방지하여 시스템 부하를 낮추고, 시작 위치를 지정하는 오프셋 설정과 결합하여 게시판의 페이징 처리를 구현할 때 주로 활용.

- 행 개수 제한
    + 문법
      ```sql
      SELECT 컬럼명 FROM 테이블명 LIMIT [시작위치,] 개수;
      ```
    + 주요 설정 방식
        - 단일 값 지정: LIMIT 개수 형식으로 처음부터 지정한 개수만큼 반환
        - 오프셋 지정: LIMIT 시작위치, 개수 형식으로 시작위치(0부터 시작)에서 지정한 개수만큼 반환
    + 예시
      ```sql
      -- 가장 최근에 작성된 게시글 5개만 조회
      SELECT id, title, created_at
      FROM post
      ORDER BY created_at DESC
      LIMIT 5;
  
      -- 페이징 처리: 한 페이지에 2건씩, 2페이지 조회 (3번째~4번째 행)
      SELECT id, title, created_at
      FROM post
      ORDER BY created_at DESC
      LIMIT 2, 2;
      ```

## 2.4 주요 기본 함수 (문자열, 날짜, 집계, 조건)
- SQL은 조회 결과를 가공하거나 통계 데이터를 손쉽게 구할 수 있도록 기본 내장 함수들을 제공

### 2.4.1 문자열 함수
- CONCAT(문자1, 문자2, ...): 인자로 전달된 문자열들을 하나로 합침
    + 예시
      ```sql
      -- 회원 이름과 이메일을 결합하여 표현
      SELECT CONCAT(name, ' (', email, ')') AS member_info
      FROM member;
      ```
- LENGTH(문자열): 문자열의 바이트 길이를 연산
    + 예시
      ```sql
      -- 각 회원 이메일의 바이트 길이를 조회
      SELECT email, LENGTH(email) AS email_length
      FROM member;
  
      -- 게시글 제목의 바이트 길이를 조회
      SELECT title, LENGTH(title) AS title_length
      FROM post;
      ```
- REPLACE(문자열, 대상텍스트, 대체텍스트): 특정 문자열 패턴을 찾아 다른 내용으로 치환
    + 예시
      ```sql
      -- 게시글 본문 내의 특정 문자열을 다른 내용으로 치환하여 조회
      SELECT content, REPLACE(content, '안녕하세요', '반갑습니다') AS replaced_content
      FROM post
      WHERE content LIKE '%안녕하세요%';
      ```
- SUBSTRING(문자열, 시작위치, 길이): 문자열의 지정 위치부터 지정한 길이만큼 데이터를 추출
    + 예시
      ```sql
      -- 게시글 본문의 첫 10글자만 미리보기로 추출하여 조회
      SELECT title, SUBSTRING(content, 1, 10) AS preview
      FROM post;
      ```
- UPPER(문자열) / LOWER(문자열): 문자열을 대문자 또는 소문자로 변환
    + 예시
      ```sql
      -- 이메일을 소문자로 통일하여 조회
      SELECT LOWER(email) AS email_lower
      FROM member;
  
      -- 이메일을 대문자로 통일하여 조회
      SELECT UPPER(email) AS email_upper
      FROM member;
      ```

- TRIM(문자열): 문자열 양쪽의 공백을 제거
    + 예시
      ```sql
      -- 이름 앞뒤 공백을 제거하여 조회
      SELECT TRIM(name) AS trimmed_name
      FROM member;
      ```

### 2.4.2 날짜 함수
- NOW(): 현재 시스템의 날짜와 시간을 가져옴
    + 예시
      ```sql
      -- 현재 날짜와 시간을 조회
      SELECT NOW() AS current_datetime;
      ```
- DATE_FORMAT(날짜데이터, 포맷형식): 날짜 정보를 원하는 양식의 문자열로 가공하여 출력
    + 연도 관련 포맷
        - %Y: 4자리 연도 (예: 2026)
        - %y: 2자리 연도 (예: 26)
    + 월 관련 포맷
        - %m: 2자리 월 (01 ~ 12)
        - %c: 1자리 또는 2자리 월 (1 ~ 12)
        - %M: 영문 월 이름 (January ~ December)
        - %b: 영문 약식 월 이름 (Jan ~ Dec)
    + 일 관련 포맷
        - %d: 2자리 일 (01 ~ 31)
        - %e: 1자리 또는 2자리 일 (1 ~ 31)
    + 시간 관련 포맷
        - %H: 24시간제 2자리 시간 (00 ~ 23)
        - %h: 12시간제 2자리 시간 (01 ~ 12)
        - %p: AM 또는 PM 구분 표시
    + 분 및 초 관련 포맷
        - %i: 2자리 분 (00 ~ 59)
        - %s: 2자리 초 (00 ~ 59)
    + 요일 관련 포맷
        - %W: 영문 요일 이름 (Sunday ~ Saturday)
        - %a: 영문 약식 요일 이름 (Sun ~ Sat)
    + 예시
      ```sql
      -- 연-월-일 형식으로 가공하여 조회 (예: 2026-06-10)
      SELECT id, title, DATE_FORMAT(created_at, '%Y-%m-%d') AS write_date
      FROM post;
  
      -- 연-월-일 시:분:초 형식으로 가공하여 조회 (예: 2026-06-10 23:25:54)
      SELECT id, title, DATE_FORMAT(created_at, '%Y-%m-%d %H:%i:%s') AS write_datetime
      FROM post;
  
      -- 12시간제 형식과 오전/오후 표시 추가하여 조회 (예: 11:25 PM)
      SELECT id, title, DATE_FORMAT(created_at, '%h:%i %p') AS write_time_ampm
      FROM post;
  
      -- 영문 요일과 월 이름을 포함한 포맷 형태로 조회 (예: Sunday, June 10, 2026)
      SELECT id, title, DATE_FORMAT(created_at, '%W, %M %d, %Y') AS formal_write_date
      FROM post;
  
      -- 축약형 연도와 월, 일 형식으로 조회 (예: 26/6/10)
      SELECT id, title, DATE_FORMAT(created_at, '%y/%c/%e') AS short_date
      FROM post;
      ```
- CURDATE(): 현재 날짜 정보(시간 정보 제외)만 반환
    + 예시
      ```sql
      -- 오늘 날짜 조회
      SELECT CURDATE();
  
      -- 오늘 작성된 게시글만 조회
      SELECT id, title
      FROM post
      WHERE created_at >= CURDATE();
      ```
- DATE_ADD(날짜, INTERVAL 값 단위) / DATE_SUB(날짜, INTERVAL 값 단위): 날짜에 특정 기간을 더하거나 빼서 연산
    + 단위로는 다음과 같은 단일 단위 및 복합 단위가 사용됨
        - 단일 단위
            * YEAR: 연도 (예시: INTERVAL 1 YEAR)
            * QUARTER: 분기 (3개월 단위, 예시: INTERVAL 1 QUARTER)
            * MONTH: 월 (예시: INTERVAL 1 MONTH)
            * WEEK: 주 (7일 단위, 예시: INTERVAL 2 WEEK)
            * DAY: 일 (예시: INTERVAL 7 DAY)
            * HOUR: 시 (예시: INTERVAL 12 HOUR)
            * MINUTE: 분 (예시: INTERVAL 30 MINUTE)
            * SECOND: 초 (예시: INTERVAL 45 SECOND)
            * MICROSECOND: 마이크로초 (예시: INTERVAL 1000 MICROSECOND)
        - 복합 단위 (두 개 이상의 시간 단위를 조합하여 정밀한 연산 수행)
            * YEAR_MONTH: 연과 월 (예시: INTERVAL '1-2' YEAR_MONTH -> 1년 2개월 더하기/빼기)
            * DAY_HOUR: 일과 시 (예시: INTERVAL '1 05' DAY_HOUR -> 1일 5시간 더하기/빼기)
            * DAY_MINUTE: 일, 시, 분 (예시: INTERVAL '1 05:30' DAY_MINUTE -> 1일 5시간 30분 더하기/빼기)
            * DAY_SECOND: 일, 시, 분, 초 (예시: INTERVAL '1 05:30:10' DAY_SECOND -> 1일 5시간 30분 10초 더하기/빼기)
            * HOUR_MINUTE: 시와 분 (예시: INTERVAL '05:30' HOUR_MINUTE -> 5시간 30분 더하기/빼기)
            * HOUR_SECOND: 시, 분, 초 (예시: INTERVAL '05:30:10' HOUR_SECOND -> 5시간 30분 10초 더하기/빼기)
            * MINUTE_SECOND: 분과 초 (예시: INTERVAL '30:10' MINUTE_SECOND -> 30분 10초 더하기/빼기)
    + 예시
      ```sql
      -- DAY 단위: 최근 7일 이내에 가입한 회원 조회
      SELECT id, name, created_at
      FROM member
      WHERE created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY);
  
      -- MONTH 단위: 가입한 지 3개월이 지난 회원 정보 조회 (3개월 전 이전 가입자)
      SELECT id, name, created_at
      FROM member
      WHERE created_at <= DATE_SUB(NOW(), INTERVAL 3 MONTH);
  
      -- YEAR 단위: 현재 날짜 기준으로 1년 뒤의 날짜 계산
      SELECT CURDATE(), DATE_ADD(CURDATE(), INTERVAL 1 YEAR) AS next_year;
  
      -- HOUR / MINUTE 단위: 최근 12시간 30분 이내에 작성된 게시글 조회
      -- (현재 시간에서 12시간 30분을 빼서 연산하기 위해 복합 단위인 HOUR_MINUTE를 활용)
      SELECT id, title, created_at
      FROM post
      WHERE created_at >= DATE_SUB(NOW(), INTERVAL '12:30' HOUR_MINUTE);
  
      -- 복합 단위 (YEAR_MONTH): 현재 시점으로부터 1년 6개월 전 날짜 계산
      SELECT CURDATE(), DATE_SUB(CURDATE(), INTERVAL '1-6' YEAR_MONTH) AS year_and_half_ago;
  
      -- 복합 단위 (DAY_HOUR): 현재 시점으로부터 2일 10시간 후의 날짜와 시간 계산
      SELECT NOW(), DATE_ADD(NOW(), INTERVAL '2 10' DAY_HOUR) AS after_2days_10hours;
      ```
- DATEDIFF(날짜1, 날짜2): 두 날짜 사이의 일수 차이를 연산
    + 예시
      ```sql
      -- 각 회원의 가입 후 경과 일수를 조회
      SELECT name, created_at, DATEDIFF(NOW(), created_at) AS days_since_join
      FROM member;
      ```

### 2.4.3 집계 함수
- 테이블 내의 여러 행으로부터 연산을 적용하여 하나의 단일 결괏값으로 요약
- COUNT(컬럼): 지정한 컬럼의 행 개수를 셈
    + 예시
      ```sql
      -- 전체 회원 수 조회
      SELECT COUNT(*)
      FROM member;
      ```
- SUM(컬럼): 수치 데이터의 합계를 연산
    + 예시
      ```sql
      -- 전체 게시글의 조회수 합계를 연산 (view_count 컬럼이 존재한다고 가정)
      SELECT SUM(view_count) AS total_views
      FROM post;
      ```
- AVG(컬럼): 수치 데이터의 평균값을 연산
    + 예시
      ```sql
      -- 게시글당 평균 조회수를 연산
      SELECT AVG(view_count) AS avg_views
      FROM post;
      ```
- MAX(컬럼) / MIN(컬럼): 컬럼의 최댓값과 최솟값을 추출
    + 예시
      ```sql
      -- 가장 최근에 가입한 회원의 가입일과 가장 먼저 가입한 회원의 가입일을 조회
      SELECT MAX(created_at) AS latest_join, MIN(created_at) AS first_join
      FROM member;
      ```

### 2.4.4 NULL 처리 함수
- IFNULL(값, 대체값): 값이 NULL이면 지정한 대체값으로 변환하여 반환
    + 예시
      ```sql
      -- 전화번호가 NULL인 회원은 '미등록'으로 표시하여 조회
      SELECT name, IFNULL(phone, '미등록') AS phone
      FROM member;
      ```
- COALESCE(값1, 값2, ...): 인자 목록에서 NULL이 아닌 첫 번째 값을 반환 (여러 컬럼 중 우선순위를 두고 선택할 때 활용)
    + 예시
      ```sql
      -- 전화번호가 NULL이면 이메일을, 이메일도 NULL이면 '연락처 없음'으로 표시
      SELECT name, COALESCE(phone, email, '연락처 없음') AS contact
      FROM member;
      ```

### 2.4.5 흐름 제어 및 조건 함수
- IF(조건, 참일 때 값, 거짓일 때 값): 조건식이 참이면 첫 번째 값을, 거짓이면 두 번째 값을 반환
    + 예시
      ```sql
      -- 전화번호 등록 여부에 따라 상태를 표시하여 조회
      SELECT name, IF(phone IS NULL, '연락처 없음', '연락처 등록') AS phone_status
      FROM member;
      ```
- CASE WHEN 조건 THEN 결과 END: 여러 개의 조건 분기를 처리할 때 사용하는 조건문
    + 문법
      ```sql
      CASE
          WHEN 조건1 THEN 결과1
          WHEN 조건2 THEN 결과2
          ELSE 기본결과
      END
      ```
    + 예시
      ```sql
      -- 회원 가입 연도에 따른 회원 등급 부여 조회
      SELECT name, created_at,
      CASE
          WHEN created_at < DATE_SUB(NOW(), INTERVAL 1 YEAR) THEN '우수 회원'
          WHEN created_at < DATE_SUB(NOW(), INTERVAL 1 MONTH) THEN '일반 회원'
          ELSE '신규 회원'
      END AS member_grade
      FROM member;
      ```

## 2.5 그룹화 및 필터링 (GROUP BY, HAVING)
- GROUP BY 절은 테이블 데이터를 지정한 열(컬럼)의 값을 기준으로 그룹화 시켜서, 그룹별로 개수나 합계 같은 통계를 구할 때 사용

### 2.5.1 그룹화 (GROUP BY)
- 지정한 컬럼이 동일한 데이터들을 그룹으로 묶어 집계 연산을 수행할 수 있도록 준비

- 그룹화가 필요한 상황
    + 무작위로 섞여서 판매된 과일 내역 테이블
      | 과일이름 | 판매수량 |
      | --- | --- |
      | 사과 | 3 |
      | 바나나 | 2 |
      | 사과 | 5 |
      | 바나나 | 1 |
      | 오렌지 | 4 |
    + 과일이름 컬럼을 기준으로 그룹을 묶는 것은 같은 과일이름끼리 각각의 상자에 나누어 담는 작업과 같음.
        - 사과 상자: [3, 5]
        - 바나나 상자: [2, 1]
        - 오렌지 상자: [4]
    + 이렇게 분류한 뒤 각 상자별 판매수량의 합계를 구하면 아래와 같이 종류별 통계가 나옴.
      | 과일이름 | 총 판매수량 |
      | --- | --- |
      | 사과 | 8 |
      | 바나나 | 3 |
      | 오렌지 | 4 |
    + 이를 SQL 문으로 작성하면 다음과 같음.
      ```sql
      SELECT 과일이름, SUM(판매수량) AS 총_판매수량
      FROM 판매테이블
      GROUP BY 과일이름;
      ```

- 문법
  ```sql
  SELECT 그룹할_컬럼명, 집계함수(컬럼명)
  FROM 테이블명
  [WHERE 조건식]
  GROUP BY 그룹할_컬럼명;
  ```

- 예시
  ```sql
  -- 각 회원(member_id)별로 작성한 게시글 개수를 세어 조회
  SELECT member_id, COUNT(*) AS post_count
  FROM post
  GROUP BY member_id;

  -- 각 게시글(post_id)별 댓글 개수 조회
  SELECT post_id, COUNT(*) AS reply_count
  FROM reply
  GROUP BY post_id;

  -- 회원별로 작성한 게시글의 수, 평균 조회수, 총 조회수 조회
  SELECT member_id, COUNT(*) AS count, AVG(view_count) AS avg_views, SUM(view_count) AS total_views
  FROM post
  GROUP BY member_id;

  -- 가입 연도별 회원 수 조회
  SELECT DATE_FORMAT(created_at, '%Y') AS join_year, COUNT(*) AS member_count
  FROM member
  GROUP BY DATE_FORMAT(created_at, '%Y');
  ```

### 2.5.2 그룹 필터링 (HAVING)
- GROUP BY를 통해 생성된 그룹 결과 집합에 대해 필터링 조건을 적용
- WHERE 절은 그룹으로 묶기 이전의 개별 원본 행을 필터링하는 조건이고, HAVING 절은 그룹화가 완료되어 집계 함수 연산이 끝난 집계 결괏값에 필터링을 적용한다는 차이가 있음
- 문법
  ```sql
  SELECT 그룹할_컬럼명, 집계함수(컬럼명)
  FROM 테이블명
  [WHERE 조건식]
  GROUP BY 그룹할_컬럼명
  HAVING 집계함수_필터조건식;
  ```
- 예시
  ```sql
  -- 게시글을 2개 이상 작성한 회원(member_id)들만 선별하여 글 개수와 함께 조회
  SELECT member_id, COUNT(*) AS post_count
  FROM post
  GROUP BY member_id
  HAVING COUNT(*) >= 2;
  ```

### 2.5.3 GROUP BY 사용 시 주의사항
#### 1) SELECT 절에는 GROUP BY에 지정한 컬럼 또는 집계 함수만 명시할 수 있음
- ONLY_FULL_GROUP_BY [^13] 모드가 활성화된 데이터베이스 환경에서는 GROUP BY로 지정되지 않은 일반 컬럼을 SELECT 절에 그대로 적을 경우 문법 에러가 발생함
- 에러의 원인과 개념적 이해
    + post(게시글) 테이블
      | member_id | title |
      | --- | --- |
      | 1 | 첫 번째 글 |
      | 1 | 두 번째 글 |
      | 2 | 질문 있습니다 |
    + GROUP BY member_id를 실행하면 결과창에는 member_id 기준으로 중복이 제거된 그룹 행(1번 그룹, 2번 그룹)이 각각 단 한 줄만 출력되어야 함
      ```sql
      -- 게시글 테이블에서 회원 id 별 작성한 게시글 수 조회
      SELECT member_id, COUNT(*) AS post_count
      FROM post
      GROUP BY member_id;
      ```
      | member_id | post_count |
          | --- | --- |
      | 1 | 2 |
      | 2 | 1 |

      ```sql
      -- 게시글 테이블에서 회원 id 별 작성한 게시글 수 조회
      SELECT member_id, COUNT(*) AS post_count, title
      FROM post
      GROUP BY member_id;
      ```
      | member_id | post_count | title |
          | --- | --- | --- |
      | 1 | 2 | 첫 번째 글??? 두 번째 글??? |
      | 2 | 1 | 질문 있습니다 |
    + SELECT 절에 title 컬럼을 적으면 데이터베이스는 1번 그룹의 결과 한 행에 '첫 번째 글'과 '두 번째 글' 중 어떤 타이틀을 매핑해야 할지 알 수 없게 됨 (선택 장애 유발)
    + 과거 구 버전이나 특정 설정 환경에서는 에러 없이 임의의 첫 번째 글을 강제로 출력해 주었으나, 이는 예측 불가능한 결과를 낳아 버그의 원인이 됨
    + 따라서 최신 RDBMS 환경에서는 ONLY_FULL_GROUP_BY가 기본 활성화되어 모호한 조회를 시도하면 문법 에러를 유발해 수정을 강제함
- 잘못된 예시
  ```sql
  -- 에러 발생: title이 GROUP BY 기준에 존재하지 않음
  SELECT member_id, COUNT(*) AS post_count, title
  FROM post
  GROUP BY member_id;
  ```
- 올바른 해결법 예시
    + 해결 방법 1: 집계 함수를 적용하여 단일 결과값으로 보장
      ```sql
      -- 해결 방법 1: 집계 함수를 적용하여 단일 결과값으로 보장
      SELECT member_id, COUNT(*) AS post_count, MAX(title) AS title
      FROM post
      GROUP BY member_id;
      ```
      | member_id | post_count | title |
          | --- | --- | --- |
      | 1 | 2 | 첫 번째 글 |
      | 2 | 1 | 질문 있습니다 |
    + 해결 방법 2: group_concat을 사용해 여러 개의 title을 하나의 텍스트로 합침
        - 문법
          ```sql
          GROUP_CONCAT([DISTINCT] 합칠_컬럼명 [ORDER BY 정렬기준] [SEPARATOR '구분자'])
          ```
            + DISTINCT: 그룹 내 중복된 값을 제거하고 합침
            + ORDER BY: 합쳐질 값들의 순서를 정렬함
            + SEPARATOR: 값들을 연결할 구분 기호를 지정함 (생략 시 기본값은 쉼표)
        - 쿼리 예시
          ```sql
          -- 해결 방법 2: group_concat을 사용해 여러 개의 title을 하나의 텍스트로 합침
          SELECT member_id, COUNT(*) AS post_count, GROUP_CONCAT(title) AS title
          FROM post
          GROUP BY member_id;
          ```
          | member_id | post_count | title |
                | --- | --- | --- |
          | 1 | 2 | 첫 번째 글,두 번째 글 |
          | 2 | 1 | 질문 있습니다 |
    + 해결 방법 3: 해당 컬럼도 GROUP BY 기준에 추가하여 공동 그룹으로 묶음
      ```sql
      SELECT member_id, title, COUNT(*) AS post_count
      FROM post
      GROUP BY member_id, title;
      ```
      | member_id | title | post_count |
          | --- | --- | --- |
      | 1 | 첫 번째 글 | 1 |
      | 1 | 두 번째 글 | 1 |
      | 2 | 질문 있습니다 | 1 |

#### 2) WHERE 절과 HAVING 절의 명확한 역할 분리
- WHERE 절과 HAVING 절은 데이터를 필터링하는 조건절이지만, 쿼리가 실행되는 시점이 다름
- 잘못된 예시
  ```sql
  -- 게시글을 2개 이상 작성한 회원의 id와 게시글 수 조회
  -- 에러 발생: 아직 그룹화되지 않은 상태인 WHERE 절에서 집계 함수 COUNT(*)를 사용하려 함
  SELECT member_id, COUNT(*)
  FROM post
  WHERE COUNT(*) >= 2
  GROUP BY member_id;
  ```
- 에러의 원인과 개념적 이해
    + 데이터베이스의 SQL 쿼리 실행 순서:
        - FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY
    + WHERE 절의 역할:
        - 그룹화를 수행하기 전, 원본 테이블의 개별 행들을 대상으로 필터링을 수행함
        - 이때는 그룹이 아직 묶이지 않은 상태이므로 COUNT(*), SUM() 등 전체 행에 대한 집계 함수를 조건식에 사용할 수 없음
    + HAVING 절의 역할:
        - GROUP BY로 그룹화가 완료되어 집계 연산이 모두 끝난 결과 집합을 대상으로 필터링을 수행함
        - 따라서 집계 함수를 사용한 조건 검사는 반드시 HAVING 절에 작성해야 함

- 올바른 해결법
  ```sql
  -- 게시글을 2개 이상 작성한 회원의 id와 게시글 수 조회 (HAVING 사용)
  SELECT member_id, COUNT(*)
  FROM post
  GROUP BY member_id
  HAVING COUNT(*) >= 2;
  ```

- 그룹화하기 전에 개별 데이터 자체를 먼저 필터링해야 하는 경우 (WHERE 사용)
  ```sql
  -- 1번 회원을 제외하고 나머지 회원들의 그룹별 작성 게시글 수 조회
  SELECT member_id, COUNT(*)
  FROM post
  WHERE member_id != 1
  GROUP BY member_id;
  ```
- 개별 데이터 필터링(WHERE)과 집계 결과 필터링(HAVING)을 모두 조합해야 하는 경우
  ```sql
  -- 2026년 6월에 작성된 게시글을 대상으로, 작성한 글 개수가 2개 이상인 회원 그룹만 조회
  SELECT member_id, COUNT(*) AS post_count
  FROM post
  WHERE DATE_FORMAT(created_at, '%Y-%m') = '2026-06'
  GROUP BY member_id
  HAVING COUNT(*) >= 2;
  ```

## 2.6 DCL (사용자 관리, 권한 조회, GRANT, REVOKE, ROLE)
- DCL(Data Control Language, 데이터 제어어)은 데이터베이스에 대한 접근 권한을 부여하거나 회수하기 위해 사용하는 명령어 집합
- 사용자 계정 생성 및 권한 관리를 통해 데이터베이스 보안을 유지하는 역할

### 2.6.1 사용자 계정 생성 (CREATE USER)
- 데이터베이스에 접속할 수 있는 새로운 사용자 계정을 생성.
- 계정 생성 시 접속 호스트[^14]와 비밀번호를 함께 지정하며, 생성 직후에는 아무런 권한이 없으므로 GRANT를 통해 필요한 권한을 별도로 부여해야 함.

- 계정 생성
    + 문법
      ```sql
      CREATE USER '사용자명'@'호스트' IDENTIFIED BY '비밀번호';
      ```
    + 호스트 지정 방식
        - localhost: 해당 서버에서만 접속 가능한 로컬 전용 계정
        - %: 모든 호스트에서 접속 가능한 원격 계정
        - 특정 IP 또는 도메인[^15]: 지정된 IP 주소나 도메인(호스트명)에서만 접속 가능한 계정
    + 예시
      ```sql
      -- 로컬 호스트 전용 계정 생성
      CREATE USER 'user1'@'localhost' IDENTIFIED BY '1111';
  
      -- 모든 호스트에서 접속 가능한 계정 생성
      CREATE USER 'user2'@'%' IDENTIFIED BY '2222';
  
      -- 특정 도메인(또는 호스트명)에서만 접속 가능한 계정 생성
      CREATE USER 'board_app'@'board.likelion.net' IDENTIFIED BY '1234';
      ```

### 2.6.2 사용자 계정 수정 (ALTER USER)
- 이미 생성된 사용자 계정의 비밀번호 등을 변경.
- 보안 정책에 따른 주기적인 비밀번호 교체 시 사용.

- 계정 수정
    + 문법
      ```sql
      ALTER USER '사용자명'@'호스트' IDENTIFIED BY '새비밀번호';
      ```
    + 예시
      ```sql
      -- user1 계정의 비밀번호를 변경
      ALTER USER 'user1'@'localhost' IDENTIFIED BY '3333';
      ```

### 2.6.3 사용자 계정 삭제 (DROP USER)
- 더 이상 사용하지 않는 계정을 데이터베이스에서 영구적으로 제거.
- 삭제된 계정에 부여된 모든 권한도 함께 소멸.

- 계정 삭제
    + 문법
      ```sql
      DROP USER '사용자명'@'호스트';
      ```
    + 예시
      ```sql
      -- user2 계정을 삭제
      DROP USER 'user2'@'localhost';
      ```

### 2.6.4 사용자 권한 조회 (SHOW GRANTS)
- 특정 사용자 계정이나 현재 접속 중인 계정에 부여된 데이터베이스 권한 목록을 조회.
- 권한을 새로 부여(GRANT)하거나 회수(REVOKE)하기 전, 기존에 설정된 권한 정보를 확인하고자 할 때 사용.

- 권한 조회
    + 문법
      ```sql
      -- 현재 접속 중인 계정의 권한 조회
      SHOW GRANTS;
  
      -- 특정 사용자 계정의 권한 조회
      SHOW GRANTS FOR '사용자명'@'호스트';
      ```
    + 예시
      ```sql
      -- 로컬 호스트 전용 계정인 user1의 권한 조회
      SHOW GRANTS FOR 'user1'@'localhost';
  
      -- 원격 계정인 board_app의 권한 조회
      SHOW GRANTS FOR 'board_app'@'board.likelion.net';
      ```

### 2.6.5 권한 부여 (GRANT)
- 데이터베이스 내 특정 객체에 대해 사용자가 작업을 수행할 수 있도록 권한을 설정.
- 조회, 삽입, 수정, 삭제 등의 개발 권한부터 테이블 생성 및 삭제 같은 관리 권한까지 계정별로 권한을 다르게 부여하여 데이터 보안을 강화.

- 권한 부여
    + 문법
      ```sql
      GRANT 권한 목록 ON 객체명 TO 사용자계정;
      ```
    + 주요 권한 유형
        - 데이터 조작 권한: SELECT, INSERT, UPDATE, DELETE (데이터의 조회, 삽입, 수정, 삭제)
        - 스키마[^6]<sup>8</sup> 및 객체 관리 권한: CREATE, DROP, ALTER (테이블 등 객체의 생성, 삭제, 구조 변경)
        - 인덱스[^16] 및 참조 권한: INDEX, REFERENCES (인덱스 생성 및 삭제, 외래 키 참조 생성)
        - 전체 권한: ALL PRIVILEGES (해당 객체에 대한 모든 권한 일괄 할당)
        - 권한 그룹(ROLE) 부여: 여러 권한을 하나의 그룹으로 묶어둔 역할(ROLE)을 사용자에게 일괄 할당
    + 객체명 지정 방식 (권한 적용 범위)
        - 글로벌 권한 (서버 내 모든 데이터베이스와 테이블): *.*
        - 데이터베이스 권한 (특정 데이터베이스 내 모든 테이블): 데이터베이스명.*
        - 테이블 권한 (특정 테이블): 데이터베이스명.테이블명 (또는 현재 활성화된 데이터베이스의 테이블명)
    + 예시
      ```sql
      -- 1) 테이블 단위 권한 부여: user1 계정에 member 테이블의 조회(SELECT) 및 삽입(INSERT) 권한 부여
      GRANT SELECT, INSERT
      ON member
      TO 'user1'@'localhost';
  
      -- 2) 데이터베이스 단위 권한 부여: user1 계정에 board_db 데이터베이스의 모든 테이블에 대한 조회 권한 부여
      GRANT SELECT
      ON board_db.*
      TO 'user1'@'localhost';
  
      -- 3) 애플리케이션 전용 계정에 CRUD 권한 부여 (특정 도메인 접속 계정)
      -- board_db 데이터베이스의 모든 테이블에 대해 조회/삽입/수정/삭제 권한 일괄 부여
      GRANT SELECT, INSERT, UPDATE, DELETE
      ON board_db.*
      TO 'board_app'@'board.likelion.net';
      ```

### 2.6.6 권한 회수 (REVOKE)
- 사용자 계정에 부여된 특정 데이터베이스 권한을 다시 거두어들임.
- 업무 범위가 변경되거나 보안상 접근을 차단해야 하는 계정에 대해 즉각적으로 실행하여 불필요한 권한 남용을 방지.

- 권한 회수
    + 문법
      ```sql
      REVOKE 권한 목록 ON 객체명 FROM 사용자계정;
      ```
    + 권한 회수 특징
        - 대상별 권한 회수: 특정 권한만 선택하여 회수하거나 ALL PRIVILEGES를 사용해 모든 권한을 동시에 박탈 가능
        - 회수 적용 시점: 회수된 권한은 해당 사용자가 다음 쿼리를 수행하여 데이터베이스 접근을 시도할 때 즉각 반영되어 차단됨
    + 예시
      ```sql
      -- 로컬 호스트의 user1 계정에 부여된 member 테이블 삽입(INSERT) 권한 회수
      REVOKE INSERT
      ON member
      FROM 'user1'@'localhost';
      ```

### 2.6.7 권한 그룹(ROLE) 관리
- 여러 사용자에게 동일한 권한을 효율적으로 부여하고 회수하기 위해 다양한 권한을 하나로 묶어둔 그룹
- 사용자와 권한 사이에 역할을 두어 관리함으로써 보안 설정의 복잡도를 낮추고 일관된 권한 관리가 가능.

- 역할 관리 흐름
    + 1. 역할 생성
    ```sql
    CREATE ROLE '역할명';
    ```
    + 2. 역할에 권한 부여
    ```sql
    GRANT 권한 목록 ON 객체명 TO '역할명';
    ```
    + 3. 사용자에게 역할 부여
    ```sql
    GRANT '역할명' TO '사용자명'@'호스트';
    ```
    + 4. 역할 활성화 (MySQL 8.0 이상에서는 역할을 부여한 후 기본 역할을 설정하거나 세션에서 활성화해야 실제 적용 가능)
    ```sql
    -- 사용자의 기본 역할로 설정하여 로그인 시 자동으로 활성화되도록 함
    SET DEFAULT ROLE '역할명' TO '사용자명'@'호스트';
    ```
    + 예시
      ```sql
      -- 개발자용 권한 그룹 생성
      CREATE ROLE 'developer';
  
      -- 개발자 그룹에 board_db의 모든 테이블에 대한 CRUD 권한 부여
      GRANT SELECT, INSERT, UPDATE, DELETE ON board_db.* TO 'developer';
  
      -- user1에게 개발자 그룹 권한 부여
      GRANT 'developer' TO 'user1'@'localhost';
  
      -- user1 로그인 시 developer 권한 그룹이 기본으로 활성화되도록 설정
      SET DEFAULT ROLE 'developer' TO 'user1'@'localhost';
      ```

# 3. 다중 테이블 조인 및 집합 연산자

## 3.1 조인이란?
- 관계형 데이터베이스는 데이터 중복을 방지하고 데이터 무결성을 유지하기 위해 테이블을 쪼개어 저장하는 정규화 과정을 거침.
- 조인(JOIN)은 이렇게 여러 테이블에 분산되어 저장된 데이터를 특정 기준(주로 기본 키와 외래 키 관계)에 따라 결합하여 하나의 결과 집합으로 조회하는 데이터베이스의 핵심 기법.

### 3.1.1 조인이 필요한 이유
- 정규화 과정에서 나누어진 테이블들을 다시 논리적으로 연결하여 완전한 하나의 정보를 얻기 위함.
- 여러 테이블의 데이터를 매번 개별 쿼리로 조회하는 대신, 단 한 번의 조인 쿼리로 처리하여 애플리케이션과 데이터베이스 간의 네트워크 비용을 줄이고 개발 생산성을 높임.
- 데이터 간의 관계를 바탕으로 복합적인 분석과 연관 데이터 조회를 효율적으로 수행할 수 있음.

### 3.1.2 작동 원리
- 데이터베이스 엔진은 조인 조건(주로 ON 절에 기술)을 기반으로 기준 테이블의 각 행에 대해 대상 테이블에서 조건에 매핑되는 행을 찾아 연결함.
- 조건과 일치하지 않는 데이터를 제외하느냐(내부 조인), 일치하지 않더라도 가져오느냐(외부 조인)에 따라 조인 방식이 달라짐.

### 3.1.3 예시 데이터를 통한 작동 원리 이해
- 게시글(post) 테이블
  | id | member_id | title | content | created_at |
  | --- | --- | --- | --- | --- |
  | 1 | 1 | 안녕하세요. | 반가워요 | 2026.06.11 |
  | 2 | 2 | 질문 있어요 | DB는 어렵나요? | 2026.06.11 |
  | 3 | 1 | 두번째 게시글 | 오늘 날씨가 좋네요 | 2026.06.11 |
  | 4 | [NULL] | MySQL 설치 오류가 났어요 | 어떻게 할까요? | 2026.06.11 |

- 회원(member) 테이블
  | id | email | password | name | created_at |
  | --- | --- | --- | --- | --- |
  | 1 | `haru@gmail.com` | 123 | 하루 | 2026.06.09 |
  | 2 | `namu@gmail.com` | 234 | 나무 | 2026.06.10 |
  | 3 | `yong@gmail.com` | 345 | 용쌤 | 2026.06.10 |

위의 게시글(post) 테이블과 회원(member) 테이블을 기준으로, 게시글의 작성자 아이디(member_id)와 회원의 아이디(id)를 매칭하는 조인 연산(post.member_id = member.id)의 상세 작동 방식은 다음과 같음.

- 매칭 조건 및 대상 확인
    + 기준 데이터 확인: 게시글 테이블의 1, 2, 3번 행은 작성자 아이디가 각각 1, 2, 1로 회원 테이블의 아이디와 매칭됨.
    + 불일치 데이터 확인: 게시글 테이블의 4번 행은 작성자 아이디가 존재하지 않아 회원 테이블과 매칭되지 않음. 회원 테이블의 3번 회원(용쌤)은 작성한 게시글이 없어 게시글 테이블과 매칭되지 않음.

- 내부 조인(INNER JOIN) 수행 시 작동
    + 1단계: 게시글 1번 행(작성자 1)과 회원 1번 행(하루)을 결합하여 결과에 포함.
    + 2단계: 게시글 2번 행(작성자 2)과 회원 2번 행(나무)을 결합하여 결과에 포함.
    + 3단계: 게시글 3번 행(작성자 1)과 회원 1번 행(하루)을 결합하여 결과에 포함.
    + 4단계: 게시글 4번 행(작성자 없음)과 회원 3번 행(게시글 없음)은 서로 매칭되지 않으므로 결과 집합에서 완전히 제외됨.
    + 최종 결과 테이블
      | id | member_id | title | content | created_at | id | email | password | name | created_at |
      | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
      | 1 | 1 | 안녕하세요. | 반가워요 | 2026.06.11 | 1 | `haru@gmail.com` | 123 | 하루 | 2026.06.09 |
      | 2 | 2 | 질문 있어요 | DB는 어렵나요? | 2026.06.11 | 2 | `namu@gmail.com` | 234 | 나무 | 2026.06.10 |
      | 3 | 1 | 두번째 게시글 | 오늘 날씨가 좋네요 | 2026.06.11 | 1 | `haru@gmail.com` | 123 | 하루 | 2026.06.09 |

- 왼쪽 외부 조인(LEFT OUTER JOIN) 수행 시 작동
    + 1~3단계: 내부 조인과 동일하게 매칭되는 1, 2, 3번 게시글 행을 결합하여 결과에 포함.
    + 4단계: 매칭되는 회원이 없는 4번 게시글 행도 결과에 포함시키고, 비어 있는 회원 정보 컬럼(이름, 이메일 등)은 NULL로 채워 넣음.
    + 최종 결과 테이블
      | id | member_id | title | content | created_at | id | email | password | name | created_at |
      | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
      | 1 | 1 | 안녕하세요. | 반가워요 | 2026.06.11 | 1 | `haru@gmail.com` | 123 | 하루 | 2026.06.09 |
      | 2 | 2 | 질문 있어요 | DB는 어렵나요? | 2026.06.11 | 2 | `namu@gmail.com` | 234 | 나무 | 2026.06.10 |
      | 3 | 1 | 두번째 게시글 | 오늘 날씨가 좋네요 | 2026.06.11 | 1 | `haru@gmail.com` | 123 | 하루 | 2026.06.09 |
      | 4 | [NULL] | MySQL 설치 오류가 났어요 | 어떻게 할까요? | 2026.06.11 | [NULL] | [NULL] | [NULL] | [NULL] | [NULL] |

- 오른쪽 외부 조인(RIGHT OUTER JOIN) 수행 시 작동
    + 1~3단계: 내부 조인과 동일하게 매칭되는 1, 2, 3번 게시글 행을 결합하여 결과에 포함.
    + 4단계: 작성한 게시글이 없는 3번 회원(용쌤) 행도 결과에 포함시키고, 비어 있는 게시글 정보 컬럼(제목, 내용 등)은 NULL로 채워 넣음.
    + 최종 결과 테이블
      | id | member_id | title | content | created_at | id | email | password | name | created_at |
      | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
      | 1 | 1 | 안녕하세요. | 반가워요 | 2026.06.11 | 1 | `haru@gmail.com` | 123 | 하루 | 2026.06.09 |

      | 3 | 1 | 두번째 게시글 | 오늘 날씨가 좋네요 | 2026.06.11 | 1 | `haru@gmail.com` | 123 | 하루 | 2026.06.09 |
      | [NULL] | [NULL] | [NULL] | [NULL] | [NULL] | 3 | `yong@gmail.com` | 345 | 용쌤 | 2026.06.10 |


## 3.2 INNER JOIN (내부 조인)
- 두 테이블에서 조인 조건이 일치하는 행만 결과에 포함.
- 양쪽 테이블 모두에 매칭되는 데이터가 존재하는 경우에만 결과로 반환되며, 어느 한쪽에라도 대응되는 값이 없으면 해당 행은 결과에서 제외.

- 내부 조인
    + 문법
      ```sql
      SELECT 컬럼목록
      FROM 테이블A
      INNER JOIN 테이블B ON 테이블A.컬럼 = 테이블B.컬럼;
  
      -- 별칭(Alias) 사용 시 (선택사항)
      SELECT 컬럼목록
      FROM 테이블A [AS] a
      INNER JOIN 테이블B [AS] b ON a.컬럼 = b.컬럼;
      ```
    + 예시
      ```sql
      -- 게시글과 작성자 정보를 함께 조회 (회원 정보가 존재하는 게시글만 조회됨)
      SELECT post.id, post.title, member.name AS writer_name, post.created_at
      FROM post
      INNER JOIN member ON post.member_id = member.id;
  
      -- 별칭(Alias) 사용 시 (선택사항)
      SELECT p.id, p.title, m.name AS writer_name, p.created_at
      FROM post p
      INNER JOIN member m ON p.member_id = m.id;
  
      -- 댓글과 작성자, 원본 게시글 제목을 함께 조회
      SELECT reply.id, reply.content, member.name AS writer_name, post.title AS post_title
      FROM reply
      INNER JOIN member ON reply.member_id = member.id
      INNER JOIN post ON reply.post_id = post.id;
      ```

## 3.3 OUTER JOIN (외부 조인)
- 조인 조건이 일치하지 않아도 한쪽 또는 양쪽 테이블의 데이터를 포함하여 결과를 생성하는 기법.

### 3.3.1 LEFT OUTER JOIN (왼쪽 외부 조인)
- 왼쪽 테이블의 모든 행을 결과에 포함하고, 오른쪽 테이블에 매칭되는 데이터가 없으면 NULL로 채워서 반환.
- 데이터가 없는 쪽도 빠짐없이 확인해야 할 때 사용.

- 왼쪽 외부 조인
    + 문법
      ```sql
      SELECT 컬럼목록
      FROM 테이블A
      LEFT [OUTER] JOIN 테이블B ON 테이블A.컬럼 = 테이블B.컬럼;
  
      -- 별칭(Alias) 사용 시 (선택사항)
      SELECT 컬럼목록
      FROM 테이블A [AS] a
      LEFT [OUTER] JOIN 테이블B [AS] b ON a.컬럼 = b.컬럼;
      ```
    + 예시
      ```sql
      -- 전체 회원 목록과 각 회원이 작성한 게시글 수 조회 (게시글을 작성하지 않은 회원도 포함)
      SELECT member.id, member.name, COUNT(post.id) AS post_count
      FROM member
      LEFT JOIN post ON member.id = post.member_id
      GROUP BY member.id, member.name;
  
      -- 전체 회원 목록과 각 회원이 작성한 게시글 수 조회 (게시글을 작성하지 않은 회원도 포함)
      -- 별칭(Alias) 사용 시
      SELECT m.id, m.name, COUNT(p.id) AS post_count
      FROM member m
      LEFT JOIN post p ON m.id = p.member_id
      GROUP BY m.id, m.name;
  
      -- 전체 게시글 목록과 댓글 수 조회 (댓글이 없는 게시글도 포함하여 0으로 표시)
      SELECT post.id, post.title, COUNT(reply.id) AS reply_count
      FROM post
      LEFT JOIN reply ON post.id = reply.post_id
      GROUP BY post.id, post.title;
  
      -- 게시글과 작성자 정보를 함께 조회 (회원 정보 없는 게시글도 조회됨)
      SELECT p.id, p.title, IFNULL(m.name, '익명') AS writer_name, p.created_at
      FROM post p
      LEFT JOIN member m ON p.member_id = m.id;
      ```

### 3.3.2 RIGHT OUTER JOIN (오른쪽 외부 조인)
- LEFT JOIN과 반대로 오른쪽 테이블의 모든 행을 결과에 포함하고, 왼쪽 테이블에 매칭되는 데이터가 없으면 NULL로 채워서 반환.
- LEFT JOIN에서 테이블 순서를 바꾼 것과 동일한 결과를 얻을 수 있어, 실무에서는 가독성을 위해 LEFT JOIN을 주로 사용.

- 오른쪽 외부 조인
    + 문법
      ```sql
      SELECT 컬럼목록
      FROM 테이블A
      RIGHT [OUTER] JOIN 테이블B ON 테이블A.컬럼 = 테이블B.컬럼;
      ```
    + 예시
      ```sql
      -- 전체 회원 목록과 게시글 정보 조회 (게시글이 없는 회원도 포함)
      SELECT m.id AS member_id, m.name, p.title
      FROM post p
      RIGHT JOIN member m ON p.member_id = m.id;
  
      -- LEFT JOIN으로 post, member의 위치를 바꿔서 작성한 것과 동일한 결과
      SELECT m.id AS member_id, m.name, p.title
      FROM member m
      LEFT JOIN post p ON p.member_id = m.id;
      ```

### 3.3.3 FULL OUTER JOIN (전체 외부 조인)
- 양쪽 테이블의 모든 행을 결과에 포함하며, 매칭되는 상대 테이블 데이터가 없으면 NULL로 채워서 반환.
- MySQL의 특징 및 우회 방법
    + MySQL 데이터베이스 엔진은 FULL OUTER JOIN 문법을 직접 지원하지 않음.
    + 따라서 LEFT JOIN 결과와 RIGHT JOIN 결과를 UNION (중복 제거 합집합) 연산자로 결합하여 전체 외부 조인을 우회 구현함.

- 전체 외부 조인 우회 구현
    + 문법
      ```sql
      SELECT 컬럼목록 FROM 테이블A LEFT JOIN 테이블B ON 조인조건
      UNION
      SELECT 컬럼목록 FROM 테이블A RIGHT JOIN 테이블B ON 조인조건;
      ```
    + 예시
      ```sql
      -- 전체 회원 목록과 전체 게시글 정보를 누락 없이 결합하여 조회
      -- (게시글이 없는 회원과 작성자가 NULL인 게시글 모두 출력됨)
      SELECT m.id AS member_id, m.name, p.title
      FROM member m
      LEFT JOIN post p ON m.id = p.member_id
      UNION
      SELECT m.id AS member_id, m.name, p.title
      FROM member m
      RIGHT JOIN post p ON m.id = p.member_id;
      ```

## 3.4 SELF JOIN (자체 조인)
- 하나의 테이블을 자기 자신과 조인하여 관련 정보를 연결하는 기법.
- 특징
    + 동일한 테이블이 조인에 참여하므로, 구분을 위해 반드시 각 가상 테이블에 서로 다른 별칭(Alias)을 정의해야 함.
    + 상위 카테고리-하위 카테고리 구조나 조직 내 사원-상사 관계, 댓글에 대한 대댓글 등 동일 테이블 내에 계층형 데이터가 존재할 때 유용함.
- 예시
    +  member 테이블 수정
    ```sql
    -- member 테이블에 recommender_id(추천인 번호) 컬럼 추가
    ALTER TABLE member ADD COLUMN recommender_id INT;

    -- 자기 자신의 id를 참조하는 외래 키(FK) 제약조건 설정
    ALTER TABLE member ADD CONSTRAINT fk_member_recommender 
      FOREIGN KEY (recommender_id) REFERENCES member(id) ON DELETE SET NULL;
    ```

    + 추천인 정보 수정
      ```sql
      -- 나무(id=2) 회원의 추천인을 하루(id=1)로 등록
      UPDATE member SET recommender_id = 1 WHERE id = 2;
  
      -- 용쌤(id=3) 회원의 추천인을 나무(id=2)로 등록
      UPDATE member SET recommender_id = 2 WHERE id = 3;
      ```

    + 회원 이름과 그 회원을 추천한 추천인의 이름을 함께 조회
      ```sql
      -- 회원 이름과 그 회원을 추천한 추천인의 이름을 함께 조회
      SELECT m.name AS member_name, r.name AS recommender_name
      FROM member m
      INNER JOIN member r ON m.recommender_id = r.id;
      ```

## 3.5 집합 연산자 (UNION, UNION ALL)
- 여러 개의 SELECT 문 실행 결과를 하나의 결과 집합으로 결합(합집합)할 때 사용하는 연산자.
- 두 쿼리의 결합 조건
    + 결합하려는 모든 SELECT 문의 컬럼 개수가 일치해야 함.
    + 상응하는 컬럼들의 데이터 타입이 서로 호환 가능해야 함 (순서와 타입 매칭 필수).

### 3.5.1 UNION (중복 제거 합집합)
- 결합된 결과에서 중복된 행을 제거하고 고유한 행만 반환함.
- 내부적으로 중복을 제거하기 위한 정렬 작업(Sort)이 수행되므로, 대량 데이터 환경에서는 성능 저하가 발생할 수 있음.
- 사용 사례
    + 회원 테이블과 관리자 테이블의 모든 이메일 목록 추출
    + 오래된 주문 데이터를 백업 테이블에 보관할 경우 전체 주문 이력을 확인

- 문법
  ```sql
  SELECT 컬럼1, 컬럼2 FROM 테이블A
  UNION
  SELECT 컬럼1, 컬럼2 FROM 테이블B;
  ```
- 예시
  ```sql
  -- 하루가 작성한 게시글의 제목과 나무가 작성한 게시글의 제목을 합하여 조회 (중복 제목은 제거됨)
  SELECT title
  FROM post
  WHERE member_id = 1
  UNION
  SELECT title
  FROM post
  WHERE member_id = 2;
  ```

### 3.5.2 UNION ALL (중복 포함 합집합)
- 중복 제거 작업 없이, 결합된 모든 SELECT 문의 결과를 있는 그대로 합쳐서 반환.
- 정렬이나 중복 검사 로직이 없으므로 UNION보다 연산 속도가 훨씬 빠르며, 중복 데이터도 그대로 조회하거나 중복이 발생하지 않는 쿼리 결합 시 사용을 권장.

- 문법
  ```sql
  SELECT 컬럼1, 컬럼2 FROM 테이블A
  UNION ALL
  SELECT 컬럼1, 컬럼2 FROM 테이블B;
  ```
- 예시
  ```sql
  -- 하루와 나무가 작성한 게시글의 모든 제목 조회 (동일한 제목이 있더라도 중복 출력됨)
  SELECT title
  FROM post
  WHERE member_id = 1
  UNION ALL
  SELECT title
  FROM post
  WHERE member_id = 2;
  ```

# 4. 서브쿼리(Subquery) 활용
- 하나의 SQL 문 내부에 포함된 또 다른 SELECT 문을 의미
- 복잡한 조건이나 중간 연산 결과를 활용해야 하는 상황에서, 쿼리를 중첩하여 단계적으로 데이터를 추출하는 기법

## 4.1 WHERE 절 서브쿼리
- 조건식 내부에 서브쿼리를 삽입하여 동적으로 산출된 값을 필터 기준으로 활용.
- 서브쿼리가 반환하는 결과의 형태(단일 값, 목록)에 따라 비교 연산자 또는 IN 연산자와 결합하여 사용.

- 예시 1 (단일 행 서브쿼리: 가장 오래전에 가입한 회원의 정보 조회)
    + 서브쿼리가 반환하는 결과가 단 1개(1행 1열)이므로 일반 비교 연산자(=)를 사용
  ```sql
  -- 가장 오래된 가입일자 조회 (서브쿼리 결과: 2026.06.16 10:12:34)
  SELECT MIN(created_at) FROM member;

  -- 가장 오래전에 가입한 회원의 상세 정보 조회
  SELECT id, email, name, created_at
  FROM member
  WHERE created_at = (SELECT MIN(created_at) FROM member);
  ```

- 예시 2 (다중 행 서브쿼리: 게시글을 한 건이라도 작성한 회원의 정보 조회)
    + 서브쿼리가 반환하는 결과가 여러 개(회원 id 목록)이므로 IN 연산자를 사용
  ```sql
  -- 게시글을 작성한 회원들의 중복 없는 id 목록 조회 (서브쿼리 결과: 1, 2, 3, 4, 5)
  SELECT DISTINCT member_id FROM post WHERE member_id IS NOT NULL;

  -- 게시글을 한 건이라도 작성한 회원의 정보 조회
  SELECT id, email, name, created_at
  FROM member
  WHERE id IN (SELECT DISTINCT member_id FROM post WHERE member_id IS NOT NULL);
  ```

## 4.2 스칼라 서브쿼리
- SELECT 절 내부에 서브쿼리를 삽입하여 각 행마다 하나의 단일 값을 계산하여 반환.
- 조인 없이 다른 테이블의 요약 정보를 컬럼 형태로 함께 조회하고자 할 때 활용.

- 예시 1 (각 게시글과 함께 해당 게시글의 댓글 수 조회)
  ```sql
  -- 조인으로 처리할 경우 (댓글이 없는 게시글도 포함하기 위해 LEFT JOIN 활용)
  SELECT p.id, p.title, COUNT(r.id) AS reply_count
  FROM post p
  LEFT JOIN reply r ON p.id = r.post_id
  GROUP BY p.id, p.title;

  -- 1단계: 기준이 되는 게시글 기본 정보 조회
  SELECT id, title FROM post;

  -- 2단계: 특정 게시글(예: id = 1)의 댓글 개수 집계
  SELECT COUNT(*) FROM reply WHERE post_id = 1;

  -- 3단계: 메인 쿼리의 SELECT 절에 서브쿼리를 삽입하여 결합
  SELECT p.id, p.title,
      (SELECT COUNT(*) FROM reply r WHERE r.post_id = p.id) AS reply_count
  FROM post p;
  ```

- 예시 2 (각 회원과 함께 해당 회원이 작성한 게시글 수 조회)
  ```sql
  -- 조인으로 처리할 경우 (작성한 게시글이 없는 회원도 포함하기 위해 LEFT JOIN 활용)
  SELECT m.id, m.name, COUNT(p.id) AS post_count
  FROM member m
  LEFT JOIN post p ON m.id = p.member_id
  GROUP BY m.id, m.name;

  -- 1단계: 기준이 되는 회원 기본 정보 조회
  SELECT id, name FROM member;

  -- 2단계: 특정 회원(예: id = 1)의 게시글 작성 수 집계
  SELECT COUNT(*) FROM post WHERE member_id = 1;

  -- 3단계: 메인 쿼리의 SELECT 절에 서브쿼리를 삽입하여 결합
  SELECT m.id, m.name,
      (SELECT COUNT(*) FROM post p WHERE p.member_id = m.id) AS post_count
  FROM member m;
  ```

## 4.3 FROM 절 서브쿼리 (인라인 뷰)
- FROM 절에 서브쿼리를 삽입하여 가상의 임시 테이블을 생성하고, 이를 대상으로 추가적인 조회를 수행.
- FROM 절 서브쿼리 사용 시 별칭(Alias) 지정은 필수
    + 데이터베이스 엔진은 FROM 절에 삽입된 서브쿼리를 하나의 독립된 가상 테이블(파생 테이블)로 취급
    + 가상 테이블에 식별용 이름(별칭)을 명시하지 않으면 바깥쪽의 메인 쿼리에서 서브쿼리 내부의 컬럼들을 참조하여 접근할 수 없음.
    + 별칭을 지정하지 않고 실행할 경우 구문 에러가 발생
- 예시 (게시글을 한 건이라도 작성한 회원의 평균 게시글 수보다 많은 글을 작성한 회원 조회)
  ```sql
  -- 게시글을 작성한 회원들의 중복 없는 id 목록 조회 (서브쿼리 결과: 1, 2, 3, 4, 5)
  SELECT DISTINCT member_id FROM post WHERE member_id IS NOT NULL;

  -- 게시글을 한 건이라도 작성한 회원별 게시글 수 조회
  SELECT member_id, COUNT(*) AS cnt 
  FROM post 
  WHERE member_id IS NOT NULL 
  GROUP BY member_id;

  -- 게시글을 한 건이라도 작성한 회원의 평균 게시글 수 조회
  SELECT AVG(cnt) 
  FROM (
    SELECT COUNT(*) AS cnt 
    FROM post 
    WHERE member_id IS NOT NULL 
    GROUP BY member_id
  ) AS sub;

  -- 게시글을 한 건이라도 작성한 회원의 평균 게시글 수보다 많은 글을 작성한 회원 조회
  SELECT member_id, COUNT(*) AS post_count
  FROM post
  GROUP BY member_id
  HAVING COUNT(*) > (
    SELECT AVG(cnt) 
    FROM (
      SELECT COUNT(*) AS cnt 
      FROM post 
      WHERE member_id IS NOT NULL 
      GROUP BY member_id
    ) AS sub
  );
  ```

## 4.4 EXISTS 서브쿼리
- 서브쿼리의 결과가 한 건이라도 존재하면 참(TRUE)을 반환하는 조건 연산자.
- IN 연산자와 유사한 역할을 수행하지만, 대량 데이터 환경에서 서브쿼리의 존재 여부만 판단하므로 성능상 유리한 경우가 있음.

- EXISTS 서브쿼리
    + 예시
      ```sql
      -- 게시글을 한 건이라도 작성한 회원만 조회 (EXISTS 사용)
      SELECT m.id, m.name, m.email
      FROM member m
      WHERE EXISTS (SELECT 1 FROM post p WHERE p.member_id = m.id);
  
      -- 댓글이 달린 게시글만 조회 (NOT EXISTS로 반대 조건도 가능)
      SELECT p.id, p.title
      FROM post p
      WHERE EXISTS (SELECT 1 FROM reply r WHERE r.post_id = p.id);
  ```

# 5. 게시판 데이터베이스 스키마 작성
- DDL, DML, 조인, 서브쿼리 등 앞서 학습한 개념을 종합하여 실제 게시판 서비스의 테이블 구조를 설계하고 데이터를 조작하는 실습

## 5.1 게시판 요구사항 정의
### 5.1.1 회원(member) 요구사항
- 회원은 고유한 식별자(id)를 가지며 자동으로 1씩 증가하도록 설정.
- 로그인에 사용되는 이메일(email)은 필수 항목이며 데이터베이스 전체에서 중복될 수 없음 (최대 100자).
- 비밀번호(password)와 이름(name)은 필수로 입력받음 (비밀번호 최대 255자, 이름 최대 50자).
- 연락처(phone)는 입력 여부가 선택 사항임 (고정 12자).
- 가입 시 추천한 추천인 정보가 기록되어야 하며, 회원 테이블의 식별자(id)를 외래 키(recommender_id)로 참조. 추천인이 탈퇴할 경우 해당 추천인 번호 영역은 빈 값(NULL)으로 변경됨 (recommender_id 컬럼은 NULL 입력을 허용).
- 회원의 가입일(created_at)은 데이터가 저장되는 시점의 날짜와 시간이 자동으로 기록됨.

### 5.1.2 게시글(post) 요구사항
- 게시글은 고유한 식별자(id)를 가지며 자동으로 1씩 증가하도록 설정.
- 게시글에는 작성자 정보가 기록되어야 하며, 회원 테이블의 식별자(id)를 외래 키(member_id)로 참조.
- 회원이 탈퇴하더라도 그가 작성했던 게시글은 지워지지 않고 보존되며, 작성자 정보 영역만 빈 값(NULL)으로 변경됨 (이를 위해 member_id 컬럼은 NULL 입력을 허용).
- 게시글 제목(title)과 게시글 본문(content)은 필수로 입력받음 (제목 최대 200자, 본문 TEXT).
- 게시글 조회수(view_count)는 필수로 입력받으며 기본값은 0으로 지정 (4바이트 정수형).
- 게시글 작성일(created_at)은 저장 당시의 일시가 자동으로 기록됨.

### 5.1.3 댓글(reply) 요구사항
- 댓글은 고유한 식별자(id)를 가지며 자동으로 1씩 증가하도록 설정.
- 댓글은 특정 게시글에 종속되므로, 게시글 테이블의 식별자(id)를 외래 키(post_id)로 참조하며 필수값으로 규정.
- 댓글은 작성자 정보가 필요하므로, 회원 테이블의 식별자(id)를 외래 키(member_id)로 참조하며 필수값으로 규정.
- 댓글 본문(content)은 필수로 입력받음 (본문 TEXT).
- 댓글이 달린 원본 게시글이 삭제되거나 작성한 회원이 탈퇴하면 관련 댓글 데이터는 함께 영구적으로 자동 삭제됨.
- 댓글 작성일(created_at)은 저장 당시의 일시가 자동으로 기록됨.

- 예시
  ```sql
  -- 1. 게시글 목록 조회 (작성자 이름, 댓글 수 포함, 최신 등록순 정렬)
  SELECT p.id, m.name, p.view_count, COUNT(r.id) reply_count, p.created_at, p.title
  FROM post p
  LEFT JOIN MEMBER m ON p.member_id = m.id
  LEFT JOIN reply r ON p.id = r.post_id
  GROUP BY p.id, p.title, m.name, p.view_count, p.created_at
  ORDER BY p.created_at DESC;

  -- 작성한지 24시간 이내의 게시글 제목 앞에 (New) 추가
  -- 댓글이 3개 이상 달린 게시글 제목 앞에 (Best) 추가
  SELECT p.id, m.name, p.view_count, COUNT(r.id) reply_count, p.created_at, 
    CONCAT(
      CASE WHEN p.created_at >= DATE_SUB(NOW(), INTERVAL 1 DAY) THEN '(New) ' ELSE '' END,
      CASE WHEN COUNT(r.id) >= 3 THEN '(Best) ' ELSE '' END,
      p.title
    ) title
  FROM post p
  LEFT JOIN MEMBER m ON p.member_id = m.id
  LEFT JOIN reply r ON p.id = r.post_id
  GROUP BY p.id, p.title, m.name, p.view_count, p.created_at
  ORDER BY p.created_at DESC;

  -- 2. 게시글 상세 조회 (게시글 제목, 내용, 작성자 이름, 이메일, 댓글 작성자 이름, 댓글 내용 조회)
  SELECT
    p.title,
    p.content,
    m.name writer_name,
    m.email writer_email,
    rm.name reply_writer_name,
    r.content reply_content
  FROM post p
  LEFT JOIN member m ON p.member_id = m.id
  LEFT JOIN reply r ON p.id = r.post_id
  LEFT JOIN member rm ON r.member_id = rm.id
  WHERE p.id = 1
  ORDER BY r.created_at DESC;

  -- 3. 게시글 등록 (새로운 게시글 작성)
  INSERT INTO post (member_id, title, content)
  VALUES (1, '새로운 게시글 제목', '새로운 게시글 내용입니다.');

  -- 4. 게시글 수정 (2번 게시글의 제목과 내용 변경)
  UPDATE post
  SET title = '수정된 제목', content = '수정된 내용입니다.'
  WHERE id = 2;

  -- 5. 게시글 삭제 (3번에서 등록한 게시글 삭제)
  DELETE FROM post
  WHERE id = 21;

  -- 6. 게시글 검색 (제목 또는 내용에 '자바'가 포함된 게시글 조회)
  SELECT p.id, m.name, p.view_count, COUNT(r.id) reply_count, p.created_at, 
    CONCAT(
      CASE WHEN p.created_at >= DATE_SUB(NOW(), INTERVAL 1 DAY) THEN '(New) ' ELSE '' END,
      CASE WHEN COUNT(r.id) >= 3 THEN '(Best) ' ELSE '' END,
      p.title
    ) title

  LEFT JOIN MEMBER m ON p.member_id = m.id

  WHERE p.title LIKE '%자바%' OR p.content LIKE '%자바%'
  GROUP BY p.id, p.title, m.name, p.view_count, p.created_at
  ORDER BY p.created_at DESC;
  ```

# 각주
[^1]: 비휘발성(Non-volatile): 컴퓨터 전원이 차단되어도 저장된 데이터가 사라지지 않고 영구적으로 유지되는 성질로, 주로 하드디스크나 SSD 등의 보조기억장치가 이에 해당함
[^2]: 일관성(Consistency): 데이터가 여러 테이블이나 서로 다른 위치에서 조회되었을 때 상호 모순이 없는 성질을 의미함. 예컨대 회원이 지워졌는데 주문 기록에는 유령 회원의 주문 내역이 여전히 남아 있는 데이터 간의 어긋남을 방지하는 시스템 정합성을 뜻함
[^3]: 데이터 종속성(Data Dependency): 데이터 보관 구조가 변경될 때 이를 이용하는 애플리케이션의 소스 코드도 함께 수정해야 하는 물리적 의존성 상태를 의미함
[^4]: 무결성(Integrity): 데이터 자체가 설계된 올바른 규칙에 부합하여 잘못된 값이 저장소에 들어오는 것을 방지하는 성질을 의미함. 예컨대 나이는 음수가 될수 없는데 음수가 저장 되거나 필수값이어야 하는 데이터가 비어있는 등의 상태는 무결성이 깨진 상태
[^5]: 동시성 제어(Concurrency Control): 다중 사용자 환경에서 여러 사용자가 동시에 동일한 데이터에 접근하여 갱신을 시도할 때, 데이터의 무결성과 일관성을 해치지 않도록 제어하는 기술
[^6]: 스키마(Schema): 데이터베이스 구조, 데이터 타입, 테이블 간의 관계와 제약조건 등을 통합적으로 정의하는 명세서
[^7]: 조인(JOIN): 관계형 데이터베이스에서 여러 테이블의 데이터 행을 서로 연결하여 하나의 통합된 결과 집합으로 조회하는 연산
[^8]: 트래픽(Traffic): 네트워크를 통해 전송되는 데이터 전송량이나 흐름을 뜻하며, 시스템이 처리해야 하는 통신 데이터의 양을 의미
[^9]: 수평 확장(Scale-out): 서버 한 대의 성능을 높이는 대신, 여러 대의 서버를 추가하여 분산 처리 능력을 키우는 인프라 확장 기법
[^10]: 트랜잭션(Transaction): 데이터베이스 상태를 변화시키는 하나의 논리적인 작업 단위를 뜻하며, 완벽하게 성공하거나 완전히 실패해야 하는 분할할 수 없는 일련의 연산 과정
[^11]: UTC(Coordinated Universal Time): 세슘 원자 진동수를 기준으로 정밀하게 측정된 세계 협정 표준시로, 한국 시간(KST)보다 9시간 느린 국제 표준 타임존
[^12]: 롤백(Rollback): 데이터베이스 트랜잭션 처리 중 오류가 발생하거나 작업을 취소하고자 할 때, 데이터 상태를 이전의 정상적인 상태로 되돌리는 연산을 뜻함
[^13]: ONLY_FULL_GROUP_BY: MySQL 등 RDBMS에서 GROUP BY 절에 지정하지 않은 일반 컬럼을 SELECT 절에 집계 함수 없이 사용하지 못하도록 제한하여, 그룹화 시 모호한 데이터가 임의로 출력되는 문제를 미연에 방지하는 문법 모드
[^14]: 호스트(Host): 네트워크에 연결되어 고유한 IP 주소를 가지고 다른 장치와 데이터를 주고받는 컴퓨터나 서버 등의 개별 장치
[^15]: 도메인(Domain): 숫자로 된 IP 주소를 사람이 기억하기 쉬운 문자 형태로 표현한 네트워크 상의 컴퓨터 주소(예: board.likelion.net)
[^16]: 인덱스(Index): 데이터베이스 테이블의 검색 속도를 향상시키기 위해 특정 컬럼을 기준으로 생성하는 색인 및 탐색 구조
[^17]: 정규화(Normalization): 데이터베이스 설계 시 데이터 중복을 최소화하고 일관성을 보장하기 위해 테이블을 구조적으로 분할하는 과정
