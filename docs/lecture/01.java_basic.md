# 1. 프로그래밍의 이해

## 1.1 프로그래밍이란?
- 프로그램이란 컴퓨터에 내리는 명령의 집합이고 이를 만드는 과정을 프로그래밍이라고 함
- 컴퓨터의 CPU는 0과 1로 이루어진 기계어만 이해할 수 있는 단순한 연산 장치
- 컴퓨터에게 명령을 내리기 위해 인간이 0과 1로 구성된 기계어를 직접 작성하기는 매우 어렵기 때문에 인간이 이해하기 쉽도록 인간의 언어와 유사한 프로그래밍 언어(고급 언어)를 만들어서 사용
- 대표적인 프로그래밍 언어로 C, Java, Python, Javascript 등이 있음
- 고급 언어로 만들어진 코드를 `소스 코드`라고 함
- 소스 코드는 인간이 이해 가능하지만 컴퓨터가 이해할 수 없으므로 컴퓨터가 이해할 수 있는 `기계어`로 변환해야 하는데 이 과정을 컴파일 또는 인터프리팅이라 함

## 1.2 컴파일러와 인터프리터
- 컴파일: 개발자가 작성한 소스 코드를 컴퓨터가 이해할 수 있는 기계어로 한 번에 번역하는 과정
- 컴파일러: 컴파일을 수행하는 프로그램
- 인터프리팅: 소스 코드를 한 줄씩 읽어가며 기계어로 즉석에서 번역하는 과정
- 인터프리터: 인터프리팅을 수행하고 그 결과를 즉시 실행하는 프로그램

## 1.3 컴파일러 언어 vs. 인터프리터 언어
### 1.3.1 컴파일러(Compiler) 언어
- 코드를 실행하기 전, 전체 소스 코드를 한 번에 기계어로 변환(컴파일)하여 실행 파일을 만드는 방식
- 특징
  + 실행 속도가 매우 빠르지만, 코드를 수정할 때마다 다시 컴파일해야 하므로 개발 속도는 상대적으로 느릴 수 있음
  + CPU 아키텍처마다 사용하는 명령어 집합이 다르기 때문에 그에 맞게 기계어가 생성되어야 하고, 프로그램이 메모리를 할당받거나 화면에 글자를 출력할 때 OS에 요청을 보내는 시스템 콜[^1]이 OS마다 다름. 결과적으로 컴파일된 결과물은 특정 플랫폼(CPU + OS)[^2]에 종속됨
- 대표적인 언어
  + C / C++: 시스템 프로그래밍이나 게임 엔진 개발에 주로 쓰이며 성능이 매우 강력함
  + Rust: 메모리 안전성을 보장하면서도 C++에 준하는 성능을 내어 최근 각광받고 있음
  + Go (Golang): 구글에서 개발했으며, 컴파일 속도가 빠르고 병렬 처리에 강점이 있음

### 1.3.2 인터프리터(Interpreter) 언어
- 코드를 실행할 때 전체를 미리 번역하지 않고, 한 줄씩 읽어가며 즉석에서 기계어로 번역과 실행을 동시에 수행하는 방식
- 특징
  + 실행 파일을 미리 만들지 않으므로 코드를 수정한 후 즉각적인 확인이 가능해 개발 속도가 빠름
  + 코드를 실행할 때마다 매번 번역을 거쳐야 하므로 컴파일러 언어에 비해 실행 속도는 상대적으로 느림
  + 각 운영체제에 맞는 인터프리터만 설치되어 있으면 동일한 코드를 어디서든 실행할 수 있어 플랫폼[^2]에 독립적
- 대표적인 언어
  + Python: 문법이 직관적이고 간결하여 기초 교육부터 데이터 분석, 인공지능 분야까지 폭넓게 쓰임
  + JavaScript: 웹 브라우저에서 동작하는 유일한 언어로 시작해, 현재는 프론트엔드와 백엔드를 아우르는 거대한 생태계를 가짐
  + Ruby: 개발자의 생산성을 극대화하는 데 초점을 맞춘 언어로, 웹 프레임워크인 Ruby on Rails를 통해 널리 쓰임

### 1.3.3 하이브리드(Hybrid) 언어
- 소스 코드를 바이트코드(중간어)[^3]로 1차 컴파일한 뒤, 실행 시점에 가상 머신(VM)[^4]을 통해 기계어로 번역하며 실행하는 혼합 방식
- 특징
  + 컴파일 단계를 통해 실행 전에 문법 오류를 잡을 수 있고, 가상 머신[^4]이 실행 환경에 맞게 번역해주므로 운영체제에 독립적
  + 인터프리터의 느린 속도를 보완하기 위해 JIT 컴파일러[^5] 등을 활용하여 자주 쓰이는 코드를 기계어로 캐싱
- 대표적인 언어
  + Java: 가상 머신(JVM, Java Virtual Machine)[^4] 위에서 동작하며, 엔터프라이즈급 백엔드 서버 개발에 전 세계적으로 가장 많이 쓰이는 언어임
  + C#: 마이크로소프트 환경과 닷넷(.NET) 환경에서 구동되며, 특히 게임 개발 등에서 뛰어난 생산성과 성능을 발휘

### 1.3.4 세 방식의 언어 비교 요약

| 구분 | 컴파일러 언어 | 인터프리터 언어 | 하이브리드 언어 |
| :--- | :--- | :--- | :--- |
| 동작 방식 | 실행 전 전체 소스 코드를 한 번에 번역함 | 실행 시점에 코드를 한 줄씩 즉석에서 번역함 | 1차 컴파일 후, 실행 시점에 가상 머신[^4]이 번역함 |
| 실행 속도 | 매우 빠름 | 상대적으로 느림 | 중간 (JIT 컴파일러[^5]로 보완함) |
| 개발 속도 | 수정 시마다 재컴파일이 필요해 상대적으로 느림 | 실행 파일 생성 없이 즉시 확인이 가능해 빠름 | 컴파일 단계가 있으나, 가상 머신[^4] 덕분에 테스트가 용이함 |
| 하드웨어 독립성 | 종속적임 (CPU, OS별로 다르게 컴파일해야 함) | 독립적임 (인터프리터만 있으면 실행 가능함) | 독립적임 (가상 머신[^4] 위에서 동일하게 동작함) |
| 대표 언어 | C, C++, Rust, Go | Python, JavaScript, Ruby | Java, C# |

## 1.4 프로그래밍 패러다임
### 1.4.1 절차지향 프로그래밍 (Procedural Programming)
- 프로그램의 실행 순서, 즉 `절차`를 중요하게 여기며 데이터를 처리하는 함수(명령의 집합) 중심으로 작성하는 방식
- 데이터보다 함수(동작)가 중심이 되며, 정해진 순서대로 처리하는 것에 집중
- 특징
  + 컴퓨터의 처리 구조와 유사하여 실행 속도가 빠름
  + 프로그램의 흐름을 파악하기 쉬움
  + 데이터와 함수가 분리되어 있어, 데이터 구조가 변경되면 관련 함수를 모두 수정해야 하는 번거로움이 있음
- 대표 언어: C, Pascal, Fortran, COBOL

### 1.4.2 객체지향 프로그래밍 (Object-Oriented Programming, OOP)
- 데이터와 그 데이터를 처리하는 함수를 객체라는 하나의 단위로 묶어 관리하는 방식
- 실제 세계의 사물을 모델링하여 설계
- 특징
  + 코드 재사용성이 높고 유지보수가 쉬움
  + 설계 단계에 시간이 많이 소요되며, 절차지향에 비해 실행 속도가 상대적으로 느릴 수 있음
- 대표 언어: Java, C++, Python, C#

# 2. 자바(Java)의 탄생과 동작 방식
## 2.1 자바의 탄생
### 2.1.1 그린 프로젝트
- 1991년, 썬 마이크로시스템즈(Sun Microsystems)의 제임스 고슬링(James Gosling), 패트릭 노튼, 마이크 셰리던 등 '그린 팀'이라 불리는 소수의 엔지니어들이 모여 시작함

### 2.1.2 목표
- 가전제품(TV, 냉장고 등)들이 서로 연결되어 동작하는 `지능형 가전 네트워크`(현재의 스마트홈과 유사) 개발을 목표로 각 가전 제품의 하드웨어를 제어하는 플랫폼[^2] 구축

### 2.1.3 문제
- 가전제품마다 CPU 사양이 제각각이었고, 당시 주력 언어인 C++는 플랫폼[^2]마다 코드를 새로 짜야 하는 번거로움이 있었기 때문에 플랫폼[^2] 독립적이고 네트워크 통신에 최적화된 새로운 언어인 Java를 개발함

### 2.1.4 결과
- 프로젝트는 실패했지만 당시에 보급되기 시작한 인터넷 환경에서 강점을 보이는 Java의 애플릿이 주목을 받게 됨
- 애플릿 (Applet): 웹 브라우저에 포함되어 클라이언트[^6] 측에서 실행되는 소규모 자바 프로그램으로, HTML만으로 부족했던 동적인 기능(게임, 차트, 애니메이션 등)을 구현하기 위해 사용되었던 기술이지만 현재는 더이상 사용되지 않고 Javascript가 그 자리를 차지함

## 2.2 자바의 특징
- 슬로건: WORA(Write Once, Run Anywhere)
- 운영체제 독립성: JVM[^4]을 통해 어떤 플랫폼[^2]에서든 동일하게 실행 가능
- 순수 객체지향: 설계부터 객체지향 원칙을 철저히 따름
- 자동 메모리 관리(GC): 개발자가 직접 메모리를 해제할 필요 없이 가비지 컬렉터가 찌꺼기 메모리를 자동 청소
- 멀티스레드[^8] 지원: 언어 차원에서 강력한 멀티스레드[^8] API[^9]를 제공

# 3. JVM의 동작 방식과 메모리

## 3.1 JVM (Java Virtual Machine) 구조
- 자바 프로그램은 OS가 직접 실행하지 않고, JVM[^4]이라는 가상 컴퓨터가 중간에서 실행해 줌

### 3.1.1 코드 실행 순서
1. 개발자가 `.java` 파일 작성
2. 컴파일러(`javac`)가 바이트코드(`.class`)[^3]로 변환
3. JVM[^4]의 클래스 로더[^10]가 `.class`를 메모리로 적재
4. 실행 엔진[^11]이 한 줄씩 읽으며 기계어로 변환하여 실행

---

## 3.2 실행 엔진 구성 요소

### 3.2.1 인터프리터
바이트코드[^3] (.class 파일)를 한 줄씩 읽어서 네이티브 코드[^12]로 해석하고 즉시 실행

### 3.2.2 JIT (Just-In-Time) 컴파일러
인터프리터 방식으로 실행하다가, '핫 스팟(Hot Spot)'이라 불리는 자주 호출되는 코드 영역을 감지하면 해당 바이트코드[^3] 전체를 기계어로 컴파일하여 캐시에 저장하며, 이후에는 인터프리팅 없이 직접 실행됨

### 3.2.3 가비지 컬렉터
런타임 데이터 영역(Runtime Data Area)[^13]의 Heap 메모리를 관리하며, 더 이상 참조되지 않는 객체들을 식별하고 제거하여 메모리를 확보

## 3.3 JVM 메모리 구조
JVM[^4]은 운영체제로부터 메모리를 할당받아 세 구역으로 나누어 사용

<details>
<summary>상세 내용 펼치기</summary>

### 3.3.1 메서드 영역 (Method Area / Static Area)
- 클래스 설계도 정보, 상수, `static` 변수가 저장되는 공유 공간
- 프로그램 시작 시 할당되어 종료될 때까지 유지됨

### 3.3.2 스택 영역 (Stack Area)
- 메서드가 호출될 때마다 해당 메서드만의 작업 공간(스택 프레임)이 생성됨
- 내부의 지역 변수, 매개변수가 저장됨
- 메서드가 종료되면 메모리에서 즉시 해제 (LIFO[^14] 구조)

### 3.3.3 힙 영역 (Heap Area)
- `new` 키워드로 동적 생성되는 모든 객체(인스턴스)와 배열이 저장되는 거대한 공간
- 스택 영역의 변수들은 이 힙 영역의 메모리 주소만을 가리킴(참조)
- 어떤 변수에서도 참조하지 않는 객체는 가비지 컬렉터(GC)[^7]가 주기적으로 메모리에서 해제
</details>

# 4. 개발 환경 구성
## 4.1 JRE와 JDK
### 4.1.1 JRE (Java Runtime Environment)
- 자바 프로그램이 실행되기 위해서 필요한 환경
- JVM[^4]과 핵심 라이브러리 포함

### 4.1.2 JDK (Java Development Kit)
- JRE[^15]를 포함하며, 컴파일러, 디버거 등 자바 개발에 필요한 도구가 들어있음
- javac: 자바 소스 파일(.java)을 바이트코드(.class)[^3]로 변환하는 컴파일러
- java: 컴파일된 바이트코드[^3]를 실행하는 인터프리터. 내부의 JVM(Java Virtual Machine)[^4]을 구동
- jar: 여러 클래스 파일과 리소스를 하나로 묶어 관리하는 압축 도구
- jdb: 프로그램의 오류를 찾고 수정하는 디버거

### 4.1.3 LTS와 기능 릴리스(Feature Release)의 차이
- LTS(장기 지원 버전): 일반적인 버전보다 훨씬 더 긴 기간(보통 5년 이상) 동안 보안 패치와 버그 수정을 지원하는 버전을 의미. 실무 환경에서 서버 애플리케이션을 안정적으로 유지보수하기 위해 기업들은 주로 이 LTS 버전을 표준으로 채택하여 운영
- 기능 릴리스(Feature Release): 6개월 주기로 출시되는 일반 배포 버전으로, 다음 버전이 나오면 곧바로 지원이 종료됨. 자바의 새로운 문법이나 기능(프리뷰)을 빠르게 실험해 보기 위한 목적으로 주로 사용

# 5. 데이터 타입과 변수

## 5.1 기본 데이터 타입(Primitive Type)
- primitive: "원초적인, 기초적인, 가장 기본적인" 이라는 뜻
- 프로그래밍에서 더 이상 쪼갤 수 없는 가장 기본 단위의 데이터 타입을 의미

#### 1) 정수형
- `byte` (1 byte): -2^7 ~ 2^7-1 (-128 ~ 127)
- `short` (2 byte): -2^15 ~ 2^15-1 (-32,768 ~ 32,767)
- `int` (4 byte): -2^31 ~ 2^31-1 (약 -21억 ~ 21억, 자바 정수 기본 타입)
- `long` (8 byte): -2^63 ~ 2^63-1 (약 -9.22E18 ~ 9.22E18, 끝에 `L` 또는 `l`을 붙임)

#### 2) 실수형
- `float` (4 byte): 유효 숫자 7자리 정밀도 (정수부 포함, 끝에 `F` 또는 `f` 붙임)
- `double` (8 byte): 유효 숫자 15자리 정밀도 (정수부 포함, 자바 실수 기본 타입)

#### 3) 논리형과 문자형
- `boolean` (1 byte): `true` 또는 `false`만 가짐
- `char` (2 byte): 홑따옴표로 문자 하나만 저장. 내부적으로는 유니코드(UTF-16)[^20] 숫자로 저장됨

## 5.2 참조 데이터 타입(Reference Type)
- 기본 데이터 타입 8개를 제외한 모든 데이터 타입(배열, 클래스 등)은 참조 데이터 타입임
- 객체가 메모리 상에 실제 올라가 있는 위치 주소(Reference)를 가리키는 방식으로 작동함

## 5.3 변수와 상수
### 5.3.1 변수의 어원
#### 1) variable (변수)
- "var": 라틴어 'varius'에서 유래, '다르다', '변하다'라는 의미
- "able": "~할 수 있는", "~의 능력이 있는" 이라는 뜻을 가진 접미사

#### 2) 變數 (변수)
- 변(變): 변화, 바뀌다
- 수(數): 숫자, 셈, 개수

### 5.3.2 변수란?
- 데이터를 담는 그릇
- 변수에 값을 저장한 후 그 값이 필요할 때 변수를 통해서 값을 사용
- 언제든지 그 값을 수정할 수 있음
- 다른 변수와 식별하기 위한 고유의 이름을 가짐

#### 1) 변수 선언
- 데이터를 사용하기 전에 특징에 맞는 데이터형을 미리 지정
- `데이터타입 변수명;` (예: `int age;`)

#### 2) 변수에 값 할당
- 대입연산자(`=`)를 이용하여 값을 저장
- `변수명 = 값;` (예: `age = 25;`)

#### 3) 변수 선언과 동시에 값 할당
- 변수를 선언함과 동시에 초기값을 부여
- `데이터타입 변수명 = 값;` (예: `int score = 100;`)

- 예시:
  ```java
  int age;           // 1. 변수 선언
  age = 25;          // 2. 변수에 값 할당
  age = 26;          // 변수이므로 값 변경 가능

  int score = 100;   // 3. 변수 선언과 동시에 값 할당
  ```

- 예시:
  ```java
  byte b = 100;
  short s = 10000;
  int num = 100000000;
  long bigNum = 3000000000L; // L을 안붙이면 int로 인식해 에러남
  double pi = 3.14159;
  float smallPi = 3.14F;     // F 안붙이면 double로 인식해 에러남
  boolean isGood = true;
  char grade = 'A';

  String name1 = "멋쟁이";
  String name2 = "사자처럼";
  ```

### 5.3.3 상수의 어원
#### 1) constant (상수)
- "con": 라틴어 "com-"에서 유래, '함께', '완전히'라는 의미의 강조 접두사
- "stant": 라틴어 "stare"에서 유래, '서 있다', '머물다'라는 의미
- 즉, "변하지 않고 확고하게 서 있는 상태"를 뜻함

#### 2) 常數 (상수)
- 상(常): 항상, 일정하다
- 수(數): 숫자, 셈, 개수
- 즉, "항상 일정한 수"를 뜻함

### 5.3.4 상수란?
- 한 번 값이 저장되면 프로그램이 실행되는 동안 절대 변경할 수 없는 불변의 데이터 저장소를 가리킴
- 자바에서는 변수 선언부 앞에 `final` 키워드를 붙여 상수를 만듦
- 상수의 이름은 관례적으로 모든 글자를 대문자로 작성하며, 단어와 단어 사이는 언더스코어(`_`)로 구분함
- 상수를 사용하면 값의 의미가 명확해지고 코드의 안정성이 크게 높아짐

- 예시:
  ```java
  final int MAX_SIZE = 100; // 상수 선언 (주로 대문자와 언더스코어 사용)
  // MAX_SIZE = 200; // 에러 발생! 상수는 변경 불가
  ```

- 💻 실습 (기본 자료형 및 변수 선언): [ch05/PrimitiveType.java](../workspace/ch05/PrimitiveType.java)

### 5.3.5 리터럴(Literal)
- 소스 코드 상에서 프로그래머가 직접 입력한 고정된 값 자체
- 변수나 상수에 할당되는 데이터 값
- 종류:
  - 정수 리터럴: `10`, `0`, `-5`
  - 실수 리터럴: `3.14`, `2.5f`
  - 문자 리터럴: `'A'`, `'가'`
  - 문자열 리터럴: `"Hello"`, `"멋쟁이"`
  - 논리 리터럴: `true`, `false`

- 예시:
  ```java
  int score = 100;          // 100이 정수 리터럴
  final double PI = 3.14;   // 3.14가 실수 리터럴
  ```

## 5.4 식별자와 예약어

### 5.4.1 식별자(Identifier)
- 변수, 상수, 메서드, 클래스 등에 붙여주는 이름
- 개발자가 임의로 지정할 수 있지만 지켜야 할 문법적 규칙과 관례가 있음

#### 1) 식별자 명명 규칙 (문법적 필수)
- 영문 대소문자(유니코드[^20]를 지원하므로 한글 등 모든 언어의 문자를 사용할 수 있으나 보통 영문자만 사용), 숫자, 밑줄(`_`), 달러 기호(`$`)만 사용 가능
- 숫자로 시작할 수 없음
- 예약어는 사용할 수 없음
- 길이 제한은 없음

#### 2) 식별자 명명 관례 (개발자 간의 약속)
- 클래스 이름: 대문자로 시작 (PascalCase)
- 변수와 메서드 이름: 소문자로 시작하고 단어가 바뀔 때마다 대문자 사용 (camelCase)
- 상수 이름: 모두 대문자로 작성하며 단어 사이는 밑줄(`_`)로 연결 (SCREAMING_SNAKE_CASE)

### 5.4.2 예약어(Keyword / Reserved Word)
- 자바 언어 문법에서 미리 약속되어 특별한 의미로 사용되는 단어
- 식별자로 사용할 수 없음
- 예: `int`, `class`, `public`, `if`, `for`, `true`, `false` 등

## 5.5 형변환(Type Casting)
서로 다른 타입끼리 연산하거나 대입할 때 크기를 맞춰주는 작업.

#### 1) 자동 형변환 (묵시적 형변환)
- 작은 크기의 타입을 큰 크기의 타입으로 변환할 때 발생 (데이터 손실 없음)
- `byte` -> `short` -> `int` -> `long` -> `float` -> `double`

- 예시:
  ```java
  int a = 10;
  double b = a; // int가 double로 자동 변환. b는 10.0이 됨
  ```

#### 2) 강제 형변환 (명시적 형변환)
- 큰 크기의 타입을 작은 크기의 타입으로 강제 변환할 때 발생 (데이터 손실 위험)
- 괄호 `(타입)`를 명시해야 함

- 예시:
  ```java
  double pi = 3.14;
  int p = (int) pi; // 강제로 소수점을 버림. p는 3이 됨 (데이터 손실)
  ```

# 6. 연산자

## 6.1 산술 연산자
- `+`, `-`, `*`, `/`, `%`(나머지)
- 1+4, 1-4*5, (1+4)*5
- 9/4 -> 2
- 9%4 -> 1
- 결합 연산자(+): 문자열과 함께 사용할 경우 문자열 결합을 의미함
- 예시:
  ```java
  int age = 30;
  String str = "나이는 " + age + " 입니다.";
  System.out.println(str); // 나이는 30 입니다.
  ```

## 6.2 대입 연산자
- `=`, `+=`, `-=`, `*=`, `/=`, `%=`
- 우측 항목의 값을 계산한 후 왼쪽 항목에 대입
- 예시:
  ```java
  int a = 10 + 5; //  a = 15
  int sum = 20;
  sum += a; // sum = sum + a 를 의미. sum = 20 + 15
  System.out.println(sum); // 35
  ```

## 6.3 증감 연산자
- `++`, `--`
- 값을 1 증가 또는 감소
- 예시:
  ```java
  int count = 10;
  count++; // count = count + 1 -> 11
  count++; // count = count + 1 -> 12
  count--; // count = count - 1 -> 11
  System.out.println(count); // 11
  ```

- 변수 앞에 붙으면 연산 전 증감(전위 연산), 뒤에 붙으면 연산 후 증감(후위 연산)
- 예시:
  ```java
  int a = 10;
  int b = ++a; // 전위 연산: a의 값을 먼저 1 증가시킨 후 b에 대입함 (a는 11, b는 11이 됨)
  System.out.println("a: " + a + ", b: " + b); // a: 11, b: 11

  int x = 10;
  int y = x++; // 후위 연산: x의 현재 값인 10을 y에 먼저 대입한 후 x를 1 증가시킴 (x는 11, y는 10이 됨)
  System.out.println("x: " + x + ", y: " + y); // x: 11, y: 10
  ```

## 6.4 비교 연산자
- `==`(같다), `!=`(다르다), `>`, `<`, `>=`, `<=`
- 두 항을 비교하여 참이면 true, 거짓이면 false를 반환
- 예시:
  ```java
  System.out.println(1 > 2); // false
  System.out.println(10 <= 10); // true
  System.out.println(100 == 100); // true
  System.out.println(100 != 110); // true
  ```

## 6.5 논리 연산자
### 6.5.1 `&&` (AND)
- 두 항이 모두 참이면 true, 그 외는 false
- 예시:
  ```java
  int age = 19;
  boolean isTeenage = (age >= 10) && (age < 20); // age가 10 이상이고 age가 20 미만일 경우 true, 나머지는 false
  System.out.println(isTeenage); // age가 19이므로 true
  age++;
  isTeenage = (age >= 10) && (age < 20); // age가 10 이상이고 age가 20 미만일 경우 true, 나머지는 false
  System.out.println(isTeenage); // age가 20이므로 false
  ```

### 6.5.2 `||` (OR)
- 두 항 중 하나라도 참이면 true, 그 외는 false
- 예시:
  ```java
  int age = 8;
  boolean isFreeRide = (age <= 8) || (age >= 65); // 8세 이하이거나 65세 이상인 경우 무료 탑승 대상자
  System.out.println(isFreeRide); // age가 8이므로 true

  age = 30;
  isFreeRide = (age <= 8) || (age >= 65);
  System.out.println(isFreeRide); // age가 30이므로 false
  ```

### 6.5.3 `!` (NOT)
- 참이면 false, 거짓이면 true (반대값 반환)
- 예시:
  ```java
  boolean isRainy = true;
  boolean isSunny = !isRainy; // 비가 오면 화창하지 않음
  System.out.println("오늘은 화창한 날이다. " + isSunny); // false

  isRainy = false;
  isSunny = !isRainy; // 비가 오지 않으면 화창한 날씨
  System.out.println("오늘은 화창한 날이다. " + isSunny); // true
  ```

## 6.6 삼항 연산자
- `조건식 ? 참일_때_값 : 거짓일_때_값` 단일 조건 제어 흐름에 유용함
- 예시:
  ```java
  int score = 85;
  String result = (score >= 80) ? "합격" : "불합격";
  System.out.println(result); // 합격
  ```

## 6.7 연산자 우선순위
- 여러 연산자가 복합적으로 사용된 수식에서 컴파일러가 어떤 연산자를 먼저 계산할지 결정하는 규칙

### 6.7.1 주요 연산자 우선순위 요약 표
수식이 얽혀 있을 때 아래의 순서에 따라 차례대로 연산이 집행됨

| 순위 | 연산자 유형 | 연산자 기호 | 연산 방향 |
| :--- | :--- | :--- | :--- |
| 1 | 괄호 및 대괄호 | (), [] | 왼쪽에서 오른쪽 |
| 2 | 단항 연산자 | ++, --, +, -, ! | 오른쪽에서 왼쪽 |
| 3 | 산술 연산자 (곱셈 계열) | *, /, % | 왼쪽에서 오른쪽 |
| 4 | 산술 연산자 (덧셈 계열) | +, - | 왼쪽에서 오른쪽 |
| 5 | 비교 연산자 (크기 비교) | <, <=, >, >= | 왼쪽에서 오른쪽 |
| 6 | 비교 연산자 (동등 비교) | ==, != | 왼쪽에서 오른쪽 |
| 7 | 논리 연산자 (AND) | && | 왼쪽에서 오른쪽 |
| 8 | 논리 연산자 (OR) | \|\| | 왼쪽에서 오른쪽 |
| 9 | 삼항 연산자 | ? : | 오른쪽에서 왼쪽 |
| 10 | 대입 연산자 | =, +=, -=, *=, /=, %= | 오른쪽에서 왼쪽 |
| 11 | 증감 연산자(후위형) | ++, -- | 2순위에 있지만 편의상 따로 표기 |

### 6.7.2 연산 방향(결합성)의 의미
- 동일한 우선순위를 가진 연산자들이 여러 개 나열되어 있을 때, 컴파일러가 어느 쪽 연산자부터 먼저 해석하여 순서대로 처리해 나갈지 결정하는 방향을 말함

#### 1) 왼쪽에서 오른쪽 (Left-to-Right)
- 대부분의 산술, 비교, 논리 연산이 이에 해당하며 일반적인 계산 순서와 같음
  ```java
  int result = 5 + 3 - 2; // 동일한 우선순위인 덧셈과 뺄셈이 나열됨
  // 처리 순서: (5 + 3) -> 8이 먼저 계산된 후, 8 - 2 가 실행되어 최종 6이 됨
  ```

#### 2) 오른쪽에서 왼쪽 (Right-to-Left)
- 대입 연산자, 단항 연산자 등이 이에 해당하며 우측의 식부터 해석하여 좌측으로 누적 및 대입해 들어옴

- 예시(대입 연산자):
  ```java
  int a;
  int b;
  int c;
  a = b = c = 100; // 우측부터 해석하여 좌측으로 차례대로 저장해 들어옴
  // 처리 순서:
  // 1. 가장 오른쪽인 (c = 100) 이 실행되어 c에 100이 대입됨
  // 2. 그 후 (b = c의 결과값 100) 이 실행되어 b에 100이 대입됨
  // 3. 마지막으로 (a = b의 결과값 100) 이 실행되어 a에 100이 최종 저장됨
  System.out.println("a: " + a + ", b: " + b + ", c: " + c); // a: 100, b: 100, c: 100
  ```

- 예시(단항 연산자):
  ```java
  int x = 5;
  int y = -++x; // 우측인 ++x를 먼저 수행한 후, 그 결과에 좌측의 부호 연산자(-)를 씌움
  // 처리 순서:
  // 1. 가장 우측에 가까운 ++x가 먼저 계산되어 x가 6이 됨
  // 2. 그 결과값 6에 좌측 부호 연산자(-)가 씌워져 최종 -6이 y에 저장됨
  System.out.println("y: " + y); // -6
  ```

- 예시(삼항 연산자):
  ```java
  int score = 85;
  String grade = (score >= 90) ? "A" : (score >= 80) ? "B" : "C";
  // 삼항 연산자가 연속해서 나열될 때, 우측의 삼항 연산이 먼저 한 그룹으로 결합하고 그 평가 결과가 좌측 연산의 거짓항 요소로 사용됨
  // 처리 순서:
  // 1. 가장 우측의 중첩식인 ((score >= 80) ? "B" : "C") 가 하나의 피연산자 블록으로 먼저 결합함 -> score가 85이므로 결과는 "B"가 됨
  // 2. 이 결과값 "B"가 좌측식의 거짓항 자리에 대입되어 (score >= 90) ? "A" : "B" 가 최종 실행됨
  System.out.println("학점: " + grade); // 학점: B
  ```

### 6.7.3 우선순위 대조 예시
- 예시:
  ```java
  // 1) 곱셈과 덧셈의 우선순위 비교
  int result1 = 5 + 3 * 2; // 곱셈(*)이 덧셈(+)보다 우선하므로 3 * 2가 먼저 수행되어 11이 됨
  System.out.println(result1); // 11

  // 2) 비교 연산과 논리 연산의 우선순위 비교
  boolean result2 = 10 > 5 && 3 < 1; // 비교(>, <)가 논리(&&)보다 우선하여 (true && false)가 되므로 false가 됨
  System.out.println(result2); // false

  // 3) 괄호()를 통한 강제 우선순위 지정 (가장 안전하고 강력한 실무 권장 기법)
  int result3 = (5 + 3) * 2; // 괄호 안의 덧셈이 먼저 실행되어 8 * 2 = 16이 됨
  System.out.println(result3); // 16
  ```

### 6.7.4 실무 가이드 및 권장 사항
- 연산자 우선순위 규칙이 엄격히 존재하지만, 복잡한 수식을 개발자가 전부 암기하여 코드를 작성하면 가독성이 떨어지고 실수할 가능성이 늘어남
- 조금이라도 연산 순서가 모호하거나 수식의 명확성을 높이고자 할 때는 괄호 `()` 로 해당 연산을 감싸서 가독성을 확보하는 것이 좋음

# 7. 조건문

## 7.1 if 문
- 조건식이 참(true)일 때만 지정한 블록을 실행하고, 거짓(false)이면 실행하지 않고 건너띔
- 형식:
  ```java
  if (조건식) {
    // 조건식이 참일 때 실행할 구문
  }
  ```
- 예시:
  ```java
  int score = 95;
  if (score >= 90) {
    System.out.println("우수한 성적입니다."); // score가 95이므로 실행됨
  }

  score -= 10;
  if (score >= 90) {
    System.out.println("우수한 성적입니다."); // score가 85이므로 실행되지 않음
  }
  ```

## 7.2 if-else 문
- 조건식이 참일 경우 if 블록을, 거짓일 경우 else 블록을 실행
- 형식:
  ```java
  if (조건식) {
    // 조건식이 참일 때 실행할 구문
  } else {
    // 조건식이 거짓일 때 실행할 구문
  }
  ```
- 예시:
  ```java
  int score = 75;
  if (score >= 60) {
    System.out.println("합격입니다."); // 참일 때 실행
  } else {
    System.out.println("불합격입니다."); // 거짓일 때 실행
  }
  ```

## 7.3 if-else if 문
- 조건식이 참일 경우 해당 구문을 수행하고 거짓일 경우 else if 문의 조건식을 순차적으로 비교하여 참에 해당하는 구문 수행
- 형식:
  ```java
  if (조건식1) {
    // 조건식1이 참일 때 실행할 구문
  } else if (조건식2) {
    // 조건식2가 참일 때 실행할 구문
  } else {
    // 모든 조건식이 거짓일 때 실행할 구문
  }
  ```
- 예시:
  ```java
  int age = 19;
  if (age >= 20) {
    System.out.println("성인");
  } else if (age >= 14) {
    System.out.println("청소년"); // age가 19이므로 이 조건식이 충족되어 실행됨
  } else {
    System.out.println("어린이");
  }

  age += 1;
  if (age >= 20) {
    System.out.println("성인"); // age가 20이므로 이 조건식이 충족되어 실행됨
  } else if (age >= 14) {
    System.out.println("청소년");
  } else {
    System.out.println("어린이");
  }
  ```

- 중괄호 생략 규칙
  + if, else if, else 문 블록 내에 실행할 구문이 단 한 줄(하나의 실행문)일 경우, 중괄호 `{}`를 생략할 수 있음
  + 단, 생략할 경우 코드 가독성이 떨어질 수 있고, 나중에 실행 구문을 추가할 때 버그가 생기기 쉬우므로 실무에서는 가급적 중괄호를 명시적으로 작성하는 것을 권장
  + 예시:
    ```java
    int score = 85;

    // if, else if, else 블록 전체에서 실행문이 한 줄이므로 각각 중괄호 생략 가능
    if (score >= 90)
    System.out.println('우수');
    else if (score >= 80)
    System.out.println('보통'); // score가 85이므로 실행됨
    else
    System.out.println('노력요함');
    ```

## 7.4 switch 문
- switch 구문의 비교값과 같은 case 블록을 찾아서 실행(break 키워드를 만날때까지 아래에 위치한 case 블록을 모두 실행)
- `break` 키워드를 작성하지 않으면 아래에 위치한 다음 `case` 블록들까지 연달아 실행되므로 주의가 필요
- 형식:
  ```java
  switch (비교대상) {
    case 값1:
      // 비교대상이 값1일 때 실행할 구문
      break;
    case 값2:
      // 비교대상이 값2일 때 실행할 구문
      break;
    default:
      // 매칭되는 값이 없을 때 실행할 구문
    }
  ```
- 예시:
  ```java
  String role = "ADMIN";
  switch (role) {
    case "ADMIN":
      System.out.println("관리자 권한"); // role이 "ADMIN"이므로 이곳으로 즉시 점프하여 실행
      break; // switch 문을 즉시 빠져나감
    case "USER":
      System.out.println("일반 사용자");
      // break;
      default:
      System.out.println("권한 없음"); // default는 매칭되는 case가 없을 경우 실행
    }

    role = "USER";
    switch (role) {
      case "ADMIN":
      System.out.println("관리자 권한");
      break;
    case "USER":
      System.out.println("일반 사용자"); // role이 "USER"이므로 이곳으로 즉시 점프하여 실행
      // break;
      default:
      System.out.println("권한 없음"); // default는 매칭되는 case가 없을 경우 실행
    }
  ```

## 7.5 Switch Expression
- 자바 12 버전부터 도입(자바 14 정식 표준화)된 새로운 형태의 switch 문
- 기존의 콜론(:)과 break 키워드를 사용하는 방식 대신 화살표 연산자(->)를 활용하여 가독성을 높이고 실수를 방지
- 기존 switch 문이 실행만을 목적으로 하는 제어문(Statement)[^21]이었다면, 새로운 switch 문은 그 자체로 최종 결과를 직접 반환할 수 있는 식(Expression)[^22]으로 동작 가능
- 주요 특징:
  + break 키워드 불필요: case에 해당하는 명령문만 실행하고 자동으로 switch 문을 빠져나감
  + 다중 조건 결합: 쉼표(,)를 사용하여 여러 case 조건을 한 줄에 간결하게 묶어 선언할 수 있음
  + 값의 직접 반환: switch 식 자체를 변수의 대입 연산 우측에 배치하여 값을 직접 반환받을 수 있음
  + yield 키워드: 복잡한 명령 처리를 위해 중괄호 { } 블록을 구성할 경우, 블록 내부에서 yield 키워드를 사용하여 최종 결과값을 외부로 반환할 수 있음

- 예시(화살표 연산자):
  ```java
  String role = "ADMIN";
  switch (role) {
    case "ADMIN" -> System.out.println("관리자 권한");
      case "USER" -> System.out.println("일반 사용자");
      default -> System.out.println("권한 없음");
    }
  ```

- 예시(다중 조건 결합):
  ```java
  String day = "SATURDAY";
  String type = switch (day) {
    case "MONDAY", "TUESDAY", "WEDNESDAY", "THURSDAY", "FRIDAY" -> "평일";
      case "SATURDAY", "SUNDAY" -> "주말";
      default -> "알 수 없음";
    };
    System.out.println(type); // '주말' 출력
  ```

- 예시(switch 식 대입):
  ```java
  int number = 2;
  String result = switch (number) {
    case 1 -> "하나";
      case 2 -> "둘";
      default -> "기타";
    };
    System.out.println(result); // '둘' 출력
  ```

- 예시(블록과 yield 키워드 사용):
  ```java
  int score = 90;
  String grade = switch (score) {
    case 100, 90 -> {
        System.out.println("우수한 성적입니다.");
        yield "A"; // 중괄호 블록 내의 최종 반환값 지정
    }
    case 80 -> "B";
      default -> "C";
    };
    System.out.println("최종 학점: " + grade); // '최종 학점: A' 출력
  ```

- 예시:
  ```java
  int j = 10;

    System.out.println("do-while 무조건 한번은 실행됨: " + j);
  ```

## 8.3 for 문
- 지정한 조건식이 참일 경우 조건이 거짓이 될 때까지 해당 블록을 반복하여 수행
- 반복 횟수가 명확할 때 주로 사용
- 형식:
  ```java
  for (초기화; 조건식; 증감식) {
    // 조건식이 참인 동안 반복해서 실행할 구문
  }
  ```
- 초기화, 조건식, 증감식은 상황에 따라 생략 가능하며 모두 생략할 경우 무한루프가 됨
  ```java
  for (;;) {
    // 무한루프
  }
  ```
- 실행 순서
  + 초기화 -> 조건식 -> (조건식이 true일 경우) 실행할 구문
  + 증감식 -> 조건식 -> (조건식이 true일 경우) 실행할 구문
  + 증감식 -> 조건식 -> (조건식이 true일 경우) 실행할 구문
  + ... 조건식이 false가 될 때까지 실행
- 예시:
  ```java
  for (int i = 0; i < 5; i++) {
    System.out.println("현재 숫자: " + i); // 0부터 4까지 5번 출력
  }
  ```

## 8.4 break와 continue
- `break`: 실행되는 순간 소속된 switch문이나 반복문을 종료하고 탈출
- `continue`: 이번 턴만 건너뛰고 다음 턴으로 바로 넘어감

- 예시:
  ```java
  // 1) break: i가 3일 때 반복문을 완전히 종료하고 탈출함
  for (int i = 1; i <= 5; i++) {
    if (i == 3) {
      break;
    }
    System.out.println("break 출력: " + i); // 1, 2 출력
  }

  // 2) continue: i가 3일 때 이번 출력 턴만 건너뛰고 4로 넘어감
  for (int i = 1; i <= 5; i++) {
    if (i == 3) {
      continue;
    }
    System.out.println("continue 출력: " + i); // 1, 2, 4, 5 출력
  }
  ```

# 9. 배열과 메모리 관리

## 9.1 배열이란?
- 배열이란 같은 타입의 데이터 여러 개를 하나로 묶어서 순차적으로 관리하는 자료구조[^24]
- index(순서정보)를 이용하여 배열의 각 요소를 참조
- 배열의 핵심 특징:
  - 같은 타입만 저장 가능: 하나의 배열에는 서로 다른 타입의 데이터를 혼합해서 저장할 수 없음
  - 고정된 크기: 배열은 선언 및 생성할 때 크기를 지정해야 하며, 한 번 생성된 배열의 크기는 절대 변경할 수 없음
  - 연속된 메모리 공간: 배열의 요소들은 메모리상에 물리적으로 연속되게 배치되어 빠른 인덱스 접근이 가능함
  - 참조 타입: 배열 자체는 객체이므로 힙(Heap) 영역에 생성되며, 배열 변수는 이 객체의 주소값을 가짐

## 9.3 배열과 메모리 구조
- 자바는 메모리를 효율적으로 관리하기 위해 여러 영역으로 나누어 사용함

### 9.3.1 Stack 영역과 Heap 영역의 역할
- 스택(Stack) 영역:
  - 메서드 호출 시 생성되는 로컬 변수들이 적재되는 영역
  - 기본 타입 변수는 실제 데이터 값을 스택에 가지고 있음
  - 참조 타입 변수는 실제 객체가 저장되어 있는 힙(Heap) 영역의 주소값을 저장함
- 힙(Heap) 영역:
  - new 연산자로 생성된 모든 인스턴스와 배열 객체가 할당되는 영역
  - 가비지 컬렉터(GC)[^7]에 의해 참조 관계가 끊어진 객체들이 감지되어 자동으로 수거됨

### 9.3.2 메모리 구조 할당 예시
- 코드:
  ```java
  int age = 25;
  int[] scores = new int[3];
  ```

  ```text
         │      │            │

     age │  25  │            │

           Stack                        Heap
  ```

- 동작 메커니즘:

## 9.4 다차원 배열
- 다차원 배열은 배열의 요소로 또 다른 배열을 가지는 구조를 의미함(일반적으로 행과 열로 이루어진 표나 행렬 구조와 유사함)
- 배열이 중첩된 깊이(차수)에 따라 n차원 배열이라고 부름
  + 예를 들어, 2차원 배열은 여러 개의 1차원 배열들을 요소로 담고 있는 배열임
- 형식:
  ```java
  타입[][] 변수명 = new 타입[행크기][열크기];
  ```
- 예시:
  ```java
  int[][] matrix = new int[2][3]; // 2행 3열 배열
  matrix[0][0] = 1;
  matrix[1][2] = 6;

  // 초기화와 동시에 생성
  int[][] arr = {
    {1, 2, 3},
    {4, 5, 6}
  };
  ```
  ```text
             [0]         [1]         [2]
        ┌───────────┬───────────┬───────────┐
   [0]  │     1     │     2     │     3     │
        │ arr[0][0] │ arr[0][1] │ arr[0][2] │
        │───────────┼───────────┼───────────┤
   [1]  │     4     │     5     │     6     │
        │ arr[1][0] │ arr[1][1] │ arr[1][2] │
        └───────────┴───────────┴───────────┘
  ```
  ```text
       │      │        │
       │      │        │       [0]    [1]
       │      │        │    ┌──────┬──────┐
       │      │    ┌───┼──► │ 0x23 │ 0x37 │
       │      │    │   │    └──────┴──────┘
       │      │    │   │       │      │
       │      │    │   │       │      └─────────────┐
       │      │    │   │       ▼                    ▼
       │      │    │   │    ┌─────┬─────┬─────┐   ┌─────┬─────┬─────┐

       ├──────┤    │   │    └─────┴─────┴─────┘   └─────┴─────┴─────┘
   arr │ 0x12 │────┘   │      [0]   [1]   [2]       [0]   [1]   [2]
       └──────┘        └────────────────────────────────────────────────
         Stack                            Heap
  ```

- 다차원 배열의 가변 배열:
  - 다차원 배열은 행마다 열의 길이를 다르게 지정할 수 있음
  ```java
  int[][] ragged = new int[3][];
  ragged[0] = new int[2]; // 0행은 열 크기가 2
  ragged[1] = new int[4]; // 1행은 열 크기가 4
  ragged[2] = new int[3]; // 2행은 열 크기가 3
  ```

## 9.5 향상된 for문
- 배열이나 컬렉션의 모든 요소를 처음부터 끝까지 순차적으로 탐색할 때 인덱스 없이 편리하게 사용하는 문법
  + 컬렉션: 다수의 데이터를 효율적으로 저장하고 관리하기 위해 자바가 제공하는 표준 자료구조[^24]의 모음(예: 'List', 'Set' 등)
- 인덱스를 직접 제어하지 않으므로 인덱스 범위를 초과하는 에러를 예방할 수 있고 코드가 직관적이고 간결해짐
- 단, 값을 조회하는 용도로만 사용이 가능하며 배열의 요소를 직접 수정할 수는 없음

- 형식:
  ```java
  for (타입 변수명 : 배열 혹은 컬렉션) {
    // 반복 실행할 구문
  }
  ```

- 예시 (일반 for문과 향상된 for문 비교):
  ```java
  int[] scores = {90, 85, 95};

  // 1) 일반 for문 (인덱스 사용)
  for (int i = 0; i < scores.length; i++) {
    System.out.println("점수: " + scores[i]);
  }

  // 2) 향상된 for문 (요소에 직접 접근)
  for (int score : scores) {
    System.out.println("점수: " + score);
  }
  ```
  ```text
         │       │           │                                    
         │       │           │   ┌──────┬──────┬──────┐  
         │       │      ┌────┼─► │  90  │  85  │  95  │  
         ├───────┤      │    │   └──────┴──────┴──────┘  
  scores │ 0x36  │──────┘    │     [0]    [1]    [2]    
         └───────┘           └────────────────────────────                                    
           Stack                             Heap
  ```

## 9.6 배열의 복사와 Arrays 클래스
- 배열은 한 번 크기가 결정되면 늘리거나 줄일 수 없으므로, 더 많은 저장 공간이 필요할 때는 새로운 배열을 만들어 기존 값들을 복사해야 함

### 9.6.1 얕은 복사(Shallow Copy)
- 배열 변수의 주소값만 복사하여 두 참조 변수가 동일한 실제 배열 객체를 가리킴
- 한쪽에서 값을 수정하면 다른 쪽도 영향을 받음
  ```java
  int[] original = {10, 20, 30};
  int[] shallow = original;

  shallow[0] = 99;
  System.out.println(shallow[0]); // 99
  System.out.println(original[0]); // 99
  ```

  ```text
           │       │            │
           ├───────┤            │    ┌──────┬──────┬──────┐
   shallow │ 0x50  │────┐    ┌──┼──► │  99  │  20  │  30  │
           ├───────┤    ├────┘  │    └──────┴──────┴──────┘
  original │ 0x50  │────┘       │       [0]    [1]    [2]
           └───────┘            └────────────────────────────
             Stack                              Heap
  ```

### 9.6.2 깊은 복사(Deep Copy)
- 새 배열을 생성한 뒤 기존 배열의 데이터를 복사하는 방식
- 한쪽에서 값을 수정해도 다른 쪽은 영향을 받지 않음

#### 1) 수동 복사
- 반복문(for문)을 사용하여 원본 배열의 요소를 하나씩 대상 배열로 복사하는 방법
- 형식:
  ```java
  for (int i = 0; i < 원본배열.length; i++) {
    대상배열[i] = 원본배열[i];
  }
  ```
- 예시:
  ```java
  int[] original = {10, 20, 30};
  int[] target = new int[original.length];
  for (int i = 0; i < original.length; i++) {
    target[i] = original[i];
  }

  target[0] = 99;
  System.out.println(target[0]); // 99
  System.out.println(original[0]); // 10
  ```

  ```text
           │       │            │
           │       │            │    ┌──────┬──────┬──────┐
           │       │   ┌────────┼──► │  99  │  20  │  30  │
           │       │   │        │    └──────┴──────┴──────┘
           │       │   │        │       [0]    [1]    [2]
           │       │   │        │
           ├───────┤   │        │    ┌──────┬──────┬──────┐
    target │ 0x75  │───┘   ┌────┼──► │  10  │  20  │  30  │
           ├───────┤       │    │    └──────┴──────┴──────┘
  original │ 0x50  │───────┘    │       [0]    [1]    [2]
           └───────┘            └────────────────────────────
             Stack                               Heap
  ```

#### 2) System.arraycopy()
- JVM[^4] 레벨에서 메모리를 직접 복사하여 고속으로 배열 복사를 수행하는 메서드
- 이미 생성되어 있는 대상 배열에 덮어쓰고 싶을 때 사용
- 복사할 시작 위치와 붙여넣을 위치를 자유롭게 조절하고 싶을 때 적합. 예를 들어 원본 배열의 2번째 요소부터 대상 배열의 4번째 위치로 복사하는 것과 같은 세밀한 작업에 쓰임
- 자바 가상머신(JVM)[^4] 레벨에서 직접 고속 메모리 복사를 처리하기 때문에 대량의 데이터를 복사하여 성능 극대화가 필요할 때 사용

- 형식:
  ```java
  System.arraycopy(Object src, int srcPos, Object dest, int destPos, int length);
  ```
  - src: 원본 배열
  - srcPos: 원본 배열에서 복사를 시작할 인덱스
  - dest: 대상 배열
  - destPos: 대상 배열에서 복사가 시작될 인덱스
  - length: 복사할 요소의 개수

- 예시:
  ```java
  int[] original = {10, 20, 30};
  int[] target = new int[original.length];
  // System.arraycopy(원본배열, 원본시작인덱스, 대상배열, 대상시작인덱스, 복사할개수)
  System.arraycopy(original, 0, target, 0, original.length);

  target[0] = 99;
  System.out.println(target[0]); // 99
  System.out.println(original[0]); // 10
  ```

- 💻 실습 (배열 복사): [ch09/ArrayCopy.java](../workspace/ch09/ArrayCopy.java)

### 9.6.3 Arrays 클래스와 주요 메서드
- java.util.Arrays 클래스는 배열을 다루기 위한 다양한 헬퍼 메서드들을 제공함

#### 1) Arrays.toString()
- 배열의 모든 요소를 '[값1, 값2, 값3, ...]' 형태의 문자열로 변환하여 반환함
- 배열의 내부 값을 한눈에 확인하고 디버깅[^25]할 때 주로 사용함
- 예시:
  ```java
  import java.util.Arrays;

  int[] arr = {10, 20, 30};
  System.out.println(Arrays.toString(arr)); // '[10, 20, 30]' 출력
  ```

#### 2) Arrays.copyOf()
- 새로운 배열 생성과 배열 복사를 한 번에 처리함(깊은 복사)
- 단순히 배열 전체를 복사하거나, 배열의 크기를 늘린 새로운 배열을 생성하고 싶을 때 사용
- 대상 배열을 미리 new 연산자로 선언할 필요 없이, 복사와 동시에 새 배열 객체를 얻고자 할 때 적합함
- 내부적으로 System.arraycopy를 감싸서 제공되므로 코드의 간결함과 가독성이 중요할 때 사용함
- 형식:
  ```java
  타입[] 대상배열 = Arrays.copyOf(원본배열, 새배열의길이);
  ```
- 예시:
  ```java
  import java.util.Arrays;

  int[] original = {10, 20, 30};
  int[] target = Arrays.copyOf(original, original.length);
  
  target[0] = 99;
  System.out.println(target[0]); // 99
  System.out.println(original[0]); // 10
  ```

#### 3) Arrays.sort()
- 배열의 요소를 오름차순(기본)으로 정렬함
- 예시:
  ```java
  import java.util.Arrays;

  int[] arr = {30, 10, 20};
  Arrays.sort(arr);
  System.out.println(Arrays.toString(arr)); // '[10, 20, 30]' 출력
  ```

#### 4) Arrays.equals()
- 두 배열의 크기와 저장된 요소들이 동일한지 비교하여 true 또는 false를 반환함
- 예시:
  ```java
  import java.util.Arrays;

  int[] arr1 = {10, 20};
  int[] arr2 = {10, 20};
  int[] arr3 = {20, 10};

  System.out.println(Arrays.equals(arr1, arr2)); // true
  System.out.println(Arrays.equals(arr1, arr3)); // false (순서가 다르면 다른 배열로 인지)
  ```

## 9.7 배열 접근 시 발생할 수 있는 주요 예외
- NullPointerException:
  - 참조 변수가 null인 상태(아직 객체의 주소값을 가리키지 않는 상태)에서 배열 요소에 접근하려고 인덱스를 지정할 때 발생함

  ```java
  int[] arr = null;
  // arr[0] = 10; // NullPointerException 발생
  ```
- ArrayIndexOutOfBoundsException:

  ```java
  int[] arr = new int[3]; // 사용 가능한 인덱스 범위: 0, 1, 2
  // arr[3] = 40; // ArrayIndexOutOfBoundsException 발생
  ```

# 10. 메서드(Method)

## 10.1 메서드(Method)란?
- 특정 기능을 수행하기 위해 관련된 코드들을 하나의 블록으로 묶어놓은 것
- 필요할 때마다 호출해서 여러번 재사용 가능

## 10.2 메서드를 사용하는 이유와 장점
- 코드의 재사용성(Reusability) 증대
  + 자주 반복해서 사용하는 코드를 메서드로 한 번 정의해 두면, 필요할 때마다 호출하여 간편하게 다시 사용할 수 있어 개발 효율이 증대됨
- 코드의 중복 제거
  + 복사하여 붙여넣음으로써 발생하는 중복 코드를 제거하여 전체적인 프로그램 코드의 크기를 줄이고 깔끔하게 구성할 수 있음
- 유지보수성(Maintainability) 향상
  + 나중에 구현한 계산식이나 기능을 변경해야 할 때, 메서드 내부의 코드만 한 번 수정하면 해당 메서드를 사용하는 모든 곳에 수정 내용이 즉시 반영되므로 안전하고 빠름
- 가독성(Readability) 및 구조화
  + 메서드 내부의 복잡한 구현 세부 코드는 신경쓰지 않고 호출하는 방법만 알고 쓰면 되기 때문에 프로그램을 큰 틀에서 흐름만 눈에 들어오기 때문에, 전체 코딩 흐름을 한눈에 파악하기가 수월해짐

## 10.3 메서드 선언과 호출
### 10.3.1 메서드 선언
- 형식:
  ```java
  [접근제어자] 반환타입 메서드명(매개변수타입 매개변수명, ...) {
    // 실행할 코드 블록
    return 반환값; // 반환타입이 void가 아닐 때만 사용
  }
  ```
  - 접근제어자: 메서드를 호출할 수 있는 범위를 지정
    + public: 어디서든 호출 가능
    + private: 같은 클래스 내부에서만 호출 가능
    + protected: 동일한 패키지 내의 클래스들과, 상속 관계에 있는 자식 클래스에서 호출 가능
    + default (생략시 기본값): 동일한 패키지 내에 있는 클래스들에서만 호출 가능
  - 반환타입: 메서드가 실행을 마치고 반환할 데이터의 타입
    - int, double, String 등
    - 반환값이 없을 경우 `void`로 명시
  - 메서드명: 메서드의 이름으로, [5.4 식별자와 예약어](#54-식별자와-예약어) 단원 참고
  - 매개변수 (Parameter): 메서드 호출 시 외부에서 전달받는 값을 저장하는 변수 (필요 없을 경우 괄호만 남기고 생략 가능)

- 예시:
  ```java
  // 전달되는 인자값 두개의 합계를 반환하는 메서드
  public int getSum(int n1, int n2) {
    int sum = n1 + n2;
    return sum; // sum의 타입은 반환타입과 일치하도록 int가 되어야 함
  }

  // 10과 100의 합계를 출력하는 메서드
  void add() {
    int n1 = 10;
    int n2 = 100;
    int sum = n1 + n2;
    System.out.println(n1 + " + " + n2 + " = " + sum); // 10 + 100 = 110
  }
  ```

### 10.3.2 메서드 호출
- 선언된 메서드를 실행하기 위해 메서드명과 필요한 Argument(인자, 인수)[^27]를 전달하여 호출함
- 형식:
  ```java
  메서드명(인자1, 인자2, ...); // 반환값이 없거나 반환값을 사용하지 않을 때
  변수타입 변수명 = 메서드명(인자1, 인자2, ...); // 반환값을 변수에 저장할 때
  ```
- 예시:
  ```java
  add();
  int result = getSum(3, 5); // getSum 메서드를 호출하고 반환값 8을 result 변수에 저장
  System.out.println(result); // 8
  ```

## 10.4 main 메서드
- 자바 프로그램의 시작점(Entry Point) 역할을 하는 특수한 메서드
- 자바 가상머신(JVM)[^4]은 프로그램을 실행할 때 이 main 메서드를 찾아 실행함

### 10.4.1 전통적인 main 메서드 선언 방식
- 형식:
  ```java
  public class HelloWorld {
    public static void main(String[] args) {
      // 프로그램 실행 시 시작할 코드
      System.out.println("Hello World");
    }
  }
  ```
- 예약어 및 매개변수의 의미:
  + public: JVM[^4]이 어디서나 프로그램 시작점인 main 메서드에 접근하여 실행할 수 있어야 하므로 가장 넓은 범위인 public을 사용함
  + static: JVM[^4]이 클래스의 인스턴스 객체를 메모리에 생성하지 않고도 클래스 이름으로 바로 메서드를 호출하여 실행할 수 있도록 함
  + void: main 메서드의 실행이 끝나면 프로그램 자체가 종료되므로, 호출한 JVM[^4]에게 돌려줄 반환값(리턴값)이 없다는 것을 뜻함
  + String[] args: 프로그램 실행 시 터미널 등 외부에서 전달하는 문자열 매개변수들을 배열 형태로 전달받음

### 10.4.2 자바 21 이후의 새로운 main 메서드 문법
- Implicitly Declared Classes and Instance Main Methods
- 자바 21 버전부터는 프로그래밍 입문자가 간결하게 main 메서드를 작성할 수 있도록 새로운 문법이 제공됨

#### 1) 암묵적으로 선언된 클래스 (Implicitly Declared Classes / Unnamed Classes)
- 클래스 선언('class 클래스명 { }')을 아예 생략하고 파일 내부에 바로 멤버 메서드만 작성하여 선언할 수 있음
- 컴파일러가 소스코드 파일명을 클래스명으로 인식하여 내부적으로 암묵적인 클래스를 자동 생성함
- 단, 외부 다른 클래스에서 임포트(import)하여 사용할 수 없으므로 단독 실행용 클래스에서만 사용됨
- 인텔리제이(IntelliJ) 같은 개발 도구의 프로젝트 탐색기에서는 완전한 자바 클래스 구조로 취급되지 않아 파일명 뒤에 '.java' 확장자가 그대로 표시되는 특징이 있음

#### 2) 인스턴스 메인 메서드 (Instance Main Methods)
- 'static' 키워드와 'public' 키워드를 생략하고 'void main()' 형식으로만 간결하게 메인 메서드를 선언할 수 있음
- 명령행 매개변수가 필요 없을 경우 생략 가능 (String[] args 생략 가능)
- JVM[^4]이 클래스를 실행할 때 내부적으로 객체 인스턴스를 자동으로 먼저 생성한 후 이 main 메서드를 호출함
- 이에 따라 클래스 내부의 다른 인스턴스 메서드를 호출할 때, 예전처럼 클래스 자신의 객체를 new 연산자로 직접 생성하지 않고도 곧바로 메서드명만 써서 간편하게 호출이 가능함

- 예시:
  ```java
  // java 21부터 적용되는 간략화 문법
  void main() {
    System.out.println("New Hello World");
  }
  ```

## 10.5 명령행 매개변수
- 프로그램을 실행할 때 외부에서 값을 전달받아 사용할 수 있는 매개변수
- 자바 프로그램의 시작점인 main 메서드의 매개변수 'String[] args' 배열을 통해 전달됨
- 터미널이나 콘솔 창에서 프로그램을 실행할 때 클래스명 뒤에 공백을 기준으로 전달인자[^27]를 나열하여 전달할 수 있음
- 전달받은 데이터는 모두 문자열(String) 타입으로 처리되므로, 숫자로 사용하려면 형변환이 필요함

- 예시:
  ```java
  public static void main(String[] args) {
    if (args.length < 2) {
      System.out.println("전달된 매개변수가 부족합니다.");
      return;
    }
    String name = args[0];
    int age = Integer.parseInt(args[1]); // 문자열을 정수로 변환(String을 int로 변환)
    System.out.println("이름: " + name + ", 나이: " + age);
  }
  ```

- 실행 방식 (터미널):
  ```bash
  java ArgsTest 하루 6
  ```
  - args[0]에 '하루', args[1]에 '6'이 매칭되어 저장됨

- 💻 실습 (명령행 매개변수): [ch10/ArgsTest.java](../workspace/ch10/ArgsTest.java)

## 10.6 메서드 오버로딩 (Overloading)
- 동일한 이름을 가진 메서드를 한 클래스 내에 여러 개 정의하는 것
- 원래 클래스 내에서 메서드 이름은 중복될 수 없지만, 매개변수의 개수나 타입이 서로 다르면 동일한 이름의 메서드를 중복해서 정의할 수 있도록 허용함
  + 클래스 내의 메서드 이름이 같을 경우 컴파일러가 어떤 메서드를 호출해야 할지 결정할 수 없기 때문에 메서드 이름은 달라야 함
  + 하지만 메서드의 매개변수가 다르다면 이름이 같더라도 식별이 가능하기 때문에 같은 이름으로 정의하는게 허용됨
  + `void add()`와 `void add(int n1, int n2)`는 add라는 이름은 같지만 매개변수가 다르기 때문에 `add()`나 `add(10, 100)` 형태로 호출하면 각각 어떤 메서드를 호출해야 할지 컴파일러가 식별할 수 있음
- 메서드를 사용할 때 데이터 타입에 관계없이 일관된 하나의 이름만 사용할 수 있어 개발자의 편의성을 높일 수 있음

- 예시:
  ```java
  public int multiply(int a, int b) { 
    return a * b; 
  }
  public double multiply(double a, double b) { 
    return a * b; 
  }
  public int multiply(int a, int b, int c) { 
    return a * b * c; 
  }
  ```

## 10.7 가변 인자(varargs, Variable Arguments)
- 메서드를 호출할 때 매개변수의 개수를 동적으로 지정할 수 있게 해주는 기능
- 메서드 정의 시 타입 뒤에 세 개의 마침표(...)를 붙여 선언함
- 특징:
  - 내부적으로 배열 처리: 가변 인자로 전달받은 값들은 메서드 내부에서 해당 타입의 배열로 자동 변환되어 처리됨
  - 가변 인자의 위치 규칙: 가변 인자는 메서드의 매개변수 목록에서 반드시 가장 마지막에 위치해야 함. 마지막이 아닐 경우 컴파일 에러가 발생함
  - 단일 가변 인자 규칙: 하나의 메서드에는 단 하나의 가변 인자만 선언할 수 있음

- 예시 (기본적인 가변 인자):
  ```java
  public void printSum(int... nums) {
    int sum = 0;
    for (int num : nums) {
      sum += num;
    }
    System.out.println(sum);
  }
  printSum(1, 2, 3); // 6
  printSum(10, 20); // 30
  ```

- 예시 (일반 매개변수와 가변 인자를 함께 사용하는 경우):
  ```java
  // 일반 매개변수(String prefix)를 앞에 정의하고 가변 인자(int... nums)를 맨 마지막에 정의
  public void printList(String prefix, int... nums) {
    System.out.print(prefix + ": ");
    int sum = 0;
    for (int num : nums) {
      sum += num;
    }
    System.out.println(sum);
  }

  // 호출 시 일반 매개변수에 매핑될 값 하나를 먼저 넣고, 이어서 가변 인자 값들을 나열함
  printList("홀수 합계", 1, 3, 5); // '홀수 합계: 9' 출력
  printList("짝수 합계", 2, 4, 6, 8); // '짝수 합계: 20' 출력
  ```

[^2]: 플랫폼: 프로그램이 실행되는 컴퓨터 시스템 환경으로, 대개 하드웨어(CPU)와 운영체제(OS)의 조합을 의미
[^3]: 바이트코드: JVM(자바 가상 머신)과 같은 가상 머신이 이해할 수 있도록 설계된 중간 언어로, 기계어와 고급 언어의 중간 형태
[^4]: 가상 머신 (Virtual Machine): 실제 컴퓨터 하드웨어 위에 소프트웨어로 구축된 가상의 컴퓨터로, 플랫폼에 상관없이 동일한 바이트코드를 그 환경에 맞는 기계어로 실시간 번역해 줌
[^5]: JIT 컴파일러 (Just-In-Time Compiler): 실행 중인 프로그램의 바이트코드 중 자주 실행되는 부분(핫스팟)을 실시간으로 실제 하드웨어의 기계어로 직접 번역하여 실행 속도를 비약적으로 높여주는 장치
[^6]: 클라이언트 (Client): 네트워크를 통해 서버라는 다른 컴퓨터에 서비스를 요청하고 데이터를 받는 역할을 하는 사용자 컴퓨터나 소프트웨어
[^7]: 가비지 컬렉터 (Garbage Collector): 프로그램이 사용하지 않고 남겨둔 메모리 영역을 가상 머신이 알아서 감지하고 자동으로 회수하여 메모리 부족을 방지하는 시스템
[^8]: 멀티스레드 (Multi-thread): 하나의 프로그램 내에서 여러 개의 실행 흐름이 동시에 작동하여 작업을 병렬로 처리하는 방식
[^9]: API (Application Programming Interface): 소프트웨어 간에 서로 데이터를 주고받고 기능을 호출할 수 있도록 규격화한 연결 통로이자 규약
[^10]: 클래스 로더 (Class Loader): 컴파일된 자바 클래스 파일(.class)을 읽어서 가상 머신의 메모리 영역에 동적으로 적재하는 엔진
[^11]: 실행 엔진 (Execution Engine): 메모리에 로드된 바이트코드를 실행하여 컴퓨터가 실행할 수 있는 명령어 형태로 변환하고 처리하는 엔진
[^12]: 네이티브 코드 (Native Code): 특정 CPU와 운영체제가 직접 이해하고 실행할 수 있는 하드웨어 종속적인 기계어 코드
[^13]: 런타임 데이터 영역 (Runtime Data Area): 자바 가상 머신이 프로그램을 실행하기 위해 운영체제로부터 할당받은 메모리 공간
[^14]: LIFO (Last In First Out): 후입선출. 가장 마지막에 들어온 데이터가 가장 먼저 나가는 메모리 관리 방식 (예: 쌓아 올린 접시)
[^15]: JRE (Java Runtime Environment): 자바 실행 환경. 자바 프로그램을 실행하는 데 필요한 가상 머신과 표준 라이브러리를 묶어 제공하는 패키지
[^16]: 레거시 (Legacy): 과거에 개발되어 현재도 사용 중인 낡은 하드웨어, 소프트웨어 시스템이나 오래된 코드 구조
[^17]: 임베디드 (Embedded): 기기 내부에 특정 기능을 수행하도록 전용 하드웨어와 소프트웨어를 내장시킨 내장형 시스템 (예: 스마트 냉장고)
[^18]: 클라우드 (Cloud): 인터넷을 통해 다른 곳에 있는 서버, 저장소, 데이터베이스 등의 컴퓨팅 자원을 빌려 쓰는 서비스
[^19]: 리팩토링 (Refactoring): 프로그램의 겉으로 보이는 동작은 바꾸지 않으면서, 내부 코드의 가독성을 높이고 구조를 깔끔하게 개선하는 작업
[^20]: 유니코드 (Unicode): 전 세계의 모든 문자를 컴퓨터에서 일관되게 표현하고 다룰 수 있도록 설계된 국제 표준 문자 코드 규격
[^21]: 제어문 (Statement): 프로그램의 실행 흐름을 바꾸거나 제어하는 명령어 (예: 조건문 if, 반복문 for 등)
[^22]: 식 (Expression): 계산을 거쳐 하나의 최종 값으로 평가되는 코드의 조합 (예: 5 + 3, x > 10 등)
[^23]: 루프 (Loop): 특정 조건이 만족하는 동안 동일한 코드 블록을 반복해서 실행하는 제어 흐름 구조
[^24]: 자료구조 (Data Structure): 컴퓨터 메모리에서 데이터를 효율적으로 다루기 위해 데이터를 조직화하고 저장하는 방법
[^25]: 디버깅 (Debugging): 프로그램에 발생한 오류(버그)를 찾아내고 원인을 분석하여 수정하는 과정
[^26]: 예외 (Exception): 프로그램 실행 중에 예기치 않게 발생하는 오류나 비정상적인 상황
[^27]: Argument (인자, 인수): 함수나 메서드를 호출할 때 실제로 전달하는 구체적인 값 (매개변수에 대입됨)
