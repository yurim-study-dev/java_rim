## 가상 스레드 (Virtual Thread) - ch05/virtual

### 기존 스레드 vs 가상 스레드

```java
// 기존 방식 (플랫폼 스레드)
new Thread(odd, "홀수 스레드").start();

// 가상 스레드 (JDK 21+)
Thread.ofVirtual().start(odd);
```

| | 플랫폼 스레드 | 가상 스레드 |
|--|-------------|-----------|
| 생성 비용 | 무거움 (OS 자원 사용) | 가벼움 (JVM이 관리) |
| 동시 생성 수 | 수천 개 한계 | 수백만 개 가능 |
| 사용처 | 일반적인 멀티스레드 | 대규모 동시 접속 서버 |

### join() — 스레드가 끝날 때까지 기다리기

```java
Thread oddThread = Thread.ofVirtual().start(odd);
Thread evenThread = Thread.ofVirtual().start(even);

oddThread.join();   // 홀수 스레드 끝날 때까지 대기
evenThread.join();  // 짝수 스레드 끝날 때까지 대기

System.out.println("main 종료");  // 두 스레드 다 끝난 후 실행
```

### 실습 코드 (virtual/MultiThreadTest.java)

```java
Thread oddThread  = Thread.ofVirtual().start(odd);
Thread evenThread = Thread.ofVirtual().start(even);

// 익명 클래스로 즉석 작업 정의
Thread t3 = Thread.ofVirtual().start(new Runnable(){
    @Override
    public void run() {
        for(int i = 3; i <= 10; i += 3){
            System.out.println("3의 배수: " + i);
        }
    }
});

oddThread.join();
evenThread.join();
t3.join();
```

## 람다식 (Lambda Expression) - ch06/lambda

### 람다식이란?

익명 클래스를 간결하게 줄인 문법. 함수형 인터페이스(추상 메서드 1개)에만 사용 가능.

```java
// 1단계: 내부 클래스
class CalculatorImpl implements Calculator {
    public int add(int a, int b) { return a + b; }
}
Calculator cal = new CalculatorImpl();

// 2단계: 익명 클래스
Calculator cal = new Calculator() {
    public int add(int a, int b) { return a + b; }
};

// 3단계: 람다식 (최종)
Calculator cal = (a, b) -> a + b;
```

### 람다 캡처링 — 외부 변수 쓸 때 주의

```java
Calculator test3() {
    int defaultVal = 10; // 사실상 final (값이 바뀌지 않음)

    Calculator cal = (a, b) -> a + b + defaultVal; // 외부 변수 사용 가능
    return cal;
}
```

> 람다 안에서 외부 지역 변수를 쓸 수 있는데, 그 변수는 **값이 바뀌면 안 됨** (final이어야 함).  
> 이유: 람다의 생명주기가 변수보다 길 수 있어서, 복사해서 쓰기 때문.

## 표준 함수형 인터페이스 - ch06/lambda/StandardFunctionalTest.java

| 인터페이스 | 입력 | 반환 | 메서드 | 용도 |
|-----------|------|------|--------|------|
| `Predicate<T>` | T | boolean | `test()` | 조건 판별 |
| `Consumer<T>` | T | 없음 | `accept()` | 소비 (출력/저장) |
| `Function<T, R>` | T | R | `apply()` | 변환 |
| `Supplier<T>` | 없음 | T | `get()` | 생성/공급 |

```java
// Predicate — 100 이하인지 판별
Predicate<Integer> checkLimit = num -> num <= 100;
checkLimit.test(120); // false
checkLimit.test(90);  // true

// Consumer — 로그 출력
Consumer<String> writeLog = System.out::println; // 메서드 참조
writeLog.accept("사용자 로그인");

// Function — String을 int로 변환
Function<String, Integer> convert = Integer::parseInt; // 메서드 참조
convert.apply("100"); // 100

// Supplier — 랜덤 값 생성
Supplier<Double> randomVal = Math::random; // 메서드 참조
randomVal.get(); // 0.0 ~ 0.999...
```

### 실습 문제

```java
// 주사위: n을 받아서 1~n 사이 랜덤 정수 반환
Function<Integer, Integer> dice = (n) -> (int)(Math.random() * n) + 1;
dice.apply(6); // 1~6 중 하나
dice.apply(4); // 1~4 중 하나

// 글자수: String을 받아서 길이 반환
Function<String, Integer> strLength = String::length; // 메서드 참조
strLength.apply("hello");           // 5
strLength.apply("spring framework"); // 16
```

## 메서드 참조 (Method Reference)

람다식을 더 짧게 줄이는 방법. `클래스::메서드명` 형태.

```java
// 람다 → 메서드 참조
(s) -> Integer.parseInt(s)  →  Integer::parseInt   // 정적 메서드
(s) -> s.length()           →  String::length      // 인스턴스 메서드
(s) -> System.out.println(s) → System.out::println // 특정 객체의 메서드
() -> Math.random()         →  Math::random        // 정적 메서드
```

## 어노테이션 (Annotation) - ch06/annotation

### 어노테이션이란?

코드에 **메타데이터(추가 정보)** 를 붙이는 특수 주석.  
일반 주석(`//`)과 달리 컴파일러나 JVM이 읽고 특별한 처리를 함.

```java
@Override         // "이 메서드는 오버라이딩한 거야" → 컴파일러가 검증
@FunctionalInterface // "추상 메서드 1개만 가져야 해" → 위반 시 오류
@Deprecated       // "이건 쓰지 마세요, 곧 삭제됨"
```

### 커스텀 어노테이션 만들기

```java
@Target(ElementType.METHOD)       // 메서드에만 붙일 수 있음
@Retention(RetentionPolicy.RUNTIME) // 실행 중에도 정보 유지
public @interface MeasureTime {   // @interface = 어노테이션 선언
}
```

```java
// 사용
public class Work {
    @MeasureTime  // 이 메서드에 MeasureTime 어노테이션 적용
    public void task1() { }

    public void task2() { } // 어노테이션 없음
}
```

### @Retention 종류

| 정책 | 유지 시점 | 설명 |
|------|----------|------|
| `SOURCE` | 컴파일 전까지 | 빌드 후 사라짐 |
| `CLASS` | .class 파일까지 | 실행 중엔 사라짐 |
| `RUNTIME` | 실행 중까지 | 런타임에서도 읽을 수 있음 |

## 배운 점

1. ✅ 가상 스레드 `Thread.ofVirtual().start()` — 기존보다 훨씬 가볍고 많이 만들 수 있음.
2. ✅ `join()` — 특정 스레드가 끝날 때까지 현재 스레드를 대기시킴.
3. ✅ 람다식 발전 과정: 내부 클래스 → 익명 클래스 → 람다식 (점점 짧아짐).
4. ✅ 표준 함수형 인터페이스 4종 — `Predicate`(판별) / `Consumer`(소비) / `Function`(변환) / `Supplier`(생성).
5. ✅ 메서드 참조 `::` — 람다를 더 짧게 줄이는 문법.
6. ✅ `Math.random() * n + 1` — 1~n 랜덤 정수 공식.
7. ✅ 어노테이션 = 코드에 붙이는 메타데이터, `@interface`로 직접 만들 수 있음.
8. ✅ `@Target` / `@Retention` — 어노테이션이 어디에 붙는지, 언제까지 유지되는지 설정.

## 오늘 핵심 정리

```
가상 스레드
  Thread.ofVirtual().start(runnable) → 가볍고 많이 생성 가능
  thread.join()                      → 그 스레드 끝날 때까지 기다림

람다식
  (a, b) -> a + b           // 기본
  a -> a + 10               // 파라미터 1개: 괄호 생략
  () -> Math.random()       // 파라미터 없음

표준 함수형 인터페이스
  Predicate<T>    → test()   : 조건 판별 (boolean 반환)
  Consumer<T>     → accept() : 소비 (반환 없음)
  Function<T, R>  → apply()  : 변환 (T 받아서 R 반환)
  Supplier<T>     → get()    : 생성 (입력 없이 T 반환)

메서드 참조
  Integer::parseInt   // 정적 메서드
  String::length      // 인스턴스 메서드
  System.out::println // 특정 객체 메서드

어노테이션
  @interface 이름 { }              // 커스텀 어노테이션 선언
  @Target(ElementType.METHOD)      // 메서드에만 적용
  @Retention(RetentionPolicy.RUNTIME) // 런타임까지 유지
```
