## 자바 입출력(I/O) - ch03

### 핵심 개념: 스트림(Stream)이란?

데이터가 흐르는 단방향 파이프.  
읽기용(입력 스트림)과 쓰기용(출력 스트림)이 완전 분리되어 독립적으로 동작한다.

```
데이터 근원지(Source)  ──[입력 스트림]──→  프로그램  ──[출력 스트림]──→  목적지(Destination)
키보드, 파일, 네트워크                                                  콘솔, 파일, 네트워크
```

### 스트림 분류

**1) 데이터 단위**

| 구분 | 단위 | 최상위 클래스 | 사용 대상 |
|------|------|--------------|----------|
| 바이트 스트림 | 1byte | `InputStream` / `OutputStream` | 이미지, 영상, 모든 바이너리 파일 |
| 문자 스트림 | 2byte(char) | `Reader` / `Writer` | 텍스트 파일 |

**2) 연결 방식**

| 구분 | 설명 | 예시 |
|------|------|------|
| 1차 스트림 | 실제 장치(파일, 메모리)에 직접 연결 | `FileInputStream`, `FileOutputStream` |
| 2차 스트림 | 1차 스트림에 붙여서 기능 추가 | `BufferedInputStream` (속도 향상) |

### 오늘 실습한 4가지 흐름

```
[1번] 키보드(System.in)      →  콘솔(System.out)           KeyboardToConsole
[2번] 키보드(System.in)      →  파일(FileOutputStream)      KeyboardToFile
[3번] 파일(FileInputStream)  →  콘솔(System.out)            FileToConsole
[4번] 파일(FileInputStream)  →  파일(FileOutputStream)      FileToFile
```

코드 패턴은 4개 다 동일 — **"읽어서 → 써라"**:

```java
int readData = 0;
while ((readData = 읽기스트림.read()) != -1) {  // -1 = 끝
    쓰기스트림.write(readData);
}
```

### 실습 코드 (KeyboardToConsole.java — 1번)

```java
// 1. 키보드 → 콘솔
try {
    int readData = 0;
    while ((readData = System.in.read()) != -1) {
        System.out.write(readData);
    }
} catch (IOException e) {
    System.err.println("입출력 예외 발생: " + e.getMessage());
}
```

### 실습 코드 (FileToFile.java — 4번)

```java
// 4. 파일 → 파일 (try-with-resources로 자원 자동 해제)
try (
    InputStream fis = new FileInputStream("output.txt");
    OutputStream fos = new FileOutputStream("output-copy.txt")
) {
    int readData = 0;
    while ((readData = fis.read()) != -1) {
        fos.write(readData);
    }
} catch (IOException e) {
    System.err.println("입출력 예외 발생: " + e.getMessage());
}
```

### 성능 비교 실습 (FileCopyTest.java)

MySQL 드라이버 jar 파일을 복사하면서 3가지 방식의 속도를 비교했다.

```java
// 방법 1: 1byte씩 읽기 (가장 느림)
void copyFile(String org, String dest) { ... }

// 방법 2: BufferedInputStream 사용 (2차 스트림, 빠름)
void copyFileUseBuffer(String org, String dest) {
    InputStream bis = new BufferedInputStream(new FileInputStream(org));
    OutputStream bos = new BufferedOutputStream(new FileOutputStream(dest));
    // ...
}

// 방법 3: 직접 byte[] 버퍼 생성 (가장 빠름, 실용적)
void copyFileCustomBuffer(String org, String dest) {
    byte[] buffer = new byte[1024 * 8]; // 8KB 버퍼
    int readSize = 0;
    while ((readSize = fis.read(buffer)) != -1) {
        fos.write(buffer, 0, readSize); // 읽은 만큼만 쓰기
    }
}
```

> **왜 버퍼가 빠를까?**  
> 1byte씩 읽으면 파일 접근을 수백만 번 반복 → 느림  
> 8KB씩 읽으면 파일 접근 횟수가 수백만분의 1로 줄어듦 → 빠름

### 표준 입출력 장치

```java
System.in   // 키보드 (InputStream 타입)
System.out  // 콘솔 화면 (PrintStream 타입) - print(), println() 사용
System.err  // 에러 전용 콘솔 출력 (빨간 글씨) - 오류 메시지 출력용
```

### 예외 처리 주의 사항

| 상황 | 원인 | 대처 |
|------|------|------|
| `FileNotFoundException` | 파일 경로가 잘못됨 / 파일이 없음 | `file.exists()`로 먼저 확인 |
| 자원 누수 | 스트림을 닫지 않으면 OS 자원 고갈 | `try-with-resources` 사용 |
| 데이터 지연 | 버퍼에 갇혀서 목적지에 안 보내짐 | `flush()` 호출하거나 `close()` 시 자동 처리됨 |

## 자바 네트워크 프로그래밍 - ch04

### 기본 개념

```
IP   = 건물 주소 (어느 컴퓨터인지)
Port = 몇 호실   (그 컴퓨터의 어느 프로그램인지)
→ 192.168.0.1:8080 = "이 컴퓨터의 8080번 프로그램에 연결"
```

**자주 쓰는 포트 번호:**

| 포트 | 용도 |
|------|------|
| 80 | HTTP (웹) |
| 443 | HTTPS (보안 웹) |
| 3306 | MySQL |
| 8080 | 톰캣 (자바 웹서버) |

### TCP vs UDP

| | TCP | UDP |
|--|-----|-----|
| 비유 | 등기우편 (전달 확인함) | 전단지 배포 (그냥 던짐) |
| 신뢰성 | 높음 (유실 시 재전송) | 낮음 |
| 속도 | 느림 | 빠름 |
| 사용처 | 웹, 파일 다운로드 | 게임, 영상 스트리밍 |

### Socket과 ServerSocket

```java
// 서버: 포트 열고 클라이언트 기다리기
ServerSocket server = new ServerSocket(50000);
Socket client = server.accept(); // 접속 올 때까지 대기 (블로킹)

// 클라이언트: 서버에 접속
Socket socket = new Socket("localhost", 50000);
```

소켓에 연결되면 → `getInputStream()` / `getOutputStream()` 으로 데이터 주고받기  
= I/O에서 배운 스트림 방식 그대로 사용!

## 배운 점

1. ✅ 스트림은 단방향 — 읽기/쓰기를 따로 열어야 함.
2. ✅ 바이트 스트림(`InputStream`/`OutputStream`) vs 문자 스트림(`Reader`/`Writer`) — 텍스트는 Reader/Writer, 나머지는 바이트.
3. ✅ 1차 스트림에 2차 스트림(`Buffered~`) 붙이면 성능이 크게 향상됨.
4. ✅ 파일 I/O는 무조건 try-with-resources — 자원 자동 해제.
5. ✅ 네트워크 소켓도 결국 I/O 스트림 — 연결 후 `getInputStream()/getOutputStream()`으로 데이터 송수신.
6. ✅ `System.err`은 에러 전용 출력 — `System.out`과 별도로 구분해서 사용.
7. ✅ `flush()` — 버퍼에 갇힌 데이터 강제 전송. `close()` 시에는 자동 호출됨.

## 오늘 핵심 정리

```
I/O 스트림 구조
  입력 스트림: InputStream (바이트), Reader (문자)
  출력 스트림: OutputStream (바이트), Writer (문자)

  1차 스트림: 장치와 직접 연결  (FileInputStream, FileOutputStream)
  2차 스트림: 1차에 붙여서 기능 추가 (BufferedInputStream - 속도 향상)

파일 입출력 패턴 (항상 이 구조)
  try (InputStream fis = new FileInputStream("파일명");
       OutputStream fos = new FileOutputStream("파일명")) {
      int data;
      while ((data = fis.read()) != -1) { fos.write(data); }
  } catch (IOException e) { ... }

표준 장치
  System.in  → 키보드
  System.out → 콘솔 (print/println)
  System.err → 에러 콘솔 (빨간 글씨)

네트워크
  IP + Port = 주소 (192.168.0.1:8080)
  TCP = 신뢰성 (웹/파일), UDP = 속도 (게임/스트리밍)
  ServerSocket.accept() → 대기 → Socket 반환 → 스트림으로 통신
```
