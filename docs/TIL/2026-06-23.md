## 자료구조 개요 - 2.1

자료구조(Data Structure)란 데이터를 효율적으로 저장·관리하기 위한 논리적인 구조.  
자바 컬렉션 프레임워크는 이를 표준화된 인터페이스로 제공함.

| 자료구조 | 특징 | 자바 구현체 |
|---------|------|------------|
| List | 순서 O, 중복 허용 | ArrayList, LinkedList |
| Set | 순서 X, 중복 불허 | HashSet, TreeSet, LinkedHashSet |
| Map | Key-Value 쌍, Key 중복 불가 | HashMap, TreeMap, LinkedHashMap |
| Stack | 후입선출 (LIFO) | Stack |
| Queue | 선입선출 (FIFO) | LinkedList, PriorityQueue |

## Set 인터페이스 - 2.5

**중복 불허** 가 핵심. 구현체마다 순서 처리 방식이 다름.

```java
Set<String> set = new HashSet<>();
set.add("사과");
set.add("오렌지");
set.add("사과"); // 중복 → 무시, false 반환
System.out.println(set); // [오렌지, 사과] — 순서 랜덤
```

| 구현체 | 순서 | 성능 | 특징 |
|--------|------|------|------|
| HashSet | 없음 | 빠름 | 일반적으로 가장 많이 사용 |
| TreeSet | 오름차순 정렬 | 느림 | 삽입 시마다 정렬 연산 발생 |
| LinkedHashSet | 삽입 순서 유지 | 중간 | 순서가 필요할 때 |

## Map 인터페이스 - 2.6

**Key-Value 쌍**으로 저장. Key는 중복 불가, 동일 Key 저장 시 Value 덮어씀.

```java
Map<String, String> fruits = new LinkedHashMap<>();
fruits.put("월", "바나나");
fruits.put("화", "사과");
fruits.put("수", "오렌지");
fruits.put("수", "수박"); // "수" 키 중복 → 기존 "오렌지" 덮어씌워짐

String fridayFruit = fruits.get("금").toUpperCase(); // 값 꺼내서 바로 메서드 체이닝
```

**Map 순회 방법 비교:**

```java
// keySet() — key만 먼저 가져오고, value는 get()으로 다시 조회 (비효율)
for(String key : fruits.keySet()){
    System.out.println(key + ": " + fruits.get(key));
}

// entrySet() — key와 value를 한 번에 가져옴 (권장)
for(Map.Entry<String, String> entry : fruits.entrySet()){
    System.out.println(entry.getKey() + ": " + entry.getValue());
}
```

| 구현체 | 순서 | Key null 허용 |
|--------|------|--------------|
| HashMap | 없음 | O |
| TreeMap | Key 기준 오름차순 | X |
| LinkedHashMap | 삽입 순서 유지 | O |

## Stack과 Queue - 2.1 실습

### Stack — LIFO (마지막에 넣은 게 먼저 나옴)

```java
Stack stack = new Stack();
stack.push(10); stack.push(20); stack.push(30); stack.push(40);

System.out.println(stack.pop()); // 40 ← 마지막에 넣은 게 먼저 나옴
System.out.println(stack.pop()); // 30
System.out.println(stack.pop()); // 20
// 남은 것: [10]
```

> 비유: 접시 쌓기 — 맨 위에 올린 것부터 꺼냄

### Queue — FIFO (먼저 넣은 게 먼저 나옴)

```java
Queue queue = new LinkedList();
queue.offer(10); queue.offer(20); queue.offer(30); queue.offer(40);

System.out.println(queue.poll()); // 10 ← 먼저 넣은 게 먼저 나옴
System.out.println(queue.poll()); // 20
System.out.println(queue.poll()); // 30
// 남은 것: [40]
```

> 비유: 줄서기 — 먼저 온 사람이 먼저 나감

## 제네릭(Generic) - 2.7

### 도입 배경

제네릭 이전에는 컬렉션에 뭐든 넣으려면 `Object` 타입을 써야 했음.  
꺼낼 때마다 강제 캐스팅 필요 → 실수하면 런타임에 `ClassCastException` 발생.

```java
// 제네릭 없던 시절
List list = new ArrayList();
list.add("문자열");
list.add(123);           // 정수도 들어감 — 타입 혼재
String s = (String) list.get(1); // 런타임 에러! 123을 String으로 캐스팅 시도
```

```java
// 제네릭 도입 후
List<String> list = new ArrayList<>();
list.add("문자열");
// list.add(123); // 컴파일 에러! — 엉뚱한 타입 컴파일 시점에 차단
String s = list.get(0); // 캐스팅 불필요
```

### 기본 사용법 — MyList 인터페이스

```java
// <E>: 타입 파라미터 — 실제 타입은 사용할 때 결정
public interface MyList<E> {
    void add(E obj);          // E 타입의 요소 추가
    void add(int index, E obj);
    void remove(int index);
    E get(int index);         // E 타입의 요소 반환
    int size();
}
```

```java
MyList<String> list = new MyArray<>();  // E = String으로 확정
MyList<Integer> list2 = new MyArray<>(); // E = Integer로 확정
```

### 타입 파라미터 이름 약속

| 기호 | 의미 | 사용 예 |
|------|------|---------|
| T | Type (범용) | `class Box<T>` |
| E | Element (컬렉션 요소) | `List<E>` |
| K | Key | `Map<K, V>` |
| V | Value | `Map<K, V>` |
| N | Number | `<T extends Number>` |

### 제한된 타입 파라미터 (Bounded Type Parameter)

```java
// T에 아무 타입이나 못 넣게 Number 하위만 허용
class Calculator<T extends Number> {
    double sum(T a, T b){
        return a.doubleValue() + b.doubleValue(); // Number 메서드 안전하게 사용 가능
    }
}

Calculator<Integer> c = new Calculator<>(); // OK
// Calculator<String> c = new Calculator<>(); // 컴파일 에러!
```

## 인터페이스 다형성으로 코드 단순화 — CollectionTest

구현체별로 오버로딩하던 방식 → `Collection<String>` 하나로 통일:

```java
// Before: 각 타입마다 별도 메서드 필요 (비효율)
void printFruits(ArrayList<String> fruits){ ... }
void printFruits(LinkedList<String> fruits){ ... }
void printFruits(HashSet<String> fruits){ ... }
// ...

// After: Collection 인터페이스 하나로 전부 처리 (권장)
void printFruits(Collection<String> fruits){
    for(String fruit : fruits){
        System.out.println(fruit);
    }
}
// ArrayList, LinkedList, HashSet, TreeSet 모두 이 메서드 하나로 처리 가능!
```

> 구현체가 바뀌어도 `printFruits()` 수정 불필요 — 인터페이스 다형성의 핵심 장점.

## 배운점

1. ✅ Set은 중복 불허 — HashSet(순서 없음), TreeSet(정렬), LinkedHashSet(삽입 순서 유지).
2. ✅ Map은 Key-Value 쌍 — 동일 Key로 put하면 기존 Value가 덮어써짐.
3. ✅ Map 순회는 `entrySet()` 권장 — `keySet()`은 value 조회를 위해 `get()` 을 다시 호출해야 해서 비효율.
4. ✅ Stack은 LIFO(후입선출), Queue는 FIFO(선입선출) — `push/pop` vs `offer/poll`.
5. ✅ 제네릭은 타입 안정성 확보 + 캐스팅 생략 — 컴파일 시점에 잘못된 타입을 잡아줌.
6. ✅ `<T extends Number>` 처럼 범위를 제한하면 특정 클래스의 메서드를 안전하게 사용 가능.
7. ✅ `Collection<String>` 하나로 모든 컬렉션 구현체를 다룰 수 있음 — 인터페이스 다형성의 실용적 활용.

## 오늘 핵심 정리

```
자료구조 5가지
  List  → 순서 O, 중복 O
  Set   → 순서 X, 중복 X (HashSet: 랜덤 / TreeSet: 정렬 / LinkedHashSet: 삽입 순서)
  Map   → Key-Value, Key 중복 X (HashMap: 랜덤 / TreeMap: 정렬 / LinkedHashMap: 삽입 순서)
  Stack → LIFO: push() / pop()
  Queue → FIFO: offer() / poll()

Map 순회
  keySet()   → key만 가져오고 value는 get()으로 재조회 (비효율)
  entrySet() → key+value 한 번에 (권장)

제네릭
  List<String>         → String만 담을 수 있는 List
  <T extends Number>   → Number 하위 타입만 허용
  타입 파라미터: T(범용), E(컬렉션 요소), K(키), V(값)

인터페이스 다형성
  Collection<String>으로 ArrayList, LinkedList, HashSet 등 모두 처리 가능
```
