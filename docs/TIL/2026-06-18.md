| 개념 | 핵심 |
|------|------|
| JDBC 5단계 | Connection → Statement/PreparedStatement → 바인딩 → execute → close(역순) |
| Statement | SQL 직접 문자열 조합, SQL Injection 위험 |

## 오전: 게시글 CRUD 실습 (JdbcPostTest)

`post` 테이블을 대상으로 JDBC CRUD 전체 흐름 실습.

```java
// main 실행 순서
findAll();                                              // 전체 목록 조회
insert(2, "2번이 등록한 게시글", "안녕하세요. 자바 공부 해요."); // 등록

findAll();                                              // 전체 목록 조회
delete(10);                                             // 단건 삭제
deleteAll(2);                                           // 특정 회원 게시글 전체 삭제
findAll();                                              // 전체 목록 조회
```

### insert() — 게시글 등록 (C)

```java
static void insert(int memberId, String title, String content){
    String sql = "INSERT INTO post (member_id, title, content) VALUES ("
                 + memberId + ", '" + title + "', '" + content + "')";
    // executeUpdate() → 영향받은 행 수(int) 반환
    int affectedRows = stmt.executeUpdate(sql);
    System.out.println("게시글 등록 완료: " + affectedRows + "건 반영됨.");
}
```

---

### findAll() — 전체 목록 조회 (R)

```java
static void findAll(){
    String sql = "SELECT id, title, view_count viewCount, created_at AS createdAt FROM post";
    rs = stmt.executeQuery(sql);

    while(rs.next()){
        int id = rs.getInt("id");
        String title = rs.getString("title");
        int viewCount = rs.getInt("viewCount");   // SQL 별칭(viewCount)으로 꺼냄
        String createdAt = rs.getString("createdAt");
        System.out.println("ID: " + id + ", 제목: " + title + ", 조회수: " + viewCount + ", 작성일: " + createdAt);
    }
}
```

> SQL에서 컬럼에 별칭을 붙이면(`view_count viewCount`) Java에서 `rs.getInt("viewCount")`처럼 별칭으로 값을 꺼낼 수 있다.  
> `AS` 키워드는 생략 가능 — `view_count viewCount`와 `view_count AS viewCount`는 동일.

### findById() — 단건 조회 (R)

```java
static void findById(int id){
    String sql = "SELECT id, title, content, view_count viewCount, created_at AS createdAt FROM post WHERE id = " + id;
    rs = stmt.executeQuery(sql);

    while(rs.next()){
        String title = rs.getString("title");
        String content = rs.getString("content");
        int viewCount = rs.getInt("viewCount");
        String createdAt = rs.getString("createdAt");
        System.out.println("ID: " + id + ", 제목: " + title + ", 내용: " + content + ", 조회수: " + viewCount + ", 작성일: " + createdAt);
    }
}
```

### update() — 게시글 수정 (U)

```java

    String sql = "UPDATE post SET title = '" + title + "', content = '" + content + "' WHERE id = " + id;
    int affectedRows = stmt.executeUpdate(sql);
    System.out.println("게시글 수정 완료: " + affectedRows + "건 반영됨.");
}
```

### delete() / deleteAll() — 게시글 삭제 (D)

```java
// 특정 게시글 1건 삭제
static void delete(int id){
    String sql = "DELETE FROM post WHERE id=" + id;
    int affectedRows = stmt.executeUpdate(sql);
    System.out.println(id + "번 게시글 삭제 완료: " + affectedRows + "건 반영됨.");
}

// 특정 회원의 게시글 전체 삭제
static void deleteAll(int memberId){
    String sql = "DELETE FROM post WHERE member_id=" + memberId;
    int affectedRows = stmt.executeUpdate(sql);
    System.out.println(memberId + "번 회원의 모든 게시글 삭제 완료: " + affectedRows + "건 반영됨.");
}
```

> `delete(id)` — WHERE id로 단건 삭제  
> `deleteAll(memberId)` — WHERE member_id로 해당 회원 게시글 전체 삭제

## 오후: PreparedStatement CRUD + SQL Injection 방어 (JdbcPostPreparedTest)

오전에 `Statement`로 작성했던 CRUD를 `PreparedStatement`로 리팩토링.

### Statement vs PreparedStatement 비교

```java
// Statement — SQL 문자열 직접 조합 (SQL Injection 위험)
stmt.executeUpdate("INSERT INTO post (member_id, title, content) VALUES ("
    + memberId + ", '" + title + "', '" + content + "')");

// PreparedStatement — ? 바인딩 (SQL Injection 차단)
String sql = "INSERT INTO post (member_id, title, content) VALUES (?, ?, ?)";
pstmt = conn.prepareStatement(sql);
pstmt.setInt(1, memberId);
pstmt.setString(2, title);
pstmt.setString(3, content);
pstmt.executeUpdate();
```

---

### SQL Injection 방어 실습 — login()

```java
// 정상 로그인
login("haru@gmail.com", "pwd123");   // → 로그인 성공

// 비밀번호 틀림
login("haru@gmail.com", "123");      // → 아이디와 패스워드를 확인하세요.

// SQL Injection 시도
login("haru@gmail.com' OR '1' = '1", "sdfsadfasdf");  // → 아이디와 패스워드를 확인하세요.
```

Statement를 쓰면 세 번째 이메일이 SQL에 그대로 들어가서 조건이 항상 참이 돼 로그인이 뚫린다.
PreparedStatement는 특수문자를 이스케이프 처리해서 쿼리 구조 자체가 바뀌지 않는다.

---

### 동적 SQL — findAll(String keyword)

검색어가 있을 때만 WHERE 절을 붙이는 패턴.

```java
static void findAll(String keyword){
    String sql = "SELECT id, title, view_count viewCount, created_at AS createdAt FROM post";

    boolean hasKeyword = keyword != null && !keyword.equals("");
    if(hasKeyword){
        sql += " WHERE title LIKE ? OR content LIKE ?";
    }

    pstmt = conn.prepareStatement(sql);

    if(hasKeyword){
        pstmt.setString(1, "%" + keyword + "%");
        pstmt.setString(2, "%" + keyword + "%");
    }
    rs = pstmt.executeQuery();
}

// 사용
findAll();        // 전체 조회
findAll("자바");  // '자바' 포함 게시글만 조회
```

> `findAll()` → `findAll("")` 호출로 위임 — 오버로딩으로 두 케이스를 하나의 메서드로 처리.

## 오후: 커넥션 풀(Connection Pool) - HikariCP

### 왜 커넥션 풀이 필요한가?

`DriverManager.getConnection()`은 매번 DB와 물리적 연결을 새로 맺는다.
→ 네트워크 통신 + DB 인증 절차로 **시간 비용이 크다.**
→ 동시 요청이 많으면 서버 자원이 급격히 낭비됨.

커넥션 풀: **미리 연결을 여러 개 만들어 풀에 보관** → 요청 시 대여, 완료 후 반납(재사용).

대표 라이브러리: **HikariCP** (가볍고 빠름, Spring Boot 기본 내장)

---

### 라이브러리 설치 (3개 jar)

| 파일 | 역할 |
|------|------|
| `HikariCP-7.1.0.jar` | 커넥션 풀 본체 |
| `slf4j-api-2.0.18.jar` | HikariCP 내부 로깅 API |
| `slf4j-simple-2.0.18.jar` | 콘솔 출력용 로깅 구현체 |

> SLF4J 두 파일이 없으면 `NoClassDefFoundError` 발생 — 반드시 함께 등록해야 함.

IntelliJ 등록: `File > Project Structure > Libraries > + > Java` 에서 3개 선택

### HikariCP 설정 방법

**방법 1 — 코드에서 직접 설정 (메서드 방식)**

```java
HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:mysql://localhost:3306/board_db?...");
config.setUsername("user1");
config.setPassword("1111");
config.setMaximumPoolSize(10);   // 최대 커넥션 수
config.setMinimumIdle(5);        // 최소 대기 커넥션 수
config.setConnectionTimeout(30 * 1000);   // 30초
config.setIdleTimeout(10 * 60 * 1000);    // 10분

DataSource dataSource = new HikariDataSource(config);
```

**방법 2 — 외부 설정 파일 (properties 방식)**

```properties
# hikari.properties
jdbcUrl=jdbc:mysql://localhost:3306/board_db?serverTimezone=UTC&useSSL=false&allowPublicKeyRetrieval=true
username=user1
password=1111
maximumPoolSize=10
minimumIdle=5
connectionTimeout=30000
idleTimeout=600000
```

```java
HikariConfig config = new HikariConfig("/hikari.properties");
DataSource dataSource = new HikariDataSource(config);
```

> properties 방식은 코드 변경 없이 설정값만 수정 가능 → 환경(개발/운영) 분리에 유리.

---

### DriverManager vs DataSource 연결 비교

```java
// 기존: 매번 새 연결 생성
conn = DriverManager.getConnection(DB_URL, DB_USER, DB_PASSWORD);

// 커넥션 풀: 풀에서 대여
conn = dataSource.getConnection();
```

코드는 한 줄 차이지만, 내부 동작이 완전히 다르다. `conn.close()`를 호출해도 실제로 끊지 않고 **풀에 반납**한다.

### 성능 비교 실습 (PerformanceTest)

INSERT 10회 반복 실행으로 소요 시간 비교.

```java
// 커넥션 풀 없이 10번 INSERT
long start1 = System.currentTimeMillis();
for(int i = 1; i <= 10; i++){
    JdbcPostPreparedTest.insert(2, "커넥션 풀 사용 안함 = " + i, "내용");
}
long end1 = System.currentTimeMillis();
System.out.println("커넥션 풀 미사용: " + (end1 - start1) + "ms");

// 커넥션 풀 사용하여 10번 INSERT
long start2 = System.currentTimeMillis();
for(int i = 1; i <= 10; i++){
    ConnectionPoolTest.insert(2, "커넥션 풀 사용 함 = " + i, "내용");
}
long end2 = System.currentTimeMillis();
System.out.println("커넥션 풀 사용: " + (end2 - start2) + "ms");
```

> 커넥션 풀 사용 시 매번 연결을 새로 맺지 않으므로 반복 실행에서 확연한 속도 차이가 난다.

## 배운점

1. ✅ SQL 컬럼 별칭(`AS` 생략 가능)을 붙이면 Java에서 별칭으로 `rs.getString("별칭")` 호출 가능.
2. ✅ `executeQuery()` → ResultSet 반환 (SELECT), `executeUpdate()` → int 반환 (INSERT·UPDATE·DELETE).
3. ✅ PreparedStatement의 `?` 바인딩이 SQL Injection을 원천 차단 — 특수문자를 이스케이프 처리.
4. ✅ `findAll("")` / `findAll("키워드")`처럼 오버로딩 + 조건부 SQL로 동적 검색을 구현할 수 있다.
5. ✅ 커넥션 풀(HikariCP)은 연결을 미리 만들어 재사용 — 반복 작업에서 DriverManager보다 빠르다.
6. ✅ HikariCP는 SLF4J 2개 jar도 함께 등록해야 에러 없이 동작한다.
7. ✅ properties 파일로 DB 설정을 분리하면 코드 수정 없이 환경 변경 대응 가능.
8. ✅ `conn.close()`가 커넥션 풀에서는 연결 종료가 아닌 반납 — 풀 사용 후에도 반드시 호출해야 한다.

## 오늘 핵심 정리

```
Statement vs PreparedStatement
  Statement        → SQL 문자열 직접 조합, SQL Injection 위험
  PreparedStatement → ? 바인딩, SQL Injection 차단, 실무 표준

PreparedStatement CRUD 패턴
  pstmt = conn.prepareStatement(sql);  // SQL 사전 컴파일
  pstmt.setInt(1, value);              // ? 위치(1부터 시작)에 값 바인딩
  pstmt.executeQuery()                 // SELECT → ResultSet
  pstmt.executeUpdate()               // INSERT·UPDATE·DELETE → int

동적 SQL 패턴
  조건에 따라 sql 문자열에 WHERE 절 추가 → prepareStatement() 에 전달
  ? 바인딩도 조건에 따라 분기 처리

커넥션 풀 (HikariCP)
  DriverManager → 매번 새 연결 (느림)
  DataSource    → 풀에서 대여/반납 (빠름)
  conn.close()  → 실제 종료 아닌 풀 반납
  설정: 코드 직접(HikariConfig) or 외부 파일(hikari.properties)
```
