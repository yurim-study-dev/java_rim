## 오전: Exception 클래스 계층 구조 복습

강사님 제공 자료(Java 10 기준, 약간 구버전)를 통해 예외 계층 구조를 다시 살펴봄.  
참고 URL: https://www.falkhausen.de/Java-10/java.lang/Exceptions.html

```
Throwable
├── Error                          → JVM 수준, 복구 불가
│   ├── StackOverflowError
│   └── OutOfMemoryError
└── Exception
    ├── RuntimeException           → Unchecked (컴파일 강제 없음)
    │   ├── NullPointerException
    │   ├── ArithmeticException
    │   ├── ArrayIndexOutOfBoundsException
    │   └── IllegalArgumentException
    └── (그 외)                    → Checked (컴파일러가 처리 강제)
        ├── IOException
        └── SQLException
```

**핵심 복습 포인트:**
- `RuntimeException` 계열 → Unchecked, 처리 강제 안 함 (코드 로직 실수)
- 그 외 Exception → Checked, 반드시 try-catch 또는 throws 필요 (외부 자원 연동)
- 사용자 정의 예외는 보통 `RuntimeException` 상속 권장 (현대 트렌드)

## 오전: MyArray 실습 — ArrayList가 내부적으로 어떻게 동작하는지 직접 구현

`ArrayList`를 직접 만들어 보는 실습. 일반 배열의 단점을 이해하고, 컬렉션이 어떻게 이를 해결하는지 확인.

**일반 배열의 불편한 점:**
- 생성 시 크기를 미리 지정해야 함
- 생성 후 길이 변경 불가
- 요소 추가, 삭제, 삽입이 어려움

### 핵심 구조

```java
public class MyArray {
    private Object[] data;  // 내부적으로 Object 배열로 저장 (어떤 타입도 담을 수 있도록)
    private int count;      // 실제 담긴 요소 수 (data.length는 총 용량, count는 실제 개수)

    public MyArray() { this(10); }          // 기본 크기 10
    public MyArray(int size) {
        this.data = new Object[size];
    }
}
```

### append() — 요소 추가/삽입

```java
// 맨 끝에 추가
public void append(Object elem) {
    append(count, elem);  // count 위치 = 마지막 다음 자리
}

// 특정 index에 삽입
public void append(int index, Object elem) {
    if(count >= data.length) {
        throw new ArrayIndexOutOfBoundsException("더이상 추가할 수 없습니다.");
    }
    // index부터 끝까지 한 칸씩 뒤로 밀기
    System.arraycopy(data, index, data, index + 1, count - index);
    data[index] = elem;
    count++;
}
```

> `System.arraycopy(src, srcPos, dest, destPos, length)` — 배열 일부를 빠르게 복사/이동하는 내장 메서드

### delete() — 요소 삭제

```java
public void delete(int index) {
    if(index >= count) throw new ArrayIndexOutOfBoundsException(index + " >= " + count);
    if(index < 0)      throw new ArrayIndexOutOfBoundsException(index + " < 0");

    // index+1부터 끝까지 한 칸씩 앞으로 당기기
    System.arraycopy(data, index + 1, data, index, count - index - 1);
    count--;
    data[count] = null;  // 마지막 자리 비우기 (GC가 수거할 수 있도록)
}
```

### toString() — StringBuilder 활용

```java
@Override
public String toString() {
    StringBuilder str = new StringBuilder("[");
    if(count > 0) str.append(data[0]);
    for(int i = 1; i < count; i++) {
        str.append(", ").append(data[i]);
    }
    str.append("]");
    return str.toString();
}
```

> `StringBuilder` — 단일 스레드 환경에서 문자열 조립 시 사용 (`+` 연산보다 훨씬 빠름)  
> `StringBuffer` — 멀티 스레드 환경에서 사용 (동기화 처리됨, 대신 느림)

### 실습 흐름 (MyArrayTest)

```java
MyArray arr = new MyArray(5);  // 크기 5짜리 배열 생성

arr.append(10);   // [10]
arr.append(20);   // [10, 20]
arr.append(30);   // [10, 20, 30]
arr.append(40);   // [10, 20, 30, 40]
arr.append(50);   // [10, 20, 30, 40, 50] → 꽉 참

arr.append(2, 25); // 2번 인덱스에 25 삽입 → 뒤 요소 밀기 → 그런데 이미 꽉 차서 예외 발생!
arr.delete(1);     // 1번 인덱스(20) 삭제 → 앞으로 당기기
```

**ArrayList 내부 동작 원리 요약:**
- 삽입: 뒤 요소를 한 칸씩 밀고 → 빈 자리에 값 넣기
- 삭제: 해당 자리부터 한 칸씩 앞으로 당기기
- 인덱스 벗어나면 `ArrayIndexOutOfBoundsException` 던짐
- 모든 예외 처리가 실제 ArrayList에서도 동일하게 일어남

## 오후: List 인터페이스 - 2.4

`List`는 **순서가 있고 중복을 허용**하는 컬렉션. 대표 구현체로 `ArrayList`와 `LinkedList`가 있음.

**주요 메서드:**

| 메서드 | 설명 |
|--------|------|
| `get(int index)` | 해당 인덱스의 요소 반환 |
| `set(int index, E element)` | 해당 인덱스의 요소를 교체 |
| `add(int index, E element)` | 해당 인덱스에 요소 삽입 |
| `remove(int index)` | 해당 인덱스의 요소 삭제 |
| `indexOf(Object o)` | 해당 객체의 인덱스 반환 |

```java
List<String> arrayList = new ArrayList<>();
arrayList.add("Java");
arrayList.add("Spring");
arrayList.add(1, "JDBC");
arrayList.add(2, "Java"); // 중복 허용
System.out.println(arrayList); // [Java, JDBC, Java, Spring]

List<String> linkedList = new LinkedList<>();
linkedList.add("Docker");
linkedList.add(0, "AWS");
System.out.println(linkedList); // [AWS, Docker]
```

## 오후: MyArray 업그레이드 — 자동 크기 확장 (ch02/list)

오전에 만든 MyArray는 꽉 차면 예외를 던졌는데,  
오후 버전은 **꽉 차면 배열을 1.5배로 자동 확장** — 이게 실제 `ArrayList`의 동작 방식.

```java
public void append(int index, Object elem){
    // 꽉 찼을 때 → 1.5배 크기 새 배열 만들고 기존 데이터 복사
    if(count >= data.length){
        Object[] temp = new Object[data.length + data.length / 2];
        for(int i = 0; i < data.length; i++){
            temp[i] = data[i];
        }
        System.out.println(data.length + " -> " + temp.length); // 크기 변화 출력
        data = temp;
    }
    // 이후 삽입 로직은 동일
    System.arraycopy(data, index, data, index + 1, count - index);
    data[index] = elem;
    count++;
}
```

**테스트:** 초기 크기 5짜리 배열에 500개 데이터를 넣으면?

```
5 -> 7       // 5개 꽉 참 → 7개로 확장
7 -> 10      // 7개 꽉 참 → 10개로 확장
10 -> 15     // ...
15 -> 22
...          // 계속 1.5배씩 늘어남
```

> 실제 `ArrayList`도 동일하게 용량 부족 시 1.5배 확장함. 자주 확장되면 복사 비용이 발생하므로 처음부터 크기를 넉넉히 잡는 게 유리.

## 오후: MyLinkedList 구현 — LinkedList 직접 만들기

LinkedList는 **노드(Node)** 들이 서로 링크로 연결된 구조. 배열 없이 동작함.

### Node — 연결 리스트의 기본 단위

```java
private class Node {
    private Object data;     // 실제 저장할 값
    private Node nextNode;   // 다음 노드의 주소

    Node(Object data){
        this.data = data;
        this.nextNode = null;
    }
}
```

> 각 노드가 "다음 노드가 어디 있는지 주소"를 갖고 있어서 체인처럼 연결됨.

### 전체 구조

```java
private Node header;  // 빈 시작 노드 (실제 데이터 없음, 링크 관리용 더미 노드)
private int size;
```

```
header(null) → [데이터-0] → [데이터-1] → [데이터-2] → null
```

### 삽입 — 링크만 바꾸면 됨

```java
public void appendFirst(Object data){
    Node node = new Node(data);
    node.nextNode = header.nextNode;  // 새 노드가 기존 첫 번째를 가리킴
    header.nextNode = node;           // 헤더가 새 노드를 가리킴
    size++;
}
```

중간에 삽입할 때는 앞 노드(pNode)와 뒤 노드(nNode) 사이에 새 노드를 끼워 넣음:

```java
newNode.nextNode = nNode;   // 새 노드 → 뒤 노드
pNode.nextNode = newNode;   // 앞 노드 → 새 노드
```

### 삭제 — 링크를 건너뜀

```java
pNode.nextNode = nNode;  // 앞 노드가 삭제할 노드를 건너뛰고 다음 노드를 가리킴
```

### 조회 — 처음부터 링크를 타고 순회

```java
private Node getNode(int index){
    Node node = header.nextNode;
    for(int i = 0; i < index; i++){
        node = node.nextNode;  // 한 칸씩 이동
    }
    return node;
}
```

> 배열처럼 인덱스로 바로 접근 불가 — 처음부터 순서대로 따라가야 함. 이게 LinkedList 조회가 느린 이유.

## 오후: ArrayList vs LinkedList 최종 비교

| 항목 | ArrayList | LinkedList |
|------|-----------|------------|
| 내부 구조 | 가변 배열 | 노드 + 링크 연결 |
| 인덱스 조회 | 빠름 (바로 접근) | 느림 (처음부터 순회) |
| 맨 앞/중간 삽입·삭제 | 느림 (요소 이동 필요) | 빠름 (링크만 변경) |
| 맨 뒤 삽입·삭제 | 빠름 | 빠름 |
| 메모리 | 적음 | 많음 (노드마다 주소값 저장) |
| **실무 선택** | **대부분의 경우 사용** | 맨 앞 삽입/삭제가 매우 잦을 때 |

## 배운점

1. ✅ Exception 계층에서 `RuntimeException` 은 Unchecked — 컴파일러가 처리를 강제하지 않아서 코드가 간결해짐.
2. ✅ ArrayList는 내부적으로 `Object[]` 배열을 쓰고, 삽입/삭제 시 `System.arraycopy`로 요소를 밀거나 당김.
3. ✅ `count`(실제 요소 수)와 `data.length`(배열 총 용량)는 다름 — 이 구분이 동적 배열의 핵심.
4. ✅ `StringBuilder`는 문자열 조립 시 `+` 연산보다 효율적 — 문자열을 반복적으로 붙일 때 사용.
5. ✅ 중간 삽입/삭제 시 요소 이동 비용이 발생한다는 게 ArrayList의 단점 — 직접 구현해보니 왜 느린지 체감됨.
6. ✅ ArrayList는 용량 초과 시 1.5배 확장 — 이 과정에서 배열 전체 복사가 일어남.
7. ✅ LinkedList는 노드 + 링크 구조 — 삽입/삭제는 링크만 바꾸면 되니 빠르지만, 조회는 처음부터 순회해야 해서 느림.
8. ✅ PerformanceTest로 직접 측정해보면 맨 앞 삽입에서 LinkedList가 압도적으로 빠름 — 이론이 실제로 증명됨.

## 오늘 핵심 정리

```
Exception 계층
  Checked   → IOException, SQLException → try-catch 또는 throws 필수
  Unchecked → RuntimeException 계열    → 처리 선택 사항

MyArray (= ArrayList 직접 구현)
  Object[] data  → 내부 저장 배열 (타입 무관하게 저장)
  int count      → 실제 요소 수 (용량 data.length와 다름)
  용량 초과 시   → 1.5배 크기 새 배열 생성 후 복사 (실제 ArrayList와 동일)

요소 삽입 (append)
  System.arraycopy로 index 이후 요소들을 한 칸 뒤로 밀기 → 빈 자리에 값 저장

요소 삭제 (delete)
  System.arraycopy로 index+1 이후 요소들을 한 칸 앞으로 당기기 → 마지막 칸 null 처리

MyLinkedList (= LinkedList 직접 구현)
  Node: data + nextNode(다음 노드 주소) 로 구성
  header: 더미 시작 노드 (실제 데이터 없음, 링크 관리용)
  삽입: 링크 2개만 변경 → 빠름
  삭제: 앞 노드가 삭제 노드를 건너뜀 → 빠름
  조회: 처음부터 링크 타고 순회 → 느림

ArrayList vs LinkedList
  조회 많음      → ArrayList
  맨 앞 삽입 많음 → LinkedList
  실무 대부분    → ArrayList

StringBuilder vs StringBuffer
  StringBuilder → 싱글 스레드용, 빠름
  StringBuffer  → 멀티 스레드용, 동기화 지원 (느림)
```
