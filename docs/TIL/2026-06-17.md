### 문제 1: 게시글 목록 조회

- 작성자 이름, 댓글 수 포함
- **24시간 이내** 게시글 → 제목 앞에 `(New)` 추가
- **댓글 3개 이상** 게시글 → 제목 앞에 `(Best)` 추가
- 최신 등록순 정렬

```sql
SELECT 
    p.id,
    CONCAT(
        IF(p.created_at >= NOW() - INTERVAL 1 DAY, '(New) ', ''),
        IF(COUNT(r.id) >= 3, '(Best) ', ''),
        p.title
    ) AS title,
    m.name AS writer_name,
    COUNT(r.id) AS reply_count,
    p.created_at
FROM post p
LEFT JOIN member m ON p.member_id = m.id
LEFT JOIN reply r ON p.id = r.post_id
GROUP BY p.id, p.title, m.name, p.created_at
ORDER BY p.created_at DESC;
```

> `IF()` 안에 `COUNT()` 집계 함수를 중첩 사용할 수 있다. `GROUP BY` 이후에 집계 결과가 확정되므로 `CONCAT`과 함께 사용 가능.

### 문제 2: 게시글 상세 조회

게시글 제목/내용/작성자 + 댓글 작성자 이름/댓글 내용을 한 번의 쿼리로 조회.

핵심 포인트: **같은 `member` 테이블을 두 번 조인** — 게시글 작성자와 댓글 작성자를 별칭으로 구분.

```sql
SELECT 
    p.title AS post_title,
    p.content AS post_content,
    m.name AS post_writer_name,
    m.email AS post_writer_email,
    rm.name AS reply_writer_name,
    r.content AS reply_content
FROM post p
LEFT JOIN member m ON p.member_id = m.id       -- 게시글 작성자
LEFT JOIN reply r ON p.id = r.post_id           -- 댓글
LEFT JOIN member rm ON r.member_id = rm.id;     -- 댓글 작성자 (member 두 번째 조인)
```

## 오후: 트랜잭션(Transaction) - 6

### 트랜잭션이란?

데이터베이스의 상태를 변경하는 여러 작업을 **하나의 논리적 단위**로 묶은 실행 흐름.

예시: A 계좌 → B 계좌 송금
- A 잔액 차감 (UPDATE)
- B 잔액 증가 (UPDATE)

두 작업이 **모두 성공하거나 모두 실패**해야 데이터 정합성이 유지된다. 둘 중 하나만 성공하면 큰일남.

---

### ACID 성질

트랜잭션이 안전하게 수행되기 위한 4가지 핵심 규칙.

| 성질 | 영문 | 설명 |
|------|------|------|
| **원자성** | Atomicity | 모두 성공 or 모두 실패 — 부분 성공 없음 |
| **일관성** | Consistency | 트랜잭션 후에도 제약 조건·규칙을 만족하는 유효한 상태 유지 |
| **격리성** | Isolation | 동시에 실행되는 트랜잭션들이 서로 간섭하지 않음 |
| **지속성** | Durability | 완료된 트랜잭션 결과는 장애가 생겨도 영구 보존 |

> **격리성 구현 방식**: 대부분의 RDBMS는 락킹 대신 **MVCC(Multi-Version Concurrency Control, 다중 버전 동시성 제어)** 기법을 사용 → 읽기와 쓰기를 동시에 처리하면서도 격리성 확보

---

### COMMIT & ROLLBACK

| 명령 | 설명 |
|------|------|
| `COMMIT` | 트랜잭션 내 모든 변경을 DB에 영구 반영. 다른 세션에서도 즉시 조회 가능 |
| `ROLLBACK` | 트랜잭션 시작 전 상태로 모든 변경 취소. 원자성 보장의 안전장치 |

---

### 트랜잭션 제어 SQL

```sql
-- 1. 트랜잭션 시작
START TRANSACTION;

-- 2. 비즈니스 쿼리 실행
DELETE FROM post WHERE member_id = 2;   -- 탈퇴 회원의 게시글 삭제
DELETE FROM member WHERE id = 2;        -- 회원 삭제

-- 3-a. 정상 완료 시 영구 반영
COMMIT;

-- 3-b. 오류 발생 시 원래 상태로 복구
ROLLBACK;
```

> `post.member_id`의 FK가 `ON DELETE SET NULL`이라서, 회원 삭제 시 게시글도 함께 삭제하려면 **회원 삭제 전에 게시글을 먼저 삭제**해야 한다.

---

### DBeaver 트랜잭션 모드 주의

| 모드 | 동작 |
|------|------|
| **Auto-Commit** (기본값) | DML(INSERT/UPDATE/DELETE) 실행 즉시 자동 반영 → ROLLBACK 불가 |
| **Manual Commit** | START TRANSACTION과 동일, 명시적 COMMIT/ROLLBACK 필요 |

수동 제어 방법:
- DBeaver: `Database > Transaction mode > Manual Commit`
- SQL: `START TRANSACTION` 명시적으로 실행

---

### 격리성 실습 (transaction-A / transaction-B)

두 개의 세션을 동시에 열어 격리성 동작을 확인.

- **세션 A** (`transaction-A.sql`): `START TRANSACTION` → DELETE 실행 → COMMIT/ROLLBACK
- **세션 B** (`transaction-B.sql`): `SELECT * FROM post` / `SELECT * FROM member`

세션 A가 COMMIT 전에는 세션 B에서 조회해도 변경 사항이 보이지 않음 → **격리성 확인**

## 오후: 트랜잭션 심화 - 6.2.4 / 6.2.5

### SQL 분류에 따른 트랜잭션 지원 여부 - 6.2.4

모든 SQL이 ROLLBACK 대상이 되는 건 아니다.

| SQL 종류 | 대상 쿼리 | 트랜잭션 지원 |
|----------|-----------|--------------|
| **DML** | INSERT, UPDATE, DELETE | ✅ ROLLBACK 가능 |
| **DDL** | CREATE, ALTER, DROP, TRUNCATE | ❌ 즉시 영구 반영 |
| **DCL** | GRANT, REVOKE | ❌ 즉시 영구 반영 |

> **암묵적 커밋(Implicit Commit)**: 트랜잭션 도중 DDL/DCL 쿼리를 실행하면, 이전까지 수행한 DML이 강제로 커밋됨. 이후 ROLLBACK을 호출해도 DML 작업을 되돌릴 수 없다.

---

### 격리 수준 (Isolation Level) - 6.2.5

동시에 실행되는 트랜잭션들이 서로 얼마나 고립되어 있는지를 정의하는 설정.

**격리 수준에 따른 데이터 부정합 문제 3종**

| 문제 | 설명 |
|------|------|
| **Dirty Read** | 아직 커밋 안 된 데이터를 다른 트랜잭션이 읽음 |
| **Non-repeatable Read** | 같은 데이터를 두 번 읽었을 때 중간에 수정/삭제돼서 결과가 다름 |
| **Phantom Read** | 같은 조건으로 두 번 조회했을 때 중간에 삽입돼서 없던 행이 나타남 |

**격리 수준 4단계**

| 격리 수준 | Dirty Read | Non-repeatable Read | Phantom Read | 특징 |
|-----------|-----------|---------------------|--------------|------|
| **Read Uncommitted** | 발생 | 발생 | 발생 | 가장 빠름, 실무 거의 미사용 |
| **Read Committed** | 방지 | 발생 | 발생 | Oracle·SQL Server 기본값 |
| **Repeatable Read** | 방지 | 방지 | 발생 (MySQL은 대부분 예방) | **MySQL/MariaDB 기본값** |
| **Serializable** | 방지 | 방지 | 방지 | 가장 엄격, 성능 최저 |

```sql
-- 현재 격리 수준 확인 (MySQL 8.0 이상)
SELECT @@transaction_isolation;

-- 현재 세션 격리 수준 변경
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

## 오후: 데이터 무결성 - 6.3

데이터베이스에 저장된 데이터의 **정확성, 일관성, 유효성**을 보장하는 성질.

| 무결성 종류 | 설명 | 구현 |
|------------|------|------|
| **개체 무결성** | PK는 NULL 불가, 중복 불가 — 각 행이 고유하게 식별 | `PRIMARY KEY` |
| **참조 무결성** | FK 값은 참조 테이블의 PK 값과 일치하거나 NULL이어야 함 | `FOREIGN KEY` + `ON DELETE` |
| **도메인 무결성** | 컬럼에 입력되는 데이터가 정의된 타입·길이·규칙을 만족해야 함 | `NOT NULL`, `UNIQUE`, `CHECK` |

## 오후: JDBC 프로그래밍 - 7

### JDBC란?

자바 애플리케이션에서 다양한 RDBMS에 **표준화된 방식**으로 접속하여 SQL을 실행할 수 있도록 지원하는 자바 표준 API.

```
[자바 앱] → [JDBC 인터페이스(java.sql)] → [JDBC 드라이버(각 DB 제조사 제공)] → [DB]
```

- JDBC 인터페이스: `Connection`, `Statement`, `PreparedStatement`, `ResultSet` 등 (`java.sql` 패키지)
- JDBC 드라이버: DB 제조사가 jar 파일로 제공 (MySQL → `mysql-connector-j-xxx.jar`)
- JDBC 4.0 이후 드라이버 자동 감지 — `Class.forName()` 명시적 호출 불필요

---

### 연결 URL 형식

```
jdbc:mysql://[호스트]:[포트]/[DB명]?serverTimezone=UTC&useSSL=false&allowPublicKeyRetrieval=true
```

| 옵션 | 의미 |
|------|------|
| `serverTimezone=UTC` | 자바↔DB 간 시간대 차이 보정 |
| `useSSL=false` | 로컬 개발 환경에서 SSL 검증 생략 |
| `allowPublicKeyRetrieval=true` | 비밀번호 암호화용 공개 키 가져오기 허용 |

---

### JDBC 핵심 인터페이스

| 인터페이스 | 역할 | 주요 메서드 |
|-----------|------|------------|
| `DriverManager` | DB 연결 생성 | `getConnection(url, user, pw)` |
| `Connection` | DB 세션 표현, Statement 생성 | `createStatement()`, `prepareStatement()`, `commit()`, `rollback()` |
| `Statement` | SQL 전송 (SQL Injection 위험) | `executeQuery()`, `executeUpdate()` |
| `PreparedStatement` | 파라미터화된 SQL, SQL Injection 차단 | `setString()`, `setInt()`, `executeQuery()`, `executeUpdate()` |
| `ResultSet` | SELECT 결과 집합, 커서로 행 순회 | `next()`, `getString()`, `getInt()` |

> 실무에서는 `Statement` 대신 **`PreparedStatement`** 사용 권장 — SQL Injection 원천 차단 + 재사용 시 성능 유리.

---

### JDBC 5단계 프로세스

```
1. DB 연결 설정    → DriverManager.getConnection()으로 Connection 획득
2. SQL 실행 객체   → conn.prepareStatement(sql)으로 PreparedStatement 생성
3. 매개변수 바인딩 → pstmt.setString(1, value) 등으로 ? 채우기
4. SQL 실행 & 결과 → executeQuery() (SELECT) / executeUpdate() (INSERT·UPDATE·DELETE)
5. 리소스 역순 해제 → rs → pstmt → conn 순서로 close() (생성의 역순)
```

---

### JDBC 실습 코드 요약

```java
// PreparedStatement로 SELECT
String sql = "SELECT id, email, name FROM member";
conn = DriverManager.getConnection(DB_URL, DB_USER, DB_PASSWORD);
pstmt = conn.prepareStatement(sql);
rs = pstmt.executeQuery();

while (rs.next()) {
    int id = rs.getInt("id");
    String email = rs.getString("email");
    String name = rs.getString("name");
    System.out.println("ID: " + id + ", 이메일: " + email + ", 이름: " + name);
}

// PreparedStatement로 INSERT (? 바인딩)
String sql = "INSERT INTO member (email, password, name, phone) VALUES (?, ?, ?, ?)";
pstmt = conn.prepareStatement(sql);
pstmt.setString(1, "test@gmail.com");
pstmt.setString(2, "pwd123");
pstmt.setString(3, "테스트");
pstmt.setString(4, "01012345678");
int affectedRows = pstmt.executeUpdate();
```

> `executeQuery()` → ResultSet 반환 (SELECT용)  
> `executeUpdate()` → 영향받은 행 수(int) 반환 (INSERT·UPDATE·DELETE용)

## 배운점

1. ✅ 같은 테이블을 별칭으로 여러 번 JOIN할 수 있다 — 게시글 작성자, 댓글 작성자 동시 조회할 때 유용.
2. ✅ `CONCAT(IF(...), IF(...), 컬럼)` 패턴으로 조건부 접두사를 동적으로 붙일 수 있다.
3. ✅ DML만 ROLLBACK 대상 — DDL/DCL은 실행 즉시 영구 반영(암묵적 커밋 주의).
4. ✅ 격리 수준이 높을수록 데이터 일관성↑, 동시성↓ — MySQL 기본값은 Repeatable Read.
5. ✅ Dirty Read / Non-repeatable Read / Phantom Read 세 가지 부정합 문제와 각 격리 수준이 막는 범위를 기억할 것.
6. ✅ 데이터 무결성 3종: 개체(PK), 참조(FK), 도메인(NOT NULL·UNIQUE·CHECK).
7. ✅ JDBC는 인터페이스 표준 — DB가 바뀌어도 드라이버만 교체하면 코드 변경 최소화.
8. ✅ Statement 대신 PreparedStatement — SQL Injection 차단 + 성능 향상.
9. ✅ JDBC 리소스는 반드시 역순(rs → pstmt → conn)으로 close() — 메모리 누수 방지.

## 오늘 핵심 정리

```
게시판 종합 실습 핵심
  IF() 중첩 + CONCAT       → 조건부 태그 동적 생성 ((New), (Best))
  member 테이블 이중 JOIN  → 게시글 작성자 / 댓글 작성자 동시 조회
  LIKE '%검색어%'          → 제목 OR 내용 다중 조건 검색
  LIMIT n OFFSET m         → 페이징 (m = (페이지-1) × 개수)

트랜잭션
  ACID: 원자성 / 일관성 / 격리성(MVCC) / 지속성
  START TRANSACTION → COMMIT(영구) / ROLLBACK(취소)
  DML만 롤백 가능 — DDL/DCL은 암묵적 커밋 발생

격리 수준 (높을수록 안전, 느림)
  Read Uncommitted → Read Committed → Repeatable Read(MySQL 기본) → Serializable

데이터 무결성
  개체: PK (NULL·중복 불가)
  참조: FK (존재하는 PK만 참조)
  도메인: NOT NULL / UNIQUE / CHECK

JDBC 5단계
  Connection → PreparedStatement → 바인딩(?) → execute → close(역순)
  SELECT: executeQuery() → ResultSet.next() 루프
  DML:    executeUpdate() → int(영향받은 행 수)
```
